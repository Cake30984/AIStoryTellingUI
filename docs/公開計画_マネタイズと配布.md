## 0. 製品の位置づけ（すべての前提）

**「ノベルゲーム」ではなく「挿絵入りの本（ライトノベル形式）」を目指す。**

VN の画面構成（絵がメイン・文章は下のボックス）は AI 生成と構造的に噛み合わない。**AI の出力を事前に予測できない＝素材を用意しておけない**から。挿絵は「本文の後から生成する」ので、この問題が原理的に起きない。

| 要素 | 決定 | 根拠 |
|---|---|---|
| 全面背景・立ち絵（透かし） | **廃止** | 同一ピクセルに2つの注意対象を置く構造問題。濃さ調整では解けない（絵は見るに堪えず・文字はコントラストを失う両損） |
| 挿絵 | **残す**（本文フローに挟む図版） | 視線が「読む→絵→続きを読む」と逐次になり競合しない。ラノベの形式そのもの |
| 挿絵の役割 | 読解補助では**なく**、**獲得（SNS拡散）・報酬（収集）資産** | 絵を足しても体験の95%は読むこと。読まない層は絵の有無で動かない |
| 音 | 単一のアンビエント床か**無音** | 情報量の多い素材（セミの声＝夏・屋外・昼）は予測不能な文章に否定されて壊れる |
| ムード色 | 将来の代償措置として検討 | 背景喪失で失う「持続する空気感」を、文字と喧嘩しない色で部分的に補う |

**「本に寄せるとパイが狭まる」への結論：狭まらない。** 選択肢は「狭い読書層 vs 広い絵の層」ではなく「狭い読書層をちゃんと満たす vs 中途半端に満たして絵の層も獲れない」。反証＝なろう・カクヨム・キャラチャットは挿絵ゼロで巨大規模。

**成長レバーは絵ではない：** ①**インタラクション密度**（3000字を黙って読ませるより 300字×10回＋毎回選択）②**絵の量をユーザーが選べる可変比率**（VN は制作時に焼き込まれるが AI 生成は可変。しかも絵を欲しがる層ほど計算コストを食う＝課金意欲と一致）。

## 1. プラットフォームと規約

### 1.1 結論：DLsite ＝ 棚（集客）／BOOTH ＝ 母艦（自由）／Steam ＝ 回避

| | 役割 | 置くもの |
|---|---|---|
| **DLsite** | 集客。棚に並ぶこと自体が広告 | 制作版（ツール/アクセサリ）、カセット（作品として主要フロアへ） |
| **BOOTH** | 自由度。審査なし・頻繁な更新可 | 無料版の配布、実験版 |
| **Steam** | **使わない** | — |

### 1.2 Steam を避ける理由

- 決済の圧力元は Steam ではなく**カード会社**。逃げ先は「Steam 以外」ではなく「この種の作品を前提に決済網が組まれている場所」＝ DLsite / BOOTH。
- Steam は**アプリ内課金の外部決済を認めない**＝ BYOK と構造的に相性が悪い。
- ライブ生成 AI は「違法コンテンツを防ぐガードレールがある旨」の表明が要る。BYOK では「保証できません」になり審査摩擦になる。

### 1.3 DLsite はツールを扱う（当初の想定は誤り）

**【公式・実地確認】** 作品形式「ツール/アクセサリ」が**通常の同人フロア**に約 1,089 件（[一覧](https://www.dlsite.com/home/works/type/=/work_type/TOL)）。RPGツクールMZ／SRPG Studio／ティラノビルダー PRO／**HermitNode「孤高のAI執筆室」(¥990)**／Waifu2x (¥55) など。

- 「DLsite はツールを扱わない」という線引きは**存在しない**。
- **ティラノビルダーは本計画のほぼ完全な先例**（エンジンをツールとして売り、作品は各作者が売り、ランタイムは無料）。

### 1.4 AI 生成フロアの隔離リスク

**【公式】** AI生成フロアは既存フロアから分離した独立フロア（全年齢 <https://www.dlsite.com/ai/> ／ R18 <https://www.dlsite.com/aix/>）。ユーザー側に「AI一部利用を除外」チェックもある。

**【公式】** 区分の定義（[エイシス告知](https://info.eisys.co.jp/dlsite/bb3b0b976520e0fd?locale=default)）：**AI生成作品**＝「AIでの生成物をメインコンテンツとして利用している場合」／**AI一部利用**＝「マンガ、ゲームの背景使用等、利用が限定的な部分に留まり」利用者がその限定性を認識できる場合。

**本体（ツール）は隔離対象外の線が濃い。** 根拠：①HermitNode・Waifu2x が通常フロアのツール棚にある ②AIフロアのルール群（収録枚数上限・LoRA規制・写実NG・PSD提出）は明らかに**同梱される事前生成素材**を想定 ③本製品は**出荷物に AI 生成物が1バイトも含まれず**、生成は購入者が自分の契約で実行時に行う。

> **AI補助ツールに DLsite が厳しいとする記事は、作者が自分の絵をAIで作った場合の話**であり軸が違う。

**AI一部利用は同人フロア（通常フロア）で取り扱われる。隔離されるのは「AI生成作品」だけ。**【公式】

#### ⚠ 決定的な条項（2026-08-11 に一次情報で確認）

サークル向けヘルプの **FAQ 本体**に、画像以外の条項が明記されていた。`※` の注記ブロックだけを読んでいたため見落としていた。

| 対象 | 【公式】条文 | 本計画への影響 |
|---|---|---|
| **ノベル作品の文章** | **「AIを利用して文章の大部分を作成した場合には『AI生成作品』となります」** | **カセットの本文を AI で書くとフロア隔離。§3.4 の制作方針が確定的に変わる** |
| ノベル作品の挿絵 | 表紙・挿絵のみなら AI一部利用。ただし**挿絵の比率が本体データの30%以上**なら AI生成作品 | カセットに画像を同梱しない設計なら 0%＝該当しない |
| **ゲームのプログラミング** | 補助的・部分的なら**どちらにも該当しない**。**「プログラムの大部分をAIに書かせた場合のみ『AI生成作品』に該当」** | **本体（ツール）に直撃しうる新論点**。§4.1 で確認 |
| 市販の AI 音声合成 | タグ不要 | 該当なし |

**上の3根拠は「製品が何を出荷するか」の軸しか見ていない。** プログラミング条項は「**製品がどう作られたか**」という別の軸で、既存の根拠は1つも当たらない。HermitNode の先例も「AI を使うツールが通常フロアにある」ことを示すだけで、「AI が書いたプログラムが通常フロアにある」ことは示さない。

#### 立証責任は出品者側にある（重要）

> 【公式】AI生成物を利用したとみられるが、AIオプションの設定が適切ではないと判断される場合、**内製・外注の如何を問わずその証明を求める場合があります。** AIの利用状況について判然となる証明資料がいただけない場合、当該作品に**AIオプションを設定・変更させていただくことがあります。**

具体的な証明手続き（PSD 等の制作過程データ提出）は**画像についてのみ**書かれており、文章・プログラムに対応する手続きは示されていない。しかし上の一般条項は媒体を限定していない。

→ **「AI が書いたか証明できないから安全」ではなく、「証明できないと DLsite 側が付与する」**。目標は「バレないこと」ではなく「**疑われないこと**」と「疑われたときに出せる材料があること」。
→ 実務：**執筆・開発の過程を残す**（カセットは下書きと改稿の履歴、本体は Git の履歴と `docs/` の設計判断記録）。これがそのまま証明資料になる。

#### AI生成フロアに落ちた場合の実コスト【公式】

- **申請は各月3作品まで**（申請日基準・複数サークルでの回避は取引停止の対象）
- 販売希望日に応えられず、販売日・審査状況の問い合わせにも回答されない
- 女性向け・スマホゲームは新規受付停止中
- 写実的な AI 生成イラストは取扱不可／モザイク要件

**月3本の上限は、カセットの量産戦略を制度側から頭打ちにする。** 通常フロアを維持することの価値は、当初の想定より高い。

### 1.5 TRPG 二次創作と SPLL

**【公式】** DLsite は TRPG 二次創作の公式電子出版サイトで SPLL を運用（[告知](https://info.eisys.co.jp/dlsite/7b39a26bf1a41f67?locale=default)）。対象は**ガイドライン掲載の特定 TRPG のみ**／登録前に**申請番号の取得**が必要／**売上に対しライセンス料 10%**（公式の計算例：1,000円の作品で作者手取り 479円）。

**オリジナル世界観なら無関係。** ただし UGC を進めるなら**カセット作者向けの手続き案内**が要る。裏返せば、TRPG 層が公式に招かれている事実はターゲット選定の裏付け（CoC もシノビガミも画面は文字とダイスだけ＝**絵がなくても金を払うことを実証済みの客**）。

### 1.6 成人向け：3つの決定に分解する

| | 決定 | 判断 |
|---|---|---|
| a | 技術的にフィルタしない | **YES**（BYOK＝道具屋の帰結） |
| b | **本体を R18 作品として登録する** | **NO** |
| c | カセットの R18 を許す／自分でも作る | **YES**（ここが R18 市場の収益経路） |

**b を NO にする理由：**

- **【二次】** DLsite では成人向けが全年齢の **10倍以上**売れる（[濡羽十色](https://note.com/dlwatcher/n/nfe0db6350561)）。
- しかし **RPGツクールもティラノビルダーも全年齢ソフト**。R18 フロアが両者の製作物で溢れているのに、**エンジン自体に R18 ラベルは付いていない**。
- 全年齢にすると：全年齢フロアに載る＋R18 フロアのカセットからも逆流を受ける＝**両取り**。R18 にすると：全年齢フロアを丸ごと失い、**ツールは「抜けるかどうか」で買われない**のでリターンがない。

**BYOK との衝突（重要）：【公式報道】** 主要モデルは現状ほぼ全て成人向けを禁止（OpenAI の adult mode は **2026年3月に無期限保留**、Anthropic・Google も禁止）。→ R18 を看板に買った人が案内どおり Gemini 無料枠を設定し最初のシーンで拒否される＝**最悪の初体験**。返金とレビュー爆撃のコンボ。

**したがって：訴求しない・塞がない。** 実装で必要なのはフィルタ削除ではなく**モデル選択の案内**（§5.7）。**ローカルモデル（Ollama / LM Studio）が最も正直な着地点**＝外部サービスの規約に一切触れない。

**テキスト主体は法的に有利：** 文章は成人向けの流通が確立しモザイク等は直接かからない。画像は刑法175条・AI生成フロア規則が絡むが、**実行時にユーザーの手元で生成する＝頒布ではない**ので本体側には原則かからない。**危険なのはカセットに画像を同梱した瞬間**（そこで初めて「自分が頒布している」になる）→ **カセットに画像を同梱しない設計**で構造的に回避（§5.2 #7）。

**絶対に譲れない線：** ①**未成年の性的描写**を自分が配る看板カセット・サンプル・宣伝物に入れない ②**ストアページ・サンプル・宣伝物**で成人向けを売り文句にしない。

### 1.7 クレジット販売はしない

理由は重要な順に：

1. **クレジットを売って自分の鍵で回すと、自分がコンテンツ生成の当事者になる。** 出力の責任・決済事業者への説明責任・通報対応が全部乗る。BYOK なら「テキストエディタを売っている道具屋」で済む。**これが本質的な理由。**
2. **APIキーを取れない人への救済は OpenRouter 誘導で足りる**（1回の登録で全モデルに届き、決済もコンプラも先方が持つ）。自作するより圧倒的に得。
3. 残高型のクレジット（前払式支払手段）は資金決済法の対象になりうる。ただし**届出義務の閾値は基準日未使用残高 1,000万円超**とされ、同人規模では実質到達しない。**この理由を主軸に置かないこと**（金額が小さければ平気、と自分で判断を覆す余地を残すため）。要確認。
4. **【未確認】** DLsite サークル規約に、追加課金・外部決済・外部サービス必須の作品に関する条項は**見つからなかった**（禁止も許可もされていない）。<https://www.dlsite.com/home/circle/regulations>

## 2. 商品構成と価格

### 2.1 三層モデル（2026-08-10 改訂）

| 層 | 内容 | 価格 | 置き場 |
|---|---|---|---|
| **無料版＋無料カセット** | プレイヤーとして**無制限**。**短編カセット2〜3本を同梱**し、キー設定直後に遊べる状態で配る | ¥0 | BOOTH・自サイト・DLsite（無料頒布） |
| **カセット（有料）** | 長編。**無料版との差は「長さ・完成度」であって質ではない** | ¥300〜700 | DLsite / BOOTH（第三者作者も販売） |
| **制作版** | **エンジンの制作ライセンス**。キャラ・世界観の作成／カセットの書き出し | ¥2,500〜3,500（初期は下限寄り） | DLsite（ツール/アクセサリ） |

**価値のはしご：** 無料で遊ぶ → もっと長い話を数百円で買う → 自分でも作りたくなって数千円払う。

**なぜ無料カセットを先に置くのか（改訂の理由）：**
カセットは「別途ランタイムを落とす → API キーを取る → 従量課金」を買い手に要求する。**集客導線が製品全体で最も高い障害物をそのまま相続している**（ツクール製の作品はダブルクリックで動くので、この点でツクール構造の前提を満たしていない）。**無料にすると返金もレビュー爆撃も起きない**ので、この相続コストが消える。

**有料カセットとの差は長さで付ける。** 質で差を付けると無料版が「劣化版」になり、拡散担当としての役割を果たさなくなる。VN の体験版と同じ構造。

**制作版に全カセットを同梱しない。** 制作版が売るのは**コンテンツではなく作る権利**。同梱するとカセット売上と本体売上が食い合う。

### 2.2 値付けの根拠

- DLsite のツール棚は二極化：**ユーティリティ ¥55〜990／制作エンジン数千円**。→ **「ユーティリティ」に見えると ¥1,000 の帯に引きずられる。**「エンジン／制作ツール」として提示できるかがそのまま価格帯を決める。
- DLsite はセールが主戦場なので **30〜50%引きに耐える定価**にする。
- → **定価 ¥2,980 ＋ 発売時30%引き**を基本形にする。**「低い定価で出して後から値上げ」は採らない**（セール駆動の市場では定価が安いほど打てる手が減り、値上げは既存購入者への説明も要る。同じ実売価格なら、高い定価＋割引のほうが説明が易しい）。
- カセットは**衝動買いの帯**を外さない。ただし**固定手数料があるので ¥300 単品は率が悪い**（BOOTH のダウンロード商品は「率＋固定額」の形）。**¥500 以上、または複数本セット**にする。

### 2.3 「エディタが薄いのに課金してよいのか」への回答

> **有料ティアが売っているのは、エディタの実装量ではなく「無料ランタイムの観客へのアクセス権」。**

薄いフォームでも、その出力を再生できる人が1万人いれば1万人分の入場券の価値がつく。逆にどれだけ豪華でも遊べる人がゼロなら無価値。**価値は無料ランタイムの普及数に比例し、エディタの実装量はこの式に出てこない。**

「実装が軽いから課金が気引ける」は**労働価値説の罠**。価格は自分の手間ではなく買い手の便益と代替手段で決まる。→ **名乗りを「JSONエディタ」ではなく「AIストーリーエンジン（の制作ライセンス）」に。**

**ただしこの議論は「安すぎないか」への答えであって、発売初日のストアページに書く文言ではない。** 観客がゼロなら「観客へのアクセス権」の価値もゼロだから。**day-1 に訴えるのはこちら：**

- 自分専用の世界を、状態と関係性を保ったまま長く遊べる
- ふつうのチャットでは崩れる条件・数値・エンディングを設計できる
- 破綻を検出して、人に見せられる形に整えられる
- リプレイ／小説として書き出して残せる

**UGC 市場へのアクセスは「将来増える追加価値」として書く。** 順序を逆にすると、まだ存在しないものを売ることになる。

### 2.4 買い切りの維持費（公開前に決めておく）

BYOK は自分のコストがゼロだが、**モデルの入れ替わり・API 仕様変更への追随は永久に発生する**。買い切り1回でこれを賄う答えを、値付けと同時に決めておく（後から言い出すと反発が出る）。

**方針：`v1.x` は無償更新、`v2` は有償アップグレード。** ストアページと利用規約に最初から書く。サブスクは BYOK と噛み合わない（継続的に提供しているものが無い）ので採らない。

## 3. マーケティング戦略

### 3.1 前提：広告費では勝てない

競合は広告を焚いている。同じ土俵では勝てないので、**製品の副産物が勝手に宣伝になる**構造を作る。広告出稿はしない。

### 3.2 集客の本体はカセット

**DLsite のツール棚は入口ではなく着地点。** ツール棚 1,089 件は自分から掘らないと辿り着けない（DLsite の導線は音声・マンガ・ゲームで作られている。**BOOTH でも同じなので逃げても解決しない**）。

ツクール／ティラノビルダーが売れているのは、ツール棚が閲覧されているからではなく、**それで作られた作品が主要フロアに大量に並んでいるから**。

→ **カセット層は本体の唯一の集客導線。本体のストアページを磨くより、カセットを主要フロアに並べるほうが効く。**
→ 自作カセットは、ツールではなく**ゲーム／ノベル作品として**登録する。
→ ただし §2.1 の通り、**その導線は無料でないと摩擦を相続する**。同梱2〜3本に加えて、個別作品としても主要フロアに無料で並べる。
→ **カセットのストアページ冒頭に動作要件（別途ランタイム・API キー必須）を明記する。** 返金とレビューはここでほぼ決まる。

### 3.3 2つの自走する宣伝装置

1. **プレイ結果を小説／リプレイとして書き出せること**
   「本に寄せる」決断の最大の副次効果。VN のセーブデータは他人に見せられないが、**組版された物語テキストはカクヨムにも note にも X にも貼れる**。TRPG 界隈の**リプレイ文化**に直結する。
2. **カセットを1ファイルで配布できること**
   SillyTavern がキャラクターカードで伸びたのと同じ構造。条件やキャラ変数まで組めるので**配布物が「プロンプト」ではなく「作品」になる**。カセットが20本並べば**エンジンの広告が20個、無料で棚に並ぶ**。

### 3.4 自作カセットの進め方（2026-08-10 改訂）

**全年齢と R18 は役割が違う：**

| | 全年齢カセット | R18 カセット |
|---|---|---|
| 役割 | **拡散**（SNS共有・実況可。本体ストアのサンプル兼用） | **到達**（10倍フロアでの発見） |
| 前提モデル | Gemini 無料枠でそのまま動く | 無検閲モデル／ローカルモデルへの案内が必須 |
| 分量 | 看板として厚く | 短編で可 |

R18 は実況・配信が不可能、X でもセンシティブ扱いで検索から落ちる＝§3.3 の拡散仮説と**構造的に相性が悪い**。**順序は全年齢が先**（無料枠オンボーディングの検証を先に済ませないと、不備とモデル拒否が混ざって切り分けられない）。R18 カセットには**モデル設定案内を最初の画面に同梱**する。

#### 本文は人力で書く（2026-08-11 確定・制作方針の変更）

**【公式】「AIを利用して文章の大部分を作成した場合には『AI生成作品』となります」**（§1.4）。

→ **「AI で週末に数本」という制作前提は使えない。** それをやるとカセットが AI生成フロアへ隔離され、**§3.2 の集客導線（主要フロアに並ぶこと自体が広告）が丸ごと消える**。さらに月3本の申請上限がかかるので、量産の目的自体も達成できない。

**カセットの本文（世界観・キャラ定義・ロア・導入文）は人力で書く。** AI の使いどころは、大部分の執筆ではなく次に限る。

- 案出し・叩き台の相談（採用するのは自分の言葉で書き直したもの）
- 校正・整合性チェック
- 条件やイベントの設定漏れの洗い出し

**執筆過程を残す**（下書き・改稿の履歴をファイルで保持）。疑われたときに出せる材料が要る＝立証責任は出品者側にある（§1.4）。

#### 一度に10本作らない（重要）

**生成は速いが、検証は速くならない。** そして上の通り、生成そのものが使えなくなった。カセットの実コストは JSON を書くところではなく、**条件・イベント・エンディングが複数回の周回で本当に発火するかを確かめるところ**にある。壊れたカセットは無料でも評判を削る（金を払っていない人ほどレビューは辛口）。加えて Phase 1 でスキーマが動くので、**先に作った本数はそのまま移行対象の件数**になる。

→ 本文を人力で書く以上、**「少数を厚く」に寄せる**。無料カセットを10本並べる案は撤回し、**同梱2〜3本＋主要フロアに数本**の規模で始める。

**手順：2〜3本 → 計測 → 型が定まってから残りを量産。** 計測するのは売上ではなく次の3つ：

1. **API キー設定の突破率**（起動した人のうち何%が最初の生成に到達したか）
2. **完走率**（エンディングまで到達したか）
3. **詰まった箇所**（どのシーンで離脱したか）

#### 撤退トリガーと不発時の分岐（先に決めておく）

「第三者が現れ始めたら自作をやめる」は、**現れなかった場合に永久に作り続ける**設計になる。§3.5 の「継続的なプレッシャーは性に合わない」と正面衝突する箇所なので、判断を数字にしておく。

- **停止トリガー**：第三者カセットが**月5本以上・3か月連続**で出たら、自作カセットの**新規制作**を停止する
- **停止しても看板は保守する**：エンジンに機能が増えるたびに看板カセットは最良のサンプル兼ドキュメントになる。捨てると毎回作り直しになる
- **不発時の分岐**：公開から**12か月で第三者カセットが累計10本未満**なら、UGC 前提を降ろして**作家業（自作カセットが収益の主軸・エンジンは自分の生産性ツール）**へ切り替える

#### 初期作者の集め方：**個別に声をかけない**（2026-08-10 改訂）

第三者作者は ¥2,500〜3,500 を先払いするが、プレイヤー母数ゼロの段階でそれを買う理由がない（鶏と卵）。→ 制作版の無償配布で埋める。

**ただし「10〜20人へ個別に配る」は採らない。** その案には「声をかける」という隠れコストがあり、§3.5（継続的なプレッシャーは性に合わない）と衝突する。必要なのは継続的な交流ではなく**少数の制作結果**なので、勧誘なしで取れる形にする。

1. BOOTH・自サイトで**「制作者向け公開β」を無料配布**する（募集を置くだけ・個別の声かけはしない）
2. アプリから**テスト結果ファイルを書き出せる**ようにする
3. フォーム（匿名可）で送ってもらう
4. **完成まで到達した人へ v1 制作版を無償提供**する
5. 応募がゼロなら、3〜5人だけ**有償テスター**を募る（金で時間を買う＝関係の継続を買わない）

送ってもらうのは**本文を含まない**次の項目だけ：接続完了までの時間／最初の生成に成功したか／キャラ・世界観を作成できたか／最初のカセットを完成できたか／どの画面で止まったか／エラー分類。

これなら Discord 運営も日常的な SNS 投稿も、作者との継続的な関係も要らない。露出が足りない場合も、20人に DM するより**既存コミュニティの管理者1人に募集投稿の可否を尋ねる**ほうが負担が小さい。

**位置づけ：** 制作版の主顧客は「自分用の世界を作りたい個人」。公式カセットは実例と集客。第三者カセットは**自然に発生したら伸ばす追加要素**であって、作者コミュニティの育成を事業の必須条件にしない。

### 3.5 やらないこと

- **Ci-en / Fanbox**：継続的なプレッシャーが本人の性に合わないため採用しない。初期認知は §3.3 の2つに全振りする。
- **広告出稿**：しない。
- **個別勧誘（DM・SNS でのスカウト）**：しない（§3.4）。
- **生成済み文章による体験デモ**：**却下**（2026-08-10）。理由は制作コストではない（レール式にすれば1本の脚本で足りる）。**レール式デモは「何をしても筋書きが変わらない」ことを実演してしまい、本製品の売り文句の反証になる**から。生成済みモードが使えるのは DLsite 審査での画面遷移確認と操作説明までで、体験版の主軸にはしない。

### 3.6 静的カタログ（マーケットプレイスは作らない）

第三者作品を集める場所は要るが、**決済とファイル配布を自分で抱えない。**

- 決済・配布は DLsite / BOOTH に置いたまま
- 自サイトには**作品検索・対応モデル・想定料金・作者・販売先リンクだけ**を置く静的カタログ
- アプリからそのカタログを開ける
- **規約上可能なら DLsite のアフィリエイトを通す**（第三者作品からも少額の継続収入。返金・成人向け販売・決済の責任は先方が持ったまま）→ **アプリ内リンクでのアフィリエイト利用可否は要確認**

これなら「棚を作る」ことの利益だけ取って、運営コストと法的責任を負わない。

### 3.7 必要規模の見積もり

**三点で持つ。** 楽観だけを計画の前提にしない。

| | 制作版の本数 | 流通総額（¥2,980） |
|---|---|---|
| 悲観 | 50 | 14.9万円 |
| 中央 | 250 | 74.5万円 |
| 楽観 | 1,000 | 298万円 |

**いずれも流通総額**でありプラットフォーム手数料・源泉・税を引いた手取りではない（率＋固定額の手数料があるため、実際の手取りは1本あたり数百円下がる）。**中央値でも続ける気になる価格と工数**に設計する。無理筋なのは「万人に安く広く」のほうで、「狭くて濃い層に、道具として売る」なら買い切りは成立する。

#### 本数ではなくファネルで見る

売上は結果であって操作できない。**Phase 3 以降は次の式で見る。**

```
無料DL数 × 初回生成到達率 × 制作開始率 × 制作版購入率 × 手取り単価
```

計測する指標（§3.4 の3つを含む）：**初回生成までの時間／7日後の再起動率／カセット完走率／制作開始率／制作開始から30日以内の完成率／制作版購入者の公開率／問い合わせ件数と対応時間／有料カセットの購入率と年間購入本数**。

このうち**「問い合わせ件数と対応時間」は売上と同じ重さで見る**。BYOK の支援コストが工数を食い潰すなら、価格ではなく §5.7 の導線を直すべきという信号になる。

### 5.1 無料版と有料版の線引き

**課金点は「配布」ではなく「能力」に置く。**

当初は「作成は自由・配布に課金」を検討したが、**カセットがプレーンテキスト（JSON）である以上この方式は原理的に機能しない**：作成できてしまえば JSON は既にディスク上にあり、「書き出し」は工程ではなく**ファイルをコピーするだけ**＝ゲートを置く場所が物理的に存在しない。逆に他人のカセットを自分のエディタに貼ればそこから改変してフル機能に到達できる。ツクールで配布課金が機能するのは**出力がパッケージだから**（ビルドという実際の工程がある）。本製品はその条件を満たさない。

| 機能 | 無料版 | 制作版 |
|---|---|---|
| カセットを遊ぶ | ○ 無制限 | ○ |
| ペルソナの編集 | ○（**フィールドを絞る**・§5.2 #1） | ○ |
| セッション設定の編集 | ○ | ○ |
| **オーバーレイの編集**（発見ロア・キャラ成長） | **○** | ○ |
| キャラクター／世界観の**閲覧** | ○（読み取り専用） | ○ |
| キャラクター／世界観の**編集・新規作成** | **×** | ○ |
| カセットの作成・書き出し | **×** | ○ |
| 未署名カセットの読み込み | 段階的に運用（§5.5） | ○ |

**閲覧は許可する。** カセットの JSON はどのみち手元にあるので読めること自体は何も渡していない。「こう作るのか」が見えることが**制作版への最も自然な導線**になる。編集操作で「制作版が必要です」と出す。

**オーバーレイは開ける（2026-08-10 追加）。** 旧版は無料版から作る体験を完全に抜いていたが、それでは変換（遊ぶ人→作る人）が「見える」ことだけに依存する。`SessionOverlay` は**セッションに閉じていて配布物にならない**ので、開けても抜け道にならない。「作る楽しさ」の中心＝自分の関与で人物が変わることはここにある。実装と未解決点は `設計_公開前実装.md` R7。

**説明可能な境界：「この物語の中を変える」は無料、「配れる世界を作る」は有料。**

**採らなかった案：無料版でも小規模なカセットを作れるようにし、商用利用だけライセンスで縛る。** 理由は2つ。①無料ビルドに編集コードが入る＝実行時フラグになり §5.3 と正面衝突する ②**非商用ライセンスはこの市場で執行力を持たない**（匿名の販売者を相手に、¥2,980 の製品で違反を追及するコストが常に回収額を上回る）。ツクールで商用ライセンスが機能するのは、法務を持つ会社が売っているから。

**フォークについて：** 他人のカセットを改変して学ぶループは制作版の中だけで回る。無料版にできるのは「読む」まで（§5.5 の暗号化却下の理由からフォークループを外してあるのはこのため）。

**収益上の副次効果：** 課金点が「配布したい人」から「何か作りたい人」に移るので**支払い母数が広がる**。

### 5.2 抜け道の精査

| # | 抜け道 | 対策 | 状態 |
|---|---|---|---|
| 1 | **ペルソナに全部書く** — スキーマがキャラと同等に豊かだと実質的な作成ができる | フィールドを絞る（名前・容姿・性格程度）。**変数・条件・関係性は持たせない** | 要確認・要実装 |
| 2 | **プレイ中の編集経路** | プレイ中の編集 UI を洗い出して無料版で塞ぐ | 要調査 |
| 3 | **手書き JSON の読み込み** | カセット署名（§5.5） | 要実装 |
| 4 | **他人のカセットを改変して再利用** | 署名が壊れるので拒否（§5.5） | 要実装 |
| 5 | **実行時フラグの反転** | ビルド時にコードを除去（§5.3） | 要実装 |
| 6 | **セッション設定経由の書き込み** — Session 型が定義とプレイ進行を兼ねている（§5.6-③） | 無料版が書けるフィールドのリストを明示的に定義 | **要調査（Phase 4 内で最優先）** |
| 7 | **カセットへの画像同梱** — 法務リスク（§1.6） | カセットに画像を含めない設計にする | 要判断 |

**突破ラインの目標：「JSON を手書きできる人」まで下げる。** それは「構造がわかればツールは要らない層」と**同じ集団**で最初から顧客ではない。ローカルアプリの防御としてはそこが妥当な底。

> **⚠ 順序について（2026-08-10）：** これらは**売れる確証が出てから**着手する（§6）。守っている相手は上の通り最初から顧客ではない集団で、未検証の需要に対して防御を先に作るのは投資対効果が最も低い。

### 5.3 ビルドの分離

**方針：コードベースは1つ、ビルド成果物は2つ。実行時フラグ（`if (isPaid)`）は使わない**（設定ファイルや devtools で簡単に反転される）。無料ビルドには編集系のコードそのものを含めない。

→ 実装は `設計_公開前実装.md` R7。

### 5.4 認証・ライセンス

**結論：まず認証コード機構を作らない（実装ゼロ）。** DLsite で売るなら**購入＝制作版のダウンロード**なので認証を挟む必要がない。無料版は BOOTH・自サイトで別バイナリとして配り、アップグレードは「制作版を落とし直す」だけ（データは `%APPDATA%` に残る）。

**認証コードによる機能開放はビルド分離と正面から衝突する**（無いコードは開放できない／開放できるなら実行時フラグ＝§5.3 で退けた地点に戻る）。

**将来どうしても必要なら**：**オフラインの署名付きライセンスファイル**（Ed25519 等。公開鍵をバイナリに、秘密鍵は手元）。**オンライン認証にしない**（サーバ運用・プライバシー・オフライン起動不能の三重負債）。失効はできないので、流出したら次バージョンでブロックリストを同梱する程度。

### 5.5 カセット署名（暗号化ではなく署名）

**塞ぎたいのは「読めてしまうこと」ではなく「作れてしまうこと」。**

**方針：カセットに署名を付ける。署名鍵は制作版だけが持つ。** 手書き JSON は署名が無く、改変すれば署名が壊れる。実装コストが低い（`spec_version` を持つカード形式に `sig` を足すだけ）。

**暗号化はしない。** 鍵がクライアントにある以上は難読化にすぎない／壊れたカセットのサポートで中身が見られない／「何を隠しているのか」という不信感／そして**技術に疎い人にとっては JSON を手書きすること自体が既に無限のハードル**（暗号化が効くのは「JSON は手書きできるが暗号は解かない」という狭い中間帯だけ）。

> かつてここに「フォークという UGC の成長ループを殺す」も理由として挙げていたが、§5.1 で素材編集を制作版に寄せた時点でフォークは制作版の中でしか回らないので、暗号化の可否とは無関係になった（2026-08-10 整理）。

**効能を過大に書かない（2026-08-10 訂正）：** 旧版は「副産物として**作者の同一性証明**が付く」と書いていたが**誤り**。制作版すべてが同じ鍵を持つ以上、署名が示すのは「制作版を持つ誰かが作った」ことだけ。作者ごとの鍵と公開カタログを組み合わせて初めて同一性の話になる（将来の課題）。

**既知の限界：** 署名鍵は制作版バイナリの中にあるので、購入者が抽出すれば署名オラクルを作れる。§5.2 の突破ラインと同水準なので許容する。

**初期は未署名を全拒否しない**（第三者作者がいない段階で全拒否すると、壊れたカセットのサポートと初期の持ち込みを自分で塞ぐ）。段階的な運用は `設計_公開前実装.md` R8。

### 5.6 スキーマ・バージョニング（公開ブロッカー）

**「完璧な構造にしてから公開」は不可能かつ不要。** 未実装機能が将来フィールドを要求する以上、完璧なスキーマは今書けない。**後方互換は「構造の固定」ではなく「バージョン番号＋マイグレーション」で達成する。** 公開前に固めるのは**スキーマ全体ではなく「封筒」だけ**。

#### 公開前に必ず入れるもの

- **`schemaVersion`**（アプリ状態。**唯一あとから足せない要素**）
- **安定 ID 体系**（既存の `uid()` ベースで問題ないか確認）
- **未知フィールドを無視して読み進むパーサ**
- **カセットの `minRuntimeVersion`** — 新しいカセットを古いランタイムで開いたとき、黙って半分だけ動いて破綻するのが最悪。**明示的に拒否する**
- **カセット定義とセーブデータを別々にバージョニング**（セーブは「途中まで遊んだ人の思い出」なので定義以上に壊すと恨まれる）

| 互換の方向 | 難度 | 対策 |
|---|---|---|
| 古いカセット → 新しいランタイム | 易 | 読み込み時に変換関数を連鎖 |
| **新しいカセット → 古いランタイム** | **難** | ①未知フィールドは無視 ②`minRuntimeVersion` で明示的に拒否 |

→ ソース確認の結果と実装は `設計_公開前実装.md` R1・R2。

### 5.7 初回チュートリアル（API 案内）

**ファネルの一番広いところ（無料版）に、一番高い障害物（API キー設定）がある。** ここは本体の機能より売上に効く。**外部ドキュメントではなくアプリ内の初回ウィザードを主にする**（ドキュメントは読まれない）。

#### 決めたこと

1. **手順を減らす（案内を良くするのではなく）。** OpenRouter は **OAuth（PKCE）** で接続し、キーのコピー＆ペーストを消す。ブラウザで承認するだけ。**手動貼り付けの経路は残す**（OpenRouter の仕様変更で入口が全部死ぬ状態を作らない）
2. **接続テストが最重要。** 極小のリクエストを投げて成否を即出す。BYOK の支援コストはほぼ全部「動かないが理由がわからない」から来る
3. **エラーを日本語の原因に翻訳する。** 最低限4分類：キーが不正／残高・レート上限／モデル名が不正／**コンテンツフィルタによる拒否 → モデル選択画面へ誘導**。4つ目が専用メッセージでないと、表現の制限に当たった利用者が「壊れている」と誤解して返金に行く
4. **ローカルモデル（Ollama / LM Studio）を選択肢に置く。** 入口が Gemini 無料枠だけに依存する状態は、**他社のポリシー変更ひとつで製品の入口が消える**ことを意味する。ローカルは①従量課金の購入前不安を消し②外部サービスの規約に一切触れないので §1.6 の衝突を解き③既に OpenAI 互換に対応済みで**実装コストがほぼゼロ**。ただし数GBのダウンロードと PC 性能が要るので、「最初の5分」ではなく**継続利用・プライバシー・表現の自由度の受け皿**として置く
5. **Gemini 無料枠を無条件の初期値にしない（2026-08-10 変更）。** 無料枠は入力が提供元の品質改善に使われうる旨が規約で示されており、ロールプレイという用途で黙って既定にするのは不誠実。ラベルを「無料で始める」から**プライバシー条件を1行添えた選択式**へ

→ プロバイダ一覧の文言・OAuth の流れ・エラー翻訳の実装は `設計_公開前実装.md` R4・R5。

#### 体験の規模は呼び出し数から逆算する（2026-08-10 追加）

**本アプリは1ターンに複数回 LLM を呼ぶ**（本編＋選択肢／シーン終了時にレビュー1〜2＋次シーン候補）。無料枠には1日あたりのリクエスト数上限があるため、**5シーン構成の体験カセットは上限に触れて途中で止まる可能性が高い**＝最悪の切れ方になる。

→ **同梱する体験用カセットは3シーン以内。** 試算と対策は `設計_公開前実装.md` R6。
→ **OAuth の売りは「無料になること」ではなく「コピペが消えること」**。ここを混同すると、無料枠で完走できない設計のまま「簡単になった」と宣伝することになる。

#### 制作・設置

- **手順のスクショは最小限に**（プロバイダの UI は頻繁に変わり腐る）。直リンクと変わらない要点だけをテキストで
- **2分程度の無音キャプチャ動画**を1本。この層には文章より圧倒的に効く
- **設置は二重化**：アプリ内にオフライン HTML を同梱＋**購入前に読める公開版**を Web に（返金抑止と「APIキー 取り方」系の検索流入を兼ねる＝**案内そのものが集客物**）
- **プレイ1時間あたりの目安コスト**を必ず載せる（BYOK で最大の購入前不安）
- **免責を1段落**（§4.3）
