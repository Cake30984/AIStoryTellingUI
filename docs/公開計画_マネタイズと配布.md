## 0. 製品の位置づけ（すべての前提）

**「ノベルゲーム」ではなく「挿絵入りの本（ライトノベル形式）」を目指す。**

VN の画面構成（絵がメイン・文章は下のボックス）は AI 生成と構造的に噛み合わない。**AI の出力を事前に予測できない＝素材を用意しておけない**から。挿絵は「本文の後から生成する」ので、この問題が原理的に起きない。

| 要素 | 決定 | 根拠 |
|---|---|---|
| 全面背景・立ち絵（透かし） | **廃止** | 同一ピクセルに2つの注意対象を置く構造問題。濃さ調整では解けない（絵は見るに堪えず・文字はコントラストを失う両損） |
| 挿絵 | **残す**（本文フローに挟む図版） | 視線が「読む→絵→続きを読む」と逐次になり競合しない。ラノベの形式そのもの |
| 挿絵の役割 | 読解補助では**なく**、**獲得（SNS拡散）・報酬（収集）資産** | 絵を足しても体験の95%は読むこと。読まない層は絵の有無で動かない |
| 音 | 単一のアンビエント床か**無音** | 情報量の多い素材（セミの声＝夏・屋外・昼）は予測不能な文章に否定されて壊れる |
| ムード色 | 将来の代償措置として検討 | 背景喪失で失う「持続する空気感」を、文字と喧嘩しない色で部分的に補う |

**「本に寄せるとパイが狭まる」への結論：狭まらない。** 選択肢は「狭い読書層 vs 広い絵の層」ではなく「狭い読書層をちゃんと満たす vs 中途半端に満たして絵の層も獲れない」。反証＝なろう・カクヨム・キャラチャットは挿絵ゼロで巨大規模。

**成長レバーは絵ではない：** ①**インタラクション密度**（3000字を黙って読ませるより 300字×10回＋毎回選択）②**絵の量をユーザーが選べる可変比率**（VN は制作時に焼き込まれるが AI 生成は可変。しかも絵を欲しがる層ほど計算コストを食う＝課金意欲と一致）。

### 1.2 Steam を避ける理由

- 決済の圧力元は Steam ではなく**カード会社**。逃げ先は「Steam 以外」ではなく「この種の作品を前提に決済網が組まれている場所」＝ DLsite / BOOTH。
- Steam は**アプリ内課金の外部決済を認めない**＝ BYOK と構造的に相性が悪い。
- ライブ生成 AI は「違法コンテンツを防ぐガードレールがある旨」の表明が要る。BYOK では「保証できません」になり審査摩擦になる。

### 1.3 DLsite はツールを扱う（当初の想定は誤り）

**【公式・実地確認】** 作品形式「ツール/アクセサリ」が**通常の同人フロア**に約 1,089 件（[一覧](https://www.dlsite.com/home/works/type/=/work_type/TOL)）。RPGツクールMZ／SRPG Studio／ティラノビルダー PRO／**HermitNode「孤高のAI執筆室」(¥990)**／Waifu2x (¥55) など。

- 「DLsite はツールを扱わない」という線引きは**存在しない**。
- **ティラノビルダーは本計画のほぼ完全な先例**（エンジンをツールとして売り、作品は各作者が売り、ランタイムは無料）。

### 1.4 AI 生成フロアの隔離リスク

**【公式】** AI生成フロアは既存フロアから分離した独立フロア（全年齢 <https://www.dlsite.com/ai/> ／ R18 <https://www.dlsite.com/aix/>）。ユーザー側に「AI一部利用を除外」チェックもある。

**【公式】** 区分の定義（[エイシス告知](https://info.eisys.co.jp/dlsite/bb3b0b976520e0fd?locale=default)）：**AI生成作品**＝「AIでの生成物をメインコンテンツとして利用している場合」／**AI一部利用**＝「マンガ、ゲームの背景使用等、利用が限定的な部分に留まり」利用者がその限定性を認識できる場合。

**本体（ツール）は隔離対象外の線が濃い。** 根拠：①HermitNode・Waifu2x が通常フロアのツール棚にある ②AIフロアのルール群（収録枚数上限・LoRA規制・写実NG・PSD提出）は明らかに**同梱される事前生成素材**を想定 ③本製品は**出荷物に AI 生成物が1バイトも含まれず**、生成は購入者が自分の契約で実行時に行う。

> **AI補助ツールに DLsite が厳しいとする記事は、作者が自分の絵をAIで作った場合の話**であり軸が違う。

**AI一部利用は同人フロア（通常フロア）で取り扱われる。隔離されるのは「AI生成作品」だけ。**【公式】

#### ⚠ 決定的な条項（2026-08-11 に一次情報で確認）

サークル向けヘルプの **FAQ 本体**に、画像以外の条項が明記されていた。`※` の注記ブロックだけを読んでいたため見落としていた。

| 対象 | 【公式】条文 | 本計画への影響 |
|---|---|---|
| **ノベル作品の文章** | **「AIを利用して文章の大部分を作成した場合には『AI生成作品』となります」** | **カセットの本文を AI で書くとフロア隔離。§3.4 の制作方針が確定的に変わる** |
| ノベル作品の挿絵 | 表紙・挿絵のみなら AI一部利用。ただし**挿絵の比率が本体データの30%以上**なら AI生成作品 | カセットに画像を同梱しない設計なら 0%＝該当しない |
| **ゲームのプログラミング** | 補助的・部分的なら**どちらにも該当しない**。**「プログラムの大部分をAIに書かせた場合のみ『AI生成作品』に該当」** | **本体（ツール）に直撃しうる新論点**。§4.1 で確認 |
| 市販の AI 音声合成 | タグ不要 | 該当なし |

**上の3根拠は「製品が何を出荷するか」の軸しか見ていない。** プログラミング条項は「**製品がどう作られたか**」という別の軸で、既存の根拠は1つも当たらない。HermitNode の先例も「AI を使うツールが通常フロアにある」ことを示すだけで、「AI が書いたプログラムが通常フロアにある」ことは示さない。

#### 立証責任は出品者側にある（重要）

> 【公式】AI生成物を利用したとみられるが、AIオプションの設定が適切ではないと判断される場合、**内製・外注の如何を問わずその証明を求める場合があります。** AIの利用状況について判然となる証明資料がいただけない場合、当該作品に**AIオプションを設定・変更させていただくことがあります。**

具体的な証明手続き（PSD 等の制作過程データ提出）は**画像についてのみ**書かれており、文章・プログラムに対応する手続きは示されていない。しかし上の一般条項は媒体を限定していない。

→ **「AI が書いたか証明できないから安全」ではなく、「証明できないと DLsite 側が付与する」**。目標は「バレないこと」ではなく「**疑われないこと**」と「疑われたときに出せる材料があること」。
→ 実務：**執筆・開発の過程を残す**（カセットは下書きと改稿の履歴、本体は Git の履歴と `docs/` の設計判断記録）。これがそのまま証明資料になる。

### 1.6 成人向け：3つの決定に分解する

| | 決定 | 判断 |
|---|---|---|
| a | 技術的にフィルタしない | **YES**（BYOK＝道具屋の帰結） |
| b | **本体を R18 作品として登録する** | **NO** |
| c | カセットの R18 を許す／自分でも作る | **YES**（ここが R18 市場の収益経路） |

**b を NO にする理由：**

- **【二次】** DLsite では成人向けが全年齢の **10倍以上**売れる（[濡羽十色](https://note.com/dlwatcher/n/nfe0db6350561)）。
- しかし **RPGツクールもティラノビルダーも全年齢ソフト**。R18 フロアが両者の製作物で溢れているのに、**エンジン自体に R18 ラベルは付いていない**。
- 全年齢にすると：全年齢フロアに載る＋R18 フロアのカセットからも逆流を受ける＝**両取り**。R18 にすると：全年齢フロアを丸ごと失い、**ツールは「抜けるかどうか」で買われない**のでリターンがない。

**BYOK との衝突（重要）：【公式報道】** 主要モデルは現状ほぼ全て成人向けを禁止（OpenAI の adult mode は **2026年3月に無期限保留**、Anthropic・Google も禁止）。→ R18 を看板に買った人が案内どおり Gemini 無料枠を設定し最初のシーンで拒否される＝**最悪の初体験**。返金とレビュー爆撃のコンボ。

**したがって：訴求しない・塞がない。** 実装で必要なのはフィルタ削除ではなく**モデル選択の案内**（§5.7）。**ローカルモデル（Ollama / LM Studio）が最も正直な着地点**＝外部サービスの規約に一切触れない。

**テキスト主体は法的に有利：** 文章は成人向けの流通が確立しモザイク等は直接かからない。画像は刑法175条・AI生成フロア規則が絡むが、**実行時にユーザーの手元で生成する＝頒布ではない**ので本体側には原則かからない。**危険なのはカセットに画像を同梱した瞬間**（そこで初めて「自分が頒布している」になる）→ **カセットに画像を同梱しない設計**で構造的に回避（§5.2 #7）。

**絶対に譲れない線：** ①**未成年の性的描写**を自分が配る看板カセット・サンプル・宣伝物に入れない ②**ストアページ・サンプル・宣伝物**で成人向けを売り文句にしない。

### 1.7 クレジット販売はしない

理由は重要な順に：

1. **クレジットを売って自分の鍵で回すと、自分がコンテンツ生成の当事者になる。** 出力の責任・決済事業者への説明責任・通報対応が全部乗る。BYOK なら「テキストエディタを売っている道具屋」で済む。**これが本質的な理由。**
2. **APIキーを取れない人への救済は OpenRouter 誘導で足りる**（1回の登録で全モデルに届き、決済もコンプラも先方が持つ）。自作するより圧倒的に得。
3. 残高型のクレジット（前払式支払手段）は資金決済法の対象になりうる。ただし**届出義務の閾値は基準日未使用残高 1,000万円超**とされ、同人規模では実質到達しない。**この理由を主軸に置かないこと**（金額が小さければ平気、と自分で判断を覆す余地を残すため）。要確認。
4. **【未確認】** DLsite サークル規約に、追加課金・外部決済・外部サービス必須の作品に関する条項は**見つからなかった**（禁止も許可もされていない）。<https://www.dlsite.com/home/circle/regulations>

### 1.8 DLsite を降格した理由（2026-08-11）

「DLsite＝棚（集客）」という前提が、2つの確定事実と2つの未確認事項で崩れた。

#### ① ツール棚には流入が無い（実測）

DLsite のツール棚を実際に見ると、**販売数はほとんどが0〜10件程度**。つまり棚は需要を作っていない。そこで売れているものは、**別の場所で作られた需要が決済しに来ている**だけ。

> **DLsite はショーウィンドウではなくレジ。** レジに商品を置いても客は来ない。

ツクール／ティラノビルダーが例外に見えるのは、需要を作っているのが棚ではなく**ゲームフロアに並ぶ制作物**で、その上にブランドと十数年の蓄積が乗っているから。旧 §3.2 はこの構造を正しく診断していたが、処方（カセットを主要フロアに並べる）が下の②で塞がれた。

#### ② 無料配布ができない【公式・確定】

> 【公式】無料作品、カンパウェアは基本的に登録できません（例：**体験版と作品本体を一緒にした**）
> 【公式】無料配布につきましては、当サイトサービスとしての提供は行っておりません。

**例示が「体験版と作品本体を一緒にした」＝§2.1 の「無料版ランタイム＋カセット同梱」そのもの。** DLsite で無料の入口は作れない。

残る道は**有償カセット**だが、有償カセットは「別途ランタイム＋APIキー＋従量課金」を買い手に相続させる（§2.1）。これは**無料にすることでしか解けない**と結論した問題で、その解が規約で塞がれた。

#### ③ メインコンテンツがインターネット接続を必要とする作品は取り扱い不可【前例で解釈確定・2026-08-23】

> 【公式】次のような作品は取り扱いできません：…**メインコンテンツがインターネットに接続する必要のある作品**…

##### 旧解釈（誤り・2026-08-11〜2026-08-23）

~~この規定が並ぶリスト（実写主体・未完成品・無料作品・権利関係・不正な素材）から読むに、想定は「販売者が運営するサーバに依存する作品」で、禁止の目的は「販売者がサービスを止めたら購入物が無価値になる」ことの防止だろう。本製品の依存先は購入者自身が契約した第三者サービスなのでこの目的には当たらない。ローカルモデル（Ollama / LM Studio）で全機能が動くなら「接続が必要な作品」ではない——接続は選択肢の1つであって必須ではない。~~

**この読みは誤りだった。** 「接続しない**構成を選べる**」は「接続を必要としない」ではない。**買い手が購入物だけを手にした状態で何ができるか**が判定基準であり、そこで Ollama や ComfyUI の入手を要求するなら、要求先が販売者のサーバか第三者かに関係なく「インターネットに接続する必要のある作品」に当たる。R5' の遮断検証（`R5検証チェックリスト.md` §3）は**技術的事実としては正しい**が、**その事実からこの条文をクリアできるという結論は導けない**。

##### 正しい解釈＝**出荷状態で完結していること**

判定はこう読むべきだった。**インストールした直後、追加の入手作業なしにメインコンテンツが動くか。**

- 依存物の入手先が販売者か第三者かは関係ない
- 「設定すれば動く」「対応している」は該当しない。**同梱されているかどうか**

**同じ製品が、DLsite に出す時だけモデルを同梱している。** これが③の運用実態を示している。旧版の「先行作品は規約を意識した結果の可能性がある」という推測は当たっていたが、**それなら本製品も同じ工事が要る**という帰結を引いていなかった。

##### この前例から確定したこと2点

1. **同梱すれば通る。** 4.32GB の配布は許容範囲。単体動作の作品としてツールフロアに載っている（→ ④の懸念も、少なくとも「単体で動く形にすれば」の条件付きで解消）
2. **任意の追加ダウンロードは禁止されていない。** DLsite 版も「自己責任で無検閲モデルへ差し替え可」と書いている。**禁じられているのは「動かすために必要な入手」であって「良くするための入手」ではない。**

2 は本製品の別の懸念——**「API 機能を残したら全機能が使えないことになるのでは」——への答えでもある。ならない。** 出荷状態が単体で完結していれば、外部 API は任意のアップグレード経路として残してよい。ただし**訴求文で「別途用意が必要」を前提にしない**という制約は付く（BOOTH 版が差し替えを売り文句の中心に置き、DLsite 版が「最初から同梱」を先に立てているのは、この線引きの反映と読める）。

##### 本製品に引き直したときのコスト（前例より重い）

HermitNode と同じ工事をデリストでやる場合、**前例には無かった問題が3つ増える**。

| 項目 | 内容 |
|---|---|
| **推論ランタイムの同梱** | Ollama は外部ツール＝同梱にならない。llama.cpp 系（MIT＝再配布可）をアプリに埋め込む工事が要る。**前例と同じ難度** |
| **モデルのライセンスと成人向けの衝突** | HermitNode が Llama 3.1 を同梱できたのは**全年齢の執筆ツールだから**。本製品は R18 カセットを想定しており（§3）、Llama 系・Gemma 系には**利用規約に禁止用途方針が付く**。同梱するなら AUP を持たない Apache-2.0 系（Qwen・Mistral 等）に絞る必要がある。**HermitNode が「無検閲モデルへは自己責任で」と書いているのは、この問題を利用者へ移しているということ**＝同じ手を取るなら「同梱モデルでは R18 は動かない」を受け入れることになる |
| **画像生成の同梱は桁が違う** | ComfyUI ＋画像モデルで**合計10GB超**。しかも画像モデルのライセンス（OpenRAIL 系）は用途制限付きが多い。R18 画像の同梱は §3 の「カセットに画像を同梱しない」方針（刑法175条・AI生成フロア判定の構造的回避）とも衝突する。**画像は同梱しない＝DLsite 版では挿絵が外部依存として残る**のが現実解だが、これが「メインコンテンツ」に当たるかは未確認 |
| **既定の接続先の作り替え** | 現在の初回ウィザード（R5）は外部プロバイダへ誘導する設計。DLsite 版は同梱エンジンが既定かつ十分な経路である必要があり、**R7 のビルド分離と同種の工事**になる |

##### 判断（2026-08-23）

**DLsite 版は「検証タスク」ではなく別 SKU の開発プロジェクト。今は作らない。**

§1.8 の結論「**今後 DLsite の規約に製品設計を合わせない**」がそのまま効く。ランタイム埋め込み・モデル同梱・ライセンス精査・ビルド分離は、**BOOTH で需要が出てから**着手するかを判断する（Phase 3 の計測後）。前例が「BOOTH 版と DLsite 版を分ける」形を取っていること自体が、**本線を BOOTH に置く判断の裏付け**にもなっている。

なお **§4.1 の問い合わせから③は落としてよい**（前例で運用が確認できたため、聞く必要が薄い）。残すのは「未確定」の①本体プログラムを AI で書いたことの申告要否と、②審査時の動作確認の形式。

#### ④【一部解消】単体では動作しない作品を登録できるか

カセットは別配布のランタイムが無いと動かない。ツクール製・ティラノ製の成果物は単体で動くので前例にならない。

**③の前例（HermitNode DLsite 版 4.32GB）で、「単体で動く形にすれば本体は載る」ことは確認できた**（2026-08-23）。
残るのは**カセット単体を作品として登録できるか**で、これは③とは別の問題として §4.1 に残る。ただし
**カセットは無料配布が前提**（§2.1）で、DLsite では無料配布ができない（②）ため、**この問いは実質的に用がない**。

#### 結論

**関門が4つある通路を、唯一の集客導線にしてはいけない。** DLsite は「通れば決済窓口と R18 フロアが増えるオプション」に降格し、**製品設計を縛らせない**。

そして、そのレジ機能は **BOOTH がほぼ代替する**（決済・R18・無料配布可・審査なし）。DLsite が独自に持つのは R18 フロアの規模と検索・ランキングだけで、そこに載るための関門が上の4つ。

## 2. 商品構成と価格

### 2.1 二層モデル（2026-08-30 全面改訂）

**旧版は三層（無料版＋無料カセット／有料カセット／制作版）だった。中段を凍結し、課金点を §5.1 へ移す。**

| 層 | 内容 | 価格 | 置き場 |
|---|---|---|---|
| **無料タイトル** | **カセット1本を焼き込んだ単体 exe。** インストールして接続設定を済ませればすぐ遊べる。**外部カセットを読み込む機能は存在しない**（§5.1） | ¥0 | **BOOTH・自サイト**（DLsite は**無料配布不可**＝§1.8-②） |
| **制作版** | フル機能。キャラ・世界観の作成／複数ストーリーの管理／**任意のカセットの読み込み（インポート制限なし）**／JSON カセットの書き出し | ¥2,980（発売時30%引き） | BOOTH（DLsite は §1.8 の関門次第） |

**価値のはしご：** 無料タイトルを遊ぶ →（自分の世界でやりたくなって）制作版を買う。**二段。**

**「1本のゲームを落とした」という体験にする。** エンジンとカセットが別物だと、ダウンロード → インポートの二度手間が最初の障害物として立つ。ツクール製の作品はダブルクリックで動くのに対し、旧構成はこの前提を満たしていなかった（§3.2 で自認済み）。同梱 exe はその差を埋める。

#### なぜ中段（有料カセット）を凍結したか

1. **買い手の動機は「配布」ではなく「自分用」だと見積もった**（§7-12）。どの界隈でも作る側に回る人は少数で、「作ったものを公開したい」はさらにもう一段のハードル。**制作版の主顧客は自分の内に閉じて遊ぶ人**。ならば第三者が売る先も、自分がカセットを売る意味も薄い。
2. **有償カセットは相続コストを解けない。** 別途ランタイム・接続設定・従量課金を買い手に渡したうえで返金とレビューの対象になる。§3.2 で「無料にすることでしか解けない」と結論した問題がそのまま戻る。
3. **JSON を売る商品性が低い。** 複製が容易なプレーンテキストに数百円を払う動機が弱い（§7-11 で「保護できない」と認めていた問題は、**商品にしないこと**で消える）。

**凍結であって廃止ではない。** 無料ビルドにローダーを足せば中段は復活する（§5.1 の構造上、後から開けるのは容易）。判断は Phase 3 の計測後。

**中段を「有料タイトル（単体 exe）」の形で復活させる道は残っている**（JSON を売るのではなく**作品**を売る＝凍結理由③が当たらない）。ただし本数が増えると自分でビルドし続けることになるので、その時点で exe 書き出しの要否を判断する（§7-14）。判断材料は §7-12 の計測。

**カセットは商品ではなく販促物として割り切る。** 直接収益はゼロ、回収先は制作版の売上のみ。

### 2.2 値付けの根拠

- DLsite のツール棚は二極化：**ユーティリティ ¥55〜990／制作エンジン数千円**。→ **「ユーティリティ」に見えると ¥1,000 の帯に引きずられる。**「エンジン／制作ツール」として提示できるかがそのまま価格帯を決める。

### 2.3 「エディタが薄いのに課金してよいのか」への回答（2026-08-30 全面改訂）

## 3. マーケティング戦略

### 3.1 前提：広告費では勝てない

競合は広告を焚いている。同じ土俵では勝てないので、**製品の副産物が勝手に宣伝になる**構造を作る。広告出稿はしない。

### 3.2 ~~集客の本体はカセット~~ → **撤回**（2026-08-11）

**旧版の主張：「カセットを主要フロアに並べれば本体へ逆流する（ツクール構造）」。これを撤回する。**

診断は正しかった。**DLsite のツール棚は入口ではなく着地点**で、1,089 件は自分から掘らないと辿り着けない（DLsite の導線は音声・マンガ・ゲームで作られている。**BOOTH でも同じなので逃げても解決しない**）。実測でも**販売数はほとんどが0〜10件程度**（§1.8-①）。

処方が成立しなくなった。旧版は「主要フロアに無料カセットを並べる」で解こうとしたが——

- **DLsite は無料配布ができない**（§1.8-②・確定）
- 有償カセットは摩擦（別途ランタイム＋接続設定＋従量課金）を買い手に相続させる。これは**無料にすることでしか解けない**と結論した問題
- そもそもカセットを登録できるか（単体非動作）、本体を扱えるか（接続依存）が未確認（§1.8-③④）

**関門が4つある通路を、唯一の集客導線にしてはいけない。** → 集客の本体を §3.3 へ移す。

なお DLsite が通った場合に備えて、**カセットのストアページ冒頭に動作要件（別途ランタイム・接続設定が必要）を明記する**方針は維持する。返金とレビューはここでほぼ決まる。

### 3.3 集客の本体：製品の出力物（2026-08-11 格上げ）

**プラットフォームの許可も、継続的な露出も要らない唯一の経路。** 旧版では「副次効果」だったが、DLsite の降格により**これが集客戦略そのもの**になる。

#### ① プレイ結果を小説／リプレイとして書き出せること

「本に寄せる」決断の最大の副産物。VN のセーブデータは他人に見せられないが、**組版された物語テキストはカクヨムにも note にも X にも貼れる**。TRPG 界隈の**リプレイ文化**に直結する。面白い話ができるたびに宣伝物が世に出る。

**この機能の出来が、製品が発見されるかどうかを決める。** よって要件は「出力できること」ではなく「**貼りたくなる出力であること**」。

- **そのまま貼れる形式**（プレーンテキスト／Markdown。整形が崩れない）
- **画像1枚で完結する形**も用意する（X はテキストより画像のほうが伸びる）
- **挿絵つきの書き出し**（挿絵は §0 のとおり獲得資産＝ここで回収する）
- **出典が自然に入る**（末尾に製品名とカセット名。宣伝臭くならない範囲で）
- **プレイヤーの選択が見える形**（何を選んでどうなったかが読み取れる＝「自分でもやってみたい」のきっかけ）

→ 実装要件は `設計_公開前実装.md` R10。**Phase 2 へ繰り上げる。**

#### ② 配れるものが2つあること（2026-08-30 改訂）

**閉じたのは「無料ビルドが JSON を読むこと」だけで、JSON の流通そのものではない。**

| 配るもの | 誰が遊べるか | 誰が配れるか | 役割 |
|---|---|---|---|
| **JSON カセット** | 制作版の所有者（**インポート制限は設けない**） | **誰でも** | 制作版どうしの**カード文化**。フォーク・改造・持ち寄りはここで回る。SillyTavern のキャラクターカードと同じ構造 |
| **単体 exe（タイトル）** | **誰でも**（NSIS インストーラは実測 15MB） | **自分だけ**（exe 書き出しは作らない＝§5.1） | 無料ユーザーへ届く唯一の経路＝集客と入口 |

**どちらも棚を必要としない。** X・Discord・自サイト・BOOTH・GitHub、どこに置いてもよい。exe 側は配布単位が「作品名」になるので**見出しに説明が要らなくなる**（「デリスト（AIストーリーエンジン・無料版）」より「〈作品名〉」のほうが強い）。

**第三者が無料ユーザーへ届く経路は無い**（§5.1 の代償）。必要になったら **JSON を受け取ってこちらで exe をビルドして返す**手作業で凌ぐ（実装ゼロ。§7-14）。

### 3.4 自作カセットの進め方（2026-08-10 改訂）

**全年齢と R18 は役割が違う：**

| | 全年齢カセット | R18 カセット |
|---|---|---|
| 役割 | **拡散**（SNS共有・実況可。本体ストアのサンプル兼用） | **到達**（10倍フロアでの発見） |
| 前提モデル | Gemini 無料枠でそのまま動く | 無検閲モデル／ローカルモデルへの案内が必須 |
| 分量 | 看板として厚く | 短編で可 |

R18 は実況・配信が不可能、X でもセンシティブ扱いで検索から落ちる＝§3.3 の拡散仮説と**構造的に相性が悪い**。**順序は全年齢が先**（無料枠オンボーディングの検証を先に済ませないと、不備とモデル拒否が混ざって切り分けられない）。R18 カセットには**モデル設定案内を最初の画面に同梱**する。

#### 本文は人力で書く（2026-08-11 確定・制作方針の変更）

**【公式】「AIを利用して文章の大部分を作成した場合には『AI生成作品』となります」**（§1.4）。

→ **「AI で週末に数本」という制作前提は使えない。** それをやるとカセットが AI生成フロアへ隔離され、**§3.2 の集客導線（主要フロアに並ぶこと自体が広告）が丸ごと消える**。さらに月3本の申請上限がかかるので、量産の目的自体も達成できない。

**カセットの本文（世界観・キャラ定義・ロア・導入文）は人力で書く。** AI の使いどころは、大部分の執筆ではなく次に限る。

- 案出し・叩き台の相談（採用するのは自分の言葉で書き直したもの）
- 校正・整合性チェック
- 条件やイベントの設定漏れの洗い出し

**執筆過程を残す**（下書き・改稿の履歴をファイルで保持）。疑われたときに出せる材料が要る＝立証責任は出品者側にある（§1.4）。

#### 一度に10本作らない（重要）

**生成は速いが、検証は速くならない。** そして上の通り、生成そのものが使えなくなった。カセットの実コストは JSON を書くところではなく、**条件・イベント・エンディングが複数回の周回で本当に発火するかを確かめるところ**にある。壊れたカセットは無料でも評判を削る（金を払っていない人ほどレビューは辛口）。加えて Phase 1 でスキーマが動くので、**先に作った本数はそのまま移行対象の件数**になる。

→ 本文を人力で書く以上、**「少数を厚く」に寄せる**。無料カセットを10本並べる案は撤回し、**同梱2〜3本＋主要フロアに数本**の規模で始める。

**手順：2〜3本 → 計測 → 型が定まってから残りを量産。** 計測するのは売上ではなく次の3つ：

1. **API キー設定の突破率**（起動した人のうち何%が最初の生成に到達したか）
2. **完走率**（エンディングまで到達したか）
3. **詰まった箇所**（どのシーンで離脱したか）

#### 撤退トリガーと不発時の分岐（2026-08-30 改訂）

#### 旧前提の失効

旧版の課金点は「能力（キャラ・世界観を編集できること）」だった。これは §5.2 の突破ライン——「JSON を手書きできる人まで下げれば十分。それは構造がわかればツールは要らない層と**同じ集団**で、最初から顧客ではない」——に全面的に寄りかかっていた。

**この等式はもう成り立たない。** LLM のコーディング支援（Copilot 等）によって、JSON を書ける人は「技術者」ではなく「**やる気のある人**」になった。旧前提が「顧客ではない」と切り捨てていた集団は、いま顧客層とほぼ完全に重なる。善意を信じるかどうかの問題ではなく、前提の失効。

しかも**その経路はこちらが整備済み**：[カセット作成ガイド_AI用.md](./カセット作成ガイド_AI用.md) は 415 行の AI 向け作成仕様書で、冒頭に「アプリのソースコードを読ませる必要はありません」と書いてある。**執筆能力を守る戦線は、自分の手で開けた穴があるので最初から成立しない。**

#### 新しい課金点

> **無料ビルドには、外部カセットを読み込むコードが存在しない。**
> AI がどれだけ完璧な JSON を書いても、それを遊ぶには制作版が要る。

**執筆はもう制御できない。実行は制御できる**（自分のバイナリの中にあるから）。ゲートを、制御不能になった側から制御できる側へ移す。実装の実体は §5.3 のビルド分離そのものなので、新しい仕組みは要らない。

**ゲートは2枚あり、別々の集団に効く。**

| 集団 | 何に払うか | 止めているもの |
|---|---|---|
| 自分用に作りたい人（**多数**・§7-12） | 編集能力 | 編集系モジュールが無料ビルドに無い |
| AI で JSON を書ける人（旧・突破ライン） | **読み込み能力** | **ローダーが無料ビルドに無い** |

旧版は1枚目しか持たず、2枚目の集団を「顧客ではない」と仮定して素通ししていた。

| 機能 | 無料タイトル | 制作版 |
|---|---|---|
| 同梱カセットを遊ぶ | ○ 無制限 | ○ |
| **外部カセットの読み込み** | **×（コードごと不在）** | ○ |
| 複数ストーリーの管理 | **×**（1本のみ） | ○ |
| ペルソナの編集 | ○（**フィールドを絞る**・§5.2 #1） | ○ |
| セッション設定の編集 | ○ | ○ |
| **オーバーレイの編集**（発見ロア・キャラ成長） | **○** | ○ |
| キャラクター／世界観の**閲覧** | ○（読み取り専用） | ○ |
| キャラクター／世界観の**編集・新規作成** | **×** | ○ |
| カセットの作成 | **×** | ○ |
| **JSON カセットの書き出し** | **×** | ○ |
| 単体 exe（タイトル）の書き出し | × | **×**（作らない・§7-14） |

**閲覧は許可する（変更なし）。** 同梱カセットの JSON はどのみち手元にあるので読めること自体は何も渡していない。「こう作るのか」が見えることが**制作版への最も自然な導線**になる。編集操作で「制作版が必要です」と出す。

**オーバーレイは開ける（2026-08-10 追加）。** 旧版は無料版から作る体験を完全に抜いていたが、それでは変換（遊ぶ人→作る人）が「見える」ことだけに依存する。`SessionOverlay` は**セッションに閉じていて配布物にならない**ので、開けても抜け道にならない。「作る楽しさ」の中心＝自分の関与で人物が変わることはここにある。実装は `設計_公開前実装.md` R7（**発見キャラの扱いは 2026-08-15 に案 a で決着＝オーバーレイにキャラは持たせず、無料版では FB7-E の導線を出さない**）。

**説明可能な境界（2026-08-30 改訂）：「この物語の中を変える」は無料、「別の物語を持ち込む・作る」は有料。**

#### 実装条件：カセットはバイナリに焼き込む

**exe の隣に `.json` を置いてはいけない。** 置いた瞬間それ自体がローダーになり、差し替えで課金点が消える。Tauri の埋め込みアセット（`include_str!` 相当）としてバイナリに含める。**難読化のためではなく、差し替え経路を物理的に消すため**（中身を抽出できること自体は問題ではない＝§5.5 で暗号化を却下したのと同じ理由）。

#### 出力は JSON のみ（2026-08-30・同日に再決定）

**制作版が書き出すのは JSON カセットだけ。単体 exe の書き出し（旧 R11）は作らない。** 無料タイトルの exe は**自分が手元でビルドする**（R7 のビルド時定数で足りる）。

- **JSON カセットのインポート制限は設けない。** 制作版の所有者どうしでは自由に流通し、**カード文化はそこで育つ**（§3.3②）
- **第三者が無料ユーザーへ届ける経路は持たせない。** 必要になったら **JSON を送ってもらってこちらで exe をビルドして返す**（実装ゼロの手作業）。それが何度も起きたらツール化を検討する

**なぜ exe 書き出しを作らないか：**

1. **価値を持つのは「第三者が配りたがる」場合だけで、それは §7-12 の見積もり（買い手の大部分は自分用）と矛盾する。** 最初から少数派のための機能に、計画中で最も重い実装（ビルダー＋署名＋テンプレート配布＋規約＋サポート）を先払いすることになる
2. **署名（§5.5・R8）を道連れにする。** 署名が要るのは**注入経路があるときだけ**で、その経路を作るのが exe 書き出し自身。**作らなければ両方消える**
3. **ランタイムの版が一本化されたままになる。** 焼いた exe は当時のランタイムで固定され、BYOK は外部 API 側が勝手に動くのでいずれ動かなくなる（しかも**こちらの製品名を背負ったまま**死ぬ）。書き出しを持たない限り、**遊ばれているビルドは全部こちらが更新できるもの**になる
4. **後から足しても何も壊れない。** R7 の無料ビルド（ローダー不在＋カセット焼き込み）が**そのままテンプレートになる**ので、純粋に追加でよい

→ 経緯と復活条件は §7-14。

#### この決定で消える負債

- **カセット署名（§5.5・R8）が不要になる。** 読み込めるのは制作版だけ＝読み込む人は全員顧客で、**注入経路も存在しない**
- **§2.3 の「観客へのアクセス権」という苦しい説明が要らなくなる。** 自分用に買うので、観客の存在を前提にしない

#### 代償（明示的に飲む）

- **第三者は無料ユーザーに届かない。** JSON は**制作版どうし**でしか流通しない。~~第三者 UGC が構造的に不可能~~ という最初の記述は言い過ぎだったが（カード文化は制作版の中で回る）、**無料ユーザーへの到達は自分だけが持つ**
- **無料タイトルの供給量は自分の執筆速度で頭打ちになる。** §3.4 で撤退トリガーを「第三者の本数」から「自分のファネル」へ書き換えた時点で織り込み済み
- **戻せる（2通り）。** ①無料ビルドにローダーを足せば JSON も直接開く ②exe 書き出しは R7 のビルドをテンプレートにして後から足せる。**どちらも同梱 exe の形を維持したまま開ける**

#### 採らなかった案

- ~~作成は自由・配布に課金~~：カセットが JSON である以上、「書き出し」は工程ではなく**ファイルをコピーするだけ**＝ゲートを置く場所が物理的に無い。ツクールで配布課金が機能するのは**出力がパッケージだから**（ビルドという実際の工程がある）。旧版からの結論を**維持**
- **無料版でも個人的な範囲の編集を許す**：一度は「編集後の状態を複製すれば実質ビルドツールになる」として退けたが、**この理由は過剰**（`%APPDATA%` を手でコピーさせる経路は手書き JSON と同程度の摩擦で、§5.2 の突破ラインと同水準）。実際の理由は「**編集を守る戦線がもう成立しない**」ことなので、編集ではなく**読み込みを閉じる**ほうへ移した
- **無料版で小規模なカセットを作れるようにし、商用利用だけライセンスで縛る**：①無料ビルドに編集コードが入る＝実行時フラグになり §5.3 と正面衝突する ②**非商用ライセンスはこの市場で執行力を持たない**（匿名の販売者を相手に ¥2,980 の製品で追及するコストが常に回収額を上回る）。ツクールで商用ライセンスが機能するのは法務を持つ会社が売っているから

**フォークについて：** 他人のカセットを改変して学ぶループは制作版の中だけで回る。無料タイトルにできるのは同梱カセットを「読む」まで。

**収益上の副次効果（維持）：** 課金点が「配布したい人」ではなく「何か作りたい人」に向いているので、**支払い母数は広い**。

### 5.3 ビルドの分離 — **防御の本体（2026-08-30 格上げ）**

**方針：コードベースは1つ、ビルド成果物は2つ。実行時フラグ（`if (isPaid)`）は使わない**（設定ファイルや devtools で簡単に反転される）。無料ビルドには編集系のコードそのものを含めない。

**2026-08-30：これは補助ではなく課金点そのものになった。** §5.1 のゲートは「ローダーが存在しないこと」なので、ビルド分離が甘いとゲートごと消える。よって **Phase 4 ではなく Phase 3（無料タイトルを配る前）** に置く。

無料ビルドから落とすもの：

- **カセットの読み込み経路**（インポート UI・ファイルドロップ・`parseBundle` の呼び出し）← 2026-08-30 追加。**最重要**
- 編集系（`library/CharacterEditor`・`library/WorldEditor`・`CassetteEditor`）
- 書き出し（カード書き出し・カセット書き出し）

→ 実装は `設計_公開前実装.md` R7。**成果物を grep して検証する。**

### 5.4 認証・ライセンス

**結論：まず認証コード機構を作らない（実装ゼロ）。** 購入＝制作版のダウンロードなので認証を挟む必要がない。無料タイトルは BOOTH・自サイトで**別バイナリ**として配り、アップグレードは「制作版を落とし直す」だけ。

**2026-08-30 追加（要設計）：** 無料タイトルが複数あると **API キーの設定を毎回やり直すことになり、「落としてすぐ遊べる」利得を自分で打ち消す**。接続設定は APPDATA 配下の**タイトル間で共有するディレクトリ**に置き、セーブデータだけタイトル別のサブディレクトリに分ける（R3 の保存先と併せて決める）。制作版も同じ共有設定を読む＝アップグレード時に再設定が要らない。

**認証コードによる機能開放はビルド分離と正面から衝突する**（無いコードは開放できない／開放できるなら実行時フラグ＝§5.3 で退けた地点に戻る）。

**将来どうしても必要なら**：**オフラインの署名付きライセンスファイル**（Ed25519 等。公開鍵をバイナリに、秘密鍵は手元）。**オンライン認証にしない**（サーバ運用・プライバシー・オフライン起動不能の三重負債）。失効はできないので、流出したら次バージョンでブロックリストを同梱する程度。

### 5.5 カセット署名（暗号化ではなく署名）→ **凍結（2026-08-30）**

**実装しない。** §5.1 で読み込みを制作版に閉じ、さらに**単体 exe の書き出しも作らない**と決めたので、署名で弾く相手も、署名で守るべき注入経路も無い。

> **経緯（同日に二転した）：** ①読み込みを閉じた時点で「弾く相手がいない」として凍結 → ②exe 書き出し（旧 R11）を入れる案が出て「テンプレートへの注入を塞ぐために要る」として解除 → ③**exe 書き出し自体を作らないことにしたので再び凍結**（§5.1・§7-14）。**署名と exe 書き出しは対で復活する。片方だけ作る意味は無い。**

以下は当初（読み込み時の門番として設計していたとき）の結論。

**塞ぎたいのは「読めてしまうこと」ではなく「作れてしまうこと」。**

**方針：カセットに署名を付ける。署名鍵は制作版だけが持つ。** 手書き JSON は署名が無く、改変すれば署名が壊れる。実装コストが低い（`spec_version` を持つカード形式に `sig` を足すだけ）。

**暗号化はしない。** 鍵がクライアントにある以上は難読化にすぎない／壊れたカセットのサポートで中身が見られない／「何を隠しているのか」という不信感／そして**技術に疎い人にとっては JSON を手書きすること自体が既に無限のハードル**（暗号化が効くのは「JSON は手書きできるが暗号は解かない」という狭い中間帯だけ）。

> かつてここに「フォークという UGC の成長ループを殺す」も理由として挙げていたが、§5.1 で素材編集を制作版に寄せた時点でフォークは制作版の中でしか回らないので、暗号化の可否とは無関係になった（2026-08-10 整理）。

**効能を過大に書かない（2026-08-10 訂正）：** 旧版は「副産物として**作者の同一性証明**が付く」と書いていたが**誤り**。制作版すべてが同じ鍵を持つ以上、署名が示すのは「制作版を持つ誰かが作った」ことだけ。作者ごとの鍵と公開カタログを組み合わせて初めて同一性の話になる（将来の課題）。

**既知の限界：** 署名鍵は制作版バイナリの中にあるので、購入者が抽出すれば署名オラクルを作れる。§5.2 の突破ラインと同水準なので許容する。

**初期は未署名を全拒否しない**（第三者作者がいない段階で全拒否すると、壊れたカセットのサポートと初期の持ち込みを自分で塞ぐ）。段階的な運用は `設計_公開前実装.md` R8。

### 5.6 スキーマ・バージョニング（公開ブロッカー）

**「完璧な構造にしてから公開」は不可能かつ不要。** 未実装機能が将来フィールドを要求する以上、完璧なスキーマは今書けない。**後方互換は「構造の固定」ではなく「バージョン番号＋マイグレーション」で達成する。** 公開前に固めるのは**スキーマ全体ではなく「封筒」だけ**。

#### 公開前に必ず入れるもの

- **`schemaVersion`**（アプリ状態。**唯一あとから足せない要素**）
- **安定 ID 体系**（既存の `uid()` ベースで問題ないか確認）
- **未知フィールドを無視して読み進むパーサ**
- **カセットの `minRuntimeVersion`** — 新しいカセットを古いランタイムで開いたとき、黙って半分だけ動いて破綻するのが最悪。**明示的に拒否する**
- **カセット定義とセーブデータを別々にバージョニング**（セーブは「途中まで遊んだ人の思い出」なので定義以上に壊すと恨まれる）

| 互換の方向 | 難度 | 対策 |
|---|---|---|
| 古いカセット → 新しいランタイム | 易 | 読み込み時に変換関数を連鎖 |
| **新しいカセット → 古いランタイム** | **難** | ①未知フィールドは無視 ②`minRuntimeVersion` で明示的に拒否 |

→ ソース確認の結果と実装は `設計_公開前実装.md` R1・R2。

### 5.7 初回チュートリアル（API 案内）

**ファネルの一番広いところ（無料版）に、一番高い障害物（API キー設定）がある。** ここは本体の機能より売上に効く。**外部ドキュメントではなくアプリ内の初回ウィザードを主にする**（ドキュメントは読まれない）。

#### 決めたこと

1. **手順を減らす（案内を良くするのではなく）。** OpenRouter は **OAuth（PKCE）** で接続し、キーのコピー＆ペーストを消す。ブラウザで承認するだけ。**手動貼り付けの経路は残す**（OpenRouter の仕様変更で入口が全部死ぬ状態を作らない）
2. **接続テストが最重要。** 極小のリクエストを投げて成否を即出す。BYOK の支援コストはほぼ全部「動かないが理由がわからない」から来る
3. **エラーを日本語の原因に翻訳する。** 最低限4分類：キーが不正／残高・レート上限／モデル名が不正／**コンテンツフィルタによる拒否 → モデル選択画面へ誘導**。4つ目が専用メッセージでないと、表現の制限に当たった利用者が「壊れている」と誤解して返金に行く
4. **ローカルモデル（Ollama / LM Studio）を選択肢に置く。** 入口が Gemini 無料枠だけに依存する状態は、**他社のポリシー変更ひとつで製品の入口が消える**ことを意味する。ローカルは①従量課金の購入前不安を消し②外部サービスの規約に一切触れないので §1.6 の衝突を解き③既に OpenAI 互換に対応済みで**実装コストがほぼゼロ**。ただし数GBのダウンロードと PC 性能が要るので、「最初の5分」ではなく**継続利用・プライバシー・表現の自由度の受け皿**として置く
5. **Gemini 無料枠を無条件の初期値にしない（2026-08-10 変更）。** 無料枠は入力が提供元の品質改善に使われうる旨が規約で示されており、ロールプレイという用途で黙って既定にするのは不誠実。ラベルを「無料で始める」から**プライバシー条件を1行添えた選択式**へ

→ プロバイダ一覧の文言・OAuth の流れ・エラー翻訳の実装は `設計_公開前実装.md` R4・R5。

#### 体験の規模は呼び出し数から逆算する（2026-08-10 追加）

**本アプリは1ターンに複数回 LLM を呼ぶ**（本編＋選択肢／シーン終了時にレビュー1〜2＋次シーン候補）。無料枠には1日あたりのリクエスト数上限があるため、**5シーン構成の体験カセットは上限に触れて途中で止まる可能性が高い**＝最悪の切れ方になる。

→ **同梱する体験用カセットは3シーン以内。** 試算と対策は `設計_公開前実装.md` R6。
→ **OAuth の売りは「無料になること」ではなく「コピペが消えること」**。ここを混同すると、無料枠で完走できない設計のまま「簡単になった」と宣伝することになる。
