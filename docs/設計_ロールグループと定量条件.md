# 設計: ロールグループと定量条件（名前置換の分離・ロールのグループ化・全員/N人条件）

2026-07-20 起票。FB7-D（キャラ変数 相手1/2/3）の実使用検討から出た抜本的な作り直し。ユーザー合意事項（同日）を反映。

## 背景・目的

FB7-D で「相手1・相手2・相手3」（`Clause.charVar`）を導入したが、実プレイ検討で次の限界が判明した。

- 5人ヒロインの「全員から好感度70以上」のような条件は、相手1〜相手5 を個別に並べる必要があり煩雑。かつ相手変数は3つ上限で4人以上を書けない。
- 同一条件を複数人に課すと順列が二重に列挙される（相手1=A,相手2=B と 相手1=B,相手2=A）。
- 「攻略対象」と「モブ」のようなキャラの種別を条件側で区別できない。

**合意した方向**（2026-07-20）:

1. **名前置換（`@タグ`）とロールを完全に分離する。** 名前置換は**導入文作成専用**の機能として作り直し、現在ロールが担っている `@ロール名→実名` の役割から切り離す。
2. **プロンプト注入（登場人物の明示）はロールに一本化する。** ロールは**グループ化可能**（1..N人のメンバーを持つ）。1人だけのグループが実質的な従来型の専用ロールになる。
3. **相手1/2/3（`charVar`）は廃止し、「ロールグループ＋数量詞」に一本化する。**
4. 条件でロールグループに対し **全員 / N人以上 / N人ぴったり** を課せる。
5. **判定条件と「結果（当事者）」を分けて書ける。** 例: 「ラスボス撃破  かつ ヒロイン群の好感度70以上」で成立させつつ、エピローグ/結果の当事者は**ヒロイン群だけ**にする（ラスボスは結果に出さない）。

要望と設計の対応:

| # | 要望 | 対応 |
|---|------|------|
| ① | ロールグループ機能 | ロールを 1..N メンバーのグループへ拡張（`World.roles`＋`Session.roleAssignments` を多対多に） |
| ② | 1キャラが複数ロール兼任 | メンバーシップは多対多。1キャラが複数ロールに属せる（既に `roleAssignments` は同キャラ複数可） |
| ③ | グループ全員への条件 | `group` 複合節＋数量詞 `全員` |
| ④ | グループ内の任意人数への条件 | `group` 複合節＋数量詞 `N人以上`/`N人ぴったり` |

---

## 全体像（2部構成）

- **Part A: 名前置換とロールの分離**（前提の作り直し）
  - 導入文専用の**置換タグ**を新設（`@タグ` を実名へ置換）。
  - `World.roles` から `@名前` 役割を外し、ロールを**グループ**として再定義（複数メンバー可）。プロンプト注入（【登場人物】）はロールに一本化。
- **Part B: ロールグループと定量条件**（本体）
  - 条件節に `group`（ロール＋数量詞＋メンバー下位条件）を追加、`charVar` を撤去。
  - 「当事者（結果の対象）」を `subject` フラグで指定。`@ロール名` 置換で結果本文へ当事者名を注入。
  - 実績・エンディング・特別イベントに適用。エンディングの `N人ぴったり` はレビューでプルダウン選択。

Part A は Part B の前提（ロールをグループにするには @名前 役割を先に剥がす必要がある）。フェーズは A→B の順（後述）。

## Part A: 名前置換の分離とロールのグループ化

### A-1. 置換タグ（導入文専用）

**目的**: 再利用可能な世界観で導入文を書くとき、実キャラが未定でも `@ヒロイン` 等のプレースホルダで書けるようにする。ロールとは独立。

**原則（合意）**: 世界観は**再利用可能な資源**で、定義時点では実キャラ名は未確定。よってタグ定義は**実名を含まない自由な `@` 文字列**（例: `@主人公`・`@ヒロイン`）とし、**実キャラ/ペルソナへの対応付けはセッションまたはカセットの中で**行う（世界定義時にキャラ名・ペルソナ名を焼き込まない）。

- **定義（世界/導入文オーサリング時）**: `WorldStartPreset.introTags?: { id: string; tag: string; note?: string }[]`（世界の開始テンプレートに持つ。世界選択時に他項目と同じ規則でセッションへコピー）。`tag` は `@` を除いた表示名（例: `ヒロイン`）。**この時点では対応先を持たない**（自由文字列のみ）。
- **対応付け（セッション/カセット時）**: `Session.introBindings?: { tag: string; kind: 'persona' | 'character'; characterId?: string }[]`。各タグを **ペルソナ** または **参加キャラ1名**（`characterId` 参照）へ対応付ける。実名ではなく**参照**を持つので、キャラのリネームにも追従する。リテラル文字列（名前直書き）は再利用性を損なうため**採らない**（決定）。
- **解決**: `startStory` で導入文（`story.opening`／`openingTitle`）中の `@tag` を対応先の**現在の実名**へ置換してから掲載する（現在 `resolveCasting` が担っている処理の置換タグ版）。未対応のタグが残る場合は開始をブロック（現行の未解決 @ロール名 と同じ扱い）。
- **構造化出力との整合**: 置換タグは**実名**へ置換されるため、置換後の導入文は既存の構造化レンダラ（`matchCharacterByName`）でそのままアイコン解決できる。例: `@主人公(neutral)「…」` → `アリス(neutral)「…」`。
- **UI**: 導入文エディタ（WorldEditor 開始テンプレート／SessionEditor／CassetteEditor）に「置換タグ定義」欄（タグ追加・削除）と、導入文 textarea の近くに現在のタグ一覧を表示。セッション/カセット設定側でタグ→対応先の割り当て欄（各タグに [ペルソナ / 各参加キャラ] の1択ドロップダウン。`CastingFields` を流用または新設 `IntroTagFields`）。

### A-2. ロールのグループ化

**目的**: ロールを「1..N人のメンバー集合」にし、条件・プロンプト注入の基盤にする。@名前 の役割は A-1 へ移したので、ロールは**名前解決を持たない**。

- **型**: `WorldRole = { id, name, description, required? }`（現行と同じ。意味が「1人の配役」→「メンバー集合の定義」へ変わる）。
  - `required?`＝**メンバーが1人以上必要**（未割当では開始不可）。1人グループを必須にすれば従来の必須単独ロール相当。
- **メンバーシップ**: `Session.roleAssignments: { roleId, characterId }[]` を**多対多**に（同一 `roleId` に複数行＝複数メンバー、同一 `characterId` が複数ロール＝兼任）。既存の「1ロール1人」制約を撤廃。旧データ（1対1）はそのまま有効。
- **プロンプト注入**: 【登場人物（配役）】ブロックを「ロール名: メンバー実名（立場: description）」の形で列挙（複数メンバーは実名を併記）。`buildSystemPrompt` の現行 @配役 注入を置き換え。
- **UI**: `CastingFields` を「ロールごとに参加キャラを複数選択（チェック/マルチセレクト）」へ拡張。WorldEditor のロール節も「グループ（複数メンバー可）」前提の説明へ更新。

### A-3. 既存 casting からの移行

- `casting.ts` の `@ロール名` 解決（`findCastingRefs`/`resolveCasting`/`validateCasting`）は **A-1 の置換タグ解決へ移行**（ロール参照ではなくタグ参照に）。導入文の @記法検証もタグ基準へ。
- `World.roles` の @名前 用途を削除。`prompts.ts` の【配役】注入を A-2 の形へ。
- `cards.ts`（カセット/世界カード）で roles・introTags・introBindings を同梱対象に追加。
- カセット PNG 書き出しの「未解決の配役があると拒否」は「未束縛の置換タグがあると拒否」へ読み替え。

## Part B: ロールグループと定量条件

### B-1. 数量詞と条件節

```ts
// 数量詞（グループの何人が満たすべきか）
type Quantifier =
  | { kind: 'all' }                 // 全員
  | { kind: 'atLeast'; n: number }  // N人以上
  | { kind: 'exactly'; n: number }  // N人ぴったり

// 条件の最小単位。既存4種に group 複合節を追加。charVar は撤去
type Clause =
  | { kind: 'stat'; defId; characterId?; op; value }
  | { kind: 'counter'; defId; characterId?; op; value }
  | { kind: 'relationFlag'; fromId?; toId?; flag; have }
  | { kind: 'achievement'; defId; have }
  | { kind: 'group'; roleId: string; quantifier: Quantifier; subject?: boolean; clauses: GroupSubClause[] }

// group 内の各メンバーに課す下位条件（キャラ限定。global/実績は不可）
type GroupSubClause =
  | { kind: 'stat'; defId; op; value }       // そのメンバーの character スタット
  | { kind: 'counter'; defId; op; value }    // そのメンバーの character カウンター
  | { kind: 'relationFlag'; flag; have }     // そのメンバー→主人公 の関係フラグ

type Condition = { all: Clause[] } | { any: Clause[] }
```

- **平の character 節（characterId 未指定・group の外）** は「参加キャラの誰か1人が満たす（∃）」の存在条件として残す（charVar 廃止後の後方互換・当事者にはしない＝ゲート専用）。当事者を出したい条件は `group` 節で書く。
- `subject?: boolean`＝この群を**結果の当事者**にするか（既定 false）。当事者＝`@ロール名`/`@相手` 置換・エピローグ注入・実績/エンディング記録の対象。ゲート（ラスボス撃破など）は subject を付けない。

### B-2. 評価（`matchGroups`＝`matchAssignments` の後継）

`group` 節1つの評価:

1. `members` = セッションで `roleId` に割り当てられた参加キャラ。
2. 各 `member` に対し全 `clauses`（下位条件）を「その member をキャラとして」評価し、全て真なら satisfying に入れる（参加キャラ順を保つ）。
3. 数量詞判定:
   - `all`: `members.length > 0 && satisfying.length === members.length`
   - `atLeast n`: `satisfying.length >= n`
   - `exactly n`: `satisfying.length >= n`（成立ゲート。**当事者は n 人に絞る**＝後述）
4. **当事者（subject の時のみ）**:
   - `all` / `atLeast n`: satisfying 全員
   - `exactly n`: satisfying から **n 人を選ぶ**（エンディングはレビューのプルダウン・実績は下記 要確認）

条件全体（`all`/`any`）は各 Clause（平＋group）の真偽で合成。当事者は **subject フラグの group 節の当事者の合併**（ロールごとに束ねて保持）。

- 純関数 `matchGroups(cond, state, world, session): { ok: boolean; subjects: RoleParty[] }`（`exactly` は「候補集合」も返し、UI が n 人選択に使う）。`RoleParty = { roleId; roleName; members: Partner[] }`。`evalCondition` は `ok` の互換窓口。

### B-3. 当事者と結果の分離・`@ロール名` 置換

- 実績 `description`・エンディング `epilogueGuidance`／`name`・イベント `note` 内で:
  - `@ロール名` → その**subject ロールの当事者メンバー名**（複数は「・」連結）。
  - `@相手` → 全 subject 当事者名の連結（従来 `@相手1` の後継・単一群の簡易記法）。
- 置換ヘルパ `bindRoleNames(text, subjects)`（FB7-D の `bindPartnerNames` を置き換え）。
- **結果の分離が効く例**: 実績条件＝`all[ achievement:ラスボス撃破(have), group:ヒロイン(atLeast 1, [好感度≥70], subject:true) ]`。`description`＝「@ヒロイン と結ばれた」→ ラスボスは当事者でないので名前に出ず、ヒロインの当事者名だけが入る。

### B-4. 発火記録（キャラの組ごとの独立性）

- **実績**: `SessionState.achievements[].parties?: { roleId; characterIds: string[] }[]`（当事者の組）。同じ (defId, parties) は再解除しない。当事者を持たない（group subject 無し）定義は defId 単位で1回。
- **特別イベント**: 消化キーを `eventId` / `eventId@<subject当事者id を連結>` に（`eventUsedKey` を当事者ベースへ更新）。素の `eventId` は旧データ＝全消化扱い。
- **エンディング**: `Session.ending.parties?`／`EndingRecord.parties?` に当事者の組を記録。

**決定（by-role parties を採用）**: 記録は**ロール別の当事者組 `parties`**（`{roleId, characterIds}[]`）で持つ。理由: subject ロールが2つ以上ある条件で `@ヒロイン`/`@ライバル` を別々に解決するには、どの当事者がどのロールかの対応が必須（平坦 id 配列だと多ロール `@ロール名` が壊れる）。表示も「ヒロイン: アリス / ライバル: ボブ」とグループ見出し付きにできる。単一 subject ロールなら従来どおり素直に1群。

### B-5. `N人ぴったり` の当事者選択

- **エンディング**: レビュー画面で subject の `exactly n` 群ごとに **n 個のプルダウン**（各プルダウンの選択肢＝その群の satisfying メンバー・重複不可）。既定＝参加キャラ順の先頭 n 人。組み合わせ全列挙はしない（C(M,n) 爆発を避ける）。確定時 `endingParties` として `confirmSceneReview` へ。
- **実績**（自動解除・プルダウン不可）: **決定＝案1**。実績では `exactly n` を **`atLeast n` と同じ**扱いにし、当事者＝satisfying 全員とする（自動解除で人選できないため）。条件エディタで実績に `exactly n` を選んだ場合「実績では N人以上として扱われます」と注記する。エンディングのみプルダウンで n 人に絞る。

### B-6. 適用範囲

条件エンジンを使う全箇所を `matchGroups` 経由へ:

- 実績 `unlockAchievements`（defs × 当事者組で反復・連鎖依存は現行どおり反復）
- エンディング `checkEndings`（最上位成立の当事者候補を返す・`exactly` は選択候補も）
- 特別イベント `nextScheduledEvent`（未消化の (イベント, 当事者組) を day 順・参加キャラ順で1つ）
- `ScheduledEvent.condition`・`AchievementDef.condition`・`EndingDef.condition`

### B-7. UI（条件エディタ）

- ClauseRow に種別「グループ条件」を追加。選ぶと: **ロール選択**＋**数量詞（全員/N人以上/N人ぴったり＋Nの数値入力）**＋**下位条件の行**（スタット/カウンター/関係フラグ・メンバーに課す）＋**「結果の当事者にする」チェック（subject）**。
- 実績・エンディング・イベントの説明文を「グループ条件は対象ロールのメンバーに課され、当事者にしたロールの名前が `@ロール名` に入ります。判定だけに使うゲート条件（ラスボス撃破等）は当事者にしないでください」に更新。
- 実績/エンディング一覧（StatusView 等）は当事者の組ごとの解除/到達行を表示。

## フェーズ分割

- **Phase 1（Part A）**: 置換タグ新設＋ロールのグループ化＋【登場人物】注入一本化＋casting 移行。（見た目/導入文の作り直しが中心・条件はまだ触らない）
- **Phase 2（Part B コア）**: `group` 節・`matchGroups`・`charVar` 撤去・subject と `@ロール名` 置換・実績/エンディング/イベント適用（数量詞は 全員/N人以上）。
- **Phase 3（Part B 拡張）**: `N人ぴったり`＋エンディングのプルダウン選択。

各フェーズ完了ごとに tsc→build、純関数の node/preview 検証、コミット＋AGENTS.md 更新。

## 検証方針

- `matchGroups`／`bindRoleNames`／`eventUsedKey` を合成 state で直叩き（全員/N人以上/N人ぴったり・subject 分離・複数群・平の∃・実績組ごと解除・イベント消化キー）。
- 置換タグ解決（ペルソナ/キャラ/リテラル・未束縛ブロック）。
- ユーザー確認（見た目/UX）は各フェーズ完了時に手順つきで提示。

## 決定事項（2026-07-20 合意）

1. **A-1** 置換タグの対応先は **ペルソナ / 参加キャラ の参照**（実名・リテラルは焼き込まない）。定義は世界（自由 `@` 文字列）、対応付けはセッション/カセット。
2. **B-4** 発火記録は**ロール別 `parties`**（多ロール `@ロール名` 解決に必須）。
3. **B-5** 実績の `N人ぴったり` は **`N人以上` と同視**（当事者＝満たした全員）。エンディングのみプルダウンで n 人選択。
4. **フェーズ順 A→B→拡張** で進める。Phase 1（導入文・ロールの作り直し）から着手。
