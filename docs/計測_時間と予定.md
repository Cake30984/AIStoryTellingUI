# 計測_時間と予定

固定タイムライン（`Timeline` の日・時間帯スロット）を廃止し、**現在時刻を自由文字列にして予定を言語で管理する**案の実測記録（2026-09-06）。

> ## 結論
>
> 1. **予定リストを本編プロンプトへ常時注入してはいけない。** 該当予定が無い時点で、15件のリストを注入すると **28/30** で無関係な先の予定（七回忌・衣替え・12月24日の待ち合わせ等）を本文に引きずり出す。リスト無しの対照は **0/30**
> 2. **本編へ渡すのは「照合済みの一文（前景）」だけでよい。** 触れてほしい予定への言及は 6/30（現在のみ）→ **26/30**（前景一文のみ）へ上がり、しかも無関係な予定の漏れは **0/30** のまま
> 3. **照合に id を返させない。** 読解は成功しているのに id の書き写しだけが落ちる事故が 450回中 **50回**。前景の一文だけを書かせれば、この失敗モードは丸ごと消える
> 4. **予定の件数で設計を縛る必要はない。** 3件・8件・15件で照合精度は 91% / 86% / 89% とほぼ変わらない（「件数が増えると取りこぼす」という事前の仮説は**外れ**）
> 5. **相対表現（「来週水曜」「三日後の夜」）は書かせない。** 30回中2回しか発火せず、その2回とも誤り＝基準日が無いので解釈しようがない
>
> 実コスト: **$0.153**（生成・判定こみ 1214 呼び出し）

## 1. 測定の枠組み

| | |
|---|---|
| 本編・照合モデル | `deepseek/deepseek-v4-flash`（普段使い帯。`計測_登場制御.md` と同じ帯） |
| 判定モデル | `qwen/qwen3-30b-a3b-instruct-2507`・温度 0（同上） |
| 温度 | 照合 0.4（アプリのレビューと同じ）／本編 0.9（既定と同じ） |
| 出力形式 | 照合は `response_format: json_schema`（アプリのレビューと同じ） |
| reasoning | プロバイダ既定のまま（アプリは `reasoning` に触れないため） |

**フラグの立った件は全部人手で読み直した。** 前例（`計測_迎合対策文面.md` §5・`計測_登場制御.md` §3.3）どおり、判定 LLM の分類をそのまま採らない。今回もこれで結論が2回ひっくり返っている（§5）。

スクリプトはスクラッチパッド（`scratchpad/meas/`）に置いた。フィクスチャは1つの物語世界（高校2年・6月〜翌春）に予定スリップ15件を持たせ、**「現在」だけを差し替える**構成にしてある＝件数の効果を素材の違いで汚さないため。

## 2. 測定A — 現在時刻と予定の照合精度（480呼び出し）

「現在」と予定スリップ N 件を渡し、**いま前景に出すべき項目**と、突き合わせた一文（`foreground`）を返させた。

### 2.1 件数の効果（30回/セル・5ケース合計）

| 予定の件数 | `foreground` 文で採点 | `fire`（id 配列）で採点 |
|---|---|---|
| 3件 | **136/150（91%）** | 122/150（81%） |
| 8件 | **129/150（86%）** | 111/150（74%） |
| 15件 | **133/150（89%）** | 112/150（75%） |

**件数はほぼ効かない。** 事前に立てていた「15件では取りこぼすので上限8件を設ける」という設計は根拠を失った。

### 2.2 2つの採点基準が15ポイント離れた理由

**読解は当たっているのに id の書き写しだけが落ちる。** 450回中 **50回**。

```
fire=[]  foreground='8月31日朝、夏休み最終日、田舎から東京へ帰る。'
```

`fire` に行全体（`'p01 いつ: 夏休み最終日 / なに: 田舎から東京へ帰る'`）や `'現在'` が入る形式崩れも各セル 1〜5件あった。

→ **照合には id を返させず、前景の一文だけを書かせる。** 消化（`done`）の判定は別の呼び出しに分ける。

### 2.3 ケース別（15件・`foreground` 採点）

| ケース | 現在 | 正解 | 結果 |
|---|---|---|---|
| C4 条件つき | 三日降り続いた雨がやんだ朝 | 「雨が止んだら」の項目 | **29/30** |
| C5 前日 | 9月9日 夜 | 「9月10日」の項目 | **29/30** |
| C1 暦の常識 | 8月31日 朝 | 「夏休み最終日」の項目 | 27/30 |
| C2 幅の解釈 | 6月半ば | 「6月後半」の項目 | 26/30 |
| C3 該当なし | 9月20日 放課後 | （何も選ばない） | 22/30 |

**事前の見立てと強弱が逆だった。** 一番不安だった条件つきが最も強く、一番安全に見えた暦の常識が弱い。ただしどれも 26/30 以上で、「言語的ニュアンスで予定を管理する」という方針自体は成立する。

### 2.4 相対表現は死に項目

「来週水曜」「三日後の夜」を混ぜたところ、発火は **2/30**。しかもその2回とも誤りだった（基準日が無いので解釈できない）。

→ **スリップの「いつ」に相対表現を書かせない。** 本文に「来週水曜に会う約束をした」と出たら、記録する時点で絶対表現へ解決する。

## 3. 測定A-3 — 条件つきの誤発火は「場面の状況」で止まるか（120呼び出し）

C3（該当なし）で「雨が止んだので」「彼女と二人きりになったので」と**前提を捏造して**発火する例が出たため、照合の入力に固定トラッカー枠（場所・居合わせている人・状況）を足して比較した。

| 入力 | 15件のとき正しく「該当なし」 |
|---|---|
| 現在のみ | 23/30 |
| 現在＋場面の状況 | 25/30 |

**差は無い。** ただしフラグの立った12件を全部読み直したところ、**判断そのものを誤っていたものは無かった**。

| 中身 | 件数 | 実際は何か |
|---|---|---|
| 「雨が止んだので、川べりの捜索を再開する」 | 5 | **フィクスチャの欠陥**。状況に「晴れていて雨は降っていない」と書いたので条件は成立していると読める |
| 「次に彼女と二人きりになったら、約束のことを切り出す」 | 3 | 条件文をそのまま書き写しただけ（成立を主張していない） |
| 「冬になる前なので、屋根の修理を頼む」 | 2 | 「冬になる前」は幅が広く 9月20日を含むとも読める |
| 「文化祭は始まっているが、まだ二人きりになっていない」 | 1 | **成立していないと正しく書いた上で** `fire` に入れた＝§2.2 の帳簿の失敗 |
| 推論をそのまま `foreground` に出力 | 1 | 判断は全部正しい。形式が崩れただけ |

### 3.1 ここから出る作者向けの指針

**条件つきスリップは「状態」として読まれる。**

- **点**で書く（8月31日・明日・9月10日）→ その時だけ出る
- **遷移**で書く（降り続いた雨が**やんだとき**）→ 一度だけ出やすい
- **幅**で書く（冬になる前・6月後半）→ その期間ずっと出続ける

「一度きり」にしたいなら遷移で書く。**機構は要らず、ガイドの1節で済む。**

## 4. 測定B — 注入形式の比較（300生成＋300判定）

予定15件を持つ状態で、本編プロンプトへの渡し方を4条件で比べた。

| 条件 | 本編へ渡すもの |
|---|---|
| W3 | 【現在】だけ（対照） |
| W0 | 【現在】＋【控えていること】15件のリスト |
| W1 | W0 ＋ 深さ0へ照合済みの前景一文 |
| W2 | 【現在】＋前景一文のみ（**リストを渡さない**） |

### 4.1 B2「6月半ば／6月後半に中間試験」（判別力のある場面）

| 条件 | 試験に触れた | **無関係な先の予定が本文に漏れた** |
|---|---|---|
| W3 現在のみ | 6/30（20%） | **0/30** |
| W0 リスト | 27/30（90%） | **17/30（57%）** |
| W1 リスト＋前景 | 30/30（100%） | 6/30（20%） |
| **W2 前景のみ** | **26/30（87%）** | **0/30** |

**W2 が最良。** 効果はほぼ最大で、副作用が無い。

### 4.2 B3「該当する予定が無い時点」（誤爆テスト）

| 条件 | リスト固有語（七回忌・捜索・衣替え・12月24日・屋根の修理）への言及 |
|---|---|
| W3 リスト無し | **0/30** |
| W0 リスト有り | **28/30** |

実例:

> 悠は言いながら、ふと壁のカレンダーに目をやる。10月1日は衣替え。その翌週には祖母の七回忌がある。冬になる前に屋根の修理も頼まなければ。

**リストは背景情報として静かに保持されない。「いま語るべき話題」として読まれ、脈絡なく列挙される。**

### 4.3 B1「8月31日／夏休み最終日に帰る」は判別力が無かった

| 条件 | 判定LLM | 客観指標 |
|---|---|---|
| W3 | 22/30 | 23/30 |
| W0 | 22/30 | 26/30 |
| W1 | 22/30 | 19/30 |
| W2 | 14/30 | 18/30 |

**対照（W3）が既に 23/30。** 「8月31日」＋「田舎に滞在」「東京に学校がある」から、モデルは予定を渡されなくても夏の終わりを推論する。**天井効果でこの場面は条件を比べられない。** 判定LLMが W2 を 14/30 と低く出したのは誤分類で、原文には「八月も今日で終わりだ」「もう帰っちまうのかい」が入っていた（§5）。

## 5. 踏んだ落とし穴（次に測る人へ）

1. **`fire`（id 配列）で採点すると読解力を15ポイント過小評価する。** 壊れているのは理解ではなく帳簿。**測りたいものが「読めているか」なら、id ではなく文章で採点する**
2. **判定 LLM は B1 の W2 を系統的に取りこぼした。** 「帰る」ことを婉曲に描いた文（「もう帰っちまうのかい」）を不言及と判定する。前2回の実測と同じ罠なので、**フラグの立った件は必ず人手で読む**
3. **B3 の判定質問「まだ先の予定に触れているか」は、モデルが自前で発明した学校行事も拾ってしまう**（W3 が 22/30 に見えた）。リスト固有語での客観採点に切り替えて 0/30 と判明した。**注入したものの影響を測るなら、注入物にしか出てこない語で採点する**
4. **条件つきスリップのフィクスチャは、条件が成立しているとも読める状況を書いてしまうと測定にならない**（§3 の「雨が止んだら」）

## 6. 設計へ返すもの

| 事前の設計案 | 実測後 |
|---|---|
| 予定を【控えていること】として本編に常時注入する | **廃止**（§4.2） |
| 前景昇格（照合済みの一文を深さ0へ） | **採用**（§4.1）。ただし**リストは渡さない** |
| 照合は id と前景の両方を返す | **前景の一文だけ**（§2.2） |
| 予定は8件を上限とする | **上限は不要**（§2.1） |
| 照合の入力に場所・居合わせている人・状況を足す | **照合のためには不要**（§3）。固定枠自体は別の理由（表示・引き継ぎ）で残す |
| 「いつ」は自由文字列 | **相対表現だけ禁止**（§2.4）。点／遷移／幅の使い分けはガイドで示す（§3.1） |

**予定スリップは記録と照合のための内部データであって、本編プロンプトには出ない。** 本編が受け取るのは【現在】と前景の一文だけ——これが実測から出た最大の単純化。
