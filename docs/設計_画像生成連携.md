# 設計: 画像生成連携（ComfyUI／OpenAI互換API・アバター生成・挿絵・セッションカード）

`docs/設計_画像カードとアバター.md` の P5 の詳細設計。P1〜P4（IndexedDB画像ストア・EntityAvatar・PNGカード入出力）は実装済みで、本設計はその基盤の上に載る。

- 決定事項（ユーザー合意済み）:
  - 生成先は **ComfyUI（ローカル）と OpenAI 互換 images API の2種** を最初からサポート（プロバイダ抽象層を作る）
  - 挿絵は **手動生成のみ**（自動生成・レビュー連動はしない）
  - 画像プロンプトは **裏方LLMが起案 → ユーザーが編集 → 生成**
  - Character/Persona に **`imagePrompt`（画風・外見の固定英語タグ。LoRAトリガー等）** を持たせ、カードにも含めて共有可能にする
- 実装フェーズ: G1〜G4（1フェーズ＝1ターンで実装・検証・コミット）
- 永続化: 追加フィールドはすべて **任意（optional）** なので persist キーは `-v3` のまま（破壊的変更なし）。

---

## 全体アーキテクチャ

```
[ImageProvider]  kind: 'comfyui' | 'openai-image'   ← Provider（LLM用）とは別系統のリスト
      │ generateImage(provider, req) → Blob
      ▼
[imageGen.ts]  ComfyUI: POST /prompt → /history ポーリング → /view で取得
               OpenAI互換: POST /images/generations (b64_json)
      │
      ├─ アバター生成: ImageGenModal → normalizeImage(512) → putImage → avatar.imageId
      ├─ 挿絵:        ImageGenModal → putImage → Scene.illustrations に追記（messageId アンカー）
      │
[プロンプト起案] illustrationPromptSystem()（prompts.ts）
      直近本文＋シーン情報＋キャラ appearance/imagePrompt → 裏方LLM（reviewModelOf）
      → {"prompt","negative"} JSON（extractJson。失敗時は raw を prompt に）→ 編集可のテキストエリアへ

[セッションカード] aist_session チャンク（G4）
      session＋参照素材＋参照画像（base64同梱）を挿絵1枚に埋め込み → 1ファイルで完全共有
```

  createdAt: number

## G1: 画像生成基盤（プロバイダ管理＋ generateImage）

### `src/lib/imageGen.ts`

```ts
export interface ImageGenRequest {
  prompt: string
  negative?: string
  width?: number    // 既定 1024
  height?: number   // 既定 1024
}
/** プロバイダ種別を吸収して1枚生成する。失敗は throw（呼び出し側で表示） */
export async function generateImage(p: ImageProvider, req: ImageGenRequest, signal?: AbortSignal): Promise<Blob>
/** 接続テスト。ComfyUI: GET /system_stats、openai-image: GET /models（失敗しても 401 以外は到達扱いにするなど寛容に） */
export async function testImageProvider(p: ImageProvider): Promise<{ ok: boolean; message: string }>
export function newImageProvider(kind: ImageProviderKind): ImageProvider
/** ComfyUI 用デフォルト workflow（SD1.5/SDXL 標準構成の API Format。プレースホルダ入り） */
export const DEFAULT_COMFY_WORKFLOW: string
```

#### ComfyUI 経路

1. `workflowJson` の **プレースホルダを文字列置換**してから JSON.parse:
   - `%PROMPT%` → req.prompt / `%NEGATIVE%` → req.negative ?? ''（**JSON.stringify でエスケープしてから埋める**。`JSON.stringify(str).slice(1, -1)` で引用符を除いた安全な断片にする）
   - `%SEED%` → ランダム整数（0〜2^32）を毎回生成 / `%WIDTH%`・`%HEIGHT%` → 数値（`"%WIDTH%"` のように引用符ごと置換 → 数値リテラル化。テンプレ側は `"width": "%WIDTH%"` と書いてもらい、置換後に `"width": 1024` になるよう **引用符込みで置換**する）
2. `client_id = uid()` を生成し `POST {baseUrl}/prompt` body: `{ prompt: <workflowオブジェクト>, client_id }` → `{ prompt_id }` を得る
3. **ポーリング**: `GET {baseUrl}/history/{prompt_id}` を 1.5 秒間隔・最大 5 分。レスポンス `history[prompt_id].outputs` に `images: [{filename, subfolder, type}]` を持つノードが現れたら完了。`status.status_str === 'error'` なら `throw`
4. `GET {baseUrl}/view?filename=…&subfolder=…&type=…`（encodeURIComponent 必須）→ `res.blob()`
5. WebSocket（/ws）による進捗表示は**使わない**（追加実装に見合わない。ポーリングで足りる）

- **CORS**: ComfyUI は `--enable-cors-header '*'` を付けて起動しないとブラウザから叩けない。設定 UI に起動例を明記する（例: `python main.py --enable-cors-header '*'`）。接続テスト失敗時のエラーメッセージにも案内を入れる。
- デフォルト workflow テンプレ: CheckpointLoaderSimple → CLIPTextEncode ×2（%PROMPT% / %NEGATIVE%）→ EmptyLatentImage（%WIDTH%/%HEIGHT%）→ KSampler（%SEED%）→ VAEDecode → SaveImage の最小 API Format を定数で同梱。ckpt_name はユーザー環境依存なので `"%CKPT%"` にはせず、テンプレ冒頭コメント（UI の desc）で「モデル名は自分の環境に合わせて書き換えてください」と案内（JSON にコメントは書けないため UI 側で説明）。

#### OpenAI 互換経路

```
POST {baseUrl}/images/generations
Authorization: Bearer {apiKey}
{ model, prompt, n: 1, size: `${width}x${height}`, response_format: 'b64_json' }
```

- `data[0].b64_json` を `atob` → Uint8Array → Blob（type は 'image/png' 固定でよい）。
- `b64_json` が無く `url` のみ返す API への対応: `fetch(url)` を試すが **CORS で失敗し得る**。失敗時は「このプロバイダは URL 返却のみで、ブラウザから取得できませんでした」と明示エラー。
- `negative` はこの API に存在しないため **prompt 末尾に結合しない・単に無視**（UI 上で openai-image 選択時は negative 欄を隠す）。
- サイズは API により許容値が固定（dall-e-3: 1024x1024/1792x1024/1024x1792 等）。フリー入力にせず **プリセット選択**（1024x1024 / 1216x832 / 832x1216。comfyui は任意値可、openai は最も近い許容値に丸めず そのまま送ってエラーはAPIメッセージを表示）。

### 設定 UI（`ImageProviderSettings.tsx` → SettingsModal に組み込み）

- LLM プロバイダ管理と同じ操作感: 一覧（編集インライン）＋「＋ 画像生成の接続先を追加」（種別選択 → プリセット値投入）
- comfyui: baseUrl・workflow JSON（textarea・等幅・`DEFAULT_COMFY_WORKFLOW` を初期値）・「🔌 接続テスト」
- openai-image: baseUrl・apiKey（表示切替＋保存ボタンは LLM 側と同一パターン）・model・「🔌 接続テスト」
- persist: `imageProviders` を partialize に追加。**exportBundle に含めない**（apiKey 漏洩防止。providers と同じ扱い）

### G1 の検証

- tsc / build
- preview_eval で `testImageProvider`（ComfyUI 未起動なら失敗メッセージが返ることを確認）・`newImageProvider` の初期値

- **モック検証**: `generateImage` の ComfyUI 経路は preview_eval で fetch をモンキーパッチし、/prompt→/history→/view の呼び出し順とプレースホルダ置換結果（seed が数値化されているか・日本語プロンプトのエスケープ）を確認

## G2: 生成モーダル＋アバター生成＋ imagePrompt

### `src/components/ImageGenModal.tsx`（共用コンポーネント）

```ts
interface Props {
  /** プロンプト起案に使う文脈（呼び出し元が組み立てる。空なら起案ボタン非表示） */
  draftContext?: { system: string; user: string; modelRef: string }
  /** 初期プロンプト（キャラの imagePrompt など） */
  initialPrompt?: string
  /** 生成確定。呼び出し元が putImage 先を決める（アバター: normalize512→avatar / 挿絵: そのまま） */
  onAccept: (blob: Blob, prompt: string) => Promise<void>
  onClose: () => void
}
```

- 構成: プロバイダ select（`imageProviders`。0件なら設定への誘導文）／サイズプリセット／プロンプト textarea／negative textarea（comfyui のみ表示）／「✨ プロンプトを起案」／「🎨 生成」／プレビュー（生成後に表示）／「✔ この画像を使う」＝ onAccept／「🔁 もう一度」
- 起案: `streamChat`（onDelta 無視・temperature 0.7）→ `extractJson` で `{"prompt","negative"}` を取り、失敗時は **raw テキスト全体を prompt 欄へ**。起案結果は textarea を**上書き**（ユーザー編集後の再起案も上書きで良い。確認はしない）
- 生成中は AbortController で「✕ キャンセル」可。エラーは notice 表示（モーダルは閉じない）
- 生成した blob はまだ putImage しない（onAccept 時に呼び出し元が保存）。「もう一度」は前回 blob を破棄

### プロンプト起案（`prompts.ts` に追加）

```ts
export function illustrationPromptSystem(): string
// 出力契約: {"prompt": "英語のdanbooru風カンマ区切りタグ or 簡潔な英語描写", "negative": "..."} の JSON のみ。
// 品質タグ（masterpiece 等）は入れない（モデル依存のため。固定タグはユーザーの imagePrompt に任せる）。
```

- user 側の文脈組み立てはヘルパ `buildIllustrationContext(session, refs, messages)` を store.ts（または prompts.ts）に置く:
  - 直近メッセージ 6 件の本文（マーカー除外）
  - 現在シーンの title / note / timeLabel
  - 登場キャラ各: 名前・appearance・**imagePrompt**（そのままタグとして採用するよう指示）
- モデル解決: **`reviewModelOf(session)`**（裏方レビューモデルを流用。新フィールドは足さない）
- アバター生成時（セッション文脈なし）の起案 user 文: name / appearance / imagePrompt のみで組み立て

### AvatarField への「✨ 生成」

- `AvatarField` に props 追加: `genContext?: { name: string; appearance?: string; imagePrompt?: string }`（Character/Persona エディタが渡す。World は対象外）
- `imageProviders.length > 0` のとき「✨ 生成」ボタン表示 → ImageGenModal（draftContext は**裏方LLMなしの固定組み立て**でも起案可にするため、providers[0] が無い場合は起案ボタン非表示・手書きのみ）
- onAccept: `normalizeImage(blob, 512)` → `putImage` → `onChange({ ...avatar, imageId })`

### imagePrompt フィールド

- `CharacterEditor` / `PersonaEditor` に input を1つ追加（label「画像生成タグ（英語・任意）」、desc「LoRAトリガーや髪色などの固定タグ。挿絵・アバター生成時に自動で使われます」）
- cards.ts の normalize 2 関数に passthrough 追加（前述）

### G2 の検証

- tsc / build
- ComfyUI or 画像API が無い環境: preview_eval で `generateImage` を返り値固定のモック（`import` したモジュールの関数は差し替え不可なので、**ImageGenModal はテスト用に window.__mockImageGen があればそれを使う…はしない**。代わりに fetch モンキーパッチで openai-image 経路に 1x1 PNG の b64_json を返させ、モーダル一連（起案はスキップ）→ アバター反映まで通す）
- imagePrompt がカード書き出し→読み込みで往復すること

## G3: 挿絵（シーン紐づけ・インライン表示）

### 生成導線

- ChatPanel topbar に **🎨 ボタン**（📊 📖 の並び）→ ImageGenModal
  - draftContext = `buildIllustrationContext(...)`＋`reviewModelOf`
  - initialPrompt = 参加キャラの imagePrompt を連結したもの（起案前でも最低限の足場になる）
  - onAccept: `putImage(blob)`（挿絵は縮小しない＝原寸保存。DL や拡大表示に耐える）→ `addIllustration(sessionId, currentSceneId, { id: uid(), imageId, prompt, messageId: 最後のメッセージid, createdAt })`
- 現在シーンが無い（物語未開始）場合は 🎨 を disabled

### 表示

- メッセージ描画ループで、各メッセージの直後に `scene.illustrations` のうち `messageId === m.id` のものを `<figure class="illustration">` で表示（`useImageUrl`）。`messageId` が見つからない挿絵（メッセージ削除後）は**シーン末尾**にまとめて表示（ダングリング対策）
- ホバーで操作: 「⬇ 保存」（`downloadBlob`）／「🗑 削除」（`removeIllustration`。imageId の blob は消さず GC 任せ＝既存方針どおり）
- クリックで簡易拡大（overlay に等倍表示。ライブラリ追加はしない）
- CSS: `.illustration img { max-width: min(100%, 640px); border-radius: var(--radius); }`

### 整合性

- `gcUnusedImages` の used 集合に `sessions[].scenes[].illustrations[].imageId` を追加（**G3 で必ず同時に入れる**）
- `regenerateFrom` / `deleteMessage` で messageId が消えるのは許容（シーン末尾フォールバックで表示は継続）
- exportBundle（JSON）: illustrations は **そのまま含める**（imageId はダングリングになるが表示されないだけ。従来のアバター方針と同一）

### G3 の検証

- fetch モック経由で挿絵を1枚生成 → メッセージ直後に表示・リロード後も表示（IndexedDB 永続）・削除で消える・GC が挿絵を守ることを確認

## G4: セッションカード（aist_session。挿絵に物語まるごと埋め込み）

### 形式

```jsonc
{ "spec": "aist_session", "spec_version": "1.0",
  "data": {
    "session": { /* Session 丸ごと（model/reviewModel/choicesModel は ModelRef＝環境固有だが、文字列として無害なので残す。インポート側で解決不能なら providers[0] にフォールバックする既存挙動） */ },
    "characters": [ /* 参照している Character（imagePrompt 込み・model は除外） */ ],
    "world":      { /* 参照 World or null */ },
    "persona":    { /* 参照 Persona or null */ },
    "images":     [ { "id": "<元imageId>", "b64": "<PNG base64>" } ]  // 参照アバター＋挿絵を同梱
  } }
```

- **完全自己完結**: `images` に「参照素材のアバター画像＋セッション内全挿絵」を base64 で同梱。インポート時に `putImage` し直して**新 id へ全参照を remap**（アバター imageId・illustrations[].imageId）
- カード画像（見た目）: セッション内の挿絵から**ユーザーが1枚選択**（挿絵が無ければ `generateDefaultAvatar(session.title)` で自動生成）
- サイズ注意: base64 で膨らむため、**同梱前に合計サイズを概算し 30MB 超で警告**（続行は可能）。tEXt チャンク自体に仕様上の上限はない
- `providers` / `imageProviders`（APIキー）は**絶対に含めない**

### cards.ts 追加

```ts
export async function exportSessionCard(
  session: Session, refs: { characters: Character[]; world?: World; persona?: Persona },
  cardImageBlob: Blob,
): Promise<void>   // 収集 → images 同梱 → aist_session 埋め込み → DL
// parseCardPng に 'aist_session' 分岐を追加 → { kind: 'session', bundle: ParsedSessionBundle }
// importSessionCard(bundle)（store）: images を putImage → id remap → session/素材を id 衝突時は新id採番で追加
//   素材は「同 id が既にあればスキップ（既存優先）」…ではなく importBundle と同じ id マージに合わせる。
//   ただし session 本体は常に追加（id 衝突時は新 id）。
```

- 素材のマージ規則: **importBundle と同一（既存 id はスキップ＝既存優先）**。セッションが参照する characterIds/worldId/personaId は、スキップされた場合も既存素材の id と一致しているのでそのまま動く。素材 id が新規なら追加され、これもそのまま動く（remap 不要）。
- **例外**: 素材 id が既存と衝突しているが**中身が別物**のケースは検出しない（許容。既存優先で「手元の素材で読む」挙動になる）

### UI 導線

- ChatPanel の topbar メニュー（または Sidebar のセッション右クリックは実装が重いので **SessionEditor のフッター**）に「🖼 セッションをカード化」→ 挿絵ピッカー（サムネ一覧 or 自動生成）→ DL

## 実装上の落とし穴（必読）

1. **ComfyUI の CORS**: `--enable-cors-header '*'` なしでは fetch が TypeError。接続テスト・生成エラーの両方で起動オプションを案内すること。
2. **プレースホルダ置換のエスケープ**: プロンプトに `"` や改行・日本語が入る。`JSON.stringify(s).slice(1,-1)` で埋めないと workflow JSON が壊れる。`%SEED%`/`%WIDTH%`/`%HEIGHT%` は**引用符込み** `"%SEED%"` を数値に置換。
3. **ポーリングの離脱条件**: history に prompt_id が現れても outputs が空のことがある（実行中）。outputs に images を持つノードが出るまで待つ。最大5分で timeout throw。AbortSignal をポーリングループでも確認。
4. **b64→Blob**: `atob` の戻りは Latin-1 文字列。`Uint8Array.from(bin, c => c.charCodeAt(0))`。既存 cards.ts の `b64decode` は **UTF-8 テキスト用**なので流用しない（画像はバイナリ）。
5. **gcUnusedImages の used 集合更新**（G3）: 挿絵を入れ忘れると GC が挿絵画像を削除する。G4 実装後もセッションカードは IndexedDB を参照しないので追加対応不要。
6. **`Blob([uint8])` の型エラー**: TS の lib 更新で `Uint8Array<ArrayBufferLike>` が BlobPart に非適合。既存コードと同様 `bytes as BlobPart` でキャスト。
7. **Scene.illustrations は optional**: 既存データ（v3）には無い。読む側は必ず `scene.illustrations ?? []`。`importBundle` の worlds 最小補完と同様に sessions 側で配列補完を足すのが安全。
8. **openai-image の negative 非対応**: UI で欄ごと隠す（送ると 400 になる API がある）。
9. **画像URLのみ返す API**: CORS で取れない場合は明示エラー（silent fallback しない）。
10. **exportBundle に imageProviders を含めない**（apiKey 漏洩）。partialize には含める。
11. **セッションカードの容量**: 挿絵原寸同梱で数十MBになり得る。概算警告＋続行可。読み込み側の `atob` は大きくても動くが、`putImage` 直列で1枚ずつ処理（並列で IndexedDB を叩かない）。
12. 各フェーズ完了時: `npx tsc --noEmit` → `npm run build` → preview 検証（fetch モックで外部API非依存に）→ CLAUDE.md 更新を同一コミット → `git push origin main`。

## フェーズ間の依存

G1（基盤）→ G2（モーダル＋アバター）→ G3（挿絵）→ G4（セッションカード）は直列。G2 以降は ComfyUI 実機が無くても fetch モックで検証可能な構造にする（imageGen.ts が fetch のみに依存していれば良い）。
