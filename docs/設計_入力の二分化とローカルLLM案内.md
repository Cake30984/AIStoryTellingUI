## A. 入力の二分化（IN1）

### A-0. いま何が困っているか

コンポーザーの入力欄は1つしかなく、書いたものは**すべて主人公の発言・行動として履歴に積まれる**（`store.send` → `role:'user'` のメッセージ）。
そのため「もっと緊張感を出して」「そろそろ雨を降らせて」のようなメタな要望を書くと、

- 主人公がそれを**口に出した**ことになり、登場人物がその発言に反応してしまう
- その一文が本文として残るので、書き出し（R10）にもレビューのあらすじにも混ざる

という2つの壊れ方をする。story モードのプレースホルダは既に「物語への介入や方向づけを入力（任意）」と謳っているのに、
**中身は介入と発言を区別していない**のが現状。

### A-1. 決定（スコープ）

| 決めたこと | 内容 |
|---|---|
| 種類 | **2種類だけ**（セリフ・行動 ／ 書き手への指示）。3つ目は作らない |
| 効き方 | 指示は**その場かぎり（one-shot）**。以後もずっと効かせたい方針は既存の `authorNote`（固定メモ）が担当 |
| 送信後 | 指示も送信で**そのまま生成が走る**（＝方向づけ付きの「続ける」）。溜めておく箱は作らない |
| 履歴 | 指示は**履歴に残す**（本編プロンプトには載る）。消したい時は通常どおりメッセージ削除 |
| モード | roleplay / story のどちらでも使える（メタ指示の必要性は文体に依存しない） |

**却下した案**:

- *送信せず「次の生成にだけ効く一時メモ」として保持する* → 何が効いているのか画面から消えるうえ、チェックポイント（分岐）に乗らない状態が1つ増える。分岐で戻った時に「その時の指示」が復元できない
- *指示を `authorNote` に自動追記する* → `authorNote` は system 直下に毎ターン注入される常設メモで、一度きりの指示を積むと**永久に効き続ける**（しかも PC1+PC4 の毎ターン変わる値の禁止に触れる）
- *モードを持たず `/` や `※` などの記号で書き分ける* → FB8-E2（文字記号の全廃）と逆行し、覚えないと使えない

### A-2. データモデル

`Message` に**任意フィールドを1つ足すだけ**にする（破壊的変更なし＝`SAVE_DATA_VERSION` は 1 のまま）。

```ts
export type MessageKind = 'directive'

export interface Message {
  // …既存
  /** 通常の本文（＝未設定）ではない特別な入力。'directive' ＝書き手 AI への指示（IN1） */
  kind?: MessageKind
}
```

- 未設定＝従来どおりの本文。旧データはそのまま読める
- 追加は `partialize` の対象外作業（`messages` は Session の一部としてまるごと永続化されるため）
- 判定は `isDirective(m)`（`prompts.ts` に置き、store・UI・書き出しの全経路がこれを使う）

### A-3. プロンプトへの載せ方

`buildMessages` の `toChat` で、指示メッセージだけ**固定の枠**をかぶせて user として送る。

```
【書き手への指示】これは登場人物の発言ではなく、書き手であるあなたへの指示です。
主人公が言った・行ったこととして扱わず、この指示文そのものを本文に書かずに、続きの描写へ反映してください。
{ユーザーが書いた本文}
```

- **枠は常に同じ文面**にする。「最新の指示だけ丁寧な枠、古いものは短縮形」にすると、新しい指示を送るたびに
  **過去メッセージの中身が変わってキャッシュが切れる**（キャッシュ粒度はメッセージ単位＝`詳細設計_プロンプト構造とキャッシュ.md` §2）。
  枠が固定なら履歴は byte 安定のまま
- **深さ0への追加注入はしない**。指示を送った直後はその指示が履歴の末尾＝すでに最も強い位置にある。
  深さ0は毎ターン非キャッシュなので短く保つ（PC1+PC4）
- system プロンプトには**何も足さない**。「指示の書式はこうです」という説明を system に常設すると、
  1度も使わないセッションでも毎ターン払うことになる。枠が自己完結しているので不要

### A-4. 裏方・書き出しからは落とす

**指示は物語の本文ではない。** 本編プロンプトの履歴と画面表示以外では、マーカー（`CONTINUE_PROMPT` 等）と同じ扱いで落とす。

| 落とす場所 | 理由 |
|---|---|
| シーン終了レビューの transcript（`prepareSceneReview` の `sceneMsgs`） | あらすじ・関係性の評価対象は「起きたこと」だけ |
| 選択肢生成の直近本文（`recentPlainLines`） | 主人公の次の行動案を作る材料にならない |
| 挿絵プロンプト起案の文脈（`ChatPanel.sceneMessagesUpto`） | 絵にする対象ではない |
| 発見キャラの起案文脈（`CharacterDraftModal`） | 同上 |
| 物語の書き出し（`storyExport`） | R10 の要件＝「貼りたくなる出力」。舞台裏は載せない |
| チェックポイントのラベル（`actionCheckpointLabel` の user フォールバック） | ツリーの行に「もっと暗くして」と出ても中身が分からない |

**落とさない場所**（意図的にそのまま）:

- `buildMessages` の履歴（＝A-3 の枠付きで送る。これが本体）
- `sceneTokensOf`（文量バッジ・ペース制御の閾値）。実際に文脈を食っているので数える方が正しい

### A-5. UI

コンポーザーの入力欄の直上に、**ラベル付きの2択チップ**を常時置く（アイコン単独にしない＝FB8-E2）。

```
[ ● 主人公として書く ]  [ ○ 書き手に指示 ]
┌──────────────────────────────┐
│ （プレースホルダはモードで変わる）        │  [↑]
└──────────────────────────────┘
```

- アイコンは既存の `icons.tsx` から流用（`message-circle` ／ `clapperboard`）＝**新規アイコンを足さない**
- 指示モードのときは textarea に `.directive` を付けて枠線を変え、**送信前に見た目で分かる**ようにする
- 選択状態は ChatPanel のローカル state。**セッションを切り替えたら「主人公として書く」に戻す**
  （`session.id` の effect に相乗り）＝別の物語へ移ったときに前の気分を引きずらない
- 完結後（`isFinalized`）は入力欄ごと出ないので、チップも出ない

**本文での見え方**: 指示は主人公の吹き出し／`.prose-action`（斜体・アクセントの縦線）とは別の
`.prose-directive` で描く。破線の枠＋「書き手への指示」のラベル＋控えめな文字色で、
**地の文でもセリフでもない**ことがひと目で分かる形にする。novel / chat のどちらの文体でも同じ見た目にする
（文体は物語の描き方の設定であって、舞台裏の見た目を変える理由がない）。

**操作行**: 指示メッセージには 編集／ここから／分岐／削除 だけ出す。
挿絵・環境音・選択肢生成は出さない（挿絵と環境音ピンは本文の一点に紐づく機能で、指示行に置く意味がないうえ、
ピンは `messageId` 必須なので指示行に置かれると表示先を失う）。
