# デルシアをローカル LLM（自分の PC の AI）で動かす

デルシアは外部の AI サービスを使わなくても遊べます。自分の PC の中で動く AI（ローカル LLM）を
「接続先」として登録するだけです。**入力した文章は PC の外に出ません。月額も従量課金もありません。**

このガイドは、AI を1度も自分で動かしたことがない人が、**インストールから物語を1シーン書かせるまで**を
通しでできるように書いてあります。所要時間はダウンロード待ちを含めて 30 分ほどです。

---

## 1. これは何か・向き不向き

「ローカル LLM」は、文章を書く AI のプログラムとデータ（モデル）を自分の PC に置いて、PC の中だけで動かす方式です。

|  | ローカル LLM | 外部サービス（OpenRouter 等） |
|---|---|---|
| 文章の送信先 | 自分の PC の中だけ | 提供元のサーバ |
| 料金 | 無料（電気代のみ） | 従量課金・無料枠 |
| 準備 | 数 GB のダウンロード＋PC 性能が要る | API キーを登録するだけ |
| 文章の質 | PC の性能なりで頭打ち | 上限が高い |
| 速度 | GPU 次第。CPU だけだと厳しい | だいたい速い |

**向いている人**

- 書いた内容を外に出したくない（創作の内容そのものが個人的なもの、という理由で十分です）
- 従量課金を気にせず、何時間でも回したい
- ゲーム用の GPU（VRAM 8GB 以上）を積んだ PC がある

**向いていない人**

- ノート PC の内蔵グラフィックスしか無い（動くには動きますが、1文が出るまで分単位になることがあります）
- 空き容量が 10GB 未満
- とにかくすぐ試したい（それなら初回ウィザードの「OpenRouter で接続」が近道です）

> **迷ったら両方登録しておけます。** デルシアの接続先は何個でも登録でき、セッションごとに選べます。
> 「普段は外部サービス、機密性の高い話はローカル」という使い分けができます。

---

## 2. 必要な PC

効くのは主に **GPU の VRAM（ビデオメモリ）** です。モデルはまるごと VRAM に載ると速く、載りきらないと
メインメモリへあふれて一気に遅くなります。

| VRAM | 現実的に選べるモデルの大きさ | 体感 |
|---|---|---|
| 6GB 以下 | 3B〜4B 級 | 動くが、長い文章の一貫性は期待しにくい |
| 8GB | 7B〜8B 級（4bit 量子化） | 実用の下限。ふつうに遊べる |
| 12GB | 8B〜14B 級 | **おすすめの標準**（下の実測もこの構成） |
| 16GB 以上 | 14B〜32B 級 | 表現の幅が目に見えて広がる |

- ディスク空き容量: モデル1つあたり 2〜20GB。まずは 20GB 空けておくと安心です
- メインメモリ: 16GB 以上を推奨
- GPU 無しでも動きますが、後述の速度は望めません
- Apple Silicon の Mac（M1 以降）はメインメモリを GPU と共有するので、16GB 以上あれば快適です

### 実測（参考値）

| 測ったもの | 値 |
|---|---|
| 構成 | Windows 11 / RTX 3060 12GB / Ollama / モデル `qwen3:8b` |
| 生成速度 | 約 37 トークン/秒（短いプロンプトでの単純計測） |
| 最初の1文字が出るまで | 約 2.6 秒 |
| **実際の1ターン**（本編＋選択肢） | **8〜20 秒** |
| シーン終了レビュー（2本並列） | 約 20 秒 |
| VRAM 使用 | 約 9.9GB（他プロセス込みの合算値） |

> 「実際の1ターン」がいちばん体感に近い数字です。デルシアは長い設定文と履歴を毎回送るので、
> ベンチマークの速度そのままにはなりません。**待てるが、サクサクではない**——それがこの構成の正直なところです。
> （出典: `docs/archive/R5検証チェックリスト.md` §4）

## 3. Ollama を入れる

いちばん手数が少ない選択肢です。インストールすると、**OpenAI と同じ形式の API サーバが自動で常駐**します
（デルシアが話しかける相手はこれです）。

### Windows

1. <https://ollama.com/download> から Windows 版をダウンロード
2. インストーラを実行（管理者権限は不要）
3. インストール後、タスクトレイに Ollama のアイコンが出ます＝**もうサーバは動いています**

### macOS

1. 同じページから macOS 版（`.zip`）をダウンロードし、`Ollama.app` をアプリケーションへ移動
2. 起動するとメニューバーに常駐します

### Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

`systemd` のサービスとして登録され、自動起動します。

### 入ったかの確認

ターミナル（Windows なら PowerShell）で:

```bash
ollama --version
```

バージョンが表示されれば成功です。

## 4. モデルを選ぶ・落とす

### 選び方

デルシアは**日本語で長文を書かせ、さらに裏方で JSON も書かせる**（あらすじ・選択肢・関係性の更新など）ため、
「日本語が書ける」ことと「指示の形式を守れる」ことの両方が要ります。

| 目安 | モデル例（`ollama pull` の名前） | 大きさ |
|---|---|---|
| 8GB VRAM から | `qwen3:8b` | 約 5GB |
| 12GB VRAM の標準 | `qwen3:8b` / `gemma3:12b` | 約 5〜8GB |
| 16GB 以上 | `qwen3:14b` | 約 9GB |
| とにかく軽く | `qwen3:4b` | 約 3GB |

- **モデル名の `8b`・`14b` はパラメータ数**（大きいほど賢く、重い）
- Ollama が配るモデルは既定で **4bit 量子化**（軽量化）済みです。`:q8_0` のようなタグで精度違いも選べます
- **日本語の得意不得意はモデルごとにかなり違います。** 上の表は出発点で、合わなければ別のものへ乗り換えてください。
  この分野は入れ替わりが速いので、**新しいモデルが出ていないかを時々見る**のが結局いちばん効きます
  （<https://ollama.com/library>）

### 落とす

```bash
ollama pull qwen3:8b
```

数 GB のダウンロードが走ります。終わったら、その場で会話して確かめられます:

```bash
ollama run qwen3:8b
```

日本語で何か書かせてみて、`/bye` で抜けます。**ここで日本語が破綻するモデルは、デルシアでも破綻します。**

## 5. API を用意する

Ollama は起動しているだけで **OpenAI 互換 API** を提供します。デルシアが使うのはこのアドレスです:

```
http://localhost:11434/v1
```

### 動いているかの確認

ブラウザで <http://localhost:11434> を開いて `Ollama is running` と出れば OK です。
モデル一覧まで確認するなら:

```bash
curl http://localhost:11434/v1/models
```

落としたモデルの名前が JSON で返れば、準備完了です。

### 覚えておくと便利な環境変数

| 変数 | 何をするか |
|---|---|
| `OLLAMA_HOST=0.0.0.0:11434` | 宅内 LAN の別 PC から使えるようにする（下記参照） |
| `OLLAMA_KEEP_ALIVE=30m` | モデルを VRAM に載せたままにする（毎回の読み込み待ちが消える） |
| `OLLAMA_MODELS` | モデルの保存先を別ドライブへ変える（C ドライブが手狭なとき） |

> **別の PC で動かす構成もできます。** 家の中のゲーミング PC に Ollama を置き、ノート PC のデルシアから
> `http://192.168.0.10:11434/v1` のように指定する形です。デルシアはこの種のアドレス（`localhost`・`127.x`・
> `192.168.x`・`10.x`・`172.16〜31.x`・`.local`）を**ローカル扱い**にして API キーを要求しません。

## 6. デルシアにつなぐ

初回起動時のウィザードなら、**「PC で動かす」** を選ぶだけで下の値が入ります。あとから手で足す場合:

1. 左端のレール最下段 **「設定」** を開く
2. 接続先の **「＋ 接続先を追加」**
3. 次のとおり入力する

| 項目 | 値 |
|---|---|
| 種別 | **OpenAI 互換（カスタム）** |
| 表示名 | 任意（例: `ローカル`） |
| Base URL | `http://localhost:11434/v1` |
| API キー | **空のままでよい** |
| モデル | `qwen3:8b` など、落としたモデル名 |

4. **「接続テスト」** を押す。モデル一覧が引ければ成功です

> **API キーが空でも警告は出ません。** デルシアはアドレスを見てローカルかどうかを判定し、
> ローカル宛にはキーを要求しません（外部サービス宛にキーが無いときだけ警告します）。

5. 最後に、同じ設定画面の **「新しい物語の既定モデル」** をこの接続先にしておくと、
   これから作るセッションが最初からローカルで動きます

セッションごとに使い分けたい場合は、そのセッションの **「セッション設定 > AIと出力」** でモデルを選び直します。

## 7. 設定の勘所

ローカルで遊ぶときにだけ効いてくる注意点です。**うまく動かないときの原因は、たいていここにあります。**

### 7.1 出力上限（`max_tokens`）— いちばんハマる

`qwen3` のような**思考する（thinking）モデル**は、答えを書く前に「考えた内容」を別枠で出力し、
**それも出力上限を食います**（実測: 本編で 658 文字、画像プロンプト起案で 1,462 文字を思考に使った例あり）。

上限が足りないと、書きかけの JSON が途中で切れ、**裏方の処理（あらすじ・選択肢・関係性の更新）が黙って失敗します。**
HTTP としては成功しているので、エラーらしいエラーが出ないのが厄介なところです。

- **対処**: セッション設定の `maxTokens` を十分に大きく取る（既定の 32768 のままなら通常は足ります）
- **2000 程度まで絞ると起案が切れる**ことを実測しています。ローカルでは絞らないでください
- 思考の分だけ待ち時間も伸びます。速さを優先するなら、思考しないモデルを選ぶ手もあります

### 7.2 コンテキスト長（`num_ctx`）

デルシアは設定・履歴・あらすじをまとめて送るので、**入力が長くなります**。
Ollama の既定のコンテキスト長は控えめで、あふれた分は**古い方から黙って捨てられます**
（＝物語の前半を AI が忘れます）。

対処は、コンテキスト長を広げた自分用モデルを作ることです:

```bash
ollama show qwen3:8b --modelfile > my.Modelfile
```

`my.Modelfile` に1行足して:

```
PARAMETER num_ctx 16384
```

登録します:

```bash
ollama create qwen3-16k -f my.Modelfile
```

以後、デルシアのモデル名に `qwen3-16k` を指定します。**コンテキストを広げると VRAM も余計に食う**ので、
足りなければ 8192 に戻してください。

### 7.3 構造化出力（JSON）

デルシアは対応モデルに対して「JSON のかたちを固定する」指示（`response_format`）を送ります。
**受け付けないサーバに当たると、自動で1段ずつ緩めて投げ直す**ので、そのままでも壊れません。

実測では `qwen3:8b` は**そのまま受理**し、緩める動作は1度も起きませんでした（2026-08-16）。

### 7.4 レビューの分割

シーン終了レビューは既定で2本並列に走ります（「AIと出力」タブの設定）。
外部サービスでは待ち時間が半分になりますが、**ローカルでは GPU を取り合うので単純に半分にはなりません**。
遅いと感じたら、この設定を切って1本にするのも手です。

### 7.5 本文の形式（構造化出力）

セッション設定の「構造化出力」を ON にすると `@名前「セリフ」` の形式で書かせます。
小さいモデルは形式を崩しがちですが、崩れた行は**そのまま地の文として表示される**ので、
表示が壊れることはありません。安心して試してください。

## 8. LM Studio でやる場合

GUI で操作したい人向けの選択肢です。モデル探し・ダウンロード・サーバ起動がすべて画面から行えます。

1. <https://lmstudio.ai> からインストール
2. 検索タブでモデルを探して **Download**（VRAM に対して大きすぎるモデルには警告が出ます）
3. 左の **Developer / Local Server** タブを開き、モデルを読み込んで **Start Server**
4. 画面に出るアドレス（既定は `http://localhost:1234/v1`）をデルシアの Base URL に入れる
5. モデル名は LM Studio が表示している ID をそのまま使う（API キーは空でよい）

**Ollama との違い**: 常駐せず、**サーバを自分で起動する**必要があります（起動し忘れると接続テストが失敗します）。
コンテキスト長は読み込み時に画面のスライダーで指定できるので、7.2 の `Modelfile` 作業は不要です。

## 9. うまくいかないとき

| 症状 | 原因の見当と対処 |
|---|---|
| 接続テストが「接続できません」 | サーバが動いていない。<http://localhost:11434> を開いて確認。LM Studio は Start Server を押したか |
| モデル一覧が空 | まだ `ollama pull` していない。`ollama list` で確認 |
| 「モデルが見つからない」 | 名前が違う。`ollama list` の表記（タグ `:8b` まで）をそのまま入れる |
| 生成が始まらない・最初だけ極端に遅い | 初回はモデルを VRAM へ読み込む時間。`OLLAMA_KEEP_ALIVE=30m` で2回目以降は消える |
| とにかく遅い（1分以上） | モデルが VRAM に載りきっていない。小さいモデルか、より強い量子化へ |
| 途中で止まる・尻切れになる | 出力上限（7.1）。`maxTokens` を上げる |
| 物語の前半を忘れる | コンテキスト長（7.2）。`num_ctx` を上げる |
| あらすじや選択肢だけ失敗する | 裏方の JSON が切れている。まず 7.1、次にモデルを変える |
| ブラウザ版だけ失敗する | ブラウザの制約（CORS）。**デスクトップ版なら起きません**（下記） |
| 日本語が不自然・英語が混ざる | モデルの相性。4 章の選び方に戻って別のモデルへ |

### ブラウザ版とデスクトップ版の違い

- **デスクトップ版**: ブラウザの制約を受けないので、ローカルサーバへそのまま接続できます。設定は要りません
- **ブラウザ版**: ページとローカルサーバの間に **CORS** の制約があります。**サーバ側で「このページからの接続を
  許可する」設定が要ります**（→ [11 章](#11-ブラウザ版からつなぐときの設定cors)）

## 10. どこまでオフラインで動くか

- **物語を書く部分（本編・選択肢・あらすじ・関係性の更新・次シーンの候補）は、ローカルモデルだけで動きます。**
  ここまでは実機で確認済みです（2026-08-16 / Ollama + `qwen3:8b`）
- **画像生成は別の接続先です。** ローカルで完結させたいなら ComfyUI（自分の PC で動く画像生成）を選んでください。
  OpenRouter などを選べば、そこは当然オンラインになります
- ネットワークを完全に遮断した状態での通し確認は**まだ実施していません**。「完全にオフラインで全機能が動く」とは
  まだ言えない、というのが現時点の正確な言い方です（`docs/archive/R5検証チェックリスト.md` §3）

## 11. ブラウザ版からつなぐときの設定（CORS）

**デスクトップ版を使うならこの章は不要です。** ブラウザ版（デルシアをブラウザで開いて使う形）から
ローカルサーバへつなぐときだけ必要になります。

### なぜ要るのか

ブラウザは、あるページ（デルシア）から別のアドレス（`http://localhost:11434`）への通信を、
**接続先のサーバが明示的に許可したときだけ**通します（CORS）。許可が無いと、サーバは動いているのに
デルシア側からは「接続できません」に見えます。デルシアは**ローカル宛に余計なヘッダを付けない**ように
してあるので、あとはサーバ側で許可を足すだけです。

許可に使う「接続元」は、**デルシアを開いている URL のドメイン部分**です。ブラウザのアドレス欄が
`https://example.com/delusia/` なら、接続元は `https://example.com` になります。

### Ollama

環境変数 `OLLAMA_ORIGINS` に接続元を入れて、**Ollama を再起動**します。

| OS | やり方 |
|---|---|
| Windows | 「システム環境変数の編集」→ ユーザー環境変数に `OLLAMA_ORIGINS` を追加 → タスクトレイの Ollama を終了して起動し直す |
| macOS | `launchctl setenv OLLAMA_ORIGINS "https://example.com"` → Ollama を起動し直す |
| Linux | `systemctl edit ollama` で `Environment="OLLAMA_ORIGINS=https://example.com"` → `systemctl restart ollama` |

```bash
# 動作確認（一時的に前面で起動して試すとき）
OLLAMA_ORIGINS=https://example.com ollama serve
```

- 複数のアドレスから使うならカンマ区切り（`https://example.com,http://localhost:5173`）
- `OLLAMA_ORIGINS=*` はすべてのページからの接続を許します。**手元で試すときだけ**にしてください
  （開いている他のサイトからも、あなたの Ollama を叩けるようになります）

### LM Studio

**Developer / Local Server** タブのサーバ設定に **CORS を有効にする**トグル（`Enable CORS`）があります。
これを ON にして **Start Server**（起動中なら一度止めて入れ直す）だけです。接続元の指定は要りません。

### 確認のしかた

```bash
# 許可されていれば access-control-allow-origin が返る
curl -i -H "Origin: https://example.com" http://localhost:11434/v1/models
```

うまくいかないときは、ブラウザの開発者ツール（F12）のコンソールを見ます。
`CORS` や `Access-Control-Allow-Origin` の語が出ていれば、原因はこの章の設定です。

> **`http://localhost` は例外扱いではありません。** デルシアを `https://` のページで開いていると、
> そこからの `http://localhost` 宛の通信はブラウザによっては「混在コンテンツ」として止められます。
> Chrome / Edge はループバック宛だけ通しますが、**Safari では止まります**。Safari で使うなら
> デスクトップ版か、外部のモデル（OpenRouter 等）を選んでください。

## 付録: よく使うコマンド

```bash
ollama list                  # 落としたモデルの一覧
ollama pull <モデル名>        # モデルを落とす
ollama rm <モデル名>          # モデルを消す（容量を空ける）
ollama ps                    # いま VRAM に載っているモデル
ollama run <モデル名>         # ターミナルで直接会話して試す
curl http://localhost:11434/v1/models   # デルシアが見るのと同じ一覧
```
