# 設計仕様 — ワールド／キャラの再利用とセッション・オーバーレイ

> ワールド・キャラを「汚さずに使い回せる再利用素材」として確立するための設計。
> 物語中に発見・深化した設定は**元素材ではなくセッション側のオーバーレイ**に積み、セッション画面で閲覧・編集できる。
> 後方互換は最小限（既存フィールドへの追加のみ。persist キーは据え置き＝欠落は空で補完）。ロードマップのテーマB。

## 0. 原則
**素材は不変、発見はプレイスルー固有。**
- **素材（ライブラリ）** ＝ `Character` / `World` 本体。複数セッションから参照される再利用資産。**レビューはこれを書き換えない**。
- **発見（オーバーレイ）** ＝ そのセッションで判明・深化した設定（追加ロア・キャラの成長）。**セッションに閉じる**。
- 本編プロンプトには **「素材 ＋ そのセッションの発見」を合成した“実効ビュー”**を注入する。
- 気に入った発見だけ、ユーザーが**明示操作で素材ライブラリへ昇格**できる（自動昇格はしない＝汚染回避を既定に）。
- 状態エンジン（`SessionState` の関係 prose・数・フラグ・実績）は既存どおり。本設計は**「設定（ロア・developments）の置き場」**を素材からオーバーレイへ移すもので、状態エンジンとは独立レイヤー。

### 現状の問題（是正対象）
`confirmSceneReview` の `applyGrowth`（`store.ts`）が、レビュー承認時に
- グローバル `worlds[].entries` に発見ロアを追記（`addedInStory:true`）、
- グローバル `characters[].developments` に成長設定を追記

している。このため共有ワールド／キャラを別セッションで使い回すと、あるプレイの発見が別プレイに混入する。本設計でこの書き込み先をオーバーレイへ移す。

## 1. 全体像：3レイヤー
| レイヤー | 中身 | 書き手 | 消費者 | 永続 |
|---|---|---|---|---|
| **素材** | `Character.developments` / `World.entries` 他（初期設定） | ユーザー（ライブラリ編集）・昇格操作のみ | プロンプト（実効ビュー経由） | `characters`/`worlds` |
| **オーバーレイ** | セッションで発見した追加ロア・キャラ成長 | レビュー承認・発見ログ手動編集 | プロンプト（実効ビュー経由）・発見ログUI | `Session.overlay` |
| **状態**（既存） | 関係 prose・数・フラグ・実績 | レビュー・状態手動編集 | プロンプト・StatusPanel | `Session.state` |

- 「素材 ＝ 出荷時の設定」「オーバーレイ ＝ その周回で足された設定」。両者を合成して読む。
- オーバーレイと状態を分けるのは意味論の違いによる：**オーバーレイ＝設定テキストの上乗せ**、**状態＝ゲームシステムの現在値**。`SessionState`（状態エンジン仕様）の定義は変えない。

## 2. データモデル

### 2.1 オーバーレイ（新規・セッション固有）
```ts
/** セッション内で発見・深化した設定の上乗せ。元 Character/World は不変。レビュー承認が主な書き手。 */
interface SessionOverlay {
  /** 世界観に発見追加されたロア（元 World.entries とは別に積む） */
  lore: LoreEntry[]
  /** キャラごとの発見成長設定（元 Character.developments とは別に積む） */
  characterDevelopments: { characterId: string; developments: Development[] }[]
}

interface Session {
  // ...既存
  overlay: SessionOverlay   // 新規。factory 既定 { lore:[], characterDevelopments:[] }
}
```
- `LoreEntry` / `Development` は既存型を再利用（新型を増やさない）。オーバーレイのロアは `addedInStory:true`、`Development` は既存どおり `enabled` を持つ。
- キャラ成長は `characterId` ごとに 1 エントリへまとめる（同キャラの複数発見は `developments[]` に追加）。

### 2.2 素材（変更なし）
`Character.developments` / `World.entries`・`LoreEntry.addedInStory` はそのまま。ただし**レビューはこれらに書き込まなくなる**。`addedInStory` は「昇格された発見」を素材側で見分ける用途として残す（§6）。

## 3. 実効ビューの解決（プロンプト注入）
本編プロンプトは常に「素材 ＋ オーバーレイ」を合成した実効ビューを使う。合成は **refs 層（`store.ts` の `resolveRefs`/`computeRefs`）で1回だけ**行い、`prompts.ts` はオーバーレイの存在を知らなくてよい。

```ts
// 実効ワールド（ロア注入・キーワード抽出はこれを使う）
const effWorld = world
  ? { ...world, entries: [...world.entries, ...session.overlay.lore] }
  : undefined

// 実効キャラ（characterBlock・成長注入はこれを使う）
const effChar = (c: Character) => {
  const ov = session.overlay.characterDevelopments.find(x => x.characterId === c.id)
  return ov ? { ...c, developments: [...c.developments, ...ov.developments] } : c
}
```
- `refs.world` に `effWorld`、`refs.characters` に `effChar` 適用済み配列を格納 → `selectLoreEntries(refs.world, …)` / `characterBlock(refs.characters…)` は無改修で発見分を含む。
- **レビュー文脈の構築（`store.ts` でキャラの developments を集める箇所）も実効キャラを使う**。これを怠ると、次のレビューが過去の発見を知らずに矛盾した設定を出す。
- キーワード一致（`lorebook.ts`）は `entries` を走査するだけなので実効ワールドで自動的に発見ロアも対象になる。

## 4. 書き込みフロー（レビュー＝主な書き手）
`prepareSceneReview` の解析（`worldGrowth` / `characterGrowth`）と `SceneReviewModal` の選択UI（`worldGrowthIdx` / `growthIdx`）は**現状のまま**。変わるのは `confirmSceneReview` の適用先だけ。

- 旧 `applyGrowth`（`st.characters`/`st.worlds` を map して追記）を廃止し、対象セッションの `overlay` へ追記する `applyDiscovery` に置換：
  - 採用された `characterGrowth` → `overlay.characterDevelopments[characterId].developments` に `newDevelopment(text)` を追加（該当 characterId のエントリが無ければ作成）。
  - 採用された `worldGrowth` → `overlay.lore` に `{ ...newLoreEntry(base+i), keys, content, addedInStory:true }` を追加。
- **反映は現在シーン確定時のみ**（過去シーン再レビューは要約と次シーン方向のみ＝既存ルール踏襲）。オーバーレイ追記も現在シーン確定時のみ。
- 状態（relations/stats/…）の適用と実績再評価（`unlockAchievements`）は現状どおり。

## 5. UI — 発見ログ
セッション画面に「📖 発見ログ」を追加（`ChatPanel` トップバーの 📊 の隣。別モーダル `DiscoveryPanel.tsx`）。

- **発見ロア**（`overlay.lore`）：キーワード・本文の閲覧／編集／有効・無効／削除／「ライブラリへ昇格」。
- **キャラの発見設定**（`overlay.characterDevelopments`）：キャラ別に developments を一覧、編集／有効・無効／削除／昇格。
- **関係性 prose** は既存の 📊 `StatusPanel` に残す（重複回避）。発見ログからは「関係は 📊 で」と導線のみ。
- 空状態：「まだ発見された設定はありません。シーンを終えるとレビューでここに追記されます」。
- カンマ区切り（ロアのキーワード）は必ず `CsvInput`（CLAUDE.md 規約）。

新規ストアアクション（`characters`/`worlds` の編集アクションに倣う）：
```
updateOverlayLore(sessionId, loreId, patch)     removeOverlayLore(sessionId, loreId)
toggleOverlayLore(sessionId, loreId)
updateOverlayDev(sessionId, characterId, devId, patch)   removeOverlayDev(…)   toggleOverlayDev(…)
```

## 6. 昇格（オーバーレイ → 素材ライブラリ）
発見を「この世界の正史／このキャラの設定」として資産化する明示操作。汚染回避を既定にしつつ、意図的な素材強化を可能にする。

- `promoteOverlayLore(sessionId, loreId)`：`overlay.lore` の項目を、そのセッションの `worldId` が指す `World.entries` へ**移動**（新 id・`addedInStory:true` を維持）。オーバーレイからは削除（合成注入の二重化を防ぐため copy でなく move）。
- `promoteOverlayDev(sessionId, characterId, devId)`：`Character.developments` へ移動。
- 昇格は確認ダイアログ付き（「元素材を更新します」）。`worldId===null` のロアは昇格不可（UI で無効化）。
- 素材側の `addedInStory` バッジ（WorldEditor 既存表示）は「昇格済みの発見」を示す意味に読み替える。

## 7. 永続化（追加のみ・キー据え置き）
CLAUDE.md「スキーマ変更時：型更新 → 初期state/factory → export/import → partialize」に従う。今回は**追加フィールドのみ**で後方安全なため persist キー（`ai-storytelling-store-v2`）は変更しない。

- `types.ts`：`SessionOverlay` 追加、`Session.overlay` 追加。
- `store.ts`：セッション factory に `overlay: { lore:[], characterDevelopments:[] }`。
- `importBundle`：取り込みセッションの `overlay` 欠落を `{ lore:[], characterDevelopments:[] }` で最小補完（worlds の欠落補完と同様）。
- `exportBundle`：`sessions` 一括に `overlay` が含まれるため追加作業なし。
- `partialize`：`sessions` を丸ごと永続化済みのため追加作業なし。
- 既に**旧仕様で元ワールド／キャラへ混入済みの発見**は残る（データ損失なし）。§6 の昇格の逆＝手動削除、または WorldEditor/CharacterEditor で整理可能。移行スクリプトは作らない（クリーンブレイク方針）。

## 8. フェーズ計画
> 各フェーズ＝「型 → store → prompts/UI → 型チェック → build → Preview 検証 → commit/push」を1サイクル。

### B1 — オーバーレイ基盤＋書き込み先の切替
- `types.ts`：`SessionOverlay`、`Session.overlay`。
- `store.ts`：factory 既定、`confirmSceneReview` の `applyGrowth`→`applyDiscovery`（書き込み先をオーバーレイへ。**元 characters/worlds はもう触らない**）、`importBundle` 補完。
- 完了時：レビュー承認しても元素材が増えず、発見はセッションに蓄積（この時点では未注入・未表示でも可）。

### B2 — 実効ビューでプロンプト反映
- `store.ts`：`resolveRefs`/`computeRefs` で `effWorld`/`effChar` を合成し `refs.world`/`refs.characters` に格納。レビュー文脈のキャラ developments 収集も実効キャラに。
- 完了時：発見ロア・成長が本編プロンプトに載る（＝物語が発見を覚えている）。

### B3 — 発見ログUI
- `DiscoveryPanel.tsx` 新規、`ChatPanel` に 📖 導線、オーバーレイ編集アクション群。
- 完了時：セッション画面で発見ロア・キャラ成長を閲覧・手動編集できる。

### B4 — 昇格（任意）
- `promoteOverlayLore`/`promoteOverlayDev`＋発見ログのボタン・確認ダイアログ。
- 完了時：気に入った発見だけ元 World/Character へ反映できる。

## 9. 落とし穴・非対象
- **実効キャラの取りこぼし**：本編・レビュー・選択肢生成など developments を読む全経路で実効キャラを使うこと。片方だけ素材素の developments を読むと発見が消えたように見える。
- **昇格は move**（copy にすると実効合成で二重注入）。
- **worldId 変更**：オーバーレイはワールドでなくセッションに紐づくため、途中で `worldId` を変えても発見ロアは残り注入され続ける（仕様）。違和感が出るなら発見ログから無効化/削除で対応。
- **旧混入データ**は自動掃除しない（クリーンブレイク方針）。必要なら手動整理。
- 本設計は**設定テキスト（ロア・developments）の置き場**の話。関係 prose・数・フラグ・実績は状態エンジン仕様（`docs/設計_ステータスエンジン.md`）のまま。
- カンマ区切り入力は必ず `CsvInput`。
