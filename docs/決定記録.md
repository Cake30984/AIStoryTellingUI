## 1. 製品の位置づけ

| 決定 | 理由 | 出典 |
|---|---|---|
| **「ノベルゲーム」ではなく「挿絵入りの本」** | AI 出力は事前に予測できず素材を用意できない。絵と文字が同じ画素を奪い合う VN 構成は両損 | archive/公開計画 §0 |
| **立ち絵・全面背景・表情差分・ステージ表示は復活させない**（2026-08-01 撤去） | 上と同じ。場所の絵が欲しければ挿絵へ吸収 | archive/設計_環境音ピン_実験 |
| **読者モデル**: 物語モードの入力はすべて「書き手への指示」。ユーザーは世界の住人を演じない | 「右腕を上げる」と入力しても AI の解釈が一致しない＝入力の意味論の不一致はプロンプトでは消えない | 設計_物語の簡素化 §3 |
| **`roleplay` モードは残す**（単体キャラとの会話）。ただしモードで分けるのは入力の意味論と操作系だけ、機構は共通 | 分けると二重実装になり削った複雑さが戻る | 同 §3.3 |
| **作者の仕込み（条件・数・到達目標・配役・特別イベント・固定タイムライン）は持たない** | 作り込むほど AI を使う意義から外れ、生成の流れも阻害する。作者自身が「面倒すぎる」と判断 | 同 §0・§1 |
| **ペルソナ型は持たない**。中心人物は `focusCharacterId` が指すただの参加キャラ | 全登場人物を等しく `Character` にした方が素材の再利用・カード化が単純 | 同 F3 |
| **中心人物 `null` は許さない** | 関係性が N×(N−1) に膨らむ。中心必須なら N−1 本 | 同 §2.5 |

## 2. 物語の機構

| 決定 | 理由 | 出典 |
|---|---|---|
| **状態はすべて prose**（関係性 `stance`＋次元ごとの記述・気分・時間・場所・予定） | 数値は LLM が更新を苦手とし機微を非可逆圧縮する。数の状態は F1 で全廃 | 旧 ADR-1 → 設計_物語の簡素化 §1.2 |
| **数の状態を prose の band（5段階の言葉）で残さない** | `Relation` が band を捨てて成立している。二の轍 | 同 §8 |
| **恒久フラグ（自由文字列）は持たない** | 取り消し手段が無く永久にドリフトする | FB9-C |
| **選択肢は加点・効果を持たない**。クリックはそのまま `send` | 事前にポイントが見えると面白味が半減、独自行動と同じ土俵にならない | FB7-C |
| **選択肢はオンデマンド1ボタン**（`always`/`auto` は廃止） | `always` は大半が捨てられる無駄、`auto` は判定呼び出しが要る上に外れる | 設計_物語の簡素化 §3.4 |
| **予定（`pending`）を本編プロンプトへ渡さない** | 実測 28/30 で無関係な先の予定を列挙した | 計測_時間と予定 §4.1 |
| **予定の件数上限は設けない** | 件数は精度に効かなかった | 同 §4.2 |
| **予定の消化は id でなく `what` の引用で受け、候補がちょうど1件のときだけ消す** | id は実測で壊れた。誤爆＝予定が消えて戻らない | 同 §4.3 |
| **相対表現（「来週水曜」）を予定に書かせない** | 基準日が無く 30回中2回しか発火せず両方誤り | 同 §4.4 |
| **`now` は自由文字列でコードは解釈しない** | 暦が違う世界がありうる。コードで時計を回す流派（AI Dungeon 方式）は作者コスト最大 | 設計_物語の簡素化 §2.1 |
| **時間と予定は第3のレビュー呼び出し（`t`）に分ける** | A に載せると次シーン提案が予定に引きずられ、B は負荷が偏る | 同 §2.4.2 |
| **`happened`（出来事の記録）は入れない** | 溜まる配列を本編へ入れる失敗は実証済み。漂流が起きることを測ってから | 同 §2.3.1 |
| **エンディングは世界側に定義を持たない**。AI がいつでも提案し、ユーザーが選ぶ。到達判定はしない | 条件・auto/hidden/fallback・到達記録は「作者の仕込み」そのもの | 同 §2.7 |
| **幕間は非正典**（状態へ書き戻さない。ユーザーが選んだ解釈だけ関係性へ反映） | 本編と矛盾する | 同 §2.9.4 |
| **幕間の単位はシーン丸ごと1本**。進行中シーンでは作らせない | 途中に挿すと対象範囲が生成のたびにずれる | 同 §2.9.2.1 |
| **幕間で「観察の追加」は禁じない**。禁じるのは世界設定・過去の捏造だけ | 幕間の面白さはそこにある。読み専用なので本編は汚れない | 同 §2.9.3 |
| **幕間の品質を判定 LLM で自動確認しない** | 測れなかった。人手で読む | 計測_別視点の幕間 §4 |
| **セッション内埋め込みキャラを作らない**。発見キャラはライブラリの通常キャラとして保存 | 「素材でないキャラ」が合成ビュー・カード化・全経路に波及する | FB7-E |
| **`SessionOverlay` に `characters` を足さない** | 上と同じ。足すなら `SAVE_DATA_VERSION` を上げて移行を書く | archive/設計_公開前実装 R7 |
| **完結後に出す操作は「分岐」と挿絵だけ。最後の生成文からは分岐させない** | 同じ線の続きになり、廃止した `branchToContinue` の復活と等価 | FB9-A |
| **ツリー行クリックは移動、分岐を作る操作は本文の操作行に集約** | ツリーは読む・移動する装置 | FB7-B |
| **分岐の自動削除は保護判定を通し、`recordCheckpoint` 内では剪定しない**（fail-open） | 取り漏らしをバグとして発見できるように | FB6-C |
| **`WORLD_PRESETS`（恋愛/RPG/経営）は持たない** | `newWorld()` は中立な既定（関係次元「信頼」1つ）。→ 既定コンテンツは 2026-09-13 の計画で別途入れる | G4-b |
| **キャラ別の専用モデル（`Character.model`）は持たない** | 一度も使われず、解決経路と除去処理を余分に持つだけだった | 2026-08-16 |
| **セッションカード（`aist_session`）は読み書きとも無い** | 共有はカセット・バックアップはデータ書き出し | FB3-D |

## 3. プロンプト

## 9. 公開の方式（2026-09-19）

P7 に着手する前に、公開に関わる判断をまとめて確定した。**手順は [`計画_レビュー対応.md`](./計画_レビュー対応.md) P7 の段階 A〜F。**

| 決定 | 理由 |
|---|---|
| **Web 版は Cloudflare Pages の `delusia.tokatokage.com`**（サブドメイン。サブパスにしない） | ドメインを Cloudflare で取得済みで、DNS と配信元が同じ管理画面に収まる。GitHub Pages だと DNS は結局 Cloudflare 側で触ることになり、プロキシと SSL モードの組み合わせを意識する分だけ管理点が増える。Pages はプロジェクト単位でドメインを割り当てるので、サブパスにすると apex 側も Pages に載せるか Workers でのルーティングが要る。**ブラウザ版のデータはオリジン単位なので、公開後にアドレスの形を変えると利用者のデータが消えたように見える＝最初に決めて動かさない** |
| **撤去済み環境音を git 履歴から削除してから public にする** | VSQ plus+ の規約が禁じるのは「オリジナルの状態での再配信」で、`環境音_音源調達リスト.md` §0.2 の同梱可判断は**アプリに内蔵する**前提。public リポジトリでは加工済みとはいえ音声ファイルが1本ずつ直接ダウンロードできる形になり、§0.2 自身が残した曖昧さ（アプリ内の選べる音素材＝素材提供とみなされないか）を強める。機能は P1 で撤去済みで残す利得がゼロ、リポジトリの97%（FLAC 127MB＋Opus 12MB）を占める。**判断の非対称性**——今なら `filter-repo` 1回で済むが、公開後はクローンとフォークに散って回収できない |
| **コミットのメールアドレスを GitHub の noreply に置換する** | 273 コミットに個人アドレスが入っており、public にすると誰でも見える。履歴を書き換えるのは音源 purge と同じ1回だけなので、まとめて実施する |
| **Issues は閉じたまま。不具合の受け口は `tokatokage.com` の転送アドレス**（Cloudflare Email Routing） | 想定利用者（物語を読む人・BOOTH とブラウザ版から入る人）の多くは GitHub アカウントを持たず、Issue を立てるのは高い壁。規約 §3 の「Issue・PR は受け付けていません」を書き換えずに済み、個人アドレスも晒さない（転送アドレスは潰して作り直せる）。公開の場に未返信の Issue が並ぶと実際以上に放置されて見える。**開けるのは後からできるが、逆は難しい。** PR を受け付けない方針はどちらでも維持する（マージの判断と保守義務が生まれる） |
| ~~既定モデルは経路ごとの候補フォールバック方式~~ → **2026-09-20 に §10 で置き換え**（推奨リストから利用者が選ぶ方式。自動フォールバックはしない） | 当初の理由（README を読まずに入る人に「接続先を1つ設定すれば始められる」体験を残す）は §10 の一覧表示でも満たせる。自動で切り替わると拒否や文体の変化の理由を利用者が追えない |
| **BOOTH は全年齢カテゴリ。成人向け利用には触れない** | アプリ自体は内容の制限を持たず、扱えるかは提供元の規約が決めるという規約 §2-1 の整理と一致する |

## 10. 推奨モデル（2026-09-20）

P7 段階 A-1 で確定。§9 の「候補フォールバック方式」は**この節で置き換える**。実装は `src/lib/recommendedModels.ts`（README の表もここから書く）。

**決め方**: OpenRouter の `/api/v1/models`（447件）から現行 id と価格を取り、利用ランキング（RP・日本語）・EQ-Bench Creative Writing v3・UGI（W/10＝拒否のしにくさ）・Nejumi Leaderboard 4・SillyTavern 界隈と日本語 RP の記事で 7 件に絞り、**同じ 5 場面（口調の書き分け・戦闘・情感・推理・一人称 SF、各 400〜500 字）を 7 モデルに 1 本ずつ書かせ、モデル名を伏せてユーザーが採点**した。第 2 ラウンドで上位候補 4 件（GLM 5.3・DeepSeek V4 Pro・Grok 4.5・Kimi K3）を同じ形で追加。出力と対応表は `scripts/out/blind-test-2026-09-20*`（git 無視）。

| 決定 | 理由 |
|---|---|
| **推奨リストから利用者が選ぶ方式。** OpenRouter の3経路を1経路に統合し、4件を一言説明と価格（100 万トークンあたり、入力 / 出力）つきで一覧表示、表示できる先頭を初期選択。**接続テストに失敗しても自動で別のモデルへは切り替えない** | 説明文があれば「品質重視／緩い」の分類は要らず、同列に並べて選ばせるほうが分かりやすい。自動で切り替わると拒否や文体の変化の理由を利用者が追えない |
| **採用 4 件**: DeepSeek V4 Flash 0731（最安・緩い・迷ったらこれ）／DeepSeek V4 Pro 0813（Flash の上位）／GPT-5.6 Terra（高品質で高価）／Claude Sonnet 5（Terra と同格、どちらかといえば Terra） | ブラインドで **Terra は 5 場面すべて上位 3**（唯一）。DeepSeek Flash は 3 場面で上位 3 で費用は Terra の 1/20。Sonnet は口調で 1 位だが当たり外れが大きい。第 2 ラウンドでは V4 Pro が「安定して良い」 |
| **選外**: GLM 5.3 / 5.3 Flash・Gemma 4 31B・Grok 4.20 / 4.5 / 4.6・GPT-5.6 Luna・Kimi K3・Claude Opus 5 | GLM 5.3 Flash は OpenRouter の**日本語利用 #1・RP 利用 #5** だったが**最下位**（推論を長く吐いてから本文を書く型で「前の文に引きずられる」「歩数のカウントダウンが途中で意味を失う」）——**利用シェアやベンチは日本語の物語の出来を予測しなかった**。Gemma は日本語は自然だが場面の理解が浅い。Grok は品質の割に高い（4.6 は規制も強まり応答 70 秒）。Luna は Terra との差と提供元の審査。Kimi K3 は SF だけ良く費用は Pro の 10 倍。Opus 5 は情感で 1 位だが他は普通以下で 1 本 400 円（README で価格つきで触れるにとどめる） |
| **「品質重視」経路は設けず、高価なモデルをアプリ内で勧めない** | 100 万トークンあたりの出力価格で Flash $0.08 に対し Sonnet $10・Opus $25（125〜300 倍）。気にせず選んだ人が思ったより払う事故を避ける。Terra・Sonnet は「高価」と明記したうえで一覧に残す |
| **版は固定し、`~vendor/xxx-latest` の別名は使わない** | Grok 4.5 → 4.6 で UGI の W/10 が 5.8 → 3.0 に急落した。別名だと説明文が嘘になる。廃止されたら接続テストで落ちるので、利用者が別の推奨を選べばよい |
| **価格は定数に持たず、表示のたびに `/models` から取り直す。一覧に無くなった推奨モデルは表示しない**（全部無ければ「その他」だけ） | 価格は提供元の都合で変わる（確定翌日に V4 Pro の値が変わっていた）。廃止・改名で消えた id を勧めない。「物語 1 本あたり N 円」の目安はターン数と文章量で桁が変わり、ぶれが大きすぎるのでやめた |
| **`DEFAULT_MODEL` も推奨の先頭に** | `openrouter/auto` は説明と挙動が食い違い費用も書けない。旧 id はカセットの旧刻印の比較にだけ残す |

**評価で分かったこと**（次に選び直すときの目安）: 書き出しはどれも上手く見え、後半で状況理解の浅さが出る。推理は全モデル苦手、SF は全モデル得意。「いかにも AI」「テンプレ」「前の文に引きずられる」文が低評価の主因。1 本ずつの評価なので当たり外れは残る。
