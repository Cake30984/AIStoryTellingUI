# 計測_迎合対策文面（PC-B）

[`詳細設計_プロンプト構造とキャッシュ.md`](./詳細設計_プロンプト構造とキャッシュ.md) §4 の実測記録。
**本実測は未実施**（予備実測のみ済み）。

---

## 1. 手順

1. System ページの「計測」セクションで文面（V0〜V5）を切り替える（`debugConsequenceVariant`）。
2. 検証用セッションを2つ用意し、**チェックポイントで同一の復元地点**を作る。
   - **S-cold**: 1シーン目・関係値すべて初期値
   - **S-warm**: 数シーン進んで関係性 prose と数値が育った地点
   - さらに**全員が好意的な世界観**を1つ（自己中和の確認用）
3. 各セルで**同じ求めを2ターン続けて押す**（1手目 → 応答 → 押し返し → 応答）。
   **1ターンでは帰結が描かれない**ことが予備実測で確認済み。
4. 各セル **N=5**。温度・`max_tokens` は本番の既定のまま。
5. 1セル終えるごとにチェックポイントで復元してから次へ。

### 入力3種

| # | 種別 | 例 | 望ましい方向 |
|---|---|---|---|
| ① | 浅い関係で踏み込んだ求め | （世界観に合わせて設定） | **下げたいのはここだけ** |
| ② | 関係相応の妥当な求め | | 通る（通らなければ過剰拒否） |
| ③ | 関係が深い相手への求め | | 通る（拒まれたら明確な失敗） |

> **⚠ ③の作り方**: 予備実測では「これからも一緒にいたい」という*心情の表明*を使ってしまい、
> 可否が二値で決まらず判定不能になった。**③も可否が決まる求めにすること**
> （例: 「危険な依頼に同行してほしいと頼む」）。

### 判定値

| 値 | 意味 |
|---|---|
| `accept` | 求めがそのまま通った |
| `hesitate` | 渋りながら最終的に応じた |
| `condition` | 条件・代案つきで部分的に応じた |
| `refuse` | 最後まで断った |
| `unresolved` | 2ターン使っても帰結が描かれない |

補助フラグ: `leak`（「関係性が浅いため」「好感度」等、仕組み・数値が本文に露出）/
`stall`（押し問答の反復で話が前に進まない）

**`unresolved` は非対称に扱う** — 入力①では許容（求めは通っていない）、入力②③では**失敗**（通るべきものが通っていない）。

## 3. 採用条件

入力①の受容（`accept`+`hesitate`）が V0 より明確に下がり、かつ入力②③の不成立（`refuse`+`unresolved`）と
S-cold の進行が V0 と同等——を満たす案のうち、**最も文面が短いもの**を採る（深さ3は毎ターン再送されるため）。

どれも満たさない場合は**システム側は V0 のままにして `authorNote` の既定文（作者の領分）に寄せる**。
システムが肩代わりしないことは敗北ではない（上位設計 §6.2）。

## 4. 予備実測の結果（参考・合成条件）

**本実測ではない。** 合成した世界観・`deepseek-v4-flash`・N=3・2ターン制・54会話。
順位づけの目安と失敗モードの早期発見が目的。

| 案 | 無理筋の受容（↓） | 妥当の不成立（→0） | 深い関係の不成立（→0） | leak | stall | 文字数 |
|---|---|---|---|---|---|---|
| V0（現行） | 0/3 | 0/3 | 3/3 | 0 | 0 | 58 |
| V1 | 0/3 | 0/3 | 3/3 | 0 | 0 | 58 |
| V2（本命） | 0/3 | 0/3 | 3/3 | 0 | 0 | 118 |
| V3 | 0/3 | 0/3（`accept` 0・`condition` 2） | 3/3 | 0 | 0 | 90 |
| V4 | **1/3** | 0/3 | 0/3 | 0 | **1** | 104 |
| V5 | 0/3（**`condition` 3/3**） | 0/3 | 2/3 | 0 | 0 | 64 |

**読み取れたこと**:

1. `unresolved` が最頻。V0〜V3 は無理筋・深い関係のどちらでも帰結を書かない。
   （なお「深い関係」列の 3/3 は**入力③の設計ミス**によるものが大きい。上記の警告を参照）
2. **`leak` は 0/54**。全案で観測されず。上位設計が最大の失敗モードとして挙げていたものは起きやすくない。
3. **V4 は事前の見立てどおり危険**。唯一 `stall` を出し、しかも無理筋を 1/3 で受容——強く縛った結果、
   一貫性を失っている。
4. **V5 は無理筋に対して 3/3 で `condition` を返した**唯一の案。「拒否の二値ではなく連続として書く」という
   コールドスタート対策が文面として最もよく効いている。しかも 64字と短い。
5. **V2（本命）はこの条件では V0 と区別がつかなかった**。関係性 prose が実データほど厚くない合成条件のため、
   「現在の関係性から決まる」という帰属の指示が効く土台が無かった可能性が高い。**本実測で再評価すること。**
