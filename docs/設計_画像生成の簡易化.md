# 設計: 画像生成の簡易化（接続先3枠・プロンプトスタイル・コスト表示）

`docs/設計_画像生成連携.md`（G1〜G4）で作った基盤の**上に載る再設計**。基盤（`imageGen.ts` のプロバイダ抽象・`ImageGenModal`・挿絵の永続化）はそのまま使い、**接続先の選び方と設定項目の量**だけを作り直す。

- 位置づけ: `docs/公開計画_マネタイズと配布.md` §0（挿絵入りの本）と §5.7（初回ウィザード・BYOK）の画像側の実装
- 実装フェーズ: I1〜I5（1フェーズ＝1ターンで実装・検証・コミット）

---

## 0. 問題設定

「画像生成の設定が難しい」の中身は3層に分かれる。

| 層 | 内容 | 状態 |
|---|---|---|
| (a) 接続 | どこに繋ぐか（URL・APIキー） | 素の入力欄。プリセットなし |
| (b) 画風・品質 | どのモデル／定型ポジ・ネガ／サイズ | 全部ユーザー任せ |
| (c) 内容 | この1枚に何を描くか | **裏方LLM起案＋`imagePrompt` で解決済み** |

難しさは (a)(b) に集中している。しかも `newImageProvider()` が返すのは**一度も動かないオブジェクト**（キー空・`model: 'dall-e-3'`・ComfyUI は `ckpt_name` が環境依存）で、埋めないと1枚も出ない。

> **これは UI の問題ではなく既定値の問題。** 空欄だらけのフォームはどれだけ磨いても簡単にならない。逆に「そのまま動く既定」が1つあれば UI は欄1つで済む。作り込む方向を「フォームを親切にする」から「既定を1つ正解にする」へ振り替えると、実装量はむしろ減る。

### 却下した方向

- **フォームの作り込み**（説明文・バリデーション・ウィザード）で解決する — 空欄の数が減らないので効かない
- **接続先を増やして選択肢で解決する** — アダプタ1本ごとにエラー翻訳・接続テスト・実機確認が永続的な固定費になる
- **サービス × モデルのプリセット表** — 組合せ爆発する。アダプタとプロンプトスタイルは**直交する2軸**として別々に持つ（3×3 の表ではなく 3+3）

## 1. 実測記録（2026-08-09）

設計の前提を実APIで確定させた。以下は推測ではなく実測値。

### 1.1 OpenRouter — 文章側のキーがそのまま使える

**`/chat/completions` + `modalities` でも画像は返るが、専用の `/api/v1/images` を使う。**

```
POST https://openrouter.ai/api/v1/images
Authorization: Bearer <文章側と同じ OpenRouter キー>
Content-Type: application/json

{ "model": "openai/gpt-5-image-mini", "prompt": "...", "n": 1,
  "size": "1024x1024", "quality": "low" }
```

レスポンス（**既存 `generateOpenAiImage` とほぼ同型**）:

```jsonc
{ "created": 1754…,
  "data": [ { "b64_json": "<PNG base64>", "media_type": "image/png" } ],
  "usage": { "cost": 0.0022635, "completion_tokens_details": { "image_tokens": 272 } } }
```

| 経路・設定 | 実コスト | 所要 |
|---|---|---|
| `/chat/completions` gpt-5-image-mini 既定 | **$0.041（約6.3円）** | 0.8s |
| `/api/v1/images` gpt-5-image-mini `quality:"low"` 1024×1024 | **$0.0023（約0.35円）** | 11.7s |
| `/api/v1/images` flux.2-klein-4b 832×1216（quality 非対応） | $0.014（約2.2円） | 6.9s |
| gemini-2.5-flash-image（nano banana・単価表から） | 約6円 | — |

- **`quality:"low"` が18分の1にする。** 品質は挿絵として十分（実機確認済み）
- `?output_modalities=image` で **42モデル**。OpenAI系も FLUX 系も**同一エンドポイント・同一レスポンス形**で叩けた＝1アダプタで多モデル
- `/chat/completions` 経路は reasoning トークンが乗るぶん割高で、サイズ・品質を指定できない。**使わない**
- 縦長（832×1216）可

### 1.2 Civitai — 成人向け枠の技術面は全部通った

**生成は Site API ではなく Orchestration API。ホストが別。**

```
POST https://orchestration.civitai.com/v2/consumer/recipes/textToImage
    [?whatif=true][&allowMatureContent=true]
Authorization: Bearer <Civitai APIキー>

{ "model": "urn:air:sdxl:checkpoint:civitai:101055@128078",
  "prompt": "...", "negativePrompt": "...",
  "width": 832, "height": 1216,
  "steps": 25, "cfgScale": 6, "scheduler": "EulerA", "clipSkip": 2,
  "quantity": 1, "seed": 12345,
  "additionalNetworks": { "urn:air:sdxl:lora:civitai:599757@2620790": { "type": "Lora", "strength": 0.8 } } }
```

レスポンス:

```jsonc
{ "images": [ { "width": 832, "height": 1216, "id": "…jpeg", "jobId": "…",
                "url": "https://orchestration-new.civitai.com/v2/consumer/blobs/…?sig=…",
                "urlExpiresAt": "2027-…", "available": true } ] }
```

**料金はレスポンスヘッダに出る**: `x-civitai-cost-total: 3` / `x-civitai-cost-by-currency: blue=3`

| 検証項目 | 結果 |
|---|---|
| SDXL 832×1216 / 25 steps | **3 Buzz**・submit 16.5s で `available:true`・画像取得まで19.5s（実質同期） |
| steps 40 | 5 Buzz |
| quantity 4 | 10 Buzz |
| LoRA 1本追加 | 3 → 4 Buzz |
| **`whatif=true`** | Buzz を消費せず**同じ形＋料金ヘッダ**を返す ＝ **生成前に正確な見積りが出せる** |
| NSFW フラグ付き checkpoint（WAI-illustrious・`nsfwLevel:60`） | **生成できた**。`allowMatureContent` の有無で料金・可否とも変化なし |
| AIR の取得 | `GET https://civitai.com/api/v1/model-versions/{id}` の **`air` / `baseModel` / `trainedWords`** |

- `air` の実例: `urn:air:sdxl:checkpoint:civitai:827184@2883731`（**Illustrious ベースでも ecosystem は `sdxl`**）
- `trainedWords`（例 `["C0lorL1nes"]`）が取れる＝**LoRA のトリガーワードを自動で既定プロンプトに入れられる**
- レスポンスヘッダ `access-control-allow-origin` が空 ＝ **ブラウザ版からは叩けない。デスクトップ版（`appFetch`）専用**

**未解決（実装前に要確認）**: Buzz の購入経路。二次情報では 2025年5月以降**クレジットカードでの直接購入が制限**され、暗号通貨か会員（Bronze/Silver/Gold で月 10,000/25,000/50,000 Buzz）経由とされる。今回の実測は**無料の blue Buzz** で通っている。ここは公開計画 §4 の決済圧力リスクの実例なので、R18 枠を確定する前に一次情報で確認する。

### 1.3 他サービスの調査結果

| サービス | 課金 | Civitai モデル | 成人向けの明確さ | 判定 |
|---|---|---|---|---|
| **Civitai** | 前払 Buzz（購入経路に難） | ◎ ネイティブ | ◎ `allowMatureContent` が一級のAPIフラグ | **R18枠の第一候補** |
| **Runware** | ◎ 従量・$0.0006〜ヽ`cost` 返却 | ◎ AIR 直指定・`lora[]` あり | △ 規約が沈黙（CSAM 禁止のみ明記） | 控え（差し替え先） |
| Novita | ◎ 従量 | ○ 独自ID | ○ NSFW 検出がオプトイン | 保留 |
| Venice | ✗ Pro $18/月 必須 | ✗ | ◎ 明示的に uncensored | 却下（サブスク） |

**判定軸は安さではなく「規約に成人向けの明示的な扱いがあるか」。** BYOK なので、黙認しているだけのサービスを案内するとアカウント停止のリスクをユーザーに転嫁することになる。

## 2. 決定事項

1. **接続先は3枠で止める**。増やすときは1本ずつ実測してから
   - 全年齢・既定 → **OpenRouter**（文章側のキーを再利用）
   - 成人向け → **Civitai**（後回し。ブロッカーではない）
   - パワーユーザー → **ComfyUI**（プリセットは用意しない）
2. **物語の途中で設定画面へ飛ばさない。** 未設定なら挿絵モーダル内で完結する小さなカードを出し、断ったら黙って続きが読める
3. **プロンプトスタイルは2択**。これは欄を増やす設定ではなく**欄を消す設定**
4. **画風は3択**（実写／アニメ／自由入力）。生成モーダルに置き、最後の選択を接続先ごとに覚える
5. **表に出す設定はプロンプト・画風・サイズ・品質の4つだけ。** サンプラー・ステップ・CFG は詳細へ降格
6. **コストを常に円で見せる**（後述 §6）
7. ComfyUI は**プリセットを配らず、持ち込みを楽にする**（自動注入・`/object_info` プルダウン）
8. LoRA はフェーズ1では**トリガーワードのみ**（既存機構で足りる）。選択UIは Civitai 限定で後から

### なぜ ComfyUI を残すか

「詳しい人向け」であると同時に、**成人向けを扱える構造的に安全な唯一の経路**（ホスト型APIは規約で消えうる）。公開計画の「訴求しないが塞がない」を画像側にも適用する。UI で前に出さないだけで、撤去はしない。

## 3. データモデル変更（`src/types.ts`）

すべて optional なので persist キーは据え置き（移行不要）。

```ts
export type ImageProviderKind =
  | 'openrouter-image'   // 新規・既定
  | 'civitai'            // 新規（I5）
  | 'comfyui'
  | 'openai-image'       // 既存（汎用 OpenAI 互換。残す）
  | 'modelslab'          // 既存（非推奨。UI の追加ボタンからは外す）

/** プロンプトの作法。モデル世代で二分される */
export type PromptStyle =
  | 'tags'      // SD1.5 / SDXL / Illustrious / Pony 系: カンマ区切りタグ。品質タグ・ネガティブが効く
  | 'natural'   // Flux / SD3 / DALL·E / gpt-image / nano banana 系: 自然文。品質タグ・ネガティブ不要

export type ArtStyle = 'anime' | 'realistic' | 'custom'

/** 生成品質。API の値をそのまま持ち、UI では日本語ラベルに翻訳して3択で見せる */
export type ImageQuality = 'low' | 'medium' | 'high'

export interface ImageProvider {
  // …既存フィールド
  /** プロンプト起案の作法。既定は kind から決めるが必ず上書き可 */
  promptStyle?: PromptStyle
  /** 画風。生成モーダルの選択がそのまま書き戻る＝「最後に選んだ画風」 */
  artStyle?: ArtStyle
  /** artStyle==='custom' のときの英語文字列 */
  artStyleCustom?: string
  /** openrouter-image / civitai: 既定の生成品質（生成モーダルの選択が書き戻る） */
  quality?: ImageQuality
  /** アダプタ固有の値の袋。4本目で型が破綻しないように最初から分けておく */
  params?: Record<string, unknown>
}
```

`params` の中身（アダプタごと）:

| kind | params |
|---|---|
| `openrouter-image` | `{ }`（`model` は既存フィールドを使う） |
| `civitai` | `{ air, modelName, baseModel, trainedWords: string[], steps, cfgScale, scheduler, clipSkip, loras: { air, name, strength, trainedWords }[] }` |
| `comfyui` | `{ objectInfoCache?: … }`（永続化しない。§5.3） |

`ImageGenRequest` に追加:

```ts
quality?: ImageQuality
```

## 4. アダプタ仕様

### 4.1 `openrouter-image`（既定・全年齢）

`newImageProvider('openrouter-image')` の既定値:

```ts
{ label: 'OpenRouter（画像）', baseUrl: 'https://openrouter.ai/api/v1',
  model: 'openai/gpt-5-image-mini', quality: 'low',
  promptStyle: 'natural', artStyle: 'anime', apiKey: '' }
```

- **キー再利用**: `apiKey` が空のとき、`providers` の中から `kind === 'openrouter'` のものを探してそのキーを使う。UI では「文章と同じ接続（OpenRouter）のキーを使う」チェックで表現し、既定 ON
- リクエストは §1.1 のとおり。`quality` は API の値（`low`/`medium`/`high`）をそのまま送る
- **`quality` 非対応モデルへの追従**: 400 が返り本文に `quality` が含まれていたら、**`quality` を外して1回だけ投げ直す**（`openrouter.ts` の JSON モード降格と同じ idiom）。実測では flux 系は `quality` を送らずに動いたので、対応状況はモデル依存と考える
- `size` は `${width}x${height}`。モデルが非対応なら API のエラーメッセージをそのまま表示（丸めない）
- レスポンスの `usage.cost`（USD）を**必ず記録**（§6）
- 推奨モデルは3つだけプルダウンに出す＋自由入力:

| ラベル | model | style | 実測コスト |
|---|---|---|---|
| 安い・十分な品質（既定） | `openai/gpt-5-image-mini` | natural | 0.35円（standard） |
| 高品質 | `google/gemini-2.5-flash-image` | natural | 約6円 |
| 別系統（好みで） | `black-forest-labs/flux.2-klein-4b` | natural | 2.2円 |

### 4.2 `civitai`（成人向け・I5）

- エンドポイント・ボディ・レスポンスは §1.2 のとおり
- **モデル指定は URL 貼り付けのみ。** AIR や ID を打たせない
  1. ユーザーが Civitai のモデルページ URL を貼る
  2. `modelVersionId` を URL から抽出（無ければ `/api/v1/models/{id}` から最新版を取る）
  3. `GET /api/v1/model-versions/{id}` → `air` / `baseModel` / `trainedWords` / `name` を保存
  4. `baseModel` から `promptStyle` を自動判定（`Flux`/`SD 3` を含む → `natural`、それ以外 → `tags`）。**判定結果は必ず上書き可**
  5. `trainedWords` があれば `defaultPositive` の末尾に追記候補として提示（自動では入れない。ユーザーが確認して入れる）
- LoRA も同じ URL 貼り付けで追加し、`additionalNetworks` に `{ [air]: { type: 'Lora', strength } }` を組み立てる。`trainedWords` はここでこそ自動挿入する価値がある
- `seed` は **0〜4294967295**。`-1` は 400 になる（§7-2）
- `allowMatureContent=true` は常に付ける（付けても料金・挙動は変わらないことを確認済み。将来の出力モデレーション用）
- `whatif=true` で生成前見積り（§6）
- **ブラウザ版では使えない**。`isTauri()` でない環境では追加ボタンを出さず、理由を1行書く

### 4.3 `comfyui`（パワーユーザー・I4）

プリセットは配らない。持ち込みを楽にする方向に投資する。

**注入の優先順位（明示指定が常に勝つ）**

1. `workflowJson` に `%PROMPT%` 等のプレースホルダが**1つでも**あれば、従来どおりプレースホルダ置換のみ。自動検出はしない
2. 無ければ**自動検出**して注入する:
   - 最終 `SaveImage` から遡り、それに繋がる sampler ノードを特定
   - `inputs.positive` / `inputs.negative` の指す `CLIPTextEncode` の `text` を置換
   - `inputs.latent_image` の指す `EmptyLatentImage` の `width` / `height`
   - `seed` / `steps` / `cfg` / `sampler_name` / `scheduler` は sampler ノード自身
   - `CheckpointLoaderSimple` の `ckpt_name`
3. **sampler が複数見つかったら（hires fix・refiner 構成）自動検出をあきらめ、その旨を表示する。**黙って片方に入れない

**プルダウンの選択肢は ComfyUI から取る**

- `GET /object_info/{クラス名}`（`omitOrigin: true` 必須）で入力仕様を取り、列挙候補 `input.required.<名前>[0]` から `ckpt_name` / `sampler_name` / `scheduler` / `lora_name` のプルダウンを作る
- **全体（`/object_info`）は数MBあるので使うクラスだけ個別に取る**（`CheckpointLoaderSimple` / `KSampler` / `LoraLoader` の3本を並列）
- **こちらが用意するどんなプリセットより正確**（その PC に実在するモデル名だけが並ぶ）
- **メモリ保持のみ・永続化しない**（モデルフォルダは変わる）。`baseUrl` ごとにプロセス内キャッシュ
- LoRA は「ワークフローに `LoraLoader` が既にあれば `lora_name` と `strength` を差し替える」だけ。**ノードを追加しない**。LoRA 欄は `plan.loraId` が取れたときだけ出す

**上書きの意味論**

- プルダウンの既定は **「ワークフローの値を使う」（＝未選択）**。未選択なら**そのフィールドに触らない**
- 保存先は `ImageProvider.params`（`ckptName` / `samplerName` / `scheduler` / `steps` / `cfg` / `loraName` / `loraStrength`）
- 注入は `key in node.inputs` のときだけ行う＝**存在しない入力を勝手に生やさない**（`KSampler` は `seed`、`KSamplerAdvanced` / `SamplerCustom` は `noise_seed`。両方に書きに行き、在る方だけが入る）

**同梱テンプレ（`DEFAULT_COMFY_WORKFLOW`）はプレースホルダを持たない**素の SDXL 構成にする。そのまま自動検出に載るので、新規ユーザーが最初に見る状態が「貼るだけで動く」になる。既存ユーザーの `%PROMPT%` 入りテンプレは手動パスで動き続ける（移行不要）。

## 5. プロンプトスタイルと画風

### 5.1 スタイルが欄を消す

| | `tags` | `natural` |
|---|---|---|
| 起案の出力契約 | 英語のカンマ区切りタグ | 1〜3文の英語描写 |
| ネガティブ欄（モーダル） | 出す | **隠す** |
| `defaultPositive`（品質タグ） | 出す | **隠す** |
| `defaultNegative` | 出す | **隠す** |

自然文を選ぶと設定欄が3つ消える。既定の OpenRouter 経路は**プロンプト1本だけの世界**になる。

### 5.2 `illustrationPromptSystem()` の分岐

現状（[`prompts.ts`](../src/lib/prompts.ts) `illustrationPromptSystem`）は

> `{"prompt": "英語のカンマ区切りタグまたは簡潔な英語描写", …}`

と書いていて**どっちつかず**＝出力形式が起案モデルの気分で揺れる。ここを `PromptStyle` で断言させる。

```ts
export function illustrationPromptSystem(style: PromptStyle): string
```

- `tags`: 「英語の danbooru 風カンマ区切りタグのみ。文にしない」＋ `{"prompt","negative"}` を要求
- `natural`: 「英語の自然な描写文1〜3文。タグの羅列にしない」＋ **`negative` を JSON 契約から外す**（不要なのに書かせると余計な語が混ざる）

どちらも「品質タグ・画風タグを入れない」指示は維持（接続先側で結合するため）。

### 5.3 画風

`ArtStyle × PromptStyle` の対応表（ハードコード4行＋自由入力）:

| | `tags` | `natural` |
|---|---|---|
| `anime` | `anime style, anime screencap` | `Drawn in a Japanese anime illustration style.` |
| `realistic` | `photorealistic, realistic` | `Rendered as a photorealistic photograph.` |

**合成位置がスタイルで違う**（`applyArtStyle`）:

- `tags` … **先頭にタグとして結合**（`combineWithDefaults` 経由で重複トークンを除去）
- `natural` … **末尾に1文として添える**。前置きにすると起案文の主語より前に出て文が壊れるため。手前に終止符が無ければ `. ` を補う

実例（実測）:

```
tags:    watercolor painting, masterpiece, best quality, 1girl, silver hair, alley
natural: A silver-haired girl looks back in a rainy alley. Drawn in a Japanese anime illustration style.
```

- `custom` は入力文字列をそのまま使う（ラベルは日本語「自由入力」、注記に「英語で入力してください」）
- UI ラベルは日本語（実写／アニメ／自由入力）
- **置き場所は生成モーダル。**設定欄を増やさない。選択は `ImageProvider.artStyle` に書き戻る＝「最後に選んだ画風」が既定として残る
- **結合位置は `generateImage` の中1箇所**（AGENTS.md の不変条件。モーダル側で足さない）
- **`natural` では `defaultPositive`/`defaultNegative` を結合しない**。UI で隠すだけだと、スタイルを切り替えた後に古いタグが見えないまま混ざる
- 自動付加される内容は生成モーダルに「生成時に自動付加: …」として**必ず見せる**（既存 UI の idiom を踏襲）

## 6. コスト表示

BYOK の最大の購入前不安は「いくらかかるか」（公開計画 §5.7）。**円で、生成のたびに見せる。**

### 6.1 表示形式 —— 「10枚で約○円」に統一

生成ボタンの脇に常時1行:

```
10枚で約 3.5 円（前回の実績）
```

- **分母は10枚に固定する。** 1枚あたりだと桁が小さすぎて実感が湧かず（0.4円）、100枚あたりだと総額が大きく見えて割高な印象を与える（40円）。10枚が挿絵の実際の使用感にも近い
- **「100円で何枚」は併記しない。** 「○枚で○円」と「○円で○枚」は分母が逆になり、並べると読み違えを誘う

### 6.2 数字の出どころ（推測値を出さない）

| kind | 表示 | 出どころ |
|---|---|---|
| `openrouter-image` | **「（前回の実績）」を必ず添える** | 同一 `model`・`quality`・サイズでの**直近1回の実測** `usage.cost`。実績が無い間は §4.1 の表を「（目安）」と明記して出す |
| `civitai` | 「（見積り）」 | **`whatif=true` の `x-civitai-cost-total`＝正確値**（Buzz 消費なし） |
| `comfyui` | 表示しない（自前GPU） | — |
| `openai-image` / `modelslab` | 表示しない（コストを返さない） | — |

**OpenRouter は「前回値」であることを文言で明示する。** 同じモデル・同じ設定でもプロンプト長やモデル側の挙動で変動しうるので、確定値のように見せてはいけない。設定を変えた直後（＝その組合せの実績がまだ無い）は「（目安）」に戻る。

- 実測値は `ImageProvider.params.costSamples: { key: string; usd: number }[]`（key ＝ `model|quality|size`）に**直近1件だけ**保存
- 為替は `src/lib/cost.ts` に `USD_JPY = 150` の定数1つ。**設定にはしない**（過剰）。コメントに「概算表示専用。厳密な請求額ではない」と明記
- Buzz → 円は `BUZZ_JPY` 定数。§1.2 の未確認事項が片付くまでは**「約」を必ず付ける**

### 6.3 `quality` を表に出す理由

18倍の価格差はサンプラーやステップより体感に効く。**API の3段階をそのまま3択で見せる**（日本語ラベルに翻訳するだけ）。

| API 値 | ラベル | 備考 |
|---|---|---|
| `low` | 標準 | **既定**。実測 0.35円/枚で挿絵として十分 |
| `medium` | 高品質 | |
| `high` | 最高品質 | |

2択に丸めても難しさは変わらない（どちらも「選ぶ」動作は1回）ので、**情報を落とさず3択のまま**にする。コストは §6.1 の行が選択に追従して更新されるので、価格差はそこで伝わる。

## 7. UI

### 7.1 未設定時の導線（物語を止めない）

挿絵ボタンは**未設定でも表示する**（機能の存在を知らせる価値がある）。押したとき:

- 文章側に OpenRouter プロバイダが**ある** → モーダル内に1行だけ:
  > 文章と同じ接続（OpenRouter）で画像を生成できます。［この接続で生成する］
  - 押すと `newImageProvider('openrouter-image')` を既定値で作って即生成画面へ。**設定画面に行かない**
- **ない** → 「画像生成には接続先の設定が必要です」＋［設定を開く］［今はしない］
  - 「今はしない」を押したら**そのセッション中は二度と出さない**（メモリ上のフラグ。永続化しない）
- **設定画面へ自動遷移させない**。遷移は必ずユーザーのクリック起点
- 断りの記憶は `src/lib/imageSetup.ts` のモジュール変数（**store に置かない**。エクスポート・セッション・チェックポイントのどれとも関係しない一時状態のため）

### 7.2 生成モーダル（表に出るもの）

```
[プロンプト（編集可・起案ボタン付き）]
[ネガティブ]  ← promptStyle==='tags' のときだけ
画風 [アニメ ▾]   サイズ [縦長 ▾]   品質 [標準 ▾]
10枚で約 3.5 円（前回の実績）           [ 生成 ]
▸ 詳細設定
```

`▸ 詳細設定` の中: 枚数・サンプラー・ステップ・CFG・カスタムサイズ・seed。

**サンプラーとステップを表から外す理由**（記録として残す）:

1. 横断で語彙が共通でない（ComfyUI は `euler`＋scheduler 別フィールド、ModelsLab は `UniPCMultistepScheduler`、Civitai は `EulerA`、Replicate はモデルごとに独自 enum）。共通の欄を1つ置くとどのアダプタでも微妙に嘘になる
2. 最適値がモデル依存（Flux schnell は4、SDXL は25〜30、LCM は8）。知らずに動かすと**品質が下がる方向にしか動かない**
3. 「思った通りの画像」に効かない。効くのは起案プロンプト・画風・モデル

### 7.3 設定画面

- 追加ボタンは **「OpenRouter（画像）」「ComfyUI」「Civitai」の3つ**。ModelsLab・汎用画像API は「その他の接続先を追加 ▾」に畳む（既存データは動き続ける）
- 各接続先の表側: 名前・キー（or キー再利用チェック）・モデル・プロンプトスタイル・画風
- `defaultPositive` / `defaultNegative` は `promptStyle==='tags'` のときだけ表示
- ComfyUI の workflow JSON textarea は「▸ ワークフロー（詳細）」に畳む。自動注入が効くので**通常は触らない**

## 9. 実装上の落とし穴（必読）

1. **OpenRouter は `/chat/completions` ではなく `/api/v1/images`。** 前者は動くが割高（reasoning トークンが乗る）でサイズ・品質を指定できない
2. **Civitai の `seed` は 0〜4294967295。** `-1` は 400 になる。ランダムは「フィールドを送らない」で表現する
3. **Civitai は未知プロパティを黙って無視する。** `{"__bogus__": 123}` を足しても 200 が返った ＝ **パラメータ名を間違えても気付けない**。パラメータ名は §1.2 の実測形から動かさない
4. **Civitai はホストが違う。** `api.civitai.com` は Web サイトを返す（Next.js の 404 HTML）。正しくは `orchestration.civitai.com`
5. **Civitai は CORS ヘッダが空 ＝ ブラウザ版から叩けない。** `isTauri()` でない環境では接続先として出さない
6. **AIR の ecosystem はベースモデル名と一致しない。** Illustrious ベースでも `urn:air:sdxl:…`。自前で組み立てず、必ず `/api/v1/model-versions/{id}` の `air` をそのまま使う
7. **ComfyUI の自動検出はプレースホルダより弱い。** `%PROMPT%` があれば自動検出を**走らせない**。両方効くと二重注入で壊れる
8. **`/object_info` にも `omitOrigin: true` が要る**（ComfyUI 経路に新エンドポイントを足すときは必ず付ける。`docs/設計_Tauri化.md`）
9. **定型タグ・画風の結合は `generateImage` 1箇所のみ**（AGENTS.md の既存不変条件）。`ImageJob.prompt` / `SceneIllustration.prompt` は結合前のユーザープロンプトを保つ
10. **コスト表示に推測値を混ぜない。** 実測が無い状態で数字を出すときは必ず「目安」と明記する。`USD_JPY` は概算専用で請求額ではない
11. **キー再利用の失敗を握り潰さない。** 文章側 OpenRouter のキーが無効な場合、画像側で 401 が出る。エラー文言は「文章側と同じキーを使っています」と明示して切り分け可能にする
12. **`modelslab` を消さない。** 既存ユーザーのデータが動かなくなる。UI の追加ボタンから外すだけ
