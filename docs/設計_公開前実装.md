## R1. `schemaVersion` + migrate

**唯一あとから足せない要素。** 他の何より先に入れる。

### 現状

[store.ts](../src/store.ts) の persist 設定に zustand の `version` も `migrate` も無く、「クリーンブレイク：後方互換は不要なため migrate 連鎖は持たない」と明記されている。公開後はこの前提が崩れる。

### 実装

- `persist(..., { version: 1, migrate })` を入れる。**中身が空の migrate でよい**（v1 が初版）。要るのは「番号が刻まれている状態で世に出ること」
- migrate は `(persisted, from) => state` の連鎖にする。`from` ごとの変換関数を配列に持ち、順に適用する形にしておく（`migrations[1→2]`, `[2→3]` …）
- **セーブデータ（`sessions` / `branchTrees` / チェックポイント）とカセット定義は別々にバージョニングする。** 片方の変更でもう片方を壊さないため。セーブは「途中まで遊んだ人の思い出」なので定義以上に壊すと恨まれる
- 移行に失敗したときは**黙って落とさず**、起動時に「このデータはこのバージョンでは読めません」を出してバックアップを促す

### 検証

旧 state.json（version なし）を置いた状態で起動し、v1 として読めること。version を偽の未来値（99）にした state.json で拒否されること。

### 実装（2026-08-15）

| 置いた場所 | 中身 |
|---|---|
| [schema.ts](../src/lib/schema.ts) | `APP_STATE_VERSION` / `SAVE_DATA_VERSION` / `CASSETTE_DATA_VERSION`（いずれも 1）と移行連鎖・`migrateAppState` / `migrateSubSchemas` / `schemaErrorMessage` |
| [store.ts](../src/store.ts) の persist | `version: APP_STATE_VERSION` ＋ `migrate`。`partialize` が `schemaVersions: {save, cassette}` を書き、`merge` が毎回それを見る（入れ物の版番が据え置きでもセーブ／カセットを単独で上げられる） |
| [platform.ts](../src/lib/platform.ts) | `blockStateWrites()`（デバウンス待ちの分も捨てて以後の書き込みを封印）・`stateLocationLabel()`（バックアップ場所の表示） |
| [App.tsx](../src/App.tsx) | `schemaError` があれば本編を描かず案内画面（`.app.solo` ＋ `.schema-block`）。孤児チェックポイント掃除・画像記録バックフィルも走らせない |

**「無視して続ける」導線は置かなかった。** 続けた先の保存が全部封印されているので、できることが無い。

検証は Web 版（localStorage）で実施し、①version なしの旧データが v1 として読め、再保存で `version: 1` と `schemaVersions` が刻まれる ②`version: 99` で案内画面が出て、**保存済みデータが1バイトも書き換わらない**（ハイドレーション後に state を変更しても不変）③入れ物 v1 のまま `schemaVersions.save: 5` にすると「セーブデータ」の文言で拒否される、を確認済み。

## R2. カード読み込みの検証入口

### 現状

[cards.ts](../src/lib/cards.ts) は `{ spec: 'aist_cassette', spec_version: '1.0', data }` を**書いているが読み込み側で検証していない**。[io.ts](../src/lib/io.ts) の `parseBundle` はホワイトリストで再構築するため、**トップレベルの未知キーが静かに消える**（中身の各要素は素通しなので被害は限定的）。

### 実装

- **検証入口を1箇所に集約**する（`cards.ts` に `validateCard(parsed)` を1本）。`parseCardPng` / `importAnyFile` / D&D の全経路がここを通る
- 見るもの：`spec`（種別）／`spec_version`（読めるか）／`minRuntimeVersion`（**アプリ側が古ければ明示的に拒否**）／R8 の署名
- **`minRuntimeVersion` を書き出し側に追加する。** 新しいカセットを古いランタイムで開いて黙って半分だけ動くのが最悪の壊れ方。「本体を更新してください」と出して読み込まない
- `parseBundle` を未知キー保存に変更する。ホワイトリスト再構築をやめ、既知キーは検証・未知キーはそのまま持ち回る

### 注意

**厳格にしすぎない。** 未知の**フィールド**は無視して読み進む。拒否するのは `minRuntimeVersion` と署名だけ。

### 実装（2026-08-15）

- [cards.ts](../src/lib/cards.ts) に `validateCard(parsed, chunk)` を1本置き、`decodeCardChunk` 経由で `parseCardPng` の全種別が通る。読み込み経路（Library の D&D・Sidebar の D&D・`store.importAnyFile`）は全て `parseCardPng` を通るので、入口はここ1箇所で足りた
- 拒否するのは3つだけ：`minRuntimeVersion` が本体より新しい／`spec` が種別違い／`spec_version` のメジャーが上。**マイナー増と未知フィールドは読み進む。** `chara_card` は他ツール由来で版が独自に進むため `spec_version` を見ない（v1/v2/v3 を受理）
- 書き出し側は4種すべてに `minRuntimeVersion` を刻む。値は `CARD_MIN_RUNTIME_VERSION` という**手で上げる定数**にした。本体バージョンに自動追随させると、形式が変わっていないのに新しい本体で作ったカードを古い本体が一律で拒否する
- 本体バージョンは [version.ts](../src/lib/version.ts) の `APP_VERSION`（`vite.config.ts` の define で package.json から注入）。`src-tauri/tauri.conf.json` の `version` とは手で揃える
- `parseBundle` はホワイトリスト再構築をやめ、`...obj` を展開してから既知キーを検証で上書きする形にした。**この過程で `sessionImageLogs` がホワイトリストから漏れていた**（`importBundle` は読むのに `parseBundle` が捨てていた＝画像の永続記録がインポートで消えていた）ことが判明したので、既知キーとして明示も足した
- R8 の署名検証は `validateCard` の末尾に相乗りさせる（コメントで印を置いた）

## R3. API キーを平文 state.json から出す

### 現状（確認済み）

[store.ts:4953](../src/store.ts:4953) の `partialize` が `providers` と `imageProviders` をそのまま永続化している。`Provider.apiKey` は文字列で入っているため、[platform.ts](../src/lib/platform.ts) の `stateStorage` 経由で **Tauri では `%APPDATA%/data/state.json` に平文で書かれる**（Web は localStorage）。`exportBundle` には含まれない（コメントの通り）ので、書き出しファイル経由の漏れはない。

同人ソフトとしては珍しくないが、**BYOK を売りにする商用配布物としては直しておく**。ユーザーが預けているのは自分の課金アカウントの鍵なので、事故ったときの損害が本人の財布に直結する。

### 実装

- **Tauri：OS の資格情報ストアへ分離する。** Rust 側に `save_secret(id, value)` / `load_secret(id)` / `delete_secret(id)` の3コマンドを足し、Windows 資格情報マネージャ（`keyring` クレート等）に預ける。キーは `provider:<id>` / `imageProvider:<id>`
- `partialize` から **`apiKey` を落とす**（`providers` は残し、キーだけ抜いて保存）。読み込み時に資格情報ストアから戻す
- **既存ユーザーの移行**：起動時に state.json 内に `apiKey` が残っていたら、資格情報ストアへ移してから state.json 側を空文字で上書きする（R1 の migrate に相乗り）
- **Web 版はそのまま localStorage でよい**（開発・検証用であり配布物ではない）。ただし `platform.ts` の `SecretStore` interface を切って `isTauri()` 分岐をこのファイルの外に出さない（既存の規約どおり）

### 不採用：Tauri Stronghold

**ユーザーにパスワードを要求するため。** いま R4・R5 で削ろうとしている初回摩擦を、別の場所に足すことになる。目的は「平文で置かないこと」であって「パスフレーズで守ること」ではない。

### 実装（2026-08-16）

| 置いた場所 | 中身 |
|---|---|
| [src-tauri/Cargo.toml](../src-tauri/Cargo.toml) | `keyring = "3.6"`（`windows-native` feature） |
| [src-tauri/src/lib.rs](../src-tauri/src/lib.rs) | `save_secret` / `load_secret` / `delete_secret` の3コマンド。service 名はアプリ識別子 `com.tokatokage.delist` 固定・account 名が id |
| [platform.ts](../src/lib/platform.ts) | `persistProviderSecret` / `removeProviderSecret` / `syncProviderSecrets` / `stripApiKeyForPersist`。isTauri() 分岐はここに閉じ込め、呼び出し側（store.ts）は分岐しない（既存の規約どおり） |
| [store.ts](../src/store.ts) | `partialize` が `stripApiKeyForPersist` で apiKey を落として保存。`upsertProvider`/`upsertImageProvider`/`delete*` が資格情報ストアへも書く。新アクション `hydrateProviderSecrets`（起動時1回、資格情報ストアの値で apiKey を埋め直す） |
| [App.tsx](../src/App.tsx) | ハイドレーション後に `hydrateProviderSecrets` を待ってから「使える接続先が無ければ System へ」の判定を行う（`secretsReady` ゲート。資格情報ストアの読み出しが終わる前に空キーで誤判定して System へ飛ばすのを防ぐ） |

**既存ユーザーの移行はマイグレーション関数を別に持たない。** `syncProviderSecrets` が「資格情報ストアが空 かつ persist 由来の apiKey が残っている」ケースを移行として扱い、資格情報ストアへ書いてから返す。以後 `partialize` が apiKey を落とすので、次回の自動保存で state.json 側は自然に空になる（R1 の migrate 連鎖に相乗りする形は取らなかった。migrate は同期・純関数の縛りがあり、資格情報ストアへの書き込みは非同期 I/O のため）。

Web 版は `isTauri()` が false を返すため全関数が no-op／素通しになり、これまで通り apiKey が persist に残る（対象外）。

**未検証：** Windows 実機（`cargo tauri dev`）での資格情報マネージャへの読み書きは `cargo check` と `tsc`/`vite build` の通過までで、実機起動での動作確認はしていない。

## R4. OpenRouter OAuth（PKCE）

**目的：APIキー設定の壁を、案内の改善ではなく手順の削除で殴る。** 公開計画が最大リスクとしているのはここ。

### 流れ

```
アプリ           code_verifier を生成 → S256 で code_challenge を作る
  ↓
アプリ           ローカルの受け口（127.0.0.1:任意ポート）を立てる
  ↓
外部ブラウザ     OpenRouter の承認ページを開く（callback_url と code_challenge を渡す）
  ↓
ユーザー         ログインして「このアプリにキーを発行する」を承認
  ↓
ブラウザ         127.0.0.1 の受け口へ code を返す
  ↓
アプリ           code + code_verifier を交換エンドポイントへ POST → アプリ専用 API キーを受け取る
  ↓
アプリ           R3 の資格情報ストアへ保存 → 接続テスト → 完了
```

### 実装メモ

- **エンドポイントとパラメータ名は実装直前に OpenRouter の公式ドキュメントで確認する**（このドキュメントに書き写して腐らせない）。確認すべきは①承認ページの URL とクエリ名②コード交換の POST 先とボディ③任意ポートの localhost コールバックが許容されるか
- ローカル受け口は Rust 側で立てる（Tauri の OAuth 系プラグイン、または最小の TCP リスナ）。**受け取ったら即座に閉じる**
- **`state` パラメータ（CSRF 対策）を付け、返ってきた値を照合する**
- 受け口は `127.0.0.1` に限定する（`0.0.0.0` にしない）
- 成功後のブラウザ表示は「アプリに戻ってください」の静的 HTML を返して終わり
- **手動でのキー貼り付けは残す。** OAuth は OpenRouter 専用の近道であって、他プロバイダとローカルモデルは従来どおり。OpenRouter 側の仕様変更で入口が全部死ぬ状態を作らない
- **Web 版には実装しない**（配布物ではないため）

### 位置づけの注意

**OAuth の価値は「無料になること」ではなく「コピペが消えること」。** 無料枠で完走できるかは R6 の別問題で、混同すると「OAuth を入れたのに体験が途切れる」という設計になる。

### 実装（2026-08-16）

エンドポイントは実装直前に OpenRouter 公式ドキュメント（`openrouter.ai/docs/use-cases/oauth-pkce`）で確認した。

| 項目 | 値 |
|---|---|
| 認可ページ | `https://openrouter.ai/auth?callback_url=...&code_challenge=...&code_challenge_method=S256` |
| 交換エンドポイント | `POST https://openrouter.ai/api/v1/auth/keys`（body: `code` / `code_verifier` / `code_challenge_method`、応答: `{ key }`） |
| client_id の事前登録 | **不要** |
| localhost コールバック | **任意のポートが許容される**（`callback_url` に `http://127.0.0.1:<任意ポート>/...` を渡せる） |

**`state` パラメータは存在しない**（OpenRouter 側が対応していない。ドキュメント上に記載なし）。設計時点で想定していた「`state` を照合する」は実装できないため、代替として**ローカル受け口を「1リクエストだけ・ランダムな nonce をパスに含む URL でしか受け付けない」**方式にした（`callback_url` に nonce を埋め込めば OpenRouter 側はそこへ `?code=...` を足すだけなので両立する）。

| 置いた場所 | 中身 |
|---|---|
| [src-tauri/src/oauth.rs](../src-tauri/src/oauth.rs) | `oauth_pkce_listen` コマンド。`127.0.0.1:0`（OS 割当ポート）へ bind → JS へ `oauth-pkce-port` イベントでポート通知 → 1リクエストだけ待って `code`/`error` を返す。3分でタイムアウト。パース関数（`query_param`/`url_decode`/`parse_request_line`）はハンドロールのため単体テストを6本添えた（`cargo test oauth`） |
| [src-tauri/Cargo.toml](../src-tauri/Cargo.toml) / [lib.rs](../src-tauri/src/lib.rs) | `tauri-plugin-opener`（承認ページをシステム既定ブラウザで開く。WebView 内で開くと OAuth プロバイダ側に拒否されうるため） |
| [capabilities/default.json](../src-tauri/capabilities/default.json) | `opener:default` 許可を追加 |
| [oauthPkce.ts](../src/lib/oauthPkce.ts) | `startOpenRouterOAuth()`。code_verifier/code_challenge の生成（Web Crypto）・受け口の起動・ブラウザを開く・コード交換までを1関数に集約。Tauri 限定（`oauthPkceAvailable()` で判定。isTauri() の生の分岐は platform.ts の外に置かない既存規約を維持） |
| [SettingsModal.tsx](../src/components/SettingsModal.tsx) | 既存の接続先設定 UI に「OpenRouter にブラウザで接続」ボタンを追加（Tauri のみ表示）。成功時は R3 の資格情報ストアへ自動で保存される（`upsertProvider` 経由） |

**手動でのキー貼り付けはそのまま残した。** OAuth ボタンは既存フォームの上に追加しただけで、既存の入力導線は無変更。

**未検証：** Rust 側の URL パース・タイムアウト・イベント配線は単体テストと `cargo check`/`tsc`/`vite build` の通過までで確認したが、**実際の OpenRouter アカウントでブラウザ承認まで通す E2E は未実施**（ユーザー自身のアカウントでの承認操作が要るため）。初回利用時に実機で確認する。

## R5. 初回ウィザード

公開計画 §5.7 の実装。**3ステップ固定・分岐を作らない**（R4 が入れば OpenRouter は2ステップ）。

### プロバイダ選択（ラベルとプライバシー表示）

| ラベル | 中身 | 添える表示 |
|---|---|---|
| **かんたん接続**（初期値） | OpenRouter を OAuth で | ブラウザで承認するだけ |
| 無料枠で始める | Gemini 無料枠 | **入力が提供元の品質改善に使われる場合がある** |
| 品質重視 | Claude / GPT | 従量課金 |
| 表現の制限が緩いモデル | OpenRouter 経由の特定モデル | — |
| PC で動かす | Ollama / LM Studio（OpenAI 互換） | **外部送信なし**・数GBのダウンロードとPC性能が必要 |

- **Gemini 無料枠を無条件の初期値にしない。** 無料枠は入力が製品改善に使われうる旨が提供元の規約で示されており、ロールプレイという用途では黙って既定にするのが不誠実。「無料で始める」ではなく**プライバシー条件を1行添えた選択肢**にする
- ローカルモデルは「最初の5分」を軽くする道ではない（ダウンロードとPC性能が要る）。**継続利用・プライバシー・表現の自由度の受け皿**として置く

### R5' ローカルモデルの通し動作検証（Phase 2 の最優先・2026-08-11 追加）

**理由が1つ増えた。** DLsite には「**メインコンテンツがインターネットに接続する必要のある作品**は取り扱いできません」という規約がある（`公開計画` §1.8-③）。**ローカルモデルで全機能が動くなら「接続が必要な作品」ではない**——接続は選択肢の1つであって必須ではない。これが DLsite で扱えるかどうかの唯一の反論材料になる。

OpenAI 互換なので通るはずだが、**通しで確認していない。検証前にこの主張を DLsite にしない。**

確認する範囲（本編だけでなく裏方 LLM も全部）：

- 本編のストリーミング生成
- 選択肢生成／シーン終了レビュー。**`response_format` 非対応でも `jsonSchemas.ts` の段階降格が効くか**（schema → object → 素）
- 次シーン候補・画像プロンプト起案
- 接続テストとモデル一覧（`/models` を返さない実装への耐性）
- **ネットワークを切った状態で、最初から最後まで通るか**

ダメだった箇所は「ローカルモデルでは未対応」と正直に書く。**全機能でないなら「全機能が動く」と言わない。**

### 検証（2026-08-16 / 2026-08-23）— **完了**

詳細は [`R5検証チェックリスト.md`](./R5検証チェックリスト.md)。二段階で実施した。

**第一段（2026-08-16・Claude Code）**: Web 開発ビルドを実機の Ollama（`http://localhost:11434/v1`・`qwen3:8b`）へ

**第二段（2026-08-23・ユーザーによる実機検証）**: **外部通信をファイアウォールで遮断した状態**で、

（プロバイダ呼び出しの入口）と [`ambientAudio.ts`](../src/lib/ambientAudio.ts)（バンドル済みの環境音資産）の
2か所のみ＝**起動時に外部を叩く経路が存在しない**。

#### 結論（2026-08-23 訂正）

**⚠ この検証は DLsite §1.8-③ への反論材料にはならない。** 検証直後に一度そう書いたが誤りで、同日
[`公開計画_マネタイズと配布.md`](./公開計画_マネタイズと配布.md) §1.8-③ で解釈を訂正した。条文が問うのは
「接続しない**構成を選べるか**」ではなく「**購入物だけで動くか**」で、Ollama／ComfyUI の入手を利用者に
要求する時点で該当する（要求先が販売者か第三者かは関係ない）。**DLsite に出すならモデルと推論ランタイムの
同梱が要る＝別 SKU の開発プロジェクト**で、R5' の射程外。前例（HermitNode の BOOTH 版／DLsite 版の
2SKU 構成）と追加コストの分析は §1.8-③ を参照。

**では R5' は何を証明したのか。**

- **言ってよい**: 「Ollama／ComfyUI を用意すれば、**本編も挿絵も外部通信なしで完結する**」。ローカル構成が
  実際に通ることの実証であり、**BOOTH 版の訴求点**（送信したくない人・課金したくない人の受け皿）として有効。
  将来 DLsite 版を作るなら、この検証は**その前提条件が満たされていることの確認**として効き続ける
- **言ってはいけない**: 「オフラインで動く」を無条件に。既定の接続先は外部プロバイダで、ローカル構成は
  利用者が Ollama／ComfyUI を用意して初めて成立する。案内では必要な準備（モデルの入手・PC 性能）を必ず併記する
  （→ [`ガイド_ローカルLLMで動かす.md`](./ガイド_ローカルLLMで動かす.md)）

#### 残った小項目（R5' の成立には影響しない）

- DevTools の Network タブでの「**外部へ試行すらしない**」の裏取り。遮断下で全機能が完走したことは
  「外部通信に**依存していない**」の証拠として十分だが、失敗しても機能に影響しない通信（解析・更新チェック）が
  無いことの直接証拠は別。静的解析では該当箇所が見つかっていないため、優先度は低い
- アプリ内の未確認3件（停止ボタン・レビュー `'all'` 単体・発見キャラのキャラ起案）
- 思考モデルの `max_tokens` 方針の決定（`reasoning_content` が上限を食って JSON が黙って切れる件）。
  **R9 の更新通知を入れる時は、この検証をやり直すこと**（起動時の外部アクセスを増やす変更にあたる）

### 接続テスト

**最重要。** 極小のリクエストを投げて成否を即出す。BYOK の支援コストはほぼ全部「動かないが理由がわからない」から来る。

### エラー翻訳（生の API エラーを出さない）

| 原因 | 出す導線 |

| キーが不正 | 貼り直し |

| モデル名が不正 | 選び直し |
| **コンテンツフィルタによる拒否** | **モデル選択画面へ誘導** |

4つ目が専用メッセージでないと、表現の制限に当たった利用者が「壊れている」と誤解して返金に行く。

### 実装（2026-08-16）

| 置いた場所 | 中身 |
|---|---|
| [openrouter.ts](../src/lib/openrouter.ts) | `testProviderConnection(provider, model)`。`max_tokens:1` の極小リクエストを `/chat/completions` へ投げ、成否とエラー翻訳（`kind: invalid_key / quota / invalid_model / content_filter / unreachable / unknown`）を返す。コンテンツフィルタは 401/403 のエラー文言と 200 応答の `finish_reason: content_filter` の両方を拾う（プロバイダにより出方が違うため） |
| [FirstRunWizard.tsx](../src/components/FirstRunWizard.tsx) | 3ステップ固定のウィザード本体。5つの導線（かんたん接続/無料枠で始める/品質重視/表現の制限が緩いモデル/PCで動かす）を選択肢カードで出し、選択に応じて Base URL・種別のプリセットを流し込む。OpenRouter 系3経路は同じ接続先（id: `openrouter`）を共有し空の重複エントリを作らない。OAuth（R4）が使える環境で「かんたん接続」を選ぶと2ステップに縮む（`oauthPkceAvailable()` で判定。Web ではバッジ表示のうえ手動キー入力にフォールバック） |

**モデル一覧選択は新規に作らず既存の `ModelPicker` をそのまま流用した**（ウィザードが選択直後に `upsertProvider` で下書きをストアへ反映するため、他の画面と同じ経路で動く）。

「無料枠で始める」は Gemini の OpenAI 互換エンドポイント（`generativelanguage.googleapis.com/v1beta/openai`）をプリセットにしたが、**具体的なモデル名は書き出し側の劣化を避けるため空欄にした**（モデル名は日々変わるため、ハードコードすると「動かない初回体験」を作りかねない）。「品質重視」「表現の制限が緩いモデル」は個別モデルIDを固定せず、接続テストには OpenRouter の自動ルーティング（`openrouter/auto`）を使い、実際に使うモデルは接続後にユーザーが選ぶ前提にした（同じ理由）。

**実機確認（2026-08-16、Web版・localhost:11434 の実 Ollama 相手）：**
①「PC で動かす」を選択 → Base URL `http://localhost:11434/v1` が自動入力・API キー欄が非表示になることを確認
② 存在しないモデル名 `llama3.1` でテスト → `モデル名が正しくありません。モデルを選び直してください。（model 'llama3.1' not found）` と翻訳されて表示（`invalid_model` 判定が実際の Ollama のエラー文言で機能することを確認）
③ 実在する `qwen3:8b` でテスト → 「接続できました。この接続先が新しい物語の既定になりました。」→ System 設定の「新しい物語の既定モデル」が `[ローカル接続先] qwen3:8b` に反映されることを確認
④ リロード後、条件を満たしたため初回ウィザードが再度出ないことを確認

**未検証：** OAuth 経路（R4 の実機未検証と同じ理由）、Tauri ビルドでの実機起動、Gemini/OpenRouter など外部プロバイダでの成功パス（ネットワーク到達性・実キーが要るため）。

## R6. 体験用カセットの呼び出し予算

**本アプリは1ターンに複数回 LLM を呼ぶ。** 無料枠には1日あたりのリクエスト数上限があるため、体験用カセットの規模を上限から逆算する必要がある。

### 呼び出しの内訳

| 単位 | 呼び出し |
|---|---|
| 1ターン | 本編 1（＋選択肢生成を押せば +1） |
| シーン終了 | レビュー 1〜2（**A/B 分割実行なら2並列**）＋ 次シーン候補 1 |
| 挿絵1枚 | プロンプト起案 1（画像生成そのものは別プロバイダ） |

### 試算

| 規模 | 選択肢なし | 選択肢を毎ターン |
|---|---|---|
| 5シーン × 6ターン | 約 40〜45 | 約 70〜75 |
| **3シーン × 6ターン** | **約 22〜24** | 約 40 |

OpenRouter の無料モデルはクレジット購入前のアカウントで **1日あたりの合計リクエスト数に上限がある**（実装前に現行値を確認する）。5シーン構成は上限に触れる可能性が高く、**途中で止まる＝最悪の切れ方**になる。

### 決定

- **体験用（同梱）カセットは 3シーン以内で作る**
- レビューの分割実行（A/B）は品質向上のための仕組みだが、**呼び出し数を2倍にする**。体験用カセットでは `'all'` 1本に寄せる設定を既定にできるようにする
- 挿絵の起案は体験用カセットでは前に出さない
- ウィザードの完了画面に**残リクエスト数の目安**を出せるか検討する（OpenRouter はキー情報エンドポイントで利用状況を返すので、取れるなら出す）

## R7. 無料版の境界（オーバーレイ開放＋ビルド分離）

公開計画 §5.1 の「無料版から作る体験が完全に抜ける」問題（§7-6）への実装案。

### 方針：素材は閉じ、オーバーレイだけ開ける

[types.ts:570](../src/types.ts:570) の `SessionOverlay` は既に「元 Character/World は不変に保ち、レビュー承認による追記はここへ積む」設計になっている。**セッションに閉じていて配布物にならない**ので、ここを無料版に開けても抜け道にならない。

| | 無料版 | 制作版 |
|---|---|---|
| 素材（`characters` / `worlds`）の編集 | **×**（閲覧のみ） | ○ |
| **オーバーレイ**（発見ロア・キャラ成長）の編集 | **○** | ○ |
| カセットの作成・書き出し | × | ○ |

「作る楽しさ」の中心＝**自分の関与で人物が変わること**はオーバーレイ側にある。制作版が売るのは「その変化を他人に配れる形へ固定する能力」になり、境界の説明も一段きれいになる。

### 発見キャラが素材に書かれている問題 → **案 a で決定（2026-08-15）**

[store.ts:4104](../src/store.ts:4104) の `addDiscoveredCharacter` は `upsertCharacter` を呼んでおり、**発見キャラは素材（`characters`）に入る**。オーバーレイには `lore` と `characterDevelopments` しかなく、キャラそのものを持つ枠がない。

| 案 | 内容 | 影響 |
|---|---|---|
| **a（採用）** | 無料版では発見キャラのキャラ化（FB7-E）を出さない | 実装は軽い。ただし FB7-E は体験の目玉のひとつで、無料版から抜くと R7 の狙いを部分的に打ち消す |
| ~~b~~ | `SessionOverlay` に `characters: Character[]` を足し、発見キャラをそこへ入れる | 体験は保てる。ただし**素材とオーバーレイの合成ビュー・カード書き出し・配役・状態エンジンの全経路に「素材でないキャラ」が出てくる**＝FB7-E で一度却下した「セッション内埋め込みキャラ」の再来 |

**決定の中身：**

- `SessionOverlay` は `lore` と `characterDevelopments` の2つのまま。**キャラを持たせない**（[types.ts](../src/types.ts) の型コメントに決定として刻んだ＝思いつきで足させない）
- したがって **R1 のセーブデータ版番は v1 のまま確定**（`SAVE_DATA_VERSION = 1`）。R7 のためのスキーマ変更は発生しない
- 無料版で出さないのは **FB7-E の導線だけ**（？バッジ → `CharacterDraftModal`／レビューの `newCharacters` 承認 → `characterDraftQueue`）。オーバーレイ側の発見ロア・キャラ成長は無料版でも開ける（R7 の本体はここ）
- 実装は Phase 4 のビルド分離と同時（無料ビルドから落とすモジュールの一覧に FB7-E の2経路を足す）

**寝返る余地は残っている。** Phase 3 の計測で「無料版で作る体験が足りない」が観測されたら b を再検討する。R1 が入ったので、その時は `SessionOverlay` に `characters` を足して `SAVE_DATA_VERSION` を 2 に上げ、移行関数を1本書けばよい（判断を Phase 1 より前に済ませる必要があったのは migrate が無かったからで、**その制約は解けた**）。波及範囲の広さ（合成ビュー・カード書き出し・配役・状態エンジン）は当時のまま残るので、そこは軽くならない。

### ビルド分離

- **コードベースは1つ、ビルド成果物は2つ。** 実行時フラグ（`if (isPaid)`）は使わない（設定ファイルや devtools で反転される）
- `import.meta.env` のビルド時定数で分岐し、Rollup の tree-shaking で編集系モジュールを落とす
- 無料ビルドに含めない：`library/CharacterEditor`・`library/WorldEditor`・`CassetteEditor`・カード書き出し（`exportCharacterCard` 等）
- 無料ビルドに含める：`DiscoveryPanel`（オーバーレイ編集）・`StatusPanel`・`SessionEditor`・`PersonaEditor`（フィールドを絞ったもの）
- **成果物を grep して検証する。** 動的 import 越しに残らないかを実際のバンドルで確認する（編集系の日本語文言で引くのが早い）

## R8. カセット署名

**塞ぎたいのは「読めてしまうこと」ではなく「作れてしまうこと」。** 暗号化はしない（理由は公開計画 §5.5）。

### 実装

- カード形式（既に `spec_version` を持つ）に `sig` を足す。検証は R2 の入口に相乗りさせる
- 署名鍵は制作版だけが持つ。無料ビルドには**検証用の公開鍵だけ**入れる
- 署名対象は `data` を正規化（キー順を固定した JSON）したバイト列。**正規化規則を決めておかないと、読み書きのたびに署名が壊れる**

### 効能を過大に書かない

制作版すべてが同じ鍵を持つ以上、**署名が証明するのは「制作版を持つ誰かが作った」ことだけで、作者本人の同一性は証明しない**。作者ごとの鍵と公開カタログを組み合わせて初めて同一性の話になる（将来の課題）。

### 段階的な運用（初期は緩く）

第三者作者がまだいない段階で未署名を全拒否すると、**壊れたカセットのサポートと、初期の持ち込みを自分で塞ぐ**ことになる。初期は次で足りる。

1. 公式カセットだけ署名する
2. 未署名でも読み込みは通し、**「作者未確認」と表示する**
3. 無料版で未署名を拒否するのは、無料版に編集機能が無いこと（R7）が効いている前提の**補助**と位置づける

## R9. 配布（コード署名・更新通知・CSP）

### 現状（確認済み）

[tauri.conf.json](../src-tauri/tauri.conf.json) にコード署名の設定も更新機構（updater）も無く、`app.security.csp` は `null`。

### コード署名：**判断を保留する**

未署名の NSIS インストーラは Windows SmartScreen の警告を出し、初回起動率を直接削る。ただし——

- 証明書は**年額のランニングコスト**で、2023年以降はハードウェアトークン保管が必須になり手間も増えた
- 公開計画 §3.6 の中央ケース（流通総額62.5万円）に対して、毎年の固定費として無視できる比率ではない
- 同人ツールでは未署名配布も珍しくなく、この層のユーザーは警告に慣れている面がある

→ **Phase 3 の計測で「ダウンロードしたが一度も起動していない」層が観測されてから判断する。** それまでは、配布ページに**警告が出たときの進め方を明記**して代替する。

### 更新通知：**自動更新は作らない・通知だけ入れる**

- 静的な JSON（GitHub Releases か自サイト）に最新バージョンを置き、起動時に取りに行って新しければ案内を出す
- **自動ダウンロード・自動適用はしない**（Tauri updater は更新成果物への署名鍵管理が付いてきて、同人規模では負債になりやすい）
- 買い切りで v1.x 無償・v2 有償の方針（公開計画 §2.4）を採るなら、**この通知が「v2 が出ました」の導線を兼ねる**

### CSP

`csp: null` を配布前に埋める。本文は React が文字列として描くのでスクリプト注入の面は薄いが、**外部への意図しない読み込みを止める**意味がある。`connect-src` は BYOK で任意ホストへ繋ぐ性質上ゆるくせざるを得ないので、絞るのは `script-src` / `style-src` / `img-src` から。

## R10. 物語の書き出し（集客の本体）

**位置づけが変わった（2026-08-11）。** DLsite をオプションに降格した結果（`公開計画` §1.8）、**プラットフォームの許可も継続的な露出も要らない集客経路はこれだけ**になった。旧版では「本に寄せた決断の副次効果」だったが、いまは集客戦略そのもの（`公開計画` §3.3）。→ **Phase 3 から Phase 2 へ繰り上げ。**

### 要件は「出力できること」ではなく「貼りたくなる出力であること」

| # | 要件 | 理由 |
|---|---|---|
| 1 | **そのまま貼れる形式**（プレーンテキスト／Markdown） | カクヨム・note・X に貼ったとき整形が崩れると使われない |
| 2 | **画像1枚で完結する形**も出せる | X はテキストより画像のほうが伸びる。長文は畳まれる |
| 3 | **挿絵つきの書き出し** | 挿絵は読解補助ではなく獲得資産（`公開計画` §0）。ここで回収する |
| 4 | **出典が自然に入る** | 末尾に製品名とカセット名。**宣伝臭くならない範囲で**＝あからさまだと貼られなくなる |
| 5 | **プレイヤーの選択が見える** | 「何を選んでどうなったか」が読めることが「自分でもやってみたい」のきっかけ。ただの小説だと製品の存在が伝わらない |

### 実装メモ

- 出力単位は**シーン単位／分岐単位／セッション全体**を選べるように（全部出すと長すぎて誰も読まない）
- **構造化出力（`@名前「セリフ」`）はマークアップを剥がして出す**（`structured.ts` の `plainTextOf`）。話者名は地の文に馴染む形へ
- 画像化は**本文の一部を切り出したカード**でよい（全文の画像化は不可能）。挿絵1枚＋本文数百字＋タイトルの構成
- 既存の `io.ts` / `saveBlob` に乗せる。新しい保存経路を作らない

### 実装（2026-08-16）
