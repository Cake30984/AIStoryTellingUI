# 設計 — 環境音ピン（AM1〜AM3・実験機能）

> 2026-07-26。要望・確定方針は [`設計_環境音ピン_実験.md`](./設計_環境音ピン_実験.md)（以下「要望書」）。本書はそれを**実装可能な設計へ落とす**もので、要望書が「実装時に確定」とした未決点（アンカー粒度・型・半径・カーブ）を全部決める。要望書の §1〜§5 は再議論しない前提。
>
> 前提として既存の挿絵（`SceneIllustration`）実装を実測調査した。§1 がその結果で、**要望書 §5.3 の「DOM Range で解決」案はそのままでは成立しない**ことが分かったため §4 で方式を差し替えている。

## 1. 挿絵の仕組み — 調査結果（何を流用でき、何が流用できないか）

### 1.1 流用するもの

| 仕組み | 挿絵の現状 | 環境音ピンでの流用 |
|---|---|---|
| 置き場所 | `Scene.illustrations?`（読む側は `?? []`） | `Scene.ambientPins?`（同じ規約） |
| アンカー | `messageId`（消失時はシーン末尾へ実行時フォールバック） | 同じ。ただし `lineIndex` を足す（§2） |
| store | `addIllustration`/`removeIllustration`（scene 配列の追加・filter だけ） | `addAmbientPin`/`updateAmbientPin`/`removeAmbientPin` を同型で作る |
| チェックポイント整合 | `Scene` が `Session` の中にある**だけ**で、スナップショットに自動で入る | **同じ＝追加作業ゼロ**。分岐で過去へ戻ればその地点のピンが鳴る（要望書 §2-1 がタダで満たされる） |
| 削除の作法 | 参照除去のみ（実体は `gcUnusedImages` 回収） | 参照除去のみ（実体は内蔵アセットなので回収対象すら無い） |

`branchTrees`/`sessionImageLogs` のように **AppState 直下へ出す必要は無い**（要望書 §5.3 の「`sessionImageLogs` 相当の整合」は、ピンが `Scene` 内にある限り不要）。ピンは「本文と一緒に巻き戻ってよいデータ」なので `Session` の内側が正しい。

### 1.2 流用しないもの

- **画像ストア・GC・カセット同梱・`sessionImageIds`**: 要望書 §6 の通り全部不要。`AmbientPin` は `imageId` を持たないので、**`sessionImageIds`/`collectUsedImageIds` には絶対に足さない**（GC 集合に非画像 id が混ざる）。
- **「メッセージ直後にブロックを差し込む」描画**: 挿絵は自分自身が DOM 要素なので位置を持つ。ピンは本文を汚さないメタデータ（要望書 §5.3）なので、**Y を測る対象が存在しない**。ここが唯一の非自明な設計点で、§4 で解く。

### 1.3 実測した本文 DOM（設計の制約）

- スクロール容器は `.chat`（`overflow-y:auto`）→ `.chat-inner` の中に `[data-msg-id]` 単位で並ぶ（`ChatPanel.tsx`）。
- 小説形式の本文は `.prose-block`（`white-space:pre-wrap`）で、**段落ごとの DOM 要素が無い**。
  - 非構造化: `renderProse(m.content)` が `「」` で分割した `<span>` 列を1枚のブロックに流し込むだけ。
  - 構造化: `StructuredNovelBody` が `content.split('\n')` の行単位で、narration をインラインテキスト＋`'\n'`、dialogue を `.st-dialogue` div として出す。
- 会話形式は `.msg > .bubble > .content`（生文字列）または `StructuredChatBody`（**行をグループへ畳み、空 narration 行を捨てる**）。

→ **帰結①**: 要望書 §5.3 の「anchor → DOM Range → `getBoundingClientRect().y`」は構造化出力で崩れる。`@名前(感情)「セリフ」` のマークアップがレンダリング後テキストから剥がれ、dialogue 行には `\n` が無いため、原文の文字位置とレンダリング後の文字位置が対応しない。**Range 方式は却下**（§11）。
→ **帰結②**: 会話形式は行番号を保てない。**会話形式はメッセージ単位精度へフォールバック**する（小説形式が主・製品方針は「挿絵入りの本」なのでこれで足りる）。

## 2. 要望書の未決点への回答（確定）

| 未決点 | 決定 | 理由 |
|---|---|---|
| アンカー粒度（候補A 文字オフセット / 候補B 段落） | **候補B を「原文の行 index」として実装** — `{messageId, lineIndex}`。`lineIndex` は `message.content.split('\n')` 上の位置 | `parseStructured` と両レンダラが既に `split('\n')` を単位にしている＝マーカーの差し込み位置と**構造的に一致**する。折り返し行（要望書が禁じた不安定アンカー）ではなく原文の改行なので永続化して安全 |
| 候補A を採らない理由 | **行より細かい精度は Y に反映されない**。音量は `f(スクロール中心Y − ピンY)` で、Y は行の高さ単位でしか変わらない。行内の任意点を狙うと折り返し依存になる。半径が画面高さ規模（§2 の半径）なので体感差はゼロ | 要望書 §5.1 の「精度は到達半径と釣り合う」に従った過剰実装の回避 |
| 到達半径の単位 | **チャット表示領域の高さの倍数**（`R = radius × chat.clientHeight`）。既定 `1.0` | px 固定だとウィンドウサイズ・文字サイズでピークの体感幅が変わる。viewport 相対なら「画面1つ分の距離で消える」が常に成立 |
| 半径 UI | **狭い(0.6) / ふつう(1.0) / 広い(1.6) の3択のみ**。数値入力は作らない | 要望書 §3.2「調整子はせいぜい1つ」。knob はユーザーへの課税 |
| 音量カーブ | `t = min(d/R, 1)`、`w = 0.5·(1+cos(π·t))`、`gain = w^1.5 × master` | 中心で1・端で0・**両端で傾き0**＝ピンの縁を通過する瞬間に音量が跳ねない。`^1.5` は聴感補正。定数はコード1箇所・UI に出さない |
| スムージング（要望書 §4.1） | 目標音量へ**一定速度追従**（`RATE = 0.4 /秒` ＝ 0→1 に約2.5秒）。ティックは 80ms 固定間隔 | 生のスクロール位置直結の「音量ヒクヒク」を潰す。§4.2 の「パーク中はフェードしない」は距離が変わらない＝目標も動かないので自動的に満たされる |
| 同時発音数 | **目標音量の上位3本まで**。4本目以降は目標0 | 近接ピンが5つ重なると混ざって泥になる。クロスフェード（要望書 §3.1）は3本で十分表現できる |
| 音量0の扱い（§4.5） | 実測音量が0のまま1.5秒続いたら source を stop・破棄。再接近で作り直す（`AudioBuffer` はキャッシュ済みなので即時） | 画面外のピンを鳴らし続けない |
| 自動再生ポリシー（§4.6） | `AudioContext` は**最初のユーザー操作で生成＋`resume()`**。`App.tsx` に one-shot の `pointerdown`/`keydown` リスナを1つ | Web も Tauri（WebView2）も同じ制約。Web Audio は muted-autoplay の逃げ道が無いのでジェスチャ待ちが必須 |
| マスター音量・ON/OFF | `UiPrefs.ambientEnabled`（既定 true）/ `ambientVolume`（0..1・既定 0.6）。`ReaderSettings`（Aa）に **% 表示**で追加（FB8-E4 の規約） | 世界観データではなく読者側の表示設定。`normalizeUiPrefs` に2キー追加 |
| 追加導線 | メッセージ操作行に「環境音」ボタン（挿絵に倣う）→ `AmbientPinModal` で 段落・音・半径を選ぶ | 要望書 §3.1。行ごとのホバー UI は本文へ当たり判定を増やすので採らない |
| マーカー | 左ガターの小さな点。クリックで `MenuPopover`（音名・半径変更・削除） | 要望書 §5.3「本文へ差し込まない」 |
| カセット共有 | **v1 ではピンはカセットに載らない**。`freshSessionOf` が `scenes` を作り直すため（挿絵と同じ）。導入文へのピンも、開始時に message id が新規発行されるので原理的に不可 | 要望書 §6.3 の「カセットには soundId 文字列だけ」は、将来ピンを載せる時の方針として保持（同梱バイトが不要という結論自体は変わらない） |
| 完結後の可否 | **許可**（本文を変えない操作なので `isSessionFinalized` でロックしない＝挿絵・背景と同じ扱い） | FB9-A の規約「完結後に出す操作は分岐と挿絵・背景生成だけ」に環境音ピンを加える |

## 3. データモデル

```ts
// types.ts
/** 内蔵環境音カタログの1件（アプリの一部＝世界観データではない） */
export interface AmbientSoundDef {
  /** 安定・可読キー（例 'rain-soft'）。uid() にしない＝カタログはバージョン管理される作り込み資産 */
  id: string
  label: string            // 表示名（日本語）
  category: string         // 天候 / 水 / 風 / 屋内 / 街 / 生き物 …（カタログの並び）
  url: string              // Vite が解決した同梱アセット URL
  credit?: string          // ライセンス・帰属表記（System のクレジット節に出す）
  loop?: { start: number; end: number } // 継ぎ目のある素材のループ点（省略時は全長ループ）
}

/** 本文フロー上の一点に留めた環境音（実験機能・AM1） */
export interface AmbientPin {
  id: string
  /** AMBIENT_SOUNDS の id。カタログに無ければ黙ってスキップ（要望書 §6.3） */
  soundId: string
  /** アンカー先メッセージ。消失時はシーン末尾へ実行時フォールバック（永続データは書き換えない） */
  messageId: string
  /** messageId 本文の content.split('\n') 上の行番号。範囲外は最終行へクランプ */
  lineIndex: number
  /** 到達半径＝チャット表示領域の高さの倍数（省略時 1.0） */
  radius?: number
  createdAt: number
}

Scene { …, illustrations?, ambientPins?: AmbientPin[], … }   // 読む側は ambientPins ?? []
UiPrefs { …, ambientEnabled: boolean, ambientVolume: number }
```

挿絵と違い **`messageId` は必須**（アンカーの無いピンは Y を持てず、鳴らす場所が無い）。

## 4. アンカーの解決 — 本設計の核

Range を使わず、**レンダラが行を並べているところに不可視マーカー要素を差し込む**。マーカーは「Y の測定点」と「ガターマーカーの描画」を兼ねるので、**位置計算の JS が一切要らない**（スクロールしても CSS が勝手に追従する）。

```tsx
// <span> なので pre-wrap の中でも改行を起こさない。幅0・高さ0で組版に影響しない
<span className="ambient-mark" data-pin-id={pin.id} title={soundLabel}/>
// .ambient-mark { position: relative; display: inline-block; width: 0; height: 0 }
// .ambient-mark::before { position: absolute; left: -18px; top: .55em; width: 5px; height: 5px;
//   border-radius: 50%; background: var(--accent); opacity: .55; content: '' }
```

差し込み箇所は3か所だけ:

1. **小説形式・非構造化**（`renderNovelMessage`）: そのメッセージにピンがある時**だけ** `content` を行分割して描く（`split('\n')` → 各行 `renderProse(line)` ＋ 行間に `'\n'`）。pre-wrap なので出力文字列は現状と完全一致。
   - ⚠ 既知の制約: 現行の `renderProse` の正規表現 `/(「[^」]*」)/g` は**改行を跨いだ `「…」` も1つのセリフとして色付けする**。行分割するとその1本だけ色分けが切れる。ピンが無いメッセージは従来経路のまま（分割しない）なので影響はピン付きメッセージに限定される。稀 かつ 実験機能なので許容する。
2. **小説形式・構造化**（`StructuredNovelBody`）: 既に行ループなので `i === lineIndex` の直前に差し込むだけ。`pinsByLine` を props で受け取る。
3. **会話形式**（`.msg` / `StructuredChatBody`）: 行対応が保てないので**メッセージ先頭に1つ**（同一メッセージの複数ピンは同じ Y になる）。

`ChatPanel` は `Map<messageId, Map<lineIndex, AmbientPin[]>>` を1回組んで、`renderMessage` 系へ渡す。

**測定と音量計算**（`useAmbientScape` フック・80ms ティック）:

```
centerY = chat.getBoundingClientRect().top + chat.clientHeight / 2
R       = (pin.radius ?? 1.0) * chat.clientHeight
pinY    = document.querySelector(`[data-pin-id="${id}"]`).getBoundingClientRect().top
gain    = curve(|pinY - centerY| / R)
```

- **DOM にマーカーが無いピンは目標音量0**（畳まれた過去シーン・別セッション・アンカー消失で描画されなかったもの）。「畳んだ章の音は鳴らない」は仕様。
- 同じ `soundId` の複数ピンは **max で1本に畳む**（二重再生で音量が跳ねるのを防ぐ）。その後に上位3本へ絞る。
- 純関数として切り出して検証する: `ambientGain(d, R)` / `mergeTargets(pins, ys, center, h)` / `clampLineIndex(idx, lines)` / `resolvePinAnchor(pin, msgs)`。

## 5. オーディオエンジン（`src/lib/ambientAudio.ts`）

React 非依存の単一モジュール（`imageJobs.ts` のモジュールレベル `Map` と同じ作法）。

- API: `ensureAudio()` / `isAudioReady()` / `setMasterVolume(v)` / `applyTargets(t: {soundId, gain}[])` / `previewSound(soundId)` / `stopAll()`
- 内部: `AudioContext` 1つ、`master: GainNode`、`buffers: Map<soundId, AudioBuffer>`（`fetch` → `decodeAudioData`。失敗は1回だけ `console.warn` して以後スキップ）、`voices: Map<soundId, {src, gain, cur, zeroSince}>`
- **声は `soundId` ごとに1つ**（ピンごとではない）。
- ループは `src.loop = true`（＋`loopStart/loopEnd`）。
- 追従は `applyTargets` 呼び出しごとに `cur += clamp(target - cur, ±RATE·dt)` → `gain.gain.setTargetAtTime(cur, now, 0.05)`（ステップのクリック音防止）。
- `<audio loop>` を使わない理由: ブラウザ差でループ継ぎ目にギャップが出る／多重の音量制御が粗い。

## 6. 音源カタログとアセット

- `src/lib/ambientSounds.ts` に `AMBIENT_SOUNDS` 定数（コードの一部＝データではない。要望書 §6.2）。
- ファイルは `src/assets/ambient/<id>.ogg`。解決は
  `import.meta.glob('../assets/ambient/*.ogg', { query: '?url', import: 'default', eager: true })`。
  Vite のアセットグラフに乗るので Web / Tauri で同じ URL 解決になる（`public/` 直参照は `base` 設定に依存するので避ける）。
- **カタログに宣言があってファイルが無い id は起動時にカタログから落とす**（そのピンは鳴らないだけ＝要望書 §6.3 の寛容フォールバックと一致）。**これにより音源が1本も無い状態でも実装・型チェック・ロジック検証が通る**＝音源調達と実装を並行できる。
- ファイル仕様: モノラル / 48kHz / OGG Vorbis q3 / 45秒前後のシームレスループ / 1本 300〜600KB / 合計 5〜10MB。
- **音量は素材側で -23 LUFS に統一する**（カタログに音量補正フィールドを持たせない）。素材ごとに音量がばらつくと、同じ `radius` でもピンごとに体感距離が変わって「到達半径」が意味を失う。正規化を作り込み時に済ませればランタイムは `gain` 1本で足りる。
  - ⚠ **疎な素材（滴り等）は積分ラウドネスで揃わない**ので、その分だけゲインをファイルに焼き込む（実例は `環境音_音源調達リスト.md` §4 の `cave-drips`）。同種が増えたらこの「補正を持たせない」判断の見直しが必要。
- **ライセンスは CC0 に限定**（`公開計画_マネタイズと配布.md` の有料配布があるため、CC-BY でも帰属表記の運用コストが恒久的に出る）。CC0 でも `credit` に出所を残し、System 画面に「同梱素材のクレジット」節を置く。
- **調達リストは [`環境音_音源調達リスト.md`](./環境音_音源調達リスト.md)** に分離（28本の id / 表示名 / カテゴリ / 英語検索語 / 優先度、配布元の可否判定、`ffmpeg` の加工手順）。分担は **DL＝ユーザー / 加工（切り出し・モノラル化・-23 LUFS・ループ化・OGG 変換・リネーム）＝Claude**。★の8本が揃えば体感検証に入れる。

## 7. UI

- **メッセージ操作行**（`msgActions`）に `<Icon name="volume-2"/> 環境音`（2026-07-26 決定・挿絵に倣う）。`icons.tsx` に `volume-2` を追加（絵文字は使わない＝FB8-E2）。
  - 操作行はこれで7個になる（編集・ここから・分岐・削除・挿絵・環境音・選択肢を生成）。混雑が実使用で問題になったら「挿絵・環境音」を1つの `＋` 系メニューへ束ねる案を検討する（今はやらない）。
- **`AmbientPinModal`**（`ModalShell`）:
  ① 段落を選ぶ — 空行を除いた本文行のリスト（行番号＋先頭40字プレビュー）。保存するのは生の `lineIndex`。
  ② 音を選ぶ — カテゴリ別グリッド。行クリックで試聴トグル（`previewSound`）。
  ③ 到達半径 — 狭い / ふつう / 広い の3択。
  ④ このメッセージの既存ピン一覧＋削除。
- **ガターマーカー** `.ambient-mark`: hover でツールチップ（音名）、クリックで `MenuPopover`（半径変更・削除）。没入モードでも出す。
- **`ReaderSettings`**（Aa）: 「環境音」チェックボックス＋「環境音の音量 %」（`RsField`）。「表示を既定に戻す」の対象に含める。
- **解錠の案内**: ピンを置いたが `AudioContext` 未解錠のときだけ、`infoNotice` で「画面をクリックすると音が鳴り始めます」を1回。

## 8. 既存機構との整合

- **チェックポイント**: `Scene` 内なので自動でスナップショットに入る。`restoreCheckpoint` の passthrough には**入れない**（本文と結合したデータ＝復元対象。迷ったらスナップショット側という規約どおり）。
- **`exportBundle`/`importBundle`**: `Session` 内なので変更不要。
- **画像 GC**: 無関係。`sessionImageIds`/`collectUsedImageIds` に足さない。
- **persist**: `Scene`・`UiPrefs` への optional 追加のみなので **persist キーは据え置き**（クリーンブレイク不要）。`normalizeUiPrefs` に `ambientEnabled`/`ambientVolume` を追加（欠落補完＋クランプ）。
- **`AGENTS.md` を同一コミットで更新**: データモデル節（`AmbientPin`/`Scene`/`UiPrefs`/`AmbientSoundDef`）・ディレクトリ節（`ambientAudio.ts`/`ambientSounds.ts`/`AmbientPinModal.tsx`）・実装状況節・規約節（「ピンは imageId を持たない＝GC 集合に足すな」「行アンカーのマーカー差し込みは3か所・増やしたら全部直す」）。

## 9. 実装フェーズ（AM1 → AM2 → AM3 固定）

- **AM1 — 基盤（音が鳴るまで）**: 型追加／`ambientSounds.ts`（カタログ＋glob。音源は暫定数本）／`ambientAudio.ts`／store の `addAmbientPin`・`updateAmbientPin`・`removeAmbientPin`／`useAmbientScape`（ティック・targets 計算）／マーカー差し込み3か所＋CSS／`ReaderSettings` の ON/OFF と音量。追加 UI は最小（音を1つ選んで置けるだけ）。
  → これだけで**「そもそも面白いか」の粗い検証ができる**。
- **AM2 — UI 仕上げ**: `AmbientPinModal` 完成（段落選択・カタログ・試聴・半径）／ガターマーカーのポップオーバー／解錠の案内トースト／System のクレジット節。
- **AM3 — 音源セット投入と体感チューニング**: 残りの音（計20〜30本）を投入／`RATE`・カーブ指数・同時発音数・既定半径の実プレイ調整／System のクレジット節。当たれば拡張（カーブ編集・LLM 自動提案・共有）を別途検討。

音源調達（[`環境音_音源調達リスト.md`](./環境音_音源調達リスト.md)）は**この3フェーズと非同期に進める**。カタログはファイルが無い id を落とすので、音源0本でも AM1・AM2 は完成でき、★8本が届いた時点で体感検証に入れる。

## 11. 却下・保留した案（蒸し返さない）

| 案 | 却下/保留理由 |
|---|---|
| **DOM Range ＋ 文字オフセット**（要望書 候補A） | 構造化出力ではレンダリング後テキストが原文と一致しない（`@名前(感情)` が剥がれる・dialogue 行に `\n` が無い）ため文字位置の対応が崩れる。加えて行より細かい精度は Y に反映されない |
| **メッセージ高さの比例補間で Y を出す**（レンダラ無改修） | 実装は最小だが、ガターマーカーが狙った段落と別の場所に描かれる＝見た目で壊れて見える |
| **手続き的合成**（Web Audio のノイズから雨・風を作る／アセット0・ライセンス0） | 蝉・雑踏が作れず音質天井が低い。「そもそも面白いか」の検証を音質不足で汚すのは本末転倒。将来のフォールバックとして保留 |
| **`<audio loop>` で再生** | ループ継ぎ目のギャップ・多重音量制御の粗さ |
| **ピンごとに1声** | 同じ音のピンが近接すると二重再生で音量が跳ねる。`soundId` ごとに1声＋max に畳む |
| **半径を px で持つ** | ウィンドウサイズ・文字サイズでピークの体感幅が変わる。viewport 高さの倍数で持つ |
| **ピンをカセットに載せる** | `freshSessionOf` が `scenes` を作り直し、導入文の message id も開始時に新規発行されるため v1 では原理的に不可。当たってから設計する |
| **BGM / LLM 自動配置 / カーブ描画 / 音源持ち込み** | 要望書 §3.2・§7 のまま非スコープ |
