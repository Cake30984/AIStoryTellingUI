# 設計: 画像改善 V5 — V4 不具合修正とステージのバックドロップ化

V1〜V4（`docs/設計_画像改善_立ち絵と生成ジョブ.md`）実装後の実使用フィードバックと実装調査に基づく修正フェーズ。
**実装は V5a → V5b → V5c の順**。各フェーズごとに tsc → build → Preview 検証 → CLAUDE.md 更新 → commit → push（既存の進め方と同じ）。

## 背景（ユーザー報告 2026-07-04）

1. **［バグ］** キャラクターの立ち絵に画像をセットした後、エディタの「保存」を押して開き直すと立ち絵が消えている。
2. **［UX］** 生成した背景画像が 🎭 ボタンを押さないと見えない。チャットの文字の背景として、読みづらくならない程度に薄く常時表示したい。
3. **［UX］** 立ち絵がいつどこに表示されるのか分かりにくい。これも背景の上に薄く表示し、複数キャラは重ならないように並べたい。

## 調査で確認した不具合の全リスト（原因つき）

| # | 重大度 | 症状 | 原因 | 修正フェーズ |
|---|---|---|---|---|
| A-1 | **高（報告済み）** | 保存を押すと立ち絵が消える | `CharacterEditor` は draft（開いた時点のスナップショット）を `upsertCharacter(d)` でキャラ**全体置換**する。立ち絵は `setCharacterSprite`／`applyImageJobResult` が store を**直接**書くため、保存でスナップショット時点の `sprites` に巻き戻る。さらに「✕ 外す」→保存では、`deleteImage` 済みの旧 imageId を参照する sprite が**復活**する（壊れた参照） | V5a |
| A-2 | 高 | dismiss された実行中ジョブが裏で生成を続ける | `runImageJobLoop` の中断判定が `find(...)?.status === 'canceled'` のみ。ジョブが一覧から消えると `undefined ≠ 'canceled'` でループが**継続**し、APIを count 枚ぶん叩き続ける。`dismissImageJob` も abort しない | V5a |
| A-3 | 中 | シーンが変わっても前シーンの表情を引きずる／マーカーが判定材料に混ざる | `classifyEmotions` は直近3メッセージをマーカー疑似メッセージ（`CONTINUE_PROMPT`/`SCENE_START_PROMPT`）込みで送る。また `spriteEmotions` はシーン確定時にリセットされない | V5a |
| A-4 | 中 | 立ち絵モーダルで「✨ 起案」すると表情タグ・構図タグ・LoRA トリガーが消える | 起案結果が prompt 欄を**全文置換**する。`spritePrompt()` が組んだ `{imagePrompt}, {感情tags}, standing, upper body, ...` が失われ、「怒り」の立ち絵が怒っていない画像になり得る | V5c |
| A-5 | 中 | モーダルを開いた直後の生成でネガティブにスタイルタグが入らない | `ImageGenModal` のマウント時 prefill は prompt のみ（[ImageGenModal.tsx:60-64](../src/components/ImageGenModal.tsx)）。negative は `useState('')` のままで、スタイルを選び直すまで品質ネガティブが効かない | V5c |
| A-6 | 低 | ギャラリーに背景が出ない | V3 設計の「V4 実装後は `scene.backgroundImageId` も並べる」が未実装 | V5b |
| A-7 | 低 | 一括生成の接続先が `imageProviders[0]` 固定・二重起動可能 | `SpriteSetField.batchGenerate` 参照。接続先を選べず、⚡ 連打で 12 ジョブ走る | V5c |

UX 要望 2・3 は「**ステージ帯（260px の別枠）をやめ、チャット背面のバックドロップに変える**」ことで一括対応する（V5b）。

## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| sprites の所有権 | **store 直接管理のフィールドとし、`upsertCharacter` は既存キャラの `sprites` を常に store 側の値で保持**（draft の値を無視） | 書き手を `setCharacterSprite`/`applyImageJobResult` の2箇所に限定すれば、どのエディタ実装でも巻き戻り事故が構造的に起きない。エディタ側のマージ修正だと将来の別エディタで再発する |
| ステージの表示方式 | 独立した 260px 帯を廃止し、**チャット領域の背面レイヤー（バックドロップ）**に背景と立ち絵を薄く敷く | 報告 2・3 に直接対応。本文と同じ視界に常在させる |
| 🎭 トグルの既定値 | `session.spritesEnabled ?? true`（**未設定は ON**）。明示 OFF のみ非表示 | 背景・立ち絵が無ければバックドロップは何も描画しないため、既定 ON でも既存セッションの見た目は変わらない。「生成したのに見えない」を解消 |
| 背景生成ボタンの場所 | StageBar 内の 🏞 を**ChatPanel トップバーへ移設**（🎨 の隣） | 🎭 OFF でも背景を生成できる。バックドロップは `pointer-events: none` の表示専用にする |
| 薄さの調整 | CSS 変数 `--stage-bg-opacity: 0.25` / `--stage-sprite-opacity: 0.5` に集約 | 読みやすさの微調整を1箇所で行える。将来 UI スライダー化も容易 |
| 複数キャラの非重複 | 等分フレックスセル方式（キャラ数で横幅を等分し、各セル内に `object-fit: contain` で収める） | 何人でも数学的に重ならない。折返し・座標計算が不要 |
| 立ち絵フォールバック | 現在感情 → neutral → **最初に見つかった立ち絵** | 1枚でも立ち絵があれば表示され、機能の存在が分かる |
| シーン確定時の表情 | `confirmSceneReview` で `spriteEmotions: []` にリセット（＝neutral 相当へ） | シーンは時間・場面が飛ぶため前シーンの表情持ち越しは不自然 |
| 起案とタグの共存 | `ImageGenModal` に `pinTags`（起案後も必ず維持するタグ）を追加。**起案直後のみ**欠けたタグを末尾に補う | 手入力での削除は尊重しつつ、LoRA トリガー・表情タグの消失だけ防ぐ |

### 既知の制約（今回は対応しない・報告時に説明すること）

- 生成立ち絵は SD が透過 PNG を出せないため「背景つきの矩形」になる。バックドロップ上では低不透明度の矩形カードとして見える。**手動アップロードなら透過 PNG がそのまま使える**（`normalizeImage` は canvas → PNG 変換で α を保持する）。自動背景除去（rembg 等）は将来フェーズ。
- 背景の自動生成（シーン開始時）は引き続きやらない（V4 決定を維持）。

### V5b-1. StageBar → StageBackdrop（表示専用コンポーネント）

`src/components/StageBar.tsx` を削除し、`src/components/StageBackdrop.tsx` を新設する。**背景生成モーダルは持たない**（V5b-3 で ChatPanel へ移す）。Props は同じ `{ session, scene, participants }`。

```tsx
import type { Character, Scene, Session } from '../types'
import { useImageUrl } from '../lib/imageStore'

/** 現在感情 → neutral → 最初の1枚 の順で立ち絵を選ぶ（A-8: 1枚でもあれば表示） */
function spriteImageOf(c: Character, session: Session): string | undefined {
  const emotion = session.spriteEmotions?.find((e) => e.characterId === c.id)?.emotion ?? 'neutral'
  return (
    c.sprites?.find((s) => s.emotion === emotion)?.imageId ??
    c.sprites?.find((s) => s.emotion === 'neutral')?.imageId ??
    c.sprites?.[0]?.imageId
  )
}

function BackdropImg({ imageId, className }: { imageId: string; className: string }) {
  const url = useImageUrl(imageId)
  if (!url) return null
  return <img src={url} alt="" className={className} />
}

interface Props {
  session: Session
  scene?: Scene
  participants: Character[]
}

/** チャット背面のバックドロップ（V5b）。背景と立ち絵を薄く敷く。表示専用・クリック不可 */
export default function StageBackdrop({ session, scene, participants }: Props) {
  const chars = participants
    .map((c) => ({ id: c.id, imageId: spriteImageOf(c, session) }))
    .filter((x): x is { id: string; imageId: string } => !!x.imageId)
  if (!scene?.backgroundImageId && chars.length === 0) return null
  return (
    <div className="stage-backdrop" aria-hidden>
      {scene?.backgroundImageId && (
        <BackdropImg imageId={scene.backgroundImageId} className="stage-backdrop-bg" />
      )}
      {chars.length > 0 && (
        <div className="stage-backdrop-sprites">
          {chars.map(({ id, imageId }) => (
            <div className="stage-backdrop-cell" key={id}>
              {/* key=imageId で表情切替時に再マウント→フェードイン */}
              <BackdropImg key={imageId} imageId={imageId} className="stage-backdrop-sprite" />
            </div>
          ))}
        </div>
      )}
    </div>
  )
}
```

## V5c: 生成体験の改善（A-4・A-5・A-7）

### V5c-1. `ensureTags` ヘルパと `pinTags`（A-4）

`src/lib/imagePresets.ts` に追加:

```ts
/**
 * prompt に pins のタグ（カンマ区切り）が欠けていれば末尾に補う。
 * 比較はトークン単位の完全一致（trim・小文字）。applyStylePreset と同じ規約。
 * 起案（LLM）がプロンプトを全文置換した際に、LoRA トリガー・表情タグ等の
 * 固定タグが消えるのを防ぐために使う。
 */
export function ensureTags(prompt: string, pins: string): string {
  const have = new Set(
    prompt.split(',').map((t) => t.trim().toLowerCase()).filter(Boolean),
  )
  const missing = pins
    .split(',')
    .map((t) => t.trim())
    .filter((t) => t && !have.has(t.toLowerCase()))
  if (missing.length === 0) return prompt
  return prompt ? `${prompt}, ${missing.join(', ')}` : missing.join(', ')
}
```

`ImageGenModal` に Props `pinTags?: string` を追加し、**`draft()` の適用箇所のみ**で使う（手動編集・スタイル切替では適用しない）:

```ts
const applied = applyStylePreset({ prompt: draftedPrompt, negative: draftedNegative }, styleId)
setPrompt(pinTags ? ensureTags(applied.prompt, pinTags) : applied.prompt)
setNegative(applied.negative)
```

呼び出し元:
- `SpriteSlot`（SpriteSetField.tsx）: `pinTags={spritePrompt(imagePrompt, emotion)}`（LoRA トリガー＋表情タグ＋構図タグを保証）。
- `AvatarField`: `pinTags={genContext.imagePrompt}`（undefined 可）。
- 挿絵・背景は指定しない。

### V5c-2. negative のマウント時 prefill（A-5）

`ImageGenModal` の negative 初期値を prompt と同様にする:

```ts
const [negative, setNegative] = useState(() =>
  (lastImageStyle ?? '')
    ? applyStylePreset({ prompt: '', negative: '' }, lastImageStyle ?? '').negative
    : '',
)
```

### V5c-3. 接続先・起案モデルの記憶（A-7 の一部＋利便性）

store に永続化フィールドを2つ追加（optional・**partialize に追加**・persist キーは v3 のまま）:

```ts
/** 最後に画像生成で使った接続先（ImageGenModal・一括生成の初期値） */
lastImageProviderId?: string
setLastImageProviderId: (id: string) => void
/** 最後に起案に使ったモデル（"providerId::modelId"） */
lastDraftModel?: string
setLastDraftModel: (ref: string) => void
```

- `ImageGenModal`: `providerId` 初期値を `imageProviders.some((p) => p.id === lastImageProviderId) ? lastImageProviderId! : (imageProviders[0]?.id ?? '')` に。`generate()` 成功パスで `setLastImageProviderId(provider.id)`。`draftModel` 初期値を `lastDraftModel || draftContext?.modelRef || ''` に。ModelPicker の `onPick` で `setLastDraftModel(ref)` も呼ぶ。
- `SpriteSetField.batchGenerate`: `imageProviders[0].id` 固定をやめ、同じ解決（lastImageProviderId が有効ならそれ、無ければ先頭）を使う。

const batchRunning = useStore((s) =>
