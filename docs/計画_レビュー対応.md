### 0.2 進め方
1. §1 の状態表で担当フェーズが「未着手」または「進行中」で、**§2 の承認が必要な項目が承認済み**であることを確認する。未承認なら着手せずユーザーに聞く

5. 完了条件をすべて満たしたら「終了時の作業」を行う

### 0.3 終了時の作業（必須）
- §1 の状態表を更新（状態・日付・最後のコミット）
- 担当フェーズの末尾 **「引き継ぎ」** に **10行以内**で書く: 変えたこと／残したこと／次のフェーズが踏みそうな罠。長い説明は書かない（差分は git にある）

### 0.4 途中で止まるとき
- コンテキストの半分を使っても完了条件に届かないなら、**緑の状態でコミットして**「引き継ぎ」に現在地を書き、状態表を「進行中（引き継ぎあり）」にして終わる

## P2b. 品質基盤②: 描画の購読最適化

**目的**: ストリーミング1チャンクごとの全コンポーネント再描画をやめる。
**承認**: 不要。**依存**: P2a（テストがある状態で）。

**読む範囲**: `useStore()` をセレクタ無しで呼ぶ35箇所（`grep -rn "useStore()" src/components`）／`ChatPanel.tsx` の `renderMessage`・`renderSceneContent`・`session.scenes.map`／`StructuredMessage.tsx`／`ContextDock.tsx`／`Sidebar.tsx`／`ActivityIndicator.tsx`。

**やること**
1. 各コンポーネントの `useStore()` を**必要なスライスだけのセレクタ**に置き換える（`useShallow` で複数）。アクションは `useStore.getState()` 経由か個別セレクタで取る
2. `ChatPanel` の本文描画を分割: シーンごと・メッセージごとのコンポーネント化＋`React.memo`。ストリーミング中に再描画されるのは**末尾の pending メッセージだけ**にする
3. `session.scenes.map(sc => session.messages.filter(...))` を `useMemo` で1回の走査（sceneId → messages の Map）に
4. `parseStructured` の結果をメッセージ単位でメモ化（content と participants が同じなら再パースしない）
5. 計測: 30シーン・600発言程度のセッションを seed し、ストリーミング中の React Profiler で「1チャンクあたりの commit 数」を before/after で記録して「引き継ぎ」に書く
