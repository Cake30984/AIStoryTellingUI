### 思考モデルの `max_tokens`（2026-08-15 の実測で判明）

`qwen3:8b` は **推論部分（`reasoning_content`）を別チャンネルで出し、それも `max_tokens` を食う**
（実測: 本編で 658 字、画像プロンプト起案で 1,462 字）。上限が足りないと `finish_reason: length` で
**JSON が途中で切れる**。このとき HTTP は 200 なので `openrouter.ts` の降格は発動せず、
`extractJson` の修復も途中終了は直さない＝**裏方の呼び出しが黙って失敗する。**

さらに厄介なのは、これが **「ローカルは構造化出力に非対応」と誤読される**こと。
実際はスキーマは効いており、足りないのは出力上限だけ（`r5check.mjs` は T8 の備考でこれを区別する）。

- [ ] 裏方4種の `max_tokens` 設定を確認する。**2000 でも画像プロンプト起案は切れた**実測がある — 未確認（今回はセッションの `maxTokens`＝32,768（既定）のまま使用し、レビュー・次シーン候補・選択肢はすべて完走した＝**この上限では切れなかった**が、2000 のような低い上限での再現試行はしていない。画像プロンプト起案は画像接続先未設定のため試せていない）
- [ ] 上限を上げて解決するのか、思考しないモデル／設定に寄せるのかを決める（未着手）

## 3. ネットワークを切った状態での通し ★R5' の核心

> **未実施（2026-08-16）。ユーザーの手動実施が必要。** Claude Code はこのセッションでは
> ブラウザ操作（Web 開発ビルド）でしかアプリを動かせず、実行環境のネットワークアダプタを
> 物理的に切断する手段を持たない。0〜2章の「Ollama 経由なら通る」ことは実機で確認したが、
> それは**Wi-Fi/有線が生きたまま localhost だけを使った**結果であり、この章が要求する
> 「外部への経路そのものが無い状態」の証明にはならない。DLsite への反論材料として使うには、
> 下記手順をユーザー自身の PC で機内モード等にして実施する必要がある。

**DLsite の「メインコンテンツがインターネットに接続する必要のある作品」への反論材料はここだけで作られる**
（`公開計画_マネタイズと配布.md` §1.8-③）。ここが通らないなら R5' の主張はできない。

手順:

1. Wi-Fi / 有線を**物理的に切る**（機内モードでよい。`localhost` は残る）
2. デリストを起動する
3. 新規セッションを作り、3シーン分を最後まで進める

- [ ] 起動する（起動時に外部へ取りに行って待たされないか＝R9 の更新通知を入れる時はここに影響する）

- [ ] 選択肢・レビュー・次シーン候補が通る

- [ ] チェックポイントの記録と復元が通る
- [ ] 書き出し（カセット・バンドル）が通る
- [ ] **DevTools の Network に localhost 以外への通信が1本も出ない**（これが証拠になる）
  - フォント・アイコン・解析など、気付かずに外部を叩いている箇所が無いかを同時に洗う

> 画像生成は別プロバイダ（ComfyUI ならローカル、それ以外は外部）。
> **「本編の全機能」と「画像生成」は分けて書く**。混ぜると主張が過大になる。

## 4. 性能の実測（案内文の根拠）

R5 は利用者に「数GBのダウンロードとPC性能が必要」と案内する。**その数字の裏付けを取る。**

**実機で測定（2026-08-16。GPU: NVIDIA GeForce RTX 3060 12GB・モデル: `qwen3:8b`）：**

| 測るもの | 値 |
|---|---|
| 初回トークンまで（本編・短いプロンプト） | 約 2.6 秒（`stream:true` で最初の delta までを直接計測） |
| 生成速度（tok/s） | 約 37 tok/s（`stream:false`・completion 610 トークン／16.4 秒で算出） |
| 1ターンの体感（本編＋選択肢、アプリ内） | 実プレイでは8〜20秒程度（システムプロンプト＋履歴を含む実際の文脈量・thinking のオーバーヘッド込み。ブラウザでの目視待ち時間） |
| シーン終了レビューの待ち時間（A/B並列） | 約20秒前後（2本並列実行・両方完了までの目視待ち時間） |
| VRAM 使用（`nvidia-smi`） | 9,914 MiB / 12,288 MiB（Ollama 常駐時。他プロセスの使用分を含む合算値のため、`qwen3:8b` 単体の占有量ではない点に注意） |

**注意：** 上の tok/s・初回トークン計測は `curl` 相当の直接リクエスト（システムプロンプト無し・短い履歴）によるもので、
**実際のゲームプレイ（長い system プロンプト＋履歴＋JSON スキーマ強制）はこれより遅くなる。** 「1ターンの体感」の
行がアプリ内の実測に近い。より精密な計測（複数ターンの平均・履歴が伸びた状態での比較）は未実施。

- [ ] 「実用に耐える／耐えない」の線をどこに引くかを1行で書く — **今回のデータからの暫定所見**：
      8B 級モデル・RTX 3060（12GB）で「1ターン数秒〜20秒程度」は待てる範囲だが、テンポの良さを売りにする
      本アプリの体験としては「サクサク」とは言えない。案内文の「数GBのダウンロードとPC性能が必要」は
      裏付けが取れている。より小さい/量子化の進んだモデルでの追加計測、複数ターン後（履歴が伸びた状態）の
