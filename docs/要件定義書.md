# デルシア 要件定義書（現行機能）

## 1. 文書の目的
利用者から見て「何ができるか」を、実装方式に触れずに定義する。**2026-09-13 時点で実現済みの機能**を対象とし、F1〜F6（`設計_物語の簡素化.md`）で撤去された機能は含まない。今後の変更計画は `計画_レビュー対応.md`。

## 2. システム概要
利用者が用意した LLM（OpenRouter・OpenAI 互換 API・ローカルモデル）を使い、**自動で進む物語を読む**（物語モード）または**キャラクターと会話する**（ロールプレイモード）ためのデスクトップアプリ（Windows）。キャラクター・世界観は再利用可能な素材として管理し、物語は「シーン」の連なりとして進む。シーンを終えるたびに要約・関係性・時間と予定が引き継がれ、長い物語でも一貫性を保つ。生成した物語は分岐して読み比べたり、文章として書き出したりできる。

## 3. 用語
| 用語 | 定義 |
| --- | --- |
| セッション | 1つの物語／会話の単位。会話履歴・設定・状態を持つ |
| キャラクター | 登場人物の設定。再利用可能な素材。中心人物もその1人 |
| 中心人物 | 物語モードでは視点人物、ロールプレイでは利用者が演じる人物。関係性はこの人物に向けて記録される |
| 世界観 | 舞台設定。常時参照される概要と、キーワードで参照されるロア、関係性の次元、開始テンプレートからなる |
| シーン | 物語の一区切り。状況メモ・要約・時点・挿絵・幕間を持つ |
| レビュー | シーン終了時に要約・次の方向・成長・関係性・時間と予定をまとめて確認する工程 |
| 予定 | 「いつ・何が」の形でこれから起きること。レビューが追加・消化する |
| 分岐 | 任意の地点から別の展開を生成し、木構造で保持すること |
| カセット | 世界観・登場キャラ・開始設定を1枚にまとめた配布単位。取り込むとすぐ遊べる |

## 4. 対象利用者
- AI が書く物語を、自分の設定した世界と登場人物で読みたい人
- キャラクターとの会話を楽しみたい人
- 素材（キャラ・世界観）を蓄積し、繰り返し物語づくりに使いたい人

## 5. 機能要件

### 5.1 接続先とモデル
- FR-1: 初回起動時のウィザードで、OpenRouter（ブラウザ承認またはキー貼り付け）・Gemini 無料枠・ローカルモデル（Ollama / LM Studio）のいずれかを選び、接続テストを経て開始できる。
- FR-2: 複数の接続先を登録・切替でき、接続先ごとにモデル一覧を取得してお気に入り登録できる。
- FR-3: 本編用モデルとは別に、補助処理（レビュー・選択肢）用のモデルをセッションごとに指定できる。未指定なら本編用モデルを使う。
- FR-4: 新しい物語の既定モデルを設定できる。
- FR-5: デスクトップ版では API キーを OS の資格情報ストアに保存し、設定ファイルに平文で残さない。

### 5.2 素材の管理
- FR-6: キャラクター（名前・人格・口調・外見・セリフ例・最初のセリフ・アバター・タグ・画像生成用タグ）を作成・編集・複製・削除できる。
- FR-7: 世界観（概要・ロア・関係性の次元・暦の書き方・開始テンプレート）を作成・編集・複製・削除できる。
- FR-8: ロアは「常時参照」と「キーワード一致時のみ参照」を項目ごとに選べ、有効／無効を切り替えられる。
- FR-9: 開始テンプレートに、ジャンル・あらすじ・導入文・置換タグ・最初の方向付け・開始シーンの状況・新キャラの登場方針・固定メモ・開始時点の日時・最初から控えている予定を定義でき、世界を選んだセッションへコピーされる。
- FR-10: キャラクター・世界観を PNG カードとして書き出し・読み込みできる（キャラカードは一般的な互換形式）。
- FR-11: 素材の一覧で検索・複数選択・一括削除ができる。

### 5.3 セッションの構成
- FR-12: 物語モードまたはロールプレイモードでセッションを作成し、一覧から再開・アーカイブ・削除できる。
- FR-13: セッションに参加キャラクター（複数可）・世界観・中心人物（必須）・固定メモを設定できる。
- FR-14: 物語モードでは、ジャンル・あらすじ・導入文（そのまま掲載）・置換タグの対応付け・最初の方向付けを設定できる。
- FR-15: 文体（小説形式／会話劇）と、セリフの構造化出力（話者ごとの行表示）を選べる。
- FR-16: 未定義の新しい人物を AI が登場させてよいかを設定できる。

### 5.4 物語の進行（物語モード＝読者モデル）
- FR-17: 「続ける」で入力なしに次を書かせられる。応答は逐次表示され、途中で停止できる。
- FR-18: 「もっと詳しく」「先へ飛ばす」で尺を指示できる。
- FR-19: 気に入らない応答を再生成できる。任意の入力は「書き手への指示」として渡され、物語本文としては扱われない。
- FR-20: 「展開を選ぶ」で次の展開の候補を出させ、選んで続けられる。
- FR-21: 上限到達で切れた応答の続きを生成できる。
- FR-22: 過去の発言を編集・削除・任意地点から作り直しできる。

### 5.5 ロールプレイモード
- FR-23: 利用者は中心人物として発言・行動を入力し、AI は他のキャラクターとして応答する。
- FR-24: 入力を「演じて書く」と「書き手に指示」で切り替えられる。
- FR-25: 複数キャラクターの会話では次に話すキャラクターを指定するか、AI に任せられる。

### 5.6 シーンと引き継ぎ
- FR-26: 物語はシーン単位で管理され、各シーンに状況メモ（時・場所・居合わせる人物）を持つ。
- FR-27: シーンを終えると、要約・次のシーンの方向の候補・キャラクターの成長案・世界設定の追加案・関係性と気分の更新・新しい登場人物・時間と予定の更新を、1つの確認画面でまとめて確認・編集・承認できる。
- FR-28: 承認した成長・追加設定は素材そのものではなくセッション内の「発見」として積まれ、必要なら素材へ昇格できる。
- FR-29: 過去のシーンの会話は折りたたまれ、要約が以後の進行に引き継がれる。要約は後から編集・再生成できる。
- FR-30: 全シーンの要約を時系列で通読・コピーできる。
- FR-31: 現在のシーンの本文の分量が文字数で表示され、締め時の目安が示される。

### 5.7 時間・予定・関係性
- FR-32: 現在の日時・場所・居合わせる人物・状況が、シーンを終えるたびに AI によって更新される。日時の書き方は自由で、世界観の「暦の書き方」に体裁が揃う。
- FR-33: 「いつ・何が」の予定を AI が追加・消化し、利用者は一覧で確認できる。予定は本文に直接は渡されず、その場面に関わる一文だけが反映される。
- FR-34: 参加キャラクターから中心人物への関係性が、世界観で定めた次元ごとに文章で記録・表示され、利用者が手で編集できる。

### 5.8 終わり方と幕間
- FR-35: いつでも「終わり方を考える」で複数の結末案を出させ、目標として保持する／その場で確定してエピローグを書かせる／何も選ばない、を選べる。
- FR-36: 確定後は進行系の操作が閉じ、分岐で戻れば未確定に戻る。
- FR-37: 終了したシーンについて、中心人物以外の視点で同じ場面を描き直した「幕間」を生成できる。幕間は本編に影響せず、気に入った解釈だけ関係性へ反映できる。

### 5.9 分岐とチェックポイント
- FR-38: 生成・編集・シーン終了のたびに自動でチェックポイントが記録される。
- FR-39: 分岐ツリーで全経路を俯瞰し、行をクリックしてその地点を読みに行ける。
- FR-40: 任意のメッセージまたはツリー上の地点から名前付きの分岐を作って続けられる。
- FR-41: しおり（名前・サムネイル）を付けられ、不要な枝の削除・現在の分岐だけ残す整理ができる。

### 5.10 挿絵と画像
- FR-42: 画像生成の接続先（OpenRouter・ComfyUI・OpenAI 互換）を登録し、接続テストできる。
- FR-43: 本文の任意の位置やキャラクターのアバターに、プロンプトを AI に起案させて画像を生成・採用できる。生成は背景で進み、候補から選んで採用する。
- FR-44: 採用した挿絵はギャラリーとセッションの永続記録で一覧でき、同じプロンプトで再生成できる。
- FR-45: どこからも参照されない画像をまとめて回収できる。
- FR-46: 生成コストは実測値がある場合に、そのサービスの課金単位で表示される。

### 5.11 読書環境
- FR-47: 文字サイズ・行間・本文幅・話者アイコンの大きさ・セリフの色分け・没入モードを調整できる。
- FR-48: （撤去済み。2026-09-13 に環境音ピンを廃止）
- FR-49: コマンドパレットとキーボードショートカットで主要操作へ移動できる。

### 5.12 書き出しと共有
- FR-50: 物語をプレーンテキスト／Markdown／挿絵つき Markdown で書き出せる。特定の分岐時点のものも書き出せる。
- FR-51: タイトル・抜粋・挿絵を1枚に合成した画像（共有用カード）を作れる。
- FR-52: セッションからカセットを作成し、PNG として書き出せる。カセットを取り込んで棚に置き、そこから新しいセッションを開始できる。
- FR-53: 全データを JSON（画像同梱可）で書き出し、読み込んで統合できる。

### 5.13 データの保全
- FR-54: 素材・セッション・分岐・画像は継続的に保持され、再起動後も引き継がれる。
- FR-55: 保存形式には版番があり、新しい版で古いデータを読むと自動で移行される。読めないデータは上書きせず、保存場所を案内して停止する。

## 6. 非機能要件
- NFR-1（応答性）: 生成は逐次表示され、中断できる。
- NFR-2（コスト配慮）: 補助処理を別モデルに分けられ、過去シーンは要約に圧縮され、対応モデルではプロンプトキャッシュが効く構造で送られる。
- NFR-3（可搬性）: データは利用者のフォルダに置かれ、フォルダのコピーでバックアップ・移行できる。
- NFR-4（プライバシー）: 当方のサーバーは介在しない。生成は利用者が選んだ提供元へ直接送られ、ローカルモデルなら外部送信なしで動く。
- NFR-5（一貫性）: 世界観・キャラクター・固定メモ・過去の要約・関係性・時間と予定を踏まえて生成する。

## 7. 制約・前提
- 生成には利用者が用意する LLM の接続先が必要で、提供元の料金が発生しうる。
- 正式版は Windows のデスクトップ版。Web 版は同じ機能を持つが保存先がブラウザ内になる。
