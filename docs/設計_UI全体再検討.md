# 設計 — UI 全体の 0 ベース再検討

**ステータス: 検討ドキュメント（未実装・未合意）** — 2026-07-09 作成。

このドキュメントは「機能を足すためのUI改修」ではなく、**システム全体のUIを 0 ベースで問い直した検討結果**をまとめたもの。実装は一切行っていない。§8「未決事項」にユーザーの選択待ち質問を列挙しており、合意後に §7 のロードマップ（UI-0〜UI-7）へ分割して着手する想定。

- 検討方法: 2026-07-09 時点の全UIコード（`src/App.tsx`・`src/components/**`・`src/index.css`・`src-tauri/tauri.conf.json`）を実際に読み、数値（モーダル数・ボタン数・CSS行数等）はコードから採取した（出どころは §9 付録）。
- 位置づけ: 既存の設計書（`設計_画像改善_*` 等）が「個別機能の設計」なのに対し、本書は**横断レイヤ（情報設計・レイアウト・視覚言語・操作系）の設計**を扱う。

## 1. 前提の再確認 — このUIは何に仕えるか

### 1.1 プロダクトの本質

本アプリの主役は**本文（物語のテキスト）**である。ユーザー（作者＝プレイヤー＝読者が同一人物）は1回数時間単位でアプリに滞在し、次の4つの活動を行き来する:

| 活動 | 内容 | 主な現行UI |
|---|---|---|
| **遊ぶ／読む（Play）** | 会話・自動進行・選択肢・シーン進行。滞在時間の大半 | ChatPanel |
| **作る（Author）** | キャラ・世界観・ペルソナ・演出の素材づくり | 各 Library / Editor |
| **振り返る（Archive）** | あらすじ・状態・発見・画像・分岐という「蓄積」を眺める | 📜📊📖🖼🕘 の各モーダル |
| **整える（System）** | プロバイダ・画像接続先・データ入出力 | SettingsModal |

UIの仕事はこの順に、(a) 本文を最良の状態で読ませる、(b) 物語を進める操作を迷いなく提供する、(c) 世界を作る作業を快適にする、(d) 蓄積を資産として見せる、こと。

**現状のUIは (b)(c) に偏っており、(a)(d) への投資が薄い。** これは欠陥というより履歴の産物 — 機能追加のたびに「絵文字ボタン＋モーダル」を線形に足してきた結果が、そのまま形になっている。

### 1.2 利用文脈

- デスクトップ（Tauri 正式版・Windows・1280×800既定）。Web 版は開発検証用。
- 単一ユーザー・ローカル完結。共有・マルチテナント・レスポンシブ（モバイル）は要件でない。
- 長文の日本語テキストを長時間読む。夜間利用が主と想定（現行ダークテーマ）。

### 1.3 変えない制約（本書のスコープ外）

- 技術スタック維持: React + zustand + **手書きCSS・依存最小**（UIライブラリ導入はしない。§6 ADR-UI-3）。
- データモデル・persist スキーマは表示レイヤの都合で壊さない（UI設定の **optional 追加**は可＝persist キー v3 のまま）。
- 日本語UI・`platform.ts` への環境差集約・graceful degradation 等の既存規約はすべて維持。

## 2. 現状インベントリ（2026-07-09 のコード実態）

### 2.1 レイアウト骨格

- **2カラム固定 grid**（サイドバー 280px ＋ メイン）。右パネルは存在しない。
- `@media` クエリ **0件**（レスポンシブ処理なし）。Tauri 窓は 1280×800・**最小サイズ未設定**（極端に縮めるとレイアウト破綻を防ぐ仕組みがない）。
- メイン領域は view（`sessions | characters | worlds | personas | sceneTypes` の5種）で全面切替。

### 2.2 ナビゲーション

- サイドバー: ブランド → 5ビューの2列グリッドボタン（5個なので最終行が1個で欠ける）→「＋ロールプレイ／＋物語」→ **セッション一覧（素材ビュー中も常時表示）** → フッタ「⚙ 設定・データ管理」。
- セッション一覧・素材一覧とも**検索・並べ替え・アーカイブ機能なし**。件数が増えるとスクロールだけで探すことになる。

### 2.3 モーダル依存

- `.overlay`（モーダル）使用は **18ファイル・22箇所**。ChatPanel から開くものだけで 12種（ModelPicker / SessionEditor / SceneEditor / StoryLog / StatusPanel / DiscoveryPanel / Gallery / BranchTree / ImageGen(挿絵) / ImageGen(背景) / ImageJobsPanel / 画像ズーム）。
- **全モーダルがオーバーレイクリックで即閉じる。** draft 方式のエディタ（SessionEditor・CharacterEditor・WorldEditor・PersonaEditor・SceneTypeEditor・SceneEditor）では**編集内容が確認なしで破棄**される。SceneReviewModal も同様で、こちらは**生成済みレビュー（トークンを消費して作ったもの）が誤クリック1回で消える**。
- `Escape` でモーダルを閉じる処理・フォーカストラップは**なし**（`Escape`/`addEventListener` の検索ヒット0件）。
- 確認・入力はネイティブ `confirm()`/`prompt()` が **16箇所**（削除確認・しおり名入力等）。アプリのトーンと無関係な OS 素のダイアログが混ざる。
- モーダル幅は 560px（wide 680px）・max-height 86vh。**WorldEditor（728行・ロア/イベント/関係軸/スタット/カウンター/実績の6セクション＋条件ビルダー）もこの幅に押し込まれている。**

### 2.4 ChatPanel（中核画面）の密度

- **トップバー**: タイトル入力＋モデルチップ＋絵文字アイコンボタン最大11個（📜 📊 📖 🖼 🕘 🎭 🎨 🏞 ⏳ ⚙ 🗑）。意味の手掛かりはホバーの `title` 属性のみ（計55箇所）。
- **コンポーザー**: 最大6段の積層 — シーンバー（タイトル・登場・トークンバッジ・シーン編集・シーン終了）／話者選択チップ列／story-actions（続ける・やり直す等）／選択肢ボタン列／入力欄／ヒント行。
- **本文**: max-width 760px 固定・本文 15.5px/行間1.9 固定。**フォントサイズ・行間・本文幅・テーマのユーザー設定は一切ない。**
- ステージ（背景・立ち絵）は本文背面に固定透過度（背景0.25・立ち絵0.5）で表示。**濃度調整UIなし**（CSS変数を直接書き換えるしかない）。

### 2.5 視覚言語

- **ダークテーマ固定**（`color-scheme: dark` ハードコード）。
- CSS カスタムプロパティは**16個のみ**（bg系3・text系3・accent系3・border・user・danger・radius2・stage透過2）。**意味色が未定義** — 成功 `#4cc9a4`・警告 `#e0b341`・下降 `#ef6f6c`・スター `#f5c518`・セリフ `#cfe3ff`・RPバッジ `#f0a76b`・物語バッジ `#6bd6f0` 等がクラスごとにハードコード散在。
- アイコンは**すべて絵文字**（OSのフォントレンダリング依存。Windows/ブラウザ間で見た目が揃わず、単色化・サイズ統一・状態表現ができない）。
- `src/index.css` **1,856行の単一ファイル**・フラットなクラス命名（コメント区切りのセクション24個）。規模的にはまだ管理可能圏だが、トークン不足のため「同じ意味の色・余白」が複数箇所に重複している。

### 2.6 フィードバック系

- トースト3種（error＝赤・実績＝金紫グラデ・画像完了＝青緑グラデ）が**同一座標（bottom:20px 中央）の独立要素**として実装されており、同時発生時は**重なって下のトーストが読めない**。自動消滅もない（手動「閉じる」のみ）。
- 進行状態の表示が分散: 本編生成＝送信ボタンが◼化＋カーソル点滅、選択肢＝choices-loading 行、レビュー＝シーン終了ボタンの文言変化、画像＝トップバー⏳バッジ、表情判定・チェックポイント記録＝**表示なし（不可視）**。「いま裏で何が動いているか」を一望できる場所がない。

### 2.7 キーボード・アクセシビリティ

- ショートカットは実質 **Enter 送信のみ**（ChatPanel の textarea）。Escape・Ctrl系・ファンクションキーの割当なし。
- `aria-label` なし。絵文字ボタンはスクリーンリーダー以前に晴眼者にも意味が伝わりにくい。
- （個人用途のため優先度は低いが、キーボード操作の欠如は効率面で本人にも効いている）

### 2.8 残すべき資産（0ベースでも捨てないもの）

0ベースといっても全否定ではない。以下は明確に良く、再設計の土台に**残す**:

- **落ち着いた配色と読みやすい本文**（行間1.9・セリフの色分け）。方向性は正しい。設定可能にするだけでよい。
- **依存ゼロの軽さ**。UIライブラリなしでこの完成度は資産。起動・描画が速い。
- **CSS変数とモーダルの視覚統一**の下地。拡張すればトークン体系に育つ。
- **シーン折りたたみ＋あらすじ**による長編の一覧性（DOM肥大の実質的な対策にもなっている）。
- **ステージ・バックドロップ**（V5b）の「本文の背面に世界を薄く敷く」という発想。強化对象であって撤去対象ではない。
- **ジョブ化＋候補選択＋トースト通知**の画像生成フロー、**メッセージ単位 graceful degradation** の構造化レンダラ、**EntityAvatar への表示統一**。
- draft 方式そのもの（編集中スナップショット→保存ボタン反映）。問題は「破棄が無警告」な点だけ。

## 3. 構造的課題 — 0ベースで見たときの歪み

評価軸: **没入**（本文への集中）・**文脈保持**（読みながら参照できるか）・**発見可能性**（機能に気づけるか）・**成長耐性**（機能・データが増えても破綻しないか）・**操作効率**。

### 課題1: 「全部モーダル」— 文脈の破壊【文脈保持・没入】

📊状態・📖発見・🖼ギャラリー・🕘分岐・⏳ジョブはどれも「**本文を読みながら参照したい**」情報なのに、開くと本文が覆われる。「さっきの発言でどう関係が変わった？」を確かめるには 本文→📊→閉じる→本文 の往復になる。分岐ツリーは「本文のこの辺に戻りたい」という操作なのに、本文と並べて見られない。
さらに全モーダルがオーバーレイクリックで即閉じるため、**draft編集・生成済みレビューの無警告破棄**という実害がある（§2.3）。

### 課題2: 絵文字ツールバーのスケール限界【発見可能性・成長耐性】

トップバーのアイコンは既に11個。**新機能を足すたびに1個増える構造**で、V4〜C3 の半年で倍増した。絵文字は形の統一感がなく、📜と📖、🖼と🎨と🏞 の区別は使い込まないと覚えられない。機能の存在自体に気づかない（🕘分岐・📖発見は本アプリの目玉機能なのに、初見では「時計？本？」）。ホバー title だけが頼りで、**一覧して「このアプリに何ができるか」を把握する場所がない**。

### 課題3: 二層IAの混線 — 素材とセッションが同列【発見可能性・操作効率】

「セッション（いま遊んでいる文脈）」と「素材ライブラリ（グローバル資産）」は性質が違うのに、同じサイドバーの同じナビに並ぶ。素材ビューを開いてもセッション一覧が下に表示され続け、いま何の文脈にいるのか曖昧。逆に、セッション設定から「キャラ管理で作成」に飛ぶとセッション画面から完全に離れてしまい、**「遊びながらちょっと素材を直す」動線が遠い**。

### 課題4: コンポーザーの積層肥大【没入・操作効率】

シーンバー・話者選択・story-actions・選択肢・入力欄・ヒントで最大6段。とくにシーンバーの情報（シーンタイトル・登場・トークンバッジ）は「入力の直前に毎回見るもの」ではなく、常設が本文の面積を奪っている。story-actions のボタン群（▶開始／⏩続ける／↻やり直す／⤵続き／🔁選択肢）は状態によって現れたり消えたりし、**プライマリアクションがどれか一目で分からない**。

### 課題5: 「読む体験」のチューニング不能【没入】

本文が主役なのに、フォントサイズ・行間・本文幅（760px固定）・テーマを一切変えられない。長時間の読書に対して、視力・距離・気分に合わせる余地がゼロ。ステージ濃度も固定値で、「今日は立ち絵を濃く楽しみたい／今日は文字に集中したい」に応えられない。**没入モード（UIを退避させて本文＋ステージだけにする）も存在しない。**

### 課題6: 進行状態の分散と裏方の不可視【文脈保持】

§2.6 の通り、5系統の非同期動作（本編・選択肢・レビュー・画像・表情判定/チェックポイント）の状態表示がバラバラの場所・作法で出る。何かが動いている間に別の操作をしてよいのか判断できず、実際「レビュー中は分岐操作を disabled」等の依存関係は BranchTreeModal の中に埋まっていて外から見えない。

### 課題7: スケーラビリティの頭打ち【成長耐性】

- セッションが数十件になると一覧はスクロールのみ。完結した物語を退避する場所（アーカイブ）がない。
- 素材（キャラ・世界）も検索・タグ絞り込みがない（タグ表示はあるが機能しない）。
- 機能面: 新しい「蓄積系機能」（例: TTS・統計・年表）を足すとき、現構造では「絵文字＋モーダル」を足すしかなく、課題1・2 を悪化させる。**受け皿の構造がない。**

### 課題8: 視覚言語の負債【成長耐性】

意味色ハードコードの散在（§2.5）により、テーマ追加・一括調整・ライトモード対応が事実上不可能な状態。絵文字アイコンは状態表現（on/off・disabled・バッジ）と相性が悪い。1,856行の単一CSSは、セクションコメントで保っているが機能横断の変更（例: 余白の一括見直し）に弱い。

### 課題9: オンボーディングの薄さ【発見可能性】

初回起動は「APIキー未設定なら SettingsModal が開く」のみ。プロバイダ→モデル→素材→セッションという必要手順のガイドがなく、空状態のヒントも1行テキスト。サンプルカード（配布物）を読み込む動線も設定モーダルの奥。

### 課題10: 細かな粗（まとめて直せるもの）

1. トースト3種が同一座標で重なる（§2.6）
2. Escape でモーダルが閉じない／draft 破棄が無警告（§2.3）
3. Tauri 窓の最小サイズ未設定（§2.1）
4. ネイティブ confirm/prompt の文体不統一（§2.3）
5. ナビ2列グリッドの5個目が欠けて見える（§2.2）
6. トーストに自動消滅がない（エラーは残留でよいが、完了通知は自動で消えてよい）

## 4. 再設計コンセプト

### 4.1 北極星 — 「舞台」と「書斎」を分ける

> **Play（舞台）では chrome が退き、本文とステージが主役になる。Library（書斎）ではフォームが主役になり、広く使える。** 蓄積（状態・発見・分岐・画像）は舞台の袖＝**サイドドック**に常駐し、幕を下ろさず（＝モーダルで本文を覆わず）に参照できる。

### 4.2 情報設計: 3領域モデル

現在の5ビュー並列を、性質で3領域に再編する:

```
Play（遊ぶ・読む）          Library（作る）              System（整える）
├─ セッション一覧（検索付き）  ├─ キャラクター              ├─ プロバイダ（LLM）
└─ ChatPanel ＋ サイドドック   ├─ 世界観                    ├─ 画像生成の接続先
   ├─ 状態(📊)               ├─ ペルソナ                  ├─ データ入出力
   ├─ 発見(📖)               └─ 演出（シーンタイプ）        └─ （将来: UI設定・ショートカット）
   ├─ 分岐(🕘)
   ├─ ギャラリー(🖼)
   └─ ジョブ(⏳)
```

### 4.3 レイアウトの根本案（4案比較）

**案A【推奨】: シングルウィンドウ・3ゾーン**

```
┌──┬────────────┬──────────────────────────────┬───────────────┐
│レ │ サイドバー   │  ステージ（本文＋背景・立ち絵）   │ コンテキスト   │
│| │ （文脈追従）  │                              │ ドック         │
│ル │ Play: セッション│  topbar: タイトル・進行状態     │ （タブ切替・    │
│48 │  一覧＋検索   │  ・ドックタブ・⋯メニュー        │  開閉式・       │
│px │ Library: 素材 │                              │  約320〜380px） │
│  │  種別＋一覧   │  composer（再編後）             │ 状態/発見/分岐/ │
│  │             │                              │ 画像/ジョブ     │
└──┴────────────┴──────────────────────────────┴───────────────┘
```

- 左端に**細いレール**（Play/Library/System の領域スイッチ＋下部にジョブ・接続状態）。サイドバー第2列は**領域に追従**（Play=セッション一覧、Library=素材一覧）。→ 課題3を解消。
- 右に**コンテキストドック**: 「読みながら見る」もの（状態・発見・分岐・ギャラリー・ジョブ）をタブで常駐。開閉可・幅固定。→ 課題1・6・7（受け皿）を解消。
- モーダルは「**進行を止めて集中する**」ものだけに限定（§4.5 の配置原則）。
- 没入モードをサブモードとして持つ（§4.7）。

**案B: マルチウィンドウ（Tauri）— 却下**
状態パネルや分岐ツリーを別ウィンドウ化する案。zustand ストアの複数 WebView 間同期（Tauri の window ごとに独立した JS コンテキスト）が必要になり、T3 のファイルストレージ・デバウンス書込とも干渉する。Web 版と構造が乖離する。個人用途で得られる利益に対して複雑さが大きすぎる。

**案C: フルスクリーンVN型（ビジュアルノベル風UI）— 却下（ただし部分採用）**
ゲーム画面のように本文をステージ上のテキストボックスに重ね、UIをすべてオーバーレイにする案。没入は最大だが、本アプリは「作る・振り返る」の比重が高く、編集・レビュー・素材管理の動線が遠くなりすぎる。**「没入モード」（§4.7）として案Aのサブモードに縮退採用**する。

**案D: 現状維持＋磨き込みのみ — 却下**
トースト重なり・Escape・draft保護などの粗（課題10）だけ直す案。コストは最小だが、課題1（モーダル）・課題2（絵文字バーの線形増殖）・課題7（受け皿がない）は磨きでは解けず、次の機能追加でまた悪化する。**ただし案Dの内容はそのまま UI-0/UI-1 フェーズとして案Aに包含する。**

### 4.4 トップバーの再編（課題2）

絵文字11個 → **4要素**に整理:

1. **セッションタイトル**（現行どおりインライン編集）＋ シーン情報（現シーンタイトル・timeLabel を小さく併記。シーンバーから移譲）
2. **アクティビティ・インジケータ**（§4.6。進行中の裏方動作を1箇所に集約表示）
3. **ドックタブ**: 状態 / 発見 / 分岐 / 画像 / ジョブ（アイコン＋短ラベル。クリックでドック開閉。バッジ表示=ジョブ数・新着発見）
4. **⋯メニュー**（オーバーフロー）: あらすじ📜・挿絵生成🎨・背景生成🏞・カード化🖼・ステージ表示🎭・セッション設定⚙・削除🗑

原則: **毎ターン使うものだけ常設、それ以外はメニューかドックへ**。新機能はドックタブか⋯メニューに入るため、トップバーはもう伸びない（課題2・7）。

### 4.5 モーダル／ドック／ページの配置原則（ADR-UI-2）

| 配置 | 基準 | 対象 |
|---|---|---|
| **ドック**（常駐・並列閲覧） | 読みながら見る・進行を止めない | 状態・発見・分岐ツリー・ギャラリー・ジョブ |
| **モーダル**（中断・集中） | 進行を止めて意思決定する／短いフォーム | シーンレビュー・画像起案（ImageGen）・モデル選択・カード書き出し・セッション設定・シーン編集・確認ダイアログ |
| **ページ**（全面） | 長大なフォーム・一覧 | Library の素材一覧＋**WorldEditor（モーダル卒業・フルページ化）**・System 設定 |

- WorldEditor（728行・6セクション）は 680px モーダルに収まる規模を超えている。Library 内のフルページエディタ（左に節ナビ: 概要/ロア/イベント/関係軸/スタット/カウンター/実績）へ。
- CharacterEditor / PersonaEditor は現規模ならモーダル継続可（立ち絵セットが伸びるならページ化を再検討）。
- ネイティブ `confirm`/`prompt` は**アプリ内共通ダイアログ**（Enter/Escape 対応・テーマ準拠）に置換。draft 系モーダルは**変更がある場合のみ**「破棄しますか？」を挟む。

### 4.6 進行状態の一元化 — アクティビティ・インジケータ（課題6）

topbar に常設の小さな1領域で、非同期動作を集約表示する:

- 表示例: `✍ 本編を生成中…` / `🔀 選択肢を考え中` / `📋 レビュー作成中（中止）` / `🖼 画像 2/4` / `😊 表情判定中` / 何もなければ非表示。
- 複数同時はまとめて `✍＋2` のように畳み、クリックで内訳ポップオーバー（各行に中止ボタン）。
- store には `isStreaming` 等の状態が既に揃っており、**表示だけの追加**で済む（V5d で中断系も分離済み）。

### 4.7 リーダー体験（課題5）

- **リーダー設定**（⋯メニュー or ドックの「表示」タブ）: 本文サイズ（S/M/L/XL）・行間（狭/標準/広）・本文幅（狭660/標準760/広900px）・セリフ色の有効/無効・ステージ濃度（背景/立ち絵の2スライダー＝既存CSS変数のUI化）。
- 保存先: AppState 直下に `ui?: UiPrefs` を optional 追加（partialize に追加・persist キー v3 のまま。セッション非依存のグローバル設定）。
- **没入モード**: トグル（⋯メニュー＋ショートカット）で サイドバー/レール/ドックを退避・topbar を細く（ホバーで復帰）・ステージ濃度を没入用プリセットに。「読む夜」のためのモード。実装はCSSクラス切替（`.app.immersive`）で足りる。

### 4.8 コンポーザーの再編（課題4）

- **シーンバー廃止** → シーン情報は topbar へ（§4.4）、トークンバッジも topbar のシーン情報横へ。「シーン編集」「このシーンを終える」は入力欄の右端のシーンメニュー（📖▾）に集約。
- **プライマリアクションを常に1つ**に: story モードは大きな「⏩ 続ける」（未開始時は「▶ はじめる」）、RP モードは送信。↻やり直す・⤵続き・🔁選択肢再生成はセカンダリの小ボタン列（アイコン＋ラベル）に降格し、**出現位置を固定**する（状態で行が増減して画面が跳ねるのを防ぐ）。
- 話者選択チップ・選択肢カードは現行踏襲（機能的に良くできている）。ヒント行は初回数回のみ表示に。

### 4.9 視覚言語の再構築（課題8）

- **トークン体系の拡充**（`:root` に集約）: 意味色 `--ok / --warn / --danger / --info`（現 #4cc9a4 / #e0b341 / #ef6f6c 等を昇格）・spacing スケール（4/8/12/16/24/32）・z-index スケール（base/dock/modal/toast）・タイポグラフィ（`--font-body / --font-size-body / --line-height-reader` 等、リーダー設定と接続）。
- **CSSファイル分割**: `index.css` → `tokens.css / base.css / layout.css / chat.css / forms.css / modals.css / dock.css`（Vite でそのまま import。ビルド出力は同等）。
- **アイコン**: 絵文字 → **自前の単一 SVG アイコンモジュール**（`src/components/icons.tsx` に 20個程度のミニマルなラインアイコン。依存ゼロ維持）。ナビ・トップバー・ドックタブが対象。トースト・実績・カード種別などの「感情・彩り」用途は絵文字を残してよい。
- **ライトテーマ**: トークン化が済めば `data-theme` 切替で実現可能になるが、夜間利用主体なら優先度は低い（§8 Q4）。

### 4.10 スケーラビリティ（課題7）

- セッション一覧に**検索ボックス**（タイトル＋登場キャラ名）と**アーカイブ**（`Session.archived?: boolean` optional 追加・一覧は既定で非表示＋「アーカイブ済み (n)」トグル）。
- Library 各一覧に検索（名前＋タグ）。タグクリックで絞り込み。
- **コマンドパレット（Ctrl+K）**: セッション・素材・コマンド（「背景を生成」「分岐を開く」…）の横断検索起動。自前実装（部分一致で十分・依存なし）。機能が増えても「名前を知っていれば3秒で届く」非線形の受け皿になる。
- メッセージ一覧の仮想化は**見送り**（シーン折りたたみで実用上足りている。将来1シーンが数百メッセージ級になったら再検討）。

### 4.11 オンボーディングと空状態（課題9）

- 初回起動: SettingsModal を突然開くのをやめ、**3ステップの初回ガイド**（①プロバイダとAPIキー → ②モデルを選んで疎通テスト → ③サンプルカードを読み込む or 空で始める）。
- 空状態の強化: セッション未選択画面に「最近のセッション」「素材が0ならキャラ作成への大きな導線」。素材0でセッション設定を開いたときの誘導は現行の link 方式を維持。

## 6. ADR-UI（根本分岐の記録）

### ADR-UI-1: シングルウィンドウ・3ゾーンレイアウト（案A）を採用
- 却下: マルチウィンドウ（案B・状態同期の複雑さ／Web版乖離）、フルスクリーンVN型（案C・創作動線が遠い→没入モードとして縮退採用）、磨き込みのみ（案D・構造課題が解けない→内容はUI-0/1に包含）。

### ADR-UI-2: 「読みながら見る＝ドック／進行を止める＝モーダル／長大フォーム＝ページ」の配置原則
- 却下: 全部ドック化（レビューのような「意思決定の強制」はモーダルの方が正しい）、全部モーダル維持（課題1）。

### ADR-UI-3: CSS は手書き継続＋トークン拡充＋ファイル分割
- 却下: Tailwind / CSS-in-JS / UIコンポーネントライブラリ（shadcn 等）— 依存最小方針に反し、1,856行は手書き管理可能圏。既存クラスの書き直しコストも大きい。分割とトークン化で得られる利益がほぼ同等。

### ADR-UI-4: 機能アイコンは自前SVGモジュール、彩り用途は絵文字を残す
- 却下: 絵文字全面継続（状態表現・統一感の限界＝課題2）、アイコンフォント（部分読込・依存）、lucide-react 等の導入（依存最小方針。ただし**自前SVGのパスデータ作成が負担なら、lucide の MIT ライセンスの SVG パスを個別コピーして自前モジュールに埋める折衷は可**）。

### ADR-UI-5: キーボードは「ショートカット＋コマンドパレット」の二段構え
- 却下: ショートカットのみ（暗記依存・一覧性がない）、パレットのみ（頻出操作に2アクション要る）。

### ADR-UI-6: リーダー設定・UI設定は AppState 直下 `ui?` に optional 追加（persist キー不変）
- 却下: セッションごとのリーダー設定（設定が分散して「なぜこのセッションだけ字が大きい？」になる。ステージ表示 `spritesEnabled` のみセッション固有の現行仕様を維持）、localStorage 直書き（persist の管理外に状態を増やさない）。
