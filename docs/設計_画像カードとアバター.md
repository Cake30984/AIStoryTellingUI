# 設計: 画像カード（PNG埋め込み入出力）とアバター画像化

素材（キャラ／世界観／ペルソナ）を **PNG 画像1枚にメタデータを埋め込んだ「カード」** としてエクスポート/インポートできるようにし、あわせて **絵文字アバターを全廃して画像ベースに刷新** する。将来の画像生成（ComfyUI 等）・挿絵機能の土台（IndexedDB 画像ストア）もここで整備する。

- 対象フェーズ: P1〜P5（1フェーズ＝1ターンで実装・検証・コミット）
- 決定事項（ユーザー合意済み）:
  - キャラカードは **SillyTavern `chara_card_v2` 互換 + 独自拡張**（extensions に格納）
  - カード画像は **ユーザー画像優先、未設定なら自動生成**（将来は ComfyUI／画像生成 API 接続）
  - **絵文字は一切使わない**（全表示箇所を画像＋フォールバックに置換）
  - JSON バンドルに画像は含めない。素材共有は PNG カード、セッション共有は将来の挿絵埋め込みへ移行（それまで JSON 継続）
- 方針: クリーンブレイク（CLAUDE.md 永続化方針どおり）。`Avatar` 型が変わるため **persist キーを `ai-storytelling-store-v3` に更新** し旧データは破棄。migrate は書かない。

## 全体アーキテクチャ

```
[素材 Character/World/Persona]
   avatar: { imageId?: string; color: string }   ← 絵文字廃止
        │ imageId で参照
        ▼
[IndexedDB 'aist-images' / store 'images']       ← 画像 blob 本体（localStorage に入れない）
        │ getImage / putImage
        ▼
[EntityAvatar コンポーネント]                     ← 画像があれば表示、なければ 色＋名前イニシャル
        │
[PNG カード I/O]  png.ts(チャンク読み書き) + cards.ts(形式変換)
   エクスポート: アバター画像（無ければ自動生成） → PNG 正規化 → tEXt チャンクに JSON(base64)
   インポート:   PNG の tEXt を解読 → 素材として追加 ＋ その PNG 自体をアバター画像に登録
```

## P1: 画像基盤（IndexedDB ＋ Avatar 型刷新）

### 1-1. `src/lib/imageStore.ts`

IndexedDB は素の API で実装する（追加ライブラリなし）。DB 名 `aist-images`、version 1、objectStore `images`（keyPath: `id`）。レコード: `{ id: string, blob: Blob, createdAt: number }`。

```ts
export async function putImage(blob: Blob): Promise<string>      // uid() を発行して保存、id を返す
export async function getImage(id: string): Promise<Blob | undefined>
export async function deleteImage(id: string): Promise<void>
export async function listImageIds(): Promise<string[]>
export async function gcImages(usedIds: Set<string>): Promise<number>  // 未参照を削除、削除数を返す

// 表示用 objectURL キャッシュ（モジュールスコープの Map<id, string>。revoke はしない＝アプリ寿命で保持）
export async function imageUrlOf(id: string): Promise<string | undefined>
export function useImageUrl(id: string | undefined): string | undefined  // React hook（内部で imageUrlOf、未ロード中/無しは undefined）
```

実装注意:
- `indexedDB.open` の Promise ラッパは 20 行程度で書く（`onupgradeneeded` で objectStore 作成）。
- `useImageUrl` は `useState` + `useEffect(…, [id])`。アンマウント後の setState を避けるため cancelled フラグを持つ。キャッシュヒット時は同期的に初期値へ入れてチラつきを防ぐ。
- 削除された imageId を引いたら `undefined` を返す（例外にしない）。ダングリング参照はフォールバック表示で吸収する。
- `gcImages` は「全素材の avatar.imageId を集めた Set」を呼び出し側（store）が渡す。素材削除のたびに即 delete はしない（同じ画像を参照し得るため）。SettingsModal に「🧹 未使用画像を整理」ボタンを置き手動実行（P2 で UI 追加）。

### 1-2. `src/lib/avatarGen.ts` — デフォルト画像生成

```ts
/** 名前の頭文字＋背景色から 256x256 の PNG blob を生成（表示フォールバックと同じ見た目） */
export async function generateDefaultAvatar(name: string, color: string): Promise<Blob>
```

- OffscreenCanvas は使わず `document.createElement('canvas')`（Safari 互換・SSR なしなので問題ない）。
- 背景: `color` の単色（角丸不要。表示側で `border-radius` する）。
- 文字: 名前の先頭1文字（`Array.from(name.trim())[0] ?? '?'` — サロゲートペア対応のため `Array.from`）。白 `#fff`、`font: 'bold 128px sans-serif'`、`textAlign:'center'`、`textBaseline:'middle'` で中央描画。
- `canvas.toBlob` を Promise ラップ、`'image/png'`。

用途は **カードエクスポート時に画像未設定の素材へ使う**（P3）。日常の画面表示は EntityAvatar の CSS フォールバック（P2）で行い、blob は作らない。

### 1-3. `Avatar` 型の刷新（`src/types.ts`）

```ts
/** アバター表現（画像参照＋テーマ色）。絵文字は廃止 */

  /** IndexedDB 画像ストアの id。未設定なら色＋名前イニシャルで表示 */
```

### 1-4. スキーマ変更の連鎖対応（CLAUDE.md の手順どおり）

1. 型更新（上記）
2. 初期 state / factory 更新: `newCharacter()` / `newPersona()`（store.ts）の avatar を `{ color: pickColor() }` / `{ color: '#5b8def' }` に

## P3: PNG カード入出力（キャラカード・ST互換）

### 3-1. `src/lib/png.ts` — チャンク読み書き（自前・約100行）

```ts
/** PNG バイト列から tEXt チャンクを列挙（keyword は Latin-1、text はそのまま返す） */
export function readTextChunks(bytes: Uint8Array): { keyword: string; text: string }[]
/** 同 keyword の既存 tEXt を除去し、IEND 直前に新しい tEXt を挿入した新バイト列を返す */
export function writeTextChunk(bytes: Uint8Array, keyword: string, text: string): Uint8Array
```

実装仕様:
- 先頭 8 バイトのシグネチャ `89 50 4E 47 0D 0A 1A 0A` を検証（不一致は `throw new Error('PNG ではありません')`）。
- チャンク構造: `length(4, big-endian) | type(4, ASCII) | data(length) | crc(4)`。type が `tEXt` のとき data は `keyword \0 text`（どちらも Latin-1 バイト）。
- **CRC32 は type＋data を対象**（length は含めない）。標準の CRC-32（多項式 0xEDB88320、初期値 0xFFFFFFFF、最終 XOR）。256 要素テーブルをモジュール初期化時に構築。
- 読み取りは `iTXt` も拾えると親切だが、本アプリの書き出しは `tEXt` のみ。SillyTavern も `tEXt` なので read は tEXt だけで足りる（iTXt 対応はしない。過剰実装禁止）。
- text に非 Latin-1 を入れてはいけない → **JSON は必ず base64 化して渡す**（呼び出し側 cards.ts の責務）。

base64 ヘルパ（cards.ts 内）: UTF-8 安全に。
```ts
const b64encode = (s: string) => { const b = new TextEncoder().encode(s); let bin = ''; for (const c of b) bin += String.fromCharCode(c); return btoa(bin) }
const b64decode = (s: string) => { const bin = atob(s); const b = Uint8Array.from(bin, (c) => c.charCodeAt(0)); return new TextDecoder().decode(b) }
```

### 3-2. `src/lib/cards.ts` — キャラカード形式

**書き出し（chara_card_v2 互換）**: keyword `chara`、text は base64(JSON)。

```jsonc
{
  "spec": "chara_card_v2",
  "spec_version": "2.0",
  "data": {
    "name": "...",                    // Character.name
    "description": "...",            // persona ＋（appearance があれば "\n\n【外見】\n" + appearance）
    "personality": "...",            // speechStyle
    "scenario": "",
    "first_mes": "...",              // greeting
    "mes_example": "...",            // exampleDialogues
    "creator_notes": "AI Storytelling Studio で作成",
    "system_prompt": "", "post_history_instructions": "",
    "alternate_greetings": [], "character_book": undefined,
    "tags": [...],                   // Character.tags
    "creator": "", "character_version": "",
    "extensions": {
      "aistorytelling": {
        "version": 1,
        "kind": "character",
        "character": { /* Character を丸ごと（下記除外規則を適用） */ }
      }
    }
  }
}
```

除外規則（extensions に入れる Character から取り除く/加工する）:
- `avatar.imageId` は **除外**（受け取り側の IndexedDB に存在しないため。color は残す）
- `model` は **除外**（ModelRef は環境固有のプロバイダ id を含むため共有不可）
- `developments` は含める（素材のレイヤー。enabled も維持）
- `id` / `createdAt` / `updatedAt` は含める（インポート時の重複判定・情報として）

**読み込み**:

```ts
export type ParsedCard =
  | { kind: 'character'; character: Character }
  | { kind: 'world'; world: World }        // P4
  | { kind: 'persona'; persona: Persona }  // P4
export function parseCardPng(bytes: Uint8Array): ParsedCard | null  // カードチャンクが無ければ null
```

判定順: `aist_world` → `aist_persona` → `chara`（P3 では chara のみ実装、他は P4 で追加）。
- `chara` の JSON に `data.extensions.aistorytelling.character` があれば最優先で採用（欠落フィールドは `newCharacter()` をベースにスプレッドで補完。`avatar` は `{ color }` に正規化、`model` は捨てる）。
- 無ければ ST ネイティブカードとしてマッピング: `name`→name、`description`→persona、`personality`→speechStyle、`first_mes`→greeting、`mes_example`→exampleDialogues、`tags`→tags、appearance は空、`id` は `uid()` 新規発行。`spec` が `chara_card_v2` でなくても `data.name` か `name` があれば v1 形式（トップレベルに name/description…）としても読む（v1 は data ラッパが無い）。

**エクスポート処理フロー**（`exportCharacterCard(character): Promise<void>` を cards.ts に）:
1. 画像取得: `getImage(avatar.imageId)`。無ければ `generateDefaultAvatar(name, color)`
2. `normalizeImage(blob, 1024)` で **PNG に正規化**（JPEG/WebP 対策・既存チャンクの掃除も兼ねる）
3. `writeTextChunk(bytes, 'chara', b64encode(JSON.stringify(card)))`
4. `card_キャラ名.png` としてダウンロード（`downloadBlob(blob, filename)` ヘルパを io.ts に追加）

**インポート処理フロー**:
1. `parseCardPng` で素材を得る（null なら「カード情報が見つかりません」エラー）
2. **その PNG 自体を `normalizeImage`（512px）→ `putImage`** し、素材の `avatar.imageId` に設定（カード画像＝アバターになる）
3. store の新アクション `importCard(parsed: ParsedCard): { ok: boolean; reason?: string }` で追加。id 重複時は `uid()` を振り直して追加（JSON バンドルの「既存優先スキップ」と違い、カードは「配布物を試す」用途なので **常に追加** とする。名前に「 (2)」等は付けない）

## 実装上の落とし穴（必読）

1. **btoa に UTF-8 を直接渡さない**（`InvalidCharacterError`）。必ず 3-1 の b64encode/b64decode を使う。
2. **CRC32 の対象は type＋data**。length を含めると全 PNG ビューアで壊れる。
3. **tEXt の text に生 JSON を入れない**（日本語＝非 Latin-1 で破損する）。base64 必須。
4. `Array.from(name)[0]` でイニシャル取得（`name[0]` はサロゲートペアを割る）。
5. `useImageUrl` の非同期 setState はアンマウントガード必須（一覧の高速スクロールで警告が出る）。
6. persist キー変更を忘れると旧 emoji データが新型に流れ込み実行時エラーになる。**P1 で必ず `-v3` へ**。
7. exportBundle/importBundle・partialize の確認（CLAUDE.md のスキーマ変更手順）。P1 で imageId/emoji の正規化を importBundle に入れる。
8. カードの extensions から `model`（ModelRef）と `avatar.imageId` を必ず除外（環境固有値の漏出・ダングリング防止）。
9. `normalizeImage` は EXIF 回転を無視して良い（`createImageBitmap` が概ね処理する）が、`file.type` が空のケース（D&D）でも動くよう blob をそのまま渡す。
10. D&D ハンドラは `onDragOver` で `preventDefault` しないと `onDrop` が発火しない。
11. 各フェーズ完了時: `npx tsc --noEmit` → `npm run build` → preview 検証 → **CLAUDE.md 更新（ディレクトリ・データモデル・実装状況）を同一コミットに含めて** `git commit` → `git push origin main`。

## フェーズ間の依存

P1（基盤）→ P2（UI）→ P3（キャラカード）→ P4（世界/ペルソナカード）は直列。P5 のみ独立した追加設計が必要。各フェーズは単体でビルド・動作可能な状態で完結させること（P1 時点でも emoji 参照はすべて暫定除去し型を通す）。
