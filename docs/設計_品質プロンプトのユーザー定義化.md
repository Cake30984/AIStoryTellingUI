# 設計: 品質プロンプトのユーザー定義化（スタイルプリセット廃止）

ロードマップ項目 3 の詳細設計。V1 で導入した固定のスタイルプリセット（`STYLE_PRESETS`＝アニメ系/実写系）を廃止し、
**ImageProvider（画像生成の接続先）ごと**にユーザーが自由なデフォルト positive / negative タグ
（LoRA トリガー・画風・品質タグ）を設定できるようにする。デフォルトタグは**生成実行時に裏で結合**し、
プロンプト欄には表示しない。

実装フェーズは **Q1 → Q5 の順に1コミットで完結**（相互依存が強く分割する意味が薄い。tsc → build → Preview 検証 → CLAUDE.md 更新 → commit → push は既存の進め方と同じ）。

## 背景と目的

現状のスタイルプリセット方式には次の問題がある:

1. **タグが固定2種のみ**: `STYLE_PRESETS`（アニメ系/実写系）のタグはハードコードで、ユーザーの
   LoRA トリガー・好みの品質タグ・画風タグを反映できない。
2. **プロンプト欄が汚れる**: `applyStylePreset` がプロンプト/ネガティブ欄の**先頭にタグを直接書き込む**方式のため、
   欄の大半が毎回同じ定型タグで埋まり、本題（場面・人物の描写）が読みにくい。
3. **冪等化ロジックが脆い**: 「既知プリセットの全トークンを除去→選択プリセットを先頭付加」という
   `applyStylePreset` の冪等化は、ユーザーが自分で `masterpiece` を書いた場合も除去してしまう等、
   プリセットのタグ集合と手入力の衝突が構造的に避けられない。
4. **接続先と画風が紐付かない**: 実際には「この ComfyUI（アニメ系モデル）にはこのタグ」「この API（実写系）には
   このタグ」のように**接続先ごとに定型タグは決まる**のに、スタイル選択はモーダル側のグローバル記憶
   （`lastImageStyle`）で、接続先を切り替えるたびに人が合わせ直す必要がある。

**目指す形**: 定型タグ（品質・画風・LoRA トリガー）は接続先の属性として一度だけ設定し、以後の生成では
自動で先頭に結合される。プロンプト欄には「その場面・人物固有の内容」だけが残る。
キャラ固有の `imagePrompt`（キャラ専用 LoRA・髪色等）は**別物としてそのまま維持**する（役割が違う:
接続先デフォルト＝「どの絵でも常に付くタグ」／キャラ `imagePrompt`＝「そのキャラが写る絵にだけ付くタグ」）。

## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| デフォルトタグの持ち主 | **ImageProvider（接続先）ごと**に `defaultPositive`/`defaultNegative` | 定型タグは実際にはモデル（checkpoint/API）に紐付く。接続先を切り替えれば画風タグも自動で切り替わる |
| 結合の場所 | **`generateImage()`（imageGen.ts）の冒頭1箇所** | モーダル・一括生成・将来の呼び出し元すべてが自動で対象になる。UI 側に結合コードを書かない（書き忘れ事故の防止） |
| 結合の向き | `デフォルト, ユーザープロンプト` の順で**先頭付加**。ユーザー側にデフォルトと同一トークンがあれば重複除去 | SD 系はプロンプト先頭の重みが高く、品質タグは先頭が定石（V1 と同じ）。重複除去はカンマ区切りトークン単位の完全一致のみ（部分一致はしない） |
| プロンプト欄への表示 | **結合結果は欄に出さない**。代わりに欄の下に読み取り専用の注記（「🏷 生成時に自動付加: …」）を表示 | 欄は場面固有の内容専用に保つ（目的 2）。ただし「何が付くのか」が見えないと不安なので注記で可視化する |
| ジョブ・挿絵記録に残すプロンプト | **結合前のユーザープロンプトのまま**（`ImageJob.prompt`・`SceneIllustration.prompt` とも） | 記録の関心は「その絵で何を指示したか」。定型タグ込みだと記録が読みにくく、別の接続先で再生成する時もその接続先のデフォルトが改めて結合される方が正しい |
| 新規 comfyui 接続先の初期値 | 旧アニメ系プリセット相当のタグを `defaultPositive`/`defaultNegative` に**シード**（編集・全消し自由） | 初見ユーザーが空タグで低品質画像を引くのを防ぐ。openai-image は空のまま（DALL-E 系は danbooru タグ不要・negative 非対応） |
| 既存接続先の移行 | **しない**（`defaultPositive`/`defaultNegative` は optional 追加。既存データでは undefined＝結合なし） | クリーンブレイク方針（ADR-1）。`lastImageStyle` から自動でコピーする案は「実写系を選んでいた人にアニメ系タグが入る」等の誤爆リスクの割に得るものが小さい。既存ユーザーには設定 UI で一度入力してもらう（報告時に案内する） |
| persist キー | **v3 のまま** | `ImageProvider` への optional フィールド追加＋AppState からの `lastImageStyle` 削除のみで、スキーマ破壊が無い。persist 済み JSON に残る古い `lastImageStyle` キーは無害（partialize から外れるため次回保存で自然消滅） |
| negative の対象 | comfyui のみ入力欄を出す（既存の `ImageGenModal` と同じ方針）。結合ヘルパ自体は kind を見ない | openai-image の API は negative を送らない（`generateOpenAiImage` が使わない）ため、入力させても効かない |
| `ensureTags`（pinTags）の扱い | **現状維持**（起案の全文置換から LoRA トリガー・表情タグを守る仕組み。V5c） | スタイルプリセットとは独立の機構。ファイルのリネームに伴い import パスだけ変わる |
| 起案 LLM への指示 | 品質タグに加え**画風タグ（anime style / photorealistic 等）も入れない**と明示 | 画風は接続先デフォルト側の管轄になったため。キャラの【画像生成タグ】をそのまま含める指示は現状維持（これは接続先ではなくキャラの属性） |

### 却下した代替案

- **結合を `runImageJobLoop`（store.ts）で行う**: `generateImage` を直接呼ぶ将来コードが結合を忘れる余地が残る。
  接続先とプロンプトが揃う最終地点＝`generateImage` が最も安全。
- **モーダルで結合結果を欄に prefill する（現行方式の踏襲）**: 目的 2・3 の問題（欄が汚れる・冪等化が脆い）が
  そのまま残るため不採用。
- **グローバル1個のデフォルトタグ（接続先ごとにしない）**: 接続先＝モデルごとに定型タグは異なる（アニメ系 checkpoint と
  実写系 API を併用するユーザーで破綻）ため不採用。
- **スタイルプリセットを「ユーザー定義プリセット複数＋選択 UI」に発展させる**: 接続先とプリセットの2軸選択になり
  UI・状態管理が複雑化する。「接続先ごとに1組」で大半のユースケース（checkpoint ごとの定型タグ）を覆えるため不採用。
  必要になったら接続先自体を複製すればよい（同じ URL で別デフォルトの接続先を2つ作れる）。

### Q1-2. `imagePresets.ts` → `promptTags.ts` にリネームし中身を差し替え

`git mv src/lib/imagePresets.ts src/lib/promptTags.ts` の上で、ファイル全体を次の内容にする
（`StylePreset`/`STYLE_PRESETS`/`PRESET_TOKENS`/`stripPresetTokens`/`applyStylePreset` を削除し、
`ensureTags` は**一字も変えずに**残し、`combineWithDefaults` を追加）:

```ts
/**
 * prompt に pins のタグ（カンマ区切り）が欠けていれば末尾に補う。
 * 比較はトークン単位の完全一致（trim・小文字）。起案（LLM）がプロンプトを全文置換した際に、
 * LoRA トリガー・表情タグ等の固定タグが消えるのを防ぐために使う。
 */
export function ensureTags(prompt: string, pins: string): string {
  const have = new Set(
    prompt.split(',').map((t) => t.trim().toLowerCase()).filter(Boolean),
  )
  const missing = pins
    .split(',')
    .map((t) => t.trim())
    .filter((t) => t && !have.has(t.toLowerCase()))
  if (missing.length === 0) return prompt
  return prompt ? `${prompt}, ${missing.join(', ')}` : missing.join(', ')
}

/**
 * 接続先のデフォルトタグ（品質・画風・LoRA トリガー等）をユーザープロンプトの先頭に結合する。
 * ユーザー側にデフォルトと同一のタグ（カンマ区切りトークン単位・trim・小文字の完全一致）が
 * 既に含まれていれば除去してから結合する（"masterpiece, masterpiece" のような重複を防ぐ）。
 * defaults が空/未設定なら user を trim して返すだけ。
 */
export function combineWithDefaults(defaults: string | undefined, user: string): string {
  const d = (defaults ?? '').trim().replace(/,\s*$/, '')
  if (!d) return user.trim()
  const defaultTokens = new Set(
    d.split(',').map((t) => t.trim().toLowerCase()).filter(Boolean),
  )
  const rest = user
    .split(',')
    .map((t) => t.trim())
    .filter((t) => t && !defaultTokens.has(t.toLowerCase()))
    .join(', ')
  return rest ? `${d}, ${rest}` : d
}
```

注意:
- 重複除去は**完全一致のみ**。自然文プロンプト（openai-image でよくある文章形式）はカンマで割っても
  デフォルトタグと一致しないため、事実上素通りして先頭結合だけが効く（意図どおり）。
- `ensureTags` の import 元は `ImageGenModal.tsx` のみ。リネームに伴い import パスを
  `'../lib/imagePresets'` → `'../lib/promptTags'` に変更する（Q4-1 参照）。

## Q2: 生成時結合（imageGen.ts）

### Q2-1. `generateImage` で結合

[imageGen.ts](../src/lib/imageGen.ts) の `generateImage` を次のように変更（結合はここ**1箇所のみ**。
`generateComfy`/`generateOpenAiImage`/`fillWorkflow` は無変更）:

```ts
import { combineWithDefaults } from './promptTags'

/** プロバイダ種別を吸収して1枚生成する。接続先のデフォルトタグをここで結合する。失敗は throw（呼び出し側で表示） */
export async function generateImage(p: ImageProvider, req: ImageGenRequest, signal?: AbortSignal): Promise<Blob> {
  const merged: ImageGenRequest = {
    ...req,
    prompt: combineWithDefaults(p.defaultPositive, req.prompt),
    negative: combineWithDefaults(p.defaultNegative, req.negative ?? '') || undefined,
  }
  if (p.kind === 'comfyui') return generateComfy(p, merged, signal)
  return generateOpenAiImage(p, merged, signal)
}
```

（`ImageJob.prompt` には結合前のユーザープロンプトが入ったままになる＝決定事項どおり）。

## 落とし穴・注意

- **`ensureTags` を消さない**。`imagePresets.ts` の削除対象はスタイルプリセット系のみで、`ensureTags` は
  pinTags（V5c）の現役機構。リネーム後の import パス更新を忘れると build が落ちるので気付けるが、
  誤って関数ごと消すと立ち絵起案で表情タグが消える回帰になる。
- **`ImageJob.prompt` に結合結果を入れない**。`applyImageJobResult` が挿絵採用時に `job.prompt` を
  `SceneIllustration.prompt` へ記録する。ここに定型タグが混ざると記録・ギャラリー表示が汚れる
  （決定事項「ジョブ・挿絵記録に残すプロンプト」参照）。
- **既存接続先の `defaultPositive`/`defaultNegative` は undefined**。UI（`value={... ?? ''}`）・
  結合ヘルパ（`defaults ?? ''`）の両方で undefined 安全にする。
- **挙動変更（ユーザー報告事項）**: 既存ユーザーは更新後、接続先にデフォルトタグを設定するまで
  品質タグ無しで生成される（自動移行しない）。実装報告時に「⚙ 設定 → 接続先のデフォルトタグ」を
  設定するよう必ず案内すること。
- `exportBundle`/`importBundle`/セッションカードは `imageProviders` を一切含めない（既存方針）ため変更不要。
- `testImageProvider` は生成をしないため結合不要（変更しない）。
