## FB8-A 実装詳細（実装済み・2026-07-21）

### #13 数値入力の共通部品化（`NumberInput`）
- 新規 `src/components/NumberInput.tsx`。`ReaderSettings` の `RsField` が持っていた「フォーカス中はローカル文字列で保持し blur/Enter で確定＋クランプ」パターンを一般化した共通部品。`value:number`/`onChange:(v:number)=>void`＋`min?`/`max?`/`step?`/`integer?`。**空文字を一時的に許容**するので「0 を backspace で消してから 1 を打つ」ができる（`Number('')` が 0/NaN に化けて即スナップする問題を解消）。空のまま・非数値で確定した場合は直前の値へ戻す。
- 適用先（必須数値欄のみ）: `RsField`（自身が内部で使用）／`StatusPanel`（スタット・カウンター手動編集4欄）／`SessionEditor`（現在の日）／`WorldEditor`（条件しきい値 stat/counter・N人ぴったりの n・開始日・スタット初期値）／`SceneReviewModal`（変動幅 delta・加算量 amount）。
- **触らない**: `min/max/deltaMin/deltaMax/amountMin/amountMax`・イベント Day・総日数（`=== '' ? undefined/null` で既に空許容済み）／時間帯などのプルダウン（`<select>`）／temperature・maxTokens（スライダーのみでテキスト入力なし）。
- クランプ方針は呼び出し側の既存規約を維持: StatusPanel は保存時に store（`applyStatusEdit`）でクランプ・実績再評価する設計なので `NumberInput` に min/max を渡さない（手動編集＝ユーザー主権）。N人・開始日は `min={1} integer`、加算量は `min={0} integer`。
- 注意: onChange の発火が「毎キーストローク」から「blur/Enter 確定時」へ変わる。すべて draft／state 編集で確定タイミングが問題にならない箇所のみ（本編ストリーミング等の即時反映系には未使用）。

### #4 空シーンのタイトルが残る
- 原因: `ChatPanel.tsx` のシーン見出し表示条件 `showDivider = hasRealContent || !!sc.summary || session.scenes.length > 1`。末尾の `session.scenes.length > 1`（複数シーンあれば無条件で見出し）が、本文を全削除した空シーンでも「📖 タイトル」だけ残す原因だった。
- 修正: `showDivider = hasRealContent || !!sc.summary` に変更。健全なシーンは本文か要約を必ず持つのでこれで十分。Scene オブジェクト自体は削除しない（`currentSceneId`・タイムラインと結合するデータ層の変更は危険なので表示層のみ直す）。

### #9 ツリーリンクのスクロールずれ
- 原因（推定）: `navigateToNode` の `scrollTarget` 消化で `scrollIntoView({block:'center'})` した後、対象より上の挿絵・背景画像が遅れて読み込まれレイアウトが伸び、中央からずれる（間欠的・画像依存）。
- 修正: 中央合わせの約240ms後に、`cancelled` ガード付きで**1回だけ再中央寄せ**して補正。effect の cleanup でタイマーを解除。低リスクな微調整で、効果の目視確認はユーザーに委ねる（検証ワークフローの分業方針）。

### #11 「当事者」→「主要登場人物」
- UI表示のみ置換（`WorldEditor` の「主要登場人物にする」チェックボックス＋実績/エンディング/イベントの説明文3箇所、`SceneReviewModal` のエピローグ人選プルダウン説明）。
- 内部名（`Clause.subject`・`parties`/`PartyRef`/`RoleParty`・store/types/docs のコメント）は据え置き。改名は非表示・churn リスクのみで無益。今後 UI 文言を足す時も「主要登場人物」を使う。

## FB8-B 実装詳細（実装済み・2026-07-22）

### #3/#15 完結分岐のロック＋「⑂ ここから分岐して続ける」
- **完結判定を共通化**: `store.ts` に純関数 `isSessionFinalized(s)`（export）を追加＝`ending` があり、そのエピローグシーンに `endedAt` が付いた状態。ChatPanel の `isFinalized` と同義。
- **UI ロック（`ChatPanel`）**: `isFinalized` 時に、コンポーザーの「開始/続ける・やり直す・続きを生成・選択肢を生成」と入力欄（textarea＋送信）・選択肢ボタンを出さない。入力欄の位置には `.finalized-lock` バナー（「🏁 この物語は完結しました。続きを描くには…」）を出す。メッセージ操作行も生成系（ここから＝`regenerateFrom`／⑂分岐＝`branchFromMessage`／選択肢を生成）を隠し、編集・削除・挿絵は残す。挿絵・背景生成・シーン編集（閲覧）・ギャラリー・分岐ツリーは可能なまま。
- **継続の一本化**: シーン終了ボタンの位置に `isFinalized` なら「⑂ ここから分岐して続ける」を出す＝`branchToContinue()`。元の 🏁 ノードのスナップショットには完結が残り、`ending` により保護（`subtreeHasProtection`）されるので温存され、続きは 🏁 の**兄弟**として枝分かれする。
- **`branchToContinue()`（store）**: 完結済みのときだけ、(1) `updateSession` でエピローグシーンの `endedAt` **だけ**解除する（`ending` は残す）。これにより分岐先は **`isEpilogue` のまま（未完結）**＝普通のシーンにならず「🏁 物語を完結する」で再び締められる（不具合修正1）。(2) 続きノードを **🏁 の親（＝分岐点）の子＝🏁 の兄弟**として積むため、`recordCheckpoint` の直前に `currentId` を `🏁.parentId` へ移す（`recordCheckpoint` は `currentId` の子に積むため）。これでツリーが一直線でなく**枝分かれ**として表示される（不具合修正2）。`before`（完結状態）と現在（`endedAt` 解除後）は `stableSessionJson` が異なるので dedupe されない。`endingRecords`（周回横断の到達記録）は**消さない**（結末に到達した事実は残す）。
  - **設計変更の経緯（不具合修正・2026-07-22）**: 初版は `ending` を丸ごと消して 🏁 の子に積んでいた → 分岐先が普通の状態になり「完結する」が出ない／ツリーが一直線、という2点をユーザー報告で修正。
- **store ガード（多重防御）**: `send`/`continueStory`/`continueLast`/`regenerate`/`regenerateFrom` の冒頭で `isSessionFinalized(s)` なら早期 return。UI で隠していても `Ctrl+G`（続ける）等のショートカット・プログラム経路から完結分岐に生成が走らないようにする。

### #14 レビュー完了モーダルを該当セッション表示時のみ
- `SceneReview` に `sessionId` を追加し、`prepareSceneReview` で `s.id` を刻む。
- `App.tsx` の描画条件を `sceneReview && view === 'sessions' && sceneReview.sessionId === activeId` に変更。**Play を開いていて、かつそのセッションを表示中のときだけ**モーダルを出す。他画面・他セッション表示中は `sceneReview` を保持したまま待たせ、戻ってきたら表示する（生成の実時間は変わらないが、無関係な画面に割り込まなくなる＝#1 の体感悪化も緩和）。

## FB8-C 実装詳細（実装済み・2026-07-22）

決定（ユーザー合意）: パラメータ範囲は **ステップ・サンプラー・CFG・ネガティブ・自由サイズ**（シードは出さない＝毎回ランダム）。

### #5 ModelsLab 対応（`kind: 'modelslab'`）
- `types.ts` の `ImageProviderKind` に `'modelslab'` を追加。`ImageProvider` は既存フィールドを流用（`apiKey`＝body の `key`／`model`＝`model_id`〔空でデフォルト〕／`baseUrl`＝`https://modelslab.com/api/v6`）。`defaultPositive`/`defaultNegative` も有効。
- `imageGen.ts` に `generateModelslab`：`POST {base}/images/text2img` に `{key, model_id?, prompt, negative_prompt, width, height, samples:1, num_inference_steps, guidance_scale, scheduler, safety_checker:false, enhance_prompt:false, seed:null}`。`status:'processing'` の間は `fetch_result`（無ければ `/images/fetch/{id}`）を `success` まで最大5分ポーリング（`eta` 秒スリープ・abort 対応）。出力 URL の先頭を `appFetch`→Blob（Web は CORS で失敗しうる＝デスクトップ版で回避）。`generateImage` の分岐に追加。
- `testImageProvider`：ModelsLab は無料の疎通確認エンドポイントが無い（生成はクレジット消費）ため、API キー有無だけ確認する soft チェック。
- `MODELSLAB_SCHEDULERS`（export）＝サンプラー候補リスト。`newImageProvider('modelslab')` の既定。`ImageProviderSettings` に「ModelsLab を追加」ボタン・API キー・モデルID欄・バッジ・デフォルトネガティブ欄を追加。

### #6 生成パラメータ（種別ごとに出し分け）
- `ImageGenRequest`／`ImageJob`／`startImageJob`／`runImageJobLoop` に `steps?`・`sampler?`・`cfg?` を追加。ComfyUI/OpenAI 経路は未使用（`generateModelslab` のみ読む）。
- `ImageGenModal`：`isModelsLab`／`showNegative`（＝comfyui or modelslab）で欄を出し分け。ネガティブは comfyui＋modelslab、ステップ/サンプラー（`MODELSLAB_SCHEDULERS` のプルダウン）/CFG は modelslab のみ。**自由サイズ**＝サイズ選択に「カスタム（数値指定）」を追加し、幅・高さを `NumberInput`（64〜2048・64刻み・FB8-A の部品再利用）で指定。全種別共通。
- **ComfyUI はワークフロー JSON のまま**（ステップ/サンプラーは JSON 側）。ご要望は「ワークフローを組めない画像 API 側でパラメータを選びたい」だったため、新パラメータ欄は ModelsLab に付けた。

### #7 会話折りたたみUIの作り直し（`ChatPanel` + `chat.css`）
- **見出しの折返し崩れ修正**: `.scene-divider` を `flex-wrap:nowrap`、`.scene-title`/`.scene-cast` を `ellipsis`（`min-width:0`＋`overflow:hidden`）、`.scene-toggle` を `flex-shrink:0`＋`white-space:nowrap`。タイトルが長くてもトグルの位置・サイズが変わらない。

### #8 分岐ツリーで現在パス以外を非表示（`BranchTreeModal`）
- ツリータブに**非破壊トグル**「現在の分岐だけ表示（他 n 件を隠す・消さない）」を追加（`onlyCurrentPath` state）。ON で `buildGraph` へ渡すノードを `currentPathIds`（root→currentId）だけに絞り、一直線表示にする。既存の「✂ 現在の分岐だけ残す（削除）」＝`pruneToCurrentPath` とは別物（隠すだけ・いつでも戻せる）。表示は `pruneCount > 0`（off-path がある）時のみ。

### #2 画像→本文リンク（`GalleryModal` + store）
- store に `revealMessage(sessionId, messageId)`＝`scrollTarget` を seq 付きでセットするだけの軽量アクション（`navigateToNode` の末尾処理と同型）。
- **両タブ・全画像**（`GalleryThumb`＝挿絵／`BackgroundThumb`＝背景／`RecordThumb`＝すべての記録）に「📖 本文へ」ボタン（`onGoToText`）。押すと本文が該当箇所へスクロール（畳まれたシーンは `scrollTarget` 消化側〔ChatPanel〕が自動展開）。
- **飛び先の解決は `jumpTargetFor(messageId?, sceneId?)` に一本化**（`GalleryBody` 内・両タブ共用）: ①アンカー `messageId` が現在の分岐に現存すればそこ ②消えていても同じシーンが残っていればそのシーン先頭の本文（`assistant` の実本文を優先）③どちらも無ければ `undefined`＝**ボタンを出さない**。
  - ③が要るのは「すべての記録」が**分岐から独立した永続アルバム**だから（別分岐・削除済みシーンの記録が並ぶ）。飛べない先へ誘導しないため、既存の再生成ボタン（`canRegenerate`）と同じく現存チェックで出し分ける。
  - 背景は場面単位でアンカーを持たないため、②の経路でそのシーン先頭へ飛ぶ。

## FB8-E の方針（合意済み 2026-07-23・UI全面見直しへ拡大・**E1〜E4 実装済み**）

当初の「設定のわかりやすさ（#10/#12）」を、ユーザー要望により **UI全体の根本見直し**へ拡大。headless Chrome で全26画面を撮影する包括レビューを実施し、指摘と対案を提示→以下で合意した。

### 合意事項（ユーザー回答 2026-07-23）
1. **ドック切替は A案**: トップバーの5トグルを廃し、ドック側に常設のラベル付きタブ（状態・発見・ギャラリー・分岐・ジョブ）を持たせる。トップバーは「パネル開閉」1ボタンだけ残す。
2. **文字記号・絵文字は全廃**: `⑂` は SVG 化しても使わない（意味が読めない・デザインが好みでない）。🏁🎮🌍📖🎲✨⚙✎✕★☆▶✂↩ 等の**絵文字・装飾記号をすべて icons.tsx の SVG＋テキストラベルへ置換**。アイコン単独を許すのは ×閉じる・⋯メニュー・✎鉛筆（hover編集）など普遍的なものだけで、必ず tooltip を持つ。矢印 `→`（関係の向き）などの約物・句読点的用法は対象外。
3. **条件エディタは文章形リライト**（ロジック無改修）: `[ステータス▾][位階▾][>=▾][2]` の無ラベル列を「〜が 2 以上 になったら」と読める並び＋固定助詞テキストに組み替える。
4. **実施順**: E1 → E2 → E3 → E4。
