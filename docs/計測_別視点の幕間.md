# 計測_別視点の幕間

同じ場面を主人公以外の視点で描き直す機能（[`設計_物語の簡素化.md`](./設計_物語の簡素化.md) F6）の実測記録（2026-09-07）。

> ## 結論
>
> 1. **「言い換えに潰れる」という事前の心配は、起きなかった。** 関係 prose が薄く、差分要求の指示も無い最弱条件でも、読んだ4件すべてに主人公との受け止めの食い違いが出ている。**素材が勘違い系の構造（主人公が淡々と有能なことをして、本人は何とも思っていない）を持っていれば、LLM は放っておいてもギャップを書く**
> 2. **関係 prose の濃さは「ギャップの有無」ではなく「具体性」に効く。** 濃い条件は関係 prose に書かれた内容（過去の類似場面）を持ち込む
> 3. **捏造は稀。** 元の場面に無い出来事の混入は 30件中 1〜2件（3〜7%）で、条件による差は無い
> 4. **実装で対処が要るのは見出しの混入。** 「# 千夏の視点」のような見出しを本文へ混ぜるのが 16/120（13%）
> 5. **⚠ この構文は安い判定 LLM では測れなかった。** 段階指標は 0/4 の二値に退化し、**両方向に誤る**。数字はすべて破棄し、手読みと語の出現だけを採用した（§4）
>
> 実コスト: **$0.095**（491呼び出し）。ただし**そのうち判定ぶんは無駄になった**

---

## 1. 何を測ろうとしたか

主人公視点で書かれた場面を、別の登場人物の視点から書き直させたとき、**「同じ出来事・同じ感情価・人称だけ違う」言い換えに潰れないか**。潰れるとしたら、それを防ぐ梃子は何か。

### 1.1 条件（2×2＋対照2種）

| 軸 | 水準 |
|---|---|
| 関係 prose（`relation[千夏 → 悠]`） | **薄い**（「同じ写真部のクラスメイト。ときどき話す」）／**濃い**（「自分にはできないことを何でもない顔でやってしまう人だと思っている…」） |
| 差分要求の指示 | **なし**（「千夏の視点から書き直してください」だけ）／**あり**（「悠自身の受け止め方とは食い違う点を必ず1つ以上含めて」） |

対照は2種類。

- **対照1**: 元の本文をそのまま渡す（判定器の偽陽性を測る）
- **対照2**: 「解釈・評価・感想・内面を一切書くな」と指示して生成した言い換え（＝**潰れた状態そのもの**。これが本来の負の対照）

### 1.2 素材

元の場面は**手書きで固定**した（条件間で共通にするため生成しない）。悠が①散らばった30枚を2分で番号順に並べ直し ②千夏が言いかけてやめたとき待ち ③開いていた窓の鍵を閉め ④傘が無くても「まあいい」と流す——**4つとも本人は何とも思っていない**、という構造にしてある。

| | |
|---|---|
| 生成モデル | `deepseek/deepseek-v4-flash`・温度 0.9 |
| 判定モデル | `qwen/qwen3-30b-a3b-instruct-2507`・温度 0・JSON スキーマ |
| 回数 | 30回/セル（生成120＋対照60） |

## 2. 手読みで分かったこと（採用する所見）

各条件の**先頭4件**（スコアで選別していない）を全文読んだ。

### 2.1 対照2（言い換え強制）は、意図どおり潰れている

> 放課後の教室。千夏はプリントの束を抱えていた。その束が崩れ、床に散らばった。悠がしゃがみ、プリントを拾い集める。悠はプリントの番号を見ながら並べ直した。

4件とも純粋な出来事の記述で、解釈はゼロ。**負の対照として機能している。**

### 2.2 最弱条件（薄い prose・指示なし）でも、ギャップは出た

4件すべてに主人公との受け止めの食い違いがある。

> それはそうだ。でも、普通はそこまでしない。ぐちゃぐちゃになってようが、拾って渡せばそれでいいはずだ。なのに悠は、少しも面倒そうな様子を見せずに、整えてくれた。

> 「番号振ってあったから」／悠はあっさりと言った。まるで何でもないことのように。

> あの窓、昨日も開いてたっけ。よく気づくな、と千夏は思った。

**事前に立てた「言い換えに潰れる」という心配は、この素材では外れた。** 元の場面が勘違い系の構造を持っていれば、視点を移すだけでギャップが生まれる。

### 2.3 濃い prose の効果は「具体性」に出る

> 昨日の部活で悠が見せた、暗室での現像処理の手際よさが頭に浮かんで、まだその悔しさが喉の奥に残っている。

> 自分は、気づいても動かない。悠は気づけばすぐに動く。その差が、また千夏の胸に鈍く響いた。

> 千夏は勝手に感動していた。悠が、たかが一つの開いた窓を覚えていることに。**だが悠にしてみれば、ただ鍵が開いていたので閉めただけ。記憶に残るほどのことではなかった。**

最後の1件は**両者の受け止めの差を明示的に書いており**、勘違い系そのものの形になっている。濃い prose はギャップを生む条件ではなく、**ギャップに固有名詞と履歴を与えるもの**。

## 3. 語の出現による客観指標（採用する所見）

判定 LLM を使わずに数えられるものだけを集計した。

| 指標 | 結果 |
|---|---|
| 元の場面に無い出来事の混入（暗室・現像・大会・去年 等） | **1〜2/30（3〜7%）・条件差なし** |
| 見出しの混入（`#` で始まる） | **16/120（13%）** |
| 主人公を「彼女」と書く（性別の取り違え） | 6/120（5%） |

**捏造は稀。** 設計で心配していた「別視点が勝手に設定を作る」はほとんど起きない。手読みで見つけた「昨日の部活での暗室作業」は、むしろ例外的な1件だった。

**性別の取り違えは素材の欠陥。** 元の場面が悠の性別を明示していないため。実アプリでは `Character` の定義が入るので再現しない見込み。

**見出しの混入だけは実装で対処が要る**（プロンプトで禁じる、または後処理で削る）。

## 4. ⚠ 判定 LLM ではこの構文を測れなかった

**数字はすべて破棄した。** 経緯を残す。

### 4.1 一次判定（C-1）— 対照が壊れた

「解釈の食い違いがあるか」を二値で問うたところ、4条件すべてが 100% に張り付いた。段階化するため「悠が何とも思っていない4つの行為のうち、千夏が特別な意味を持つものとして受け取っているものを挙げよ」に変えたところ、**対照1（元の本文そのもの）が 0.80件/17件も誤検出**した。

原因: 判定器が**文章A（元の本文）にもある記述**「千夏は何か言いかけて、やめた」を、千夏の読み替えの根拠にしていた（誤検出17件のうち「待った」が17件）。

### 4.2 二次判定（C-2）— 対照1は直ったが、両方向に誤る

判定に「文章Aにも同じ記述がある事柄を根拠にしてはいけない」を足したところ、対照1は **0.00/30件** になった。しかし:

| 症状 | 中身 |
|---|---|
| **段階指標が二値へ退化** | `nActs` の分布が 0 と 4 に集中し、1〜3 がほぼ皆無（濃い/あり: 0が11件・4が18件・それ以外1件） |
| **偽陽性** | 対照2（解釈ゼロの言い換え）に 9/30 の陽性。うち8件は **`傘` の語が本文に存在しないのに「傘」を挙げた** |
| **偽陰性** | 手読みした12件のうち、明確なギャップがある11件が `nActs=0` と採点されていた（§2.2・§2.3 の引用はすべて「0件」判定） |

### 4.3 次に測る人へ

- **「解釈が異なるか」は、安い判定器には荷が重い。** 事実の有無（語が出たか・項目が挙がったか）と違い、**同じ出来事に対する評価の差**という関係を読む必要がある
- 段階化のために「4つの行為のどれか」と選択肢を与えたが、**選択肢を与えると全部挙げるか何も挙げないかに退化した**
- 測るなら、①強いモデルを判定に使う ②人手で採点する ③判定器を使わず語の出現だけで測れる指標に絞る、のいずれか。**③が最も安く、実際に §3 はそれで採れている**
- 前2回の実測（`計測_登場制御.md`・`計測_時間と予定.md`）と同じ教訓——**フラグの立った件を人手で読む工程を省くと、結論が反転する**
