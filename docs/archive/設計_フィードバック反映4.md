# 設計: フィードバック反映 第4弾（FB4）

- 日付: 2026-07-12
- 経緯: FB3 実装後の実使用フィードバック第4ラウンド。タイムラインの時間帯まわり（開始時間帯の繰り上がり・イベントの時間帯指定・設定 UI の見逃しやすさ）と、選択肢生成の既定、物語設定欄の整理。
- 進め方: 検討→選択式質問で合意→フェーズ分割実装（各フェーズで tsc/build 検証・コミット）。

## 1. 問題・要望インベントリ（診断つき）

| # | 報告 | 診断・根本原因 | 対応 |
|---|---|---|---|
| FB4-1 | 朝/昼/夜の3区切りで開始時間を「1日目の夜」にすると、次が「1日目の朝」になる（2日目にならない） | **現行コードの繰り上げは正しい**ことを全経路で確認済み（`advanceTimeline`・`startPresetPatch`・`confirmSceneReview`・`SceneReviewModal`・`freshSessionOf` すべて夜→翌日朝を返す）。症状が出るには「夜が区切り配列の末尾以外」のデータが必要。最有力仮説＝**FB2-B（開始時間帯指定）以前に作った世界観で、夜始まりにするため区切りを「夜,朝,昼」の順に定義していた**（この並びだと日付の繰り上がりは昼→夜の間になる）。ユーザー確認待ち。付随して WorldEditor の区切り編集時に `startSlot` がクランプされない潜在バグと、FB2-B 以前の古いコメント（「反映は常に1日目から」）を発見 | A |
| FB4-2 | 選択肢の生成はデフォルトで「AIが適宜」にしたい | `newSession` の既定が `choiceMode: 'off'`。`auto`（不自然な場面では空配列を返すプロンプト）と手動「選択肢を生成」ボタン（FB3-A6）は実装済みで、既定を変えるだけでよい | B |
| FB4-3 | 特別イベントは日付だけでなく時間帯まで指定したい | `ScheduledEvent` は `day?` のみ。発火判定（`nextScheduledEvent`）も日単位 | C |
| FB4-4 | 世界観にデフォルトの進行間隔が欲しい → **検討の結果、機能は既存（開始テンプレートのタイムライン定義）で足りると判明**。実際の問題は「タイムラインのチェックボックスを押さないと項目が出ない＝機能を見逃しやすい」こと | チェック OFF 時に項目を丸ごと非表示にしている（SessionEditor 進行タブ・WorldEditor 開始テンプレートとも） | D |
| FB4-5 | あらすじ・前提／固定メモ／ジャンル・トーンの使い分けの意味は？ 統合すべき？ | 実態: 3つとも同一 system プロンプトの隣接セクション（ジャンル＋あらすじ→【物語設定】、固定メモ→直後の【常に踏まえる重要事項】）。機能差は「見出しラベルの強さ」と「固定メモは RP モードでも注入される」の2点のみ。ただし欄の存在自体が『何を書けば良くなるか』を知らないユーザーへの誘導足場になる | E |

## 2. ユーザー決定事項（2026-07-12 合意）

- **FB4-1**: 区切りの並びは「夜が先頭かも（要確認）」。→ 並び順が原因なら世界観データを「朝,昼,夜」＋開始時間帯=夜へ直せば現行コードで正しく動く。コード側は原因のどちらでも効く**防御的修正**（クランプ＋開始→次シーンのライブプレビュー表示）を入れる。
- **FB4-2**: 既定を `auto` に変更（既存セッション・カセットの設定値は変えない）。
- **FB4-3**: 時間帯は**区切りラベルとの一致**で判定（インデックスでなくラベル＝セッション側で区切りを編集してもズレない。不一致・タイムライン無効時は日のみ判定に graceful degradation）。到来判定は day と同じく「その時間帯**以降**」。
- **FB4-4**: 進行間隔の新機能は**作らない**（既存機能で充足）。代わりにタイムライン設定欄を「チェック OFF 時は非表示」→「**常に表示・グレーアウト（操作不可）**」に変更。OFF の間は内容が反映されないことは従来どおり（`enabled`/`startPreset.timeline` の有無がゲート）。
- **FB4-5**: **3欄維持＋説明強化**。placeholder とヘルプ文で「何を書く欄か・いつ注入されるか」を明示する。統合はしない。

## 3. FB4-A: タイムライン開始時間帯の防御的修正

1. **クランプ**: `startPresetPatch`（store.ts）で `startDay = max(1, …)`・`startSlot = clamp(0 … slots.length-1)`。`freshSessionOf`（cards.ts）の巻き戻しにも同じクランプ。WorldEditor の区切り単位 CsvInput 変更時に `startSlot` を範囲内へクランプ。
2. **ライブプレビュー行**: タイムライン設定欄の末尾に「開始: 1日目 夜 → 次のシーンで: 2日目 朝」を常時表示（`timeLabelOf`＋`advanceTimeline` で算出）。区切りの並び順ミス（夜先頭など）が保存前に見える。SessionEditor 進行タブ（開始後は「現在 → 次のシーンで」表記）と WorldEditor 開始テンプレートの両方。
3. **古いコメント修正**: types.ts の WorldStartPreset コメント「currentDay/currentSlot は持たない＝常に1日目から開始」、store.ts の `startPresetPatch` docstring「反映は常に1日目から」→ startDay/startSlot 対応後の実態に合わせる。

## 4. FB4-B: 選択肢生成の既定を「AIが適宜（auto）」に

- store.ts `newSession` の `choiceMode: 'off'` → `'auto'`。
- 既存セッションは不変。カセットの `session.choiceMode` も取込値を尊重（`freshSessionOf` は進行設定を保持）。

## 5. FB4-C: 特別イベントの時間帯指定

- types.ts `ScheduledEvent` に `slot?: string`（区切りラベル。未指定＝日のみで判定）を optional 追加 → persist キー据え置き。カード入出力は素通し（`parseWorldCard` は scheduledEvents を配列ごと受けるため追加作業なし）。
- store.ts `nextScheduledEvent(session, world, nextDay, nextSlot)`:
  - ラベル→インデックス解決は `session.timeline.slots.indexOf(e.slot)`（不一致は -1＝時間帯条件なし）。
  - 到来判定: day 条件は従来どおり。時間帯付きは「指定日の当日はその時間帯以降のみ」（日超過済みは常に到来、日指定なし＋時間帯は毎日その時間帯以降が対象）。タイムライン無効（nextSlot=null）では時間帯条件を無視。
  - ソートを (day, 時間帯インデックス) 順に。
  - 呼び出し元2箇所（`prepareSceneReview`・`startStory`）に nextSlot/currentSlot を追加。
- WorldEditor 特別イベント行に時間帯セレクト（選択肢は開始テンプレートの区切り、無ければ既定の朝/昼/夜。現区切りに無いラベルは「（区切りに無し）」表示で保持）。

## 6. FB4-D: タイムライン設定欄のグレーアウト化

- SessionEditor 進行タブ・WorldEditor 開始テンプレートとも、`{enabled && <div className="timeline-box">…}` の条件レンダリングをやめ、**常時 `<fieldset className="timeline-box" disabled={!enabled}>`** で描画。fieldset の disabled 伝播で内部の input/select/button/CsvInput が一括操作不可になる。
- WorldEditor は `sp.timeline` が undefined の間も表示用ドラフト（直近の編集値 or 既定の朝/昼/夜）を描画。チェック OFF で `timeline: undefined` に戻す際、編集値を ref に退避し再チェックで復元（エディタを閉じるまで）。
- CSS（panels.css）: fieldset 既定スタイルのリセット（`min-width: 0` 含む）と `.timeline-box:disabled { opacity: .5 }`。

## 7. FB4-E: 物語設定3欄の説明強化

- SessionEditor 基本タブ・WorldEditor 開始テンプレートの両方で、各欄に役割と注入先を明示:
  - ジャンル・トーン: 「作風・温度感を一言で。毎回【物語設定】として AI に渡される」
  - あらすじ・前提: 「この物語で何が起きるかの前提。世界の説明は世界観素材へ、絶対に守らせたい指示は固定メモへ」
  - 固定メモ: 「【常に踏まえる重要事項】として毎回注入。文体・禁則などの指示向き。RP モードでも有効な唯一の自由記述欄」
