> **⚠ 撤去済み（2026-08-01）**: 本書のうち**立ち絵・表情差分・シーン背景・ステージ表示に関する部分はコードから全削除**されました。
> 製品の位置づけが VN ではなく**「挿絵入りの本」**（＝事前に絵素材を用意させるモデルを採らない）と決まったためです。
> 判断の根拠は `docs/公開計画_マネタイズと配布.md`／`docs/設計_環境音ピン_実験.md`（残す視覚聴覚要素の判定軸）。
> 「場所の絵」が欲しくなった場合は独立機能を作らず**挿絵に吸収する**方針です。本書は経緯の記録として残しています。

G1〜G4（`docs/設計_画像生成連携.md`）の次段。没入の核である「視覚の常在感」（立ち絵・表情差分・背景）と、生成体験の改善（品質タグ・複数枚生成・バックグラウンド化・ギャラリー）を扱う。

## 合意済みの決定事項（2026-07-04）

| 論点 | 決定 |
|---|---|
| 表情切替のトリガー | **方式A: 裏方LLMが毎応答後に感情を判定**（シーンタイプ／ディレクターには一切依存しない。ユーザーはストーリーモードでディレクターを切る運用のため） |
| 品質タグ・スタイル | **プロンプト欄・ネガティブ欄に直接書き込む（prefill）**。生成時の裏側結合ではなく、ユーザーが欄内で編集・削除できる形 |
| バックグラウンド生成の対象 | **挿絵・アバターの両方**。さらに**枚数指定でシード違いの複数枚生成**＋**候補から選択するUI** |
| 起案 maxTokens | 大幅拡大（4000）。reasoning系モデルが reasoning でトークンを食い潰す事例への対策 |
| 挿絵の起案文脈 | 直近6件固定ではなく**現在シーンの本文全体**（文字数予算で末尾からキャップ） |
| 実装の進め方 | フェーズ V1→V2→V3→V4 の順。**各フェーズごとに tsc → build → Preview検証 → commit → push**。1ターンで作りすぎない |

## フェーズ一覧

- **V1**: プロンプト品質改善（スタイルプリセット prefill・maxTokens 4000・シーン全文起案）
- **V2**: バックグラウンド生成ジョブ（store化・複数枚シード違い・候補選択UI・挿絵/アバター両対応）
- **V3**: セッション内画像ギャラリー
- **V4**: 立ち絵・表情差分・背景（ステージ表示＋裏方感情判定）

永続化: 追加フィールドは**すべて optional** にし、persist キーは `ai-storytelling-store-v3` のまま変えない（クリーンブレイク不要）。読む側は必ず `?? []` / `?? undefined` で防御する（旧データにフィールドが無い）。

## V1: プロンプト品質改善

### V1-1. スタイルプリセット（アニメ/実写）と品質タグの prefill

新規ファイル `src/lib/imagePresets.ts`:

```ts
export interface StylePreset {
  id: 'anime' | 'realistic'
  label: string          // 'アニメ系' | '実写系'
  positive: string       // prompt 欄の先頭に足すタグ列
  negative: string       // negative 欄の先頭に足すタグ列
}

export const STYLE_PRESETS: StylePreset[] = [
  {
    id: 'anime',
    label: 'アニメ系',
    positive: 'masterpiece, best quality, very aesthetic, absurdres',
    negative: 'low quality, worst quality, bad anatomy, bad hands, extra fingers, missing fingers, extra digits, jpeg artifacts, signature, watermark, username',
  },
  {
    id: 'realistic',
    label: '実写系',
    positive: 'photorealistic, RAW photo, masterpiece, best quality, 8k uhd, film grain',
    negative: 'low quality, worst quality, bad anatomy, bad hands, extra fingers, missing fingers, anime, cartoon, illustration, 3d render, painting, sketch, watermark',
  },
]

/**
 * prompt/negative の先頭にプリセットタグを適用する。
 * 冪等にするため「既知の全プリセットのタグを一旦除去 → 選択プリセットを先頭に付加」の順で行う。
 * タグ除去はカンマ区切りトークン単位の完全一致（trim・小文字比較）。部分一致で消してはいけない
 * （例: ユーザーが書いた "best quality ribbon" のような複合語を壊さない）。
 */
export function applyStylePreset(
  current: { prompt: string; negative: string },
  styleId: 'anime' | 'realistic' | '',
): { prompt: string; negative: string }
```

`applyStylePreset` の実装指針:
1. `STYLE_PRESETS` 全部の positive/negative をトークン集合にする（`split(',')` → trim → 小文字）。
2. current の prompt/negative をカンマで分割し、集合に含まれるトークンを除去（空トークンも除去）。
3. styleId が空でなければ該当プリセットのタグ列を**先頭に**結合（`preset + ', ' + rest`。rest が空なら preset のみ）。
4. styleId が空（「スタイルなし」）なら除去のみ。

**ImageGenModal の変更**:
- `useState` に `styleId` を追加。初期値は store の `lastImageStyle`（下記）。
- 接続先・サイズの行に「スタイル」select を追加（選択肢: スタイルなし / アニメ系 / 実写系）。
- select 変更時: `applyStylePreset({prompt, negative}, newStyleId)` で両欄を書き換え、`setLastImageStyle(newStyleId)` を呼ぶ。
- **✨起案の完了後**にも同じ適用を行う（起案結果がプロンプト欄を置き換えた直後に、選択中スタイルのタグを先頭に付け直す）。起案プロンプト側（`illustrationPromptSystem`）には既に「品質タグは入れない」指針があるので変更不要だが、モデルが混ぜてくることがあるため、適用時の除去ステップがその保険になる。
- negative 欄は現在 `provider?.kind === 'comfyui'` のみ表示だが、**state としては kind に関わらず保持・適用**する（openai-image では送信されないだけ。既存の `generateImage` は negative を openai 経路で無視している——この挙動は変えない）。

**store の変更**: `lastImageStyle?: 'anime' | 'realistic' | ''` を追加（persist 対象。partialize に追加）。アクション `setLastImageStyle(v)`。optional なので persist キーは v3 のまま。

**初期プロンプトとの関係**: `initialPrompt`（キャラ imagePrompt 等）でモーダルが開いたとき、マウント時に `lastImageStyle` が非空なら一度 `applyStylePreset` を適用してから表示する（開いた瞬間から品質タグ入りの欄が見える）。

### V1-2. 起案 maxTokens の拡大

（注: 作業ツリーに `600→1200`＋本文0文字時のエラーメッセージ追加の未コミット変更が既にある。この変更は活かしたまま 4000 に上げる。本文0文字ハンドリングは残す。）

### V1-3. 挿絵起案にシーン本文全体を渡す

`ChatPanel.tsx` の `draftContext.user`（現在 `slice(-6)`）を変更:

```ts
// 現在シーンのメッセージのみに絞る（旧データは sceneId 無しがあるため || !m.sceneId を維持）
const sceneMsgs = session.messages.filter(
  (m) => (m.sceneId === scene.id || !m.sceneId) && !isMarker(m) && m.content.trim(),
)
// 末尾から文字数予算でキャップ（推定 8,000 文字 ≒ 4,000〜5,000 トークン程度。起案には十分）
const budget = 8000
const recent: string[] = []
let used = 0
for (let i = sceneMsgs.length - 1; i >= 0; i--) {
  const c = sceneMsgs[i].content
  if (used + c.length > budget && recent.length > 0) break
  recent.unshift(c)
  used += c.length
}
```

## V2: バックグラウンド生成ジョブ（複数枚・候補選択）

### 目的

- モーダルを閉じても生成が続く。完了したら候補から選んで採用できる。
- 枚数（1〜4）を指定し、**シード違いで複数枚**生成して選べる。

### V2-1. データモデル（store・**永続化しない**）

`src/types.ts` には入れず、store 内かつ `src/lib/imageJobs.ts` に型を置く（Blob を含むため localStorage に絶対に入れない。**partialize から必ず除外**）:

```ts
export type ImageJobTarget =
  | { type: 'scene-illustration'; sessionId: string; sceneId: string; messageId?: string }
  | { type: 'character-avatar'; characterId: string }
  | { type: 'persona-avatar'; personaId: string }
  // V4 で追加: { type: 'character-sprite'; characterId: string; emotion: string }
  //            { type: 'scene-background'; sessionId: string; sceneId: string }

export interface ImageJob {
  id: string
  label: string                 // 通知・一覧表示用（例: '挿絵: 放課後の屋上', 'アバター: 綾瀬'）
  target: ImageJobTarget
  providerId: string
  prompt: string
  negative?: string
  width: number
  height: number
  count: number                 // 1〜4
  status: 'running' | 'selecting' | 'error' | 'canceled'
  results: Blob[]               // 完了した分から順次 push（進捗表示に使う）
  error?: string
  createdAt: number
}
```

- ジョブ完了（全枚数生成 or 一部成功で打ち切り）→ `status: 'selecting'`。**1枚でも自動採用しない**（採用は常にユーザー選択。品質が悪ければ破棄したいため）。
- AbortController は store に入れず、`imageJobs.ts` のモジュールレベル `Map<string, AbortController>` に持つ。
- objectURL は表示コンポーネント側で `useMemo`＋`useEffect` cleanup で管理（Blob から都度生成・revoke）。store には Blob のみ。

### V2-2. store アクション

```ts
imageJobs: ImageJob[]                     // 初期値 []。partialize から除外!!
startImageJob(args: {...ImageJob の入力部分}): string   // jobId を返す
cancelImageJob(jobId: string): void       // abort → status 'canceled'
dismissImageJob(jobId: string): void      // 一覧から除去（Blob参照も落ちる）
applyImageJobResult(jobId: string, index: number): Promise<void>  // 採用
```

`startImageJob` の実装指針:
- ジョブを `imageJobs` に追加後、**非同期ループを fire-and-forget** で回す（async 即時関数）。`count` 回、`generateImage(provider, req, signal)` を**直列**に呼ぶ（ComfyUI は並列に弱い・openai-image もレート制限があるため直列で良い）。シードは `fillWorkflow` が呼び出しごとに乱数生成するので追加対応不要。openai-image はシード概念がないのでそのまま count 回呼ぶ。
- 各枚完了ごとに `set` で `results` に push（進捗が UI に出る）。
- 1枚も成功せず失敗 → `status:'error'` に error message。一部成功して途中失敗 → 成功分で `'selecting'` に落とし、error にメッセージを残す（UI で「2/4枚で失敗: …」表示）。
- AbortError は `'canceled'`。
- provider はジョブ開始時点の `imageProviders.find` を実行時に都度引く（削除されていたらエラー化）。

`applyImageJobResult` の分岐:
- `scene-illustration`: `putImage(blob)` → `addIllustration(sessionId, sceneId, { id, imageId, prompt: job.prompt, messageId: job.target.messageId, createdAt })`。**messageId はジョブ開始時に確定させて target に保持**（完了時に取り直すと、生成中に進んだ会話の末尾に付いてしまう。開始時のアンカーが正しい）。
- `character-avatar` / `persona-avatar`: `normalizeImage(blob, 512)` → `putImage` → `updateCharacter(id, { avatar: {...現在の avatar, imageId} })`（persona も同様）。対象素材が削除済みならエラー表示。
- 採用後はジョブを自動 dismiss（残す必要なし）。採用しなかった Blob はそのまま破棄で良い（putImage しない）。

### V2-3. ImageGenModal の改修

- Props 変更: `onAccept: (blob, prompt) => Promise<void>` を **`target: ImageJobTarget`** に置き換える。呼び出し元（ChatPanel / AvatarField）は target を組み立てて渡すだけになり、保存ロジックは store の `applyImageJobResult` に集約される。
- 「枚数」select（1〜4枚）を追加。
- 「🎨 生成」→ `startImageJob` を呼んで**モーダルは開いたまま**ジョブの進捗を購読表示（`imageJobs.find(j => j.id === myJobId)`）。「閉じる」を押してもジョブは走り続ける。
- モーダル内でジョブが `'selecting'` になったら候補サムネイルをグリッド表示 → クリックで拡大 → 「✔ この画像を使う」で `applyImageJobResult`。
- モーダルを閉じた後の採用経路は V2-4 のジョブパネルから行う（同じ `applyImageJobResult` を呼ぶだけ）。

**AvatarField の注意（実装前に必ず確認すること）**: CharacterEditor / PersonaEditor が「ローカル draft を編集して保存ボタンで store 反映」方式の場合、バックグラウンド完了時に `onChange` へ書き戻せない（エディタが閉じている可能性がある）。この場合は:
- 既存素材（id が store にある）→ target 方式で store 直接更新。エディタが開いていれば、エディタ側は store の当該素材の avatar 変更を useEffect で draft に取り込む（または avatar だけは store 直接更新と割り切り、draft には avatar を持たせない形にリファクタ）。
- **新規作成中（未保存）の素材 → 生成ボタンを disabled にし「先に保存してください」ツールチップ**を出す（最小実装。ここで凝らない）。

### V2-4. ジョブパネル（進行中・選択待ちの一覧）

- `src/components/ImageJobsPanel.tsx` を新設。
- ChatPanel トップバー（および Sidebar 下部でも可）に、`imageJobs.length > 0` のときだけ出るバッジボタン「⏳ 画像 n」（running があればスピナー風、selecting があれば「選択待ち」強調）。
- パネル内容: ジョブごとに label・進捗（`results.length / count`）・状態。
  - running: 「✕ キャンセル」
  - selecting: サムネイル横並び → クリックで拡大プレビュー → 「✔ 採用」「🗑 破棄（ジョブごと）」
  - error / canceled: メッセージ＋「🗑 閉じる」
- 完了通知: 既存のトースト機構（実績解除 `newlyUnlockedAchievements` のトースト）を確認し、同じ見た目で「🖼 生成完了: {label}」を出す。ジョブ status が `'selecting'` に変わったタイミングで発火（store 内で `set` する際にランタイム通知配列へ積む、実績と同じパターン）。

### V2 検証

1. tsc → build。
2. Preview: 接続先未設定でも UI 遷移（枚数選択・エラー表示）を確認。生成経路は `preview_eval` で `generateImage` をモックするか、fetch をスタブして疑似 Blob を返す方法で「モーダルを閉じる→ジョブ継続→選択待ちトースト→パネルで採用→挿絵が付く」を通しで確認。

コミット例: 「V2: 画像生成のバックグラウンドジョブ化（複数枚シード違い・候補選択・ジョブパネル）」

## V4: 立ち絵・表情差分・背景（視覚の常在感）

**シーンタイプ／ディレクターには一切依存しない。** 表情は方式A（裏方LLMの毎応答判定）、背景は現在シーンの本文・timeLabel から生成する。

### V4-1. データモデル

`src/types.ts`:

```ts
/** 感情の固定セット。id は英語（プロンプトのタグと対応）、label は UI 表示用 */
export const EMOTIONS = [
  { id: 'neutral',  label: 'ふつう', tags: 'neutral expression' },
  { id: 'joy',      label: '喜び',   tags: 'smile, happy, cheerful expression' },
  { id: 'anger',    label: '怒り',   tags: 'angry, frowning, annoyed expression' },
  { id: 'sadness',  label: '悲しみ', tags: 'sad, teary eyes, downcast expression' },
  { id: 'shy',      label: '照れ',   tags: 'blushing, embarrassed, shy expression' },
  { id: 'surprise', label: '驚き',   tags: 'surprised, wide eyes, open mouth' },
] as const
export type EmotionId = (typeof EMOTIONS)[number]['id']

// Character に追加（optional）
sprites?: { emotion: EmotionId; imageId: string }[]

// Session に追加（optional）
spritesEnabled?: boolean                                  // ステージ表示 ON/OFF
spriteEmotions?: { characterId: string; emotion: EmotionId }[]  // 現在の表情（判定結果）

// Scene に追加（optional）
backgroundImageId?: string
```

- すべて optional → persist キー v3 のまま。**スキーマ変更チェックリスト**（CLAUDE.md）に従い、factory・`exportBundle`/`importBundle`・partialize への反映を忘れない。
- `Character.sprites` の imageId は環境固有なので**キャラカード（PNG）の extensions からは除外**（`avatar.imageId` と同じ扱い）。ただし**セッションカード（aist_session）には同梱する**: `cards.ts` の画像収集（アバター・挿絵を集めている箇所）に sprites と `scene.backgroundImageId` を追加し、import 時の imageId remap も同様に通す。ここを忘れるとセッションカード復元で立ち絵が消える。
- `gcUnusedImages`（SettingsModal）が「使用中 imageId の収集」をしている箇所にも sprites / backgroundImageId を追加する。**忘れると GC で立ち絵・背景が消える。最重要の落とし穴。**

### V4-2. 立ち絵セットの生成（CharacterEditor）

- CharacterEditor に「🎭 立ち絵セット」セクションを追加。EMOTIONS の6感情それぞれにスロット（サムネイル or 空枠）を表示。
- 各スロット: 「✨ 生成」→ ImageGenModal（target: `{ type: 'character-sprite', characterId, emotion }`）。初期プロンプトは:
  `{character.imagePrompt}, {EMOTIONS[emotion].tags}, standing, upper body, simple background, solo`
  （サイズ既定は縦長 832×1216。V1 のスタイル prefill も効く）
- 「⚡ 全感情を一括生成」ボタン: 6感情ぶんのジョブを一括 `startImageJob`（count=1 ずつ・直列でなくジョブ6本で良い。ComfyUI 側はジョブ内直列だがジョブ間は並行 fetch になるため、**一括時は前のジョブ完了を待って次を開始する**チェーン実装にする——`startImageJob` に `queueAfter?: jobId` を足すか、一括専用のヘルパで順次 await）。
- `applyImageJobResult` の `character-sprite` 分岐: 立ち絵は原寸だと重いので `normalizeImage(blob, 1024)`（長辺1024に縮小）→ `putImage` → `sprites` 配列を upsert（同 emotion は置換。**置換時は旧 imageId を deleteImage**）。
- 手動アップロード対応は不要（生成のみ。欲しくなったら後続）。
- 未保存の新規キャラでは AvatarField 同様 disabled。

### V4-3. 表情判定（方式A・裏方LLM）

`src/lib/prompts.ts` に追加:

```ts
/** 表情判定用 system。characterNames はセッション参加キャラ名 */
export function emotionSystem(characterNames: string[]): string
// 内容の指針:
// あなたは演出アシスタントです。直近の本文を読み、登場キャラクターの現在の感情を判定してください。
// 出力は次の JSON のみ: {"emotions":[{"character":"名前","emotion":"neutral|joy|anger|sadness|shy|surprise"}]}
// - 対象キャラ: {characterNames をカンマ区切りで}
// - 本文に登場しない・判断できないキャラは含めない。
// - emotion は上記6値のみ。それ以外の語を使わない。
```

store に `classifyEmotions(sessionId)` を追加。呼び出しタイミングは **`runCompletion` の正常完了後**（`genChoices` を fire-and-forget している箇所と同じ場所・同じ作法）:

- 条件: `session.spritesEnabled` かつ 参加キャラの少なくとも1人が `sprites` を持つ。満たさなければ何もしない（API 呼び出しゼロ）。
- モデル: `choicesModelOf(session)`（裏方の軽量枠。専用フィールドは増やさない）。
- 入力 user: 直近の本文 2〜3 メッセージ（判定には十分。長文を送らない）。temperature 0、maxTokens 300。
- 出力: `extractJson` → キャラ名から characterId を解決（完全一致 → 前方一致の順。解決できない名前は捨てる）→ emotion が6値以外なら捨てる → `session.spriteEmotions` を upsert。
- 失敗時: `console.warn('[emotion] ...')` のみ。**表情は現状維持**（リトライしない。次の応答でまた判定される）。
- ストリーミング表示や送信をブロックしない（完全に fire-and-forget）。

### V4-4. ステージ表示（ChatPanel）

- ChatPanel のメッセージリスト上部に「ステージ」帯を追加。表示条件: `session.spritesEnabled`。トップバーに「🎭」トグル（`spritesEnabled` を反転）。
- レイアウト: 高さ約 260px の帯。背景: `scene.backgroundImageId` があれば `useImageUrl` で表示（`object-fit: cover`・下に暗めのグラデーションを重ねて立ち絵を見やすく）。なければ現行テーマの無地。
- 立ち絵: 現在シーンの `activeCharacterIds` のうち `sprites` を持つキャラを横並び（`justify-content: center; gap`）。各キャラ、`spriteEmotions` の現在感情のスプライト → 無ければ `neutral` → それも無ければ非表示（アバターへのフォールバック表示はしない。小さい丸アイコンが立ち絵の並びに混ざると不格好なため）。
- 表情切替時は CSS `transition: opacity` で軽くクロスフェード（凝らない。img の key を imageId にして opacity アニメ程度）。
- モバイル/狭幅時はステージを畳めるようにする（🎭 トグルで足りるので専用処理は不要。ただし `max-height` と `img { height: 100%; width: auto }` で崩れないこと）。

### V4-5. 背景生成

- ステージ帯（またはシーン仕切り近く）に「🏞 背景を生成」ボタン → ImageGenModal（target: `{ type: 'scene-background', sessionId, sceneId }`、サイズ既定 1216×832 横長）。
- 起案文脈: `prompts.ts` に `backgroundContextUser(args: { sceneTitle?, sceneNote?, timeLabel?, worldDescription?, recentMessages: string[] })` を追加。「**人物を含めない**風景・背景のみのプロンプト（no humans, scenery）を作る」ことを system 側の指針に追記（`illustrationPromptSystem` に「背景モード」を足すか、専用 system 関数を作る。専用関数のほうが指針が濁らないので推奨）。
- `applyImageJobResult` の `scene-background` 分岐: `putImage` → `updateScene`（`backgroundImageId` を置換。**旧背景の imageId は deleteImage**）。
- 背景はシーンごとに1枚。シーンが変われば前シーンの背景は残る（履歴として意味があるのでギャラリーにも出す）。自動生成（シーン開始時に勝手に生成）は**やらない**——コスト・待ち時間・失敗時の扱いが重く、まず手動1ボタンで運用感を確かめる。

### V4 検証

1. tsc → build。
2. Preview: ダミー sprites を `preview_eval`（canvas で色違い画像を生成 → putImage → updateCharacter）で仕込み、🎭 ON でステージ表示・感情 upsert（store アクションを直接叩く）で立ち絵が差し替わることを確認。
3. `classifyEmotions` はモデル呼び出しを含むため、`extractJson` 以降の純粋部分（名前解決・6値バリデーション）を関数に切り出して `preview_eval` で直接テストできる形にする。
4. セッションカード: sprites・背景入りセッションを export → import し、立ち絵・背景が復元されること（remap）を確認。
5. `gcUnusedImages` 実行後に立ち絵・背景が消えないことを確認。
