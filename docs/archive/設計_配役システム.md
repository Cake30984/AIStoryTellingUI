# 設計: 配役システム（世界観ロールと導入文プレースホルダー）

- 日付: 2026-07-12
- 対象: World のロール定義／セッションの配役／導入文の実名解決／system プロンプトへの立ち位置注入
- 位置づけ: `設計_分岐ツリー生成順と導入ロール.md` の OR1〜OR3（番号スロット方式）を**置き換える**設計。`設計_開始テンプレートとゲームカセット.md`（W1）と `設計_構造化出力.md` を補足する
- 実装状況: **CA1〜CA3 実装済み**（2026-07-12）

## 1. 背景と決定事項

導入文テンプレートの時点では、どのキャラクター・ペルソナで遊ぶかが未確定である。旧設計（OR1〜3）は `@キャラクター1` の番号スロットで解決する案だったが、次の理由で**名前つきロール（配役）方式へ一本化**することを決めた（2026-07-12 合意）。

- 番号スロットは匿名で、配役 UI を見ても「スロット1が何の役か」がテンプレート本文を読まないと分からない。世界観が「ライバル」「案内役」のような**名前つきロール**を定義すれば、UI が自己説明的になる。
- ばらばらの世界観とキャラクターを組み合わせるとき、本当に困るのは導入文の名前ではなく **LLM がそのキャラを世界の中でどう扱えばよいか分からない**こと。ロールに立ち位置の説明文を持たせ、system プロンプトへ注入することで解決する（名前置換はロールの応用の一つに過ぎない）。
- ロール層は世界観とキャラクターの**インターフェース**であり、カセットにも効く。世界観が「穴」を宣言し、カセットは「穴を埋めた状態」で配布される。穴の定義が残っているため、遊ぶ側が別キャラへ**配役を差し替えて**遊ぶリミックスが成立する（ADR-1 の「共有可能なゲーム」思想と一貫）。

### ユーザー決定（選択式質問の回答・2026-07-12）

1. **名前つきロールに一本化**。番号スロット（`@キャラクター1`）は実装しない。OR1〜3 は未実装のまま廃止。世界観なしセッションの導入文は実名で書く割り切り。
2. **ロール説明の system プロンプト注入まで含める**。ロール＝名前＋立場の説明＋必須フラグ。
3. 開始時に未配役があれば**その場で配役モーダル**を出す（エラーで設定画面へ差し戻さない）。

### 用語

UI 文言は「**配役**」で統一する（世界観=脚本、キャラ=役者、セッション=公演のメタファー）。「ポジション」「スロット」は使わない。

## 2. データモデル

### 2.1 WorldRole（World に追加）

```ts
export interface WorldRole {
  /** 安定 id。配役はこの id で結ぶ（リネームに耐える） */
  id: string
  /** ロール名＝置換キー＝配役UIの表示名（例: ライバル） */
  name: string
  /** この立ち位置の客観的な立場・物語上の機能。system に注入する */
  description: string
  /** true なら未配役では物語を開始できない（導入文で未使用でも必須） */
  required?: boolean
}

export interface World {
  // 既存フィールド...
  /** 配役ロール定義。未設定は空配列扱い */
  roles?: WorldRole[]
}
```

`description` は**性格ではなく立場**（宿屋の主人・生徒会長・主人公と同じ道場の兄弟子、等）を書かせる。性格はキャラ本体の persona が持つ。優しいキャラを敵役に配役する「意外なキャスティング」を壊さないため。この指針は WorldEditor の placeholder 文言で示す。

### 2.2 配役（Session に追加）

```ts
export interface RoleAssignment {
  /** World.roles の WorldRole.id */
  roleId: string
  /** session.characterIds に含まれる Character.id */
  characterId: string
}

export interface Session {
  // 既存フィールド...
  /** 世界観ロールへの配役。未設定は空配列扱い */
  roleAssignments?: RoleAssignment[]
}
```

- **定義は World が持ち（参照）、配役は Session が持つ**。`startPreset` のコピー方式（W1）と混同しないこと——導入文はセッションへコピーされるが、ロール定義はコピーせず常に `effectiveWorld` 経由で参照する。世界観側でロールを直せばセッションにも反映される。
- 同じ Character を複数ロールに配役することは許可する（一人二役）。UI に注意表示のみ。
- 1つのロールに複数キャラは v1 では不可（配列内で同 roleId が重複した不正データは後勝ち）。
- `worldId` に存在しない roleId、`characterIds` に含まれない characterId は**無効として無視**する（保存値は消さない。世界観を戻したとき再利用できる）。

### 2.3 プレースホルダー記法

| 記法 | 解決先 |
|---|---|
| `@ペルソナ` | `session.personaId` が指す Persona の名前（旧設計から変更なし） |
| `@<ロール名>`（例 `@ライバル`） | そのロールに配役された Character の名前 |

- 正規記法は半角 `@`。解決時は全角 `＠` も受理し、出力は半角 `@実名` に正規化。
- `@ライバル(joy)「…」` の感情指定・セリフはそのまま残す（`@美咲(joy)「…」`）。
- ロール名に一致しない `@美咲` や本文中の通常文字列は変更しない。
- 構造化行の行頭だけでなく、地の文中の出現（「その時、@ライバルが現れた。」）も置換する。

## 3. 解決ロジック（`src/lib/casting.ts` 新設）

React・store に依存しない純粋関数のみ。旧設計の `openingRoles.ts` は作らない。

```ts
/** 本文中で使われている予約記法を検出 */
findCastingRefs(text, roles): {
  usesPersona: boolean
  roleIds: string[]        // 使用ロール（重複除去）
  unknownNames: string[]   // どのロールにも一致しない @名前 は対象外（報告もしない）ため通常は空
}

/** 配役の検証（開始前・UI 警告の両方から使う） */
validateCasting(session, world, characters, personas): CastingIssue[]

/** 導入文を実名へ解決 */
resolveCasting(text, { roles, assignments, characters, persona }): {
  content: string
  issues: CastingIssue[]
}
```

- 置換キーは「ペルソナ」＋全ロール名。**長い名前から先に**マッチさせる（「ライバル」と「ライバルの師匠」の前方一致事故を防ぐ）。ロール名は正規表現エスケープする。
- 置換は**単一パス**（全キーの alternation を1つの正規表現にし、コールバック置換）。置換後の実名を再びプレースホルダーとして処理しない。
- `CastingIssue` として列挙するもの:
  - `@ペルソナ` 使用だが `personaId` 無し／対象 Persona が存在しない
  - 導入文で使用中のロールが未配役
  - `required: true` のロールが未配役（導入文で未使用でも）
  - 配役先 Character が存在しない／`session.characterIds` に含まれない
- 導入文で使っていない任意ロール（required でない）の未配役は issue にしない。説明注入をスキップするだけ。

### 3.1 開始時の処理（`startStory` の導入あり経路）

1. `s.story.opening` を取得。
2. `validateCasting` で検証。**issue が1件でもあれば配役モーダルを開く**（開始は保留。Message・チェックポイントは作らない）。
3. モーダルで配役が確定したら `roleAssignments` を保存し、再検証 → `resolveCasting` で実名入り本文を作る。
4. 解決済み `content` を assistant Message に保存する（**焼き付け**）。以降の選択肢生成・`plainTextOf`・構造化レンダラ・チェックポイントは解決済み Message を使う。
5. `session.story.opening` 自体は書き換えない（テンプレートのまま永続化）。

解決後は `@実名` になっているため、既存の `StructuredMessage` が participants＋persona から characterId を解決してアイコンを表示できる。**構造化パーサ（`structured.ts`）の変更は不要**。`structuredOutput` OFF でも置換は行う。

### 3.2 不変条件: プレースホルダーをモデルに見せない

`@ロール名` がプロンプトへ生で流れると、few-shot（履歴は生テキストで送る規約）によりモデルが `@ライバル(joy)「…」` を真似て返す事故が起きる。

- 導入文は Message 作成前に必ず解決する（未解決なら開始しない）。
- system 注入（§4）は実名で組み立て、`@` つき記法をブロック内に書かない。
- ロア・イベント文・premise 等へのプレースホルダー展開は**対象外**（§9）。世界観作者向けには「配役記法が使えるのは開始テンプレートの導入文のみ」と UI で明示する。

## 4. system プロンプト注入（【配役】ブロック）

`buildSystemPrompt`（prompts.ts）に、配役済みロールがあるときのみ【配役】ブロックを追加する。

```text
【配役】
この物語における各キャラクターの立ち位置:
- 美咲 —「ライバル」: 主人公と同じ道場に通う兄弟子。主人公の成長を測る物差しとなる。
- 玄爺 —「案内役」: 主人公を物語の舞台へ導く長老。
```

- 毎ターンの組み立て時に `roleAssignments` から**動的解決**する（Message への焼き付けと違い、配役を変えれば次ターンから反映される）。
- 未配役の任意ロールは書かない（「登場しない」等の記述もしない）。
- ロール定義は `effectiveWorld` から読む（オーバーレイ実効ビュー規約に従う）。
- ペルソナはこのブロックに含めない。主人公の立ち位置は従来どおり premise が担う（拡張は対象外 §9）。

置換（導入文・静的・焼き付け）と注入（プロンプト・動的・毎ターン）の**2層構造**であることを実装時に混同しないこと。

## 5. UI

### 5.1 WorldEditor — 「配役」セクション

- `.section-nav` に「配役」を追加（開始テンプレートの近く）。
- 行: ロール名／立場の説明（textarea）／「開始に必須」チェック。追加・削除。
- placeholder 文言で指針を示す: 説明は**立場**を書く（例「宿屋の主人。旅人に情報を売る」）。性格はキャラクター側に書く。
- 検証（保存時警告）: ロール名の空・世界内重複・予約語衝突（「ペルソナ」「地の文」等 `NARRATION_NAMES`）。
- **リネーム時のテンプレート追従**: ロール名を変更したら、`startPreset.opening` 内の `@旧名`（全角含む）を `@新名` へ一括置換する。配役は roleId で結ばれているため無傷。既にセッションへコピー済みの `session.story.opening` までは追従できない（開始時検証で未解決として検出される）ことを設計上許容する。

### 5.2 配役 UI 共通部品（`CastingFields`）

SessionEditor と CassetteEditor で重複させないため共通部品にする。

- 世界観のロールごとに1行: ロール名＋説明の要約＋配役 select（候補は参加キャラのみ）＋必須/導入文使用中バッジ。
- `@ペルソナ` が導入文にあれば「ペルソナ → 選択中の名前／未選択」を読み取り専用表示。
- 未解決項目は警告色。解決済みプレビュー（導入文の実名版）を折りたたみ表示。
- 同一キャラの複数ロール配役は許可＋注意表示。

### 5.3 SessionEditor

- 「基本」タブ、導入欄の直下に `CastingFields`（選択中の世界観にロールがある場合のみ表示）。
- 参加キャラを外したとき、そのキャラへの配役は無効化（表示上未配役扱い。保存値の即時削除はしない）。
- 未配役があっても**保存は許可**（下書き保持）。開始時にモーダルで拾う。

### 5.4 開始時の配役モーダル

- 「物語をはじめる」押下時、`validateCasting` に issue があれば `ModalShell` で配役モーダルを表示。中身は `CastingFields` 相当＋開始ボタン。
- 埋めたらそのまま開始する（設定画面への差し戻しなし）。キャンセルなら何も起きない。
- issue が無ければモーダルは出さず従来どおり即開始（毎回確認は挟まない・ユーザー決定）。

### 5.5 CassetteEditor・カセット

- 「開始・進行」セクションの導入欄直下に同じ `CastingFields`。候補は「登場キャラ」セクションのキャラのみ。
- 棚への下書き保存は未配役でも許可。
- **PNG 書き出し時は未解決があればエラー**（配布後に開始不能なカセットを作らない）。
- `▶ 遊ぶ`（`playCassette`）は従来どおり複製のみ。未解決が残っていても、開始ボタン押下時の配役モーダルが最終ゲートになる。カセットの配役差し替えプレイもこの経路で自然に成立する。

### 5.6 プレイ中の可視性

- 状態ドック（`StatusView`）の参加キャラ表示にロールバッジを添える（「美咲（ライバル）」）。周回・配役替え時に現在の配役を思い出せるようにする。
- 世界観ライブラリのカード面に「配役: 主人公＋ライバル＋案内役（任意）」のようなロール一覧を出す（ボードゲーム箱の「プレイ人数」表示に相当。何が要る世界観かが一目で分かる）。

## 6. データ整合性

- Character 削除時: `characterIds` から外す既存処理に加え、`roleAssignments` からも該当 characterId の行を除去。
- Persona 削除時: 既存どおり `personaId=null` → `@ペルソナ` は未解決として開始時に検出。
- 世界観を差し替えたセッション: 旧世界の roleId は無効として無視（保存値は残す）。
- 開始テンプレートの「空欄のみコピー／全上書き」（`startPresetPatch`）: `opening` を更新しても配役を勝手に変更しない。新本文の検出結果に応じて警告を更新するのみ。
- `freshSessionOf`（カセット下書き化）: `roleAssignments` を保持する。
- チェックポイント: `roleAssignments` はスナップショットに含まれ復元対象（本文・進行と結合しているため passthrough にしない）。
- 解決済み Message は通常の実名本文。後から配役やペルソナを変えても過去 Message は変えない（履歴の再解釈をしない）。
- 削除時に**別キャラへ自動再配役しない**。プリフィルは新規作成時の編集可能な提案に留める（参加キャラ数とロール数が一致するときの1:1仮埋めは任意実装）。

## 7. 永続化・カード

- すべて optional 追加。persist キー `ai-storytelling-store-v3` は据え置き。
- `newSession` は `roleAssignments: []`、`newWorld`／`WORLD_PRESETS` は `roles: []` を設定。
- export/import は World・Session を丸ごと扱うため基本自動追従。`importBundle`／`normalizeSessionBundle` で roleId・characterId が文字列であることだけ正規化。
- 世界カード（`aist_world`）に `roles` を含める。カセット PNG は world＋session を同梱するため配役も保持される。取込は Character.id を変更しないマージなので remap 不要。
- 画像 id を含まないため `sessionImageIds`／`collectCardImages` の変更は不要。

- Character 削除時の配役掃除。

### CA2: UI（定義＋配役＋開始時モーダル）
- WorldEditor「配役」セクション（リネーム時のテンプレート一括置換含む）。
- `CastingFields` 共通部品 → SessionEditor 組み込み。
- 開始時配役モーダル（CA1 の暫定エラーを置き換え）。

### CA3: 注入＋カセット＋可視性

## 9. 対象外（スコープ制御）

- ロアエントリ・イベント文・premise・authorNote への配役記法の展開（ロアはキーワードマッチと干渉するため特に危険。必要性が確認されたら別設計）。
- AI 生成本文中の配役記法の動的解決。
- 主人公側のロール定義（世界観が主人公の立場を宣言する拡張。現状は premise が担う）。
- 1ロール複数キャラ（`@生徒たち` 的な群衆ロール）。
- カセット起動時に別ペルソナを選ぶ新フロー。

## 10. 却下案（後で試す用）

- **番号スロット（`@キャラクター1`・旧 OR1〜3）**: 匿名で UI が自己説明的にならない。名前つきロールに一本化して置き換え（未実装のまま廃止・設計は旧ドキュメントに保存）。
- **番号スロットと名前つきロールの併存**: 世界観なしセッションでの柔軟性はあるが、UI・検証・ドキュメントが倍になる。世界観なしの導入文は実名で書く割り切りを採用。
- **名前置換のみ（説明注入なし）**: 実装は小さいが「世界の中での役割を明示する」当初動機を満たさない。
- **開始時エラーで設定画面へ差し戻し**: 実装最小だが「設定を開いて探す」手間を生む。その場配役モーダルを採用。
- **ロール名を置換キーではなく id で書く記法**（`@role:xxxx`）: リネームに強いが人間が書けない。名前キー＋リネーム時一括置換で対応。

## 11. 総合受け入れテスト

1. 世界観に「ライバル」「案内役（任意）」を定義し、導入に `@ライバル(joy)「…」` と `@ペルソナ` を書く。セッションで配役して開始 → 最初の本文が実名＋正しいアイコンで表示される。
2. `session.story.opening` は開始後もロール記法のまま。Message だけが実名。
3. 未配役のまま「物語をはじめる」→ 配役モーダルが開き、埋めるとそのまま開始。キャンセルで Message・チェックポイントが増えない。
4. required ロールが導入文で未使用でも、未配役ならモーダルが要求する。任意ロール未配役は要求されない＋【配役】に載らない。
5. system プロンプトに【配役】ブロックが実名で入り、`@` 記法が混入しない。配役を変えると次ターンから注入が変わる。
6. ロール名を世界観側でリネーム → startPreset の導入文が追従し、配役（roleId）は無傷。
7. 同一キャラを二役に配役でき、注意表示が出る。
8. 参加キャラ削除・Persona 削除で未解決が検出され、別キャラへ自動配役されない。
9. カセット: 配役→棚保存→PNG 書き出し（未解決ならエラー）→取込→遊ぶ、で配役が保持される。別キャラへ差し替えても開始できる。
10. 全角 `＠ライバル` も解決され、半角 `@実名` に正規化される。「ライバル」「ライバルの師匠」が併存しても正しく置換される。
