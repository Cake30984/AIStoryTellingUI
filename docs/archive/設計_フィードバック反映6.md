# 設計: フィードバック反映6（画像の永続記録・後付け生成・明示分岐・ツリー折りたたみ）

2026-07-19 合意の実使用フィードバック第6弾。「画像」と「分岐」の2トラック4項目を、依存関係から **FB6-A（画像の永続記録）→ B（後付け生成）→ C（明示分岐）→ D（ツリー折りたたみ）** の順で実装する。C の上書き削除は A が先にないと画像が道連れになるため、この順序は入れ替えない。各フェーズ完了ごとにコミット＋AGENTS.md 更新。

## 項目一覧と決定

### 選択式質問の結果（2026-07-19 合意）

- **分岐の方式 = 上書き方式**。却下案: 非表示方式（全自動フォーク維持＋既定表示だけ絞る。データは消えないが容量が増え続け、「分岐させない」という意図に反する）／非表示＋自動整理（何がいつ消えるかのルールが増えて挙動が読みにくい）。採用理由: 分岐木を「意図した構造だけの地図」にする・容量の自然節約・データ保全は画像記録（A）と保護ルールで担保
- **上書きの確認 = 大きい時だけ**。シーン（レビュー確定）を跨ぐ巻き戻し・別の線へのジャンプ時のみ「上書き／⑂分岐として残す／キャンセル」の3択。同一シーン内の書き直しは確認なしで消す
- **過去画像の補完 = 全チェックポイント走査**。初回起動時に1回、全スナップショットを読んで挿絵・背景をプロンプト付きで記録に登録
- **折りたたみの既定 = 既定で折りたたみ**（現在いる章のみ展開）

## FB6-A: セッション画像記録（分岐から独立した生成画像アルバム）

### データモデル

```ts
/** 生成画像の永続記録（FB6-A）。分岐・シーンの生死と独立に「採用した画像」を残す */
export interface SessionImageRecord {
  id: string
  imageId: string
  kind: 'illustration' | 'background'
  /** 結合前のユーザープロンプト（ImageJob.prompt と同じ規約）。補完した背景など不明な場合は空文字 */
  prompt: string
  sceneId?: string
  /** 分岐が消えても表示できるよう採用時点の値を非正規化して保存 */
  sceneTitle?: string
  timeLabel?: string
  messageId?: string
  createdAt: number
}
```

- AppState 直下に `sessionImageLogs: Record<string /*sessionId*/, SessionImageRecord[]>`。**Session の中に入れない**（`branchTrees` と同じ理由: チェックポイントの深コピーに含めない・復元で巻き戻さない）。persist 対象（optional 追加なので persist キー据え置き）
- 補完済みフラグ `imageLogBackfillDone?: boolean` を AppState 直下・persist に追加

### 書き込み・削除・GC

- **追記は `applyImageJobResult` の1箇所**: `scene-illustration` / `scene-background` の採用時に putImage → **先に記録へ追記**（sceneTitle/timeLabel はその時点のシーンから best-effort で引く）→ シーンへの配置。配置先シーンが分岐切替で消えていても記録には残る（既存の「ジョブ完了前に分岐を切り替えると画像が行方不明」の穴もこれで塞がる）。立ち絵・アバター・カセット表紙は素材側が保持するので対象外
- **GC**: `collectUsedImageIds` に第5引数 `imageLogs`（省略時 `{}`）を追加し、全 record の imageId を使用中扱い。呼び出しは `gcUnusedImages` と `exportBundle`（画像収集）の2箇所を更新
- **記録の削除 = record 除去のみ**（規約どおり即時 deleteImage しない。実体は他で未使用なら次の GC で回収）
- `deleteSession` はそのセッションの `sessionImageLogs` エントリも削除（チェックポイント削除と同列）
- **エクスポート**: `ExportBundle.sessionImageLogs?` を追加（version 1 据え置き・importBundle は `?? {}` で受ける）。import はセッション単位で record id の dedupe マージ。カセットは Session の外のデータなので自然に非同梱（意図どおり）

### バックフィル（全チェックポイント走査・初回1回）

App.tsx の hydration 後（`cleanupOrphanCheckpoints` と同じ場所）で `imageLogBackfillDone` が偽なら fire-and-forget 実行:

1. `listImageIds()` を1回読んで実在 imageId の Set を作る（GC 済みの参照は登録しない）
2. 各セッションについて「ライブの scenes」＋「branchTrees 全ノードのスナップショット（`checkpointStore.get`→gunzip→parse）」から挿絵（prompt・messageId・createdAt あり）と背景（prompt 不明=空文字・createdAt はノードの createdAt）を収集
3. セッション内で **imageId をキーに dedupe**（同じ画像は多数のスナップショットに写るため）。createdAt 昇順に整列して登録
4. ノード単位で try/catch（壊れたスナップショットはスキップ）。完了時にフラグを立て、n>0 なら `infoNotice` で「過去の画像 n 件を記録に登録しました」

### UI（ギャラリーのタブ化）

- `GalleryBody` に seg 切替「**この分岐**（既定・従来表示）／**すべての記録**」を追加
- 「すべての記録」: 新しい順のサムネイルグリッド。各 record に シーン名chip（sceneTitle・timeLabel）・背景バッジ・「配置中」バッジ（imageId が `sessionImageIds(session)` に含まれる時）。操作 = クリック拡大（プロンプト・日時キャプション）／保存／**記録から削除**（danger 確認: 「本文・分岐で未使用なら実体は『未使用画像の整理』で回収されます」）
- 文言調整: 「この分岐」タブとチャット内挿絵の削除は参照除去のままだが、「本文から外す（すべての記録には残ります）」に変更して役割を明確化

### 検証

- `npx tsc --noEmit` → `npm run build`
- preview_eval: 採用→記録追記／`collectUsedImageIds` が log を含む／`deleteSession` で log が消える／バックフィルを seed（スナップショット2件・重複 imageId・欠損 imageId）で直叩きし件数と dedupe を確認／export→import 往復で record が保持される
- ユーザー確認: ①採用した画像が「すべての記録」に出る ②その分岐を削除→GC 実行しても画像が残る ③記録から削除→GC で実体が消える

## FB6-B: 挿絵・背景の後付け生成

### 決定

- **メッセージ単位**: 本文の操作行（編集・ここから・削除の並び）に「🎨 挿絵」を追加。target は既存の `{type:'scene-illustration', sessionId, sceneId, messageId: そのメッセージ}`（データ構造は変更不要）。表示は既存のアンカー描画（messageId 直後）がそのまま効く
- **過去シーン**: StoryLogModal の各シーン行に「🎨 挿絵」「🏞 背景」ボタン。挿絵アンカーはそのシーンの末尾メッセージ・背景はそのシーンの `backgroundImageId` 差し替え（`applyImageJobResult` は既に任意 sceneId を受ける）
- **起案文脈の変更**: 現在は常に「現在シーンの末尾まで」だが、「**対象シーンの、アンカーメッセージまで**」を使うよう変更。ChatPanel 内のインライン構築を `illustDraftContext(session, participants, sceneId, uptoMessageId?)` / `bgDraftContext(...)` ヘルパに抽出（文字数予算 8000 はアンカーから遡る・`plainTextOf` 適用箇所は従来どおり）
- モーダル起動 state は `showImageGen: boolean` を `illustGenFor: { sceneId, messageId? } | null`・`bgGenFor: { sceneId } | null` に置き換え（コンポーザーのボタンは従来どおり「現在シーン・末尾アンカー」で同 state を使う）。StoryLog からは onGenerate コールバックで ChatPanel の state を立てる
- 操作行が混みすぎる場合のボタン省略・アイコン化は実装後にユーザーが見た目確認で判断

### 検証

- tsc → build。preview_eval: ヘルパの文脈が「アンカーまで・予算内・シーン限定」になること（境界: アンカー=シーン先頭／旧データ sceneId なし）
- ユーザー確認: ①過去メッセージの🎨→採用でそのメッセージ直下に表示 ②過去シーンの背景を差し替えても現在シーンのバックドロップが変わらない ③採用分が「すべての記録」に載る

## FB6-C: 明示分岐（自動フォーク廃止・上書き方式）

### 意味論（合意仕様）

1. 巻き戻し系の操作（**ここから・やり直す・編集・削除・復元後の続行**）で置き去りになる暗黙の線は、**チェックポイントごと削除**する（画像は A の記録で保全済み）
2. **保護された線は消えない**: サブツリーに ⑂名前付きノード・しおり・エンディング（`ending`）を含む線は自動削除の対象外＝そのまま分岐として残る。保護ノードの祖先は消せないため、置き去りの線は「保護部分に至る骨格」だけ残る
3. **確認は大きい時だけ**（Q2 合意）: 削除対象に 📖 シーンノードが含まれる場合のみ、3択ダイアログ「**⑂ 分岐として残して進む／上書きして進む（danger）／キャンセル**」。同一シーン内の書き直しは確認なしで消す
4. `restoreCheckpoint`（戻る・しおり）は従来どおり**何も削除しない**（過去を読みに行くだけの移動は安全なまま）。削除と確認は「その地点から物語を進める最初の操作」の冒頭で行う
5. **削除対象は常に「これから続きを積むノードの直下」だけ**（実装時に単純化）: 別の線へジャンプして続けた場合、離れた元の線は削除対象にしない（意図せぬ全損を防ぐ＝安全側。不要になった線は従来どおり手動削除・✂剪定で消す）。また保護枝の**部分削除はしない**（丸ごと温存）——いま巻き戻していない枝の中身に触らないため
6. **⑂ の名前は「線の先端」に付く**（git のブランチ ref 相当）: ⑂ボタンは現在の先端 currentId に、ガードの「⑂残す」は消えかけた枝の最新の葉に命名する。保護判定は「サブツリーに ⑂/しおり/🏁 を含むか」なので、先端に付けた名前が線全体を守る

### 実装

**データ**: `BranchNode.branchName?: string`（optional 追加・persist キー据え置き）。保護判定は `branchName`／`star`／`ending` の有無から計算（専用フラグは持たない）。

**純関数（store.ts）**:

- `findReanchorTarget(tree, keptIds): nodeId | null` — 既存 `reanchorBranch` から計算部を抽出（reanchorBranch はこれを使う形に）
- `subtreeHasProtection(tree, nodeId): boolean`
- `deletableChainsBelow(tree, parentId, keepChildId?): { nodeIds: string[]; crossesScene: boolean }` — parentId の子のうち保護のないサブツリー（保護ノードがある枝は、その枝内の「保護に至らない末端サブツリー」だけ）を削除集合として列挙

**上書きガード `ensureLineTip(sessionId, parentNodeId): Promise<boolean>`**（false=キャンセル）:

- parentNodeId（＝これから子を積むノード）に削除対象チェーンが無ければ即 true
- あれば: `crossesScene` なら3択ダイアログ（→ ⑂選択時は `appPrompt` で分岐名・既定=チェーン先頭ノードの label・`branchName` を付けて温存）／跨がなければ黙って削除
- 削除は **その場で eager に** state の nodes 除去＋`checkpointStore.delete`（`deleteBranchSubtree` と同じ並列書込）
- 呼び出し箇所（ユーザー起点の物語操作の冒頭）: `send`・`continueLast`・`regenerate`・`regenerateFrom`・`editMessage`・`deleteMessage`・`beginScene`・`prepareSceneReview`。巻き戻し系は `findReanchorTarget` の結果を parent として**ミューテーション前に**呼ぶ（キャンセルなら何も変えない）。`editMessage`/`deleteMessage` は async 化
- `recordCheckpoint` 内では**剪定しない**（fail-open）: ガードを通らない経路で兄弟ができた場合は従来どおり暗黙分岐として見える＝取り漏らしをバグとして発見できる

**⑂ ここから分岐ボタン**:

- **本文の操作行**「⑂ ここから分岐」: `regenerateFrom` の変種。分岐名を `appPrompt`（既定=置き去りになる線の先頭 label）→ 現在の続きのチェーン先頭に `branchName` を付けて保護 → 以降は従来の regenerateFrom と同じ（reanchor→切り詰め→再生成）。ガードは「⑂済み＝保護」なので何も消さない
- **ツリー行メニュー**「⑂ ここから分岐して再開」: いま居る線（対象ノードから現在葉へ向かう最初の子）に `branchName` を付けてから `restoreCheckpoint`。以降の続行では保護済みなので消えない
- ツリー表示: `branchName` を持つ行に `⑂ 名前` チップ（★しおりバッジと同列）

**ダイアログ基盤**: `dialogs.ts` に3択用 `appChoices({ message, options: {label, value, danger?}[] }): Promise<string | null>` を追加（DialogHost で描画。Escape/オーバーレイ=null）。ネイティブ confirm 禁止規約は維持

**文言更新**: `restoreCheckpoint` の確認文を「この地点に戻ります。ここから物語を進めると、この先の記録は上書きされます（大きな上書きになる場合はその時に確認します）」に変更。`pruneToCurrentPath`／`deleteBranchSubtree` は従来どおり手動削除として残す（確認文に「⑂・しおり付きも消えます」を明記）

### 検証

- tsc → build。preview_eval: `findReanchorTarget`／`subtreeHasProtection`／`deletableChainsBelow` を合成ツリーで直叩き（保護の骨格温存・シーン跨ぎ判定・複数チェーン）。ガード後に `checkpointStore` の実体が消えることを確認
- ユーザー確認: ①シーン内で「ここから」を数回→ツリーに枝が増えない（線が書き換わるだけ） ②シーンを跨ぐ「ここから」→3択が出る・「⑂残す」で名前付き分岐が残る ③しおりを付けた線は黙って消えない ④⑂ボタン（本文・ツリー）で意図した分岐が作れる ⑤消えた線にしか無かった画像が「すべての記録」に残っている

## FB6-D: 分岐ツリーのレビュー単位折りたたみ

### 決定

- ノード粒度（生成1回=1マイルストーン）は現状維持。**表示だけ** 📖 シーンノード（kind:'scene'）を章見出しとして畳む
- **既定は折りたたみ・現在いる章のみ展開**（currentId 変化で自動展開）。トグルは章見出し行の ▸/▾
- 畳んでも常に表示: 分岐点（子2以上）・しおり・⑂名前付き・🏁 ending・各枝の先端（葉）・いまここ・シーンノード自身。＝木の構造と行き先は折りたたみで失われない
- 章見出し行に畳まれた件数「（n件）」を表示（縮約辺への個別バッジは置かない）

### 実装

- 純関数 `condenseTree(nodes, expandedSceneIds): { nodes: BranchNode[]; hiddenCountByScene: Map<string, number> }` を BranchTreeModal（または lib）に追加。章= 各シーンノードから次のシーンノード手前までの action 子孫。非表示可能= 畳まれた章内・kind:'action'・上記の常時表示条件に非該当（子1以下の鎖の内部ノード）。非表示ノードは鎖の内部に限られるため、**可視の子の parentId を最寄りの可視祖先へ付け替える辺縮約**が一意に決まる
- 縮約後の合成ツリーをそのまま既存 `buildGraph` へ渡す（**グラフ描画本体は無改修**）
- コンポーネント state `expandedSceneIds: Set<string>`（初期値=currentId の属する章。currentId 変化で追加）。FB6-C 後は木がほぼ線形なので、実質「📖 見出しの縦一列＝セーブポイント一覧」の見た目になる

### 検証

- tsc → build。preview_eval: `condenseTree` を合成ツリーで直叩き（全畳み/全展開/保護ノード常時表示/縮約後の親子整合/件数）
- ユーザー確認: ①開いた直後は章見出し＋現在章だけ ②畳んだ章の分岐点・しおり・先端が見える ③▸/▾ で開閉・件数表示 ④「いまここ」への自動スクロールが従来どおり効く

## 規約への追記（実装時に AGENTS.md へ反映）

- 画像 id を持つ**セッション外**データを増やしたら `collectUsedImageIds` の引数に追加（`sessionImageLogs` が前例）
- `sessionImageLogs` は `branchTrees` と同様 **Session の中に入れない**
- 分岐の自動削除は必ず保護判定（`subtreeHasProtection`）を通す。`recordCheckpoint` 内で剪定しない（fail-open）
