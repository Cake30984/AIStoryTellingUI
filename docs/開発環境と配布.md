# 開発環境と配布

日常のコマンドは `AGENTS.md` の「コマンド」節。ここには**初回だけ要る準備**と**配布ビルドの検証手順**を置く。
経緯は `docs/archive/設計_Tauri化.md`。

## 1. 初回準備（デスクトップ版のビルドに必要）

1. **VS Build Tools**（「C++ によるデスクトップ開発」ワークロード）: `winget install Microsoft.VisualStudio.2022.BuildTools`
2. **rustup**: `winget install Rustlang.Rustup` → 既定の `x86_64-pc-windows-msvc`
3. WebView2 は Win11 標準搭載のため不要
4. 確認: `rustc --version` / `cargo --version`
5. **Windows Defender「コントロールされたフォルダーアクセス」が有効なら** `cargo.exe`/`rustc.exe` を許可アプリに追加する（しないとビルドが失敗する）
6. Web dev（5173）と `tauri:dev` は同時起動不可（strictPort）。占有されていたら `npx kill-port 5173`

このマシンで使える CLI の一覧は `環境_ローカルツール_AI用.md`。

## 2. ビルド

```bash
npm run build                       # Web 版 → dist/
npm run tauri:build                 # デスクトップ版（NSIS インストーラ。初回はバンドラを取得するのでネット必須）
npm run tauri build -- --no-bundle  # 実行ファイルのみ
```

- 出力: `src-tauri/target/release/bundle/nsis/*.exe`（環境音を撤去した 2026-09-13 以降は数MB。Web 版 `dist/` は約 630KB）
- バージョンは `package.json` と `src-tauri/tauri.conf.json` の `version` を揃えて上げる（`APP_VERSION` は `vite.config.ts` の define で package.json から注入）
- 配布形式は **NSIS のみ**。未署名（SmartScreen 警告の回避手順は README）

## 2b. Web 版を静的ホスティングへ置く（P5）

`npm run build` で出る `dist/` を**そのまま置くだけ**。`base` は相対（`vite.config.ts`）なので、
ドメイン直下でもサブパス（`/delist/`）でもビルドし直さずに動く。サーバ側の設定は要らない
（1ページのアプリなので SPA フォールバックも不要）。

1. `npm run build` → `dist/` を配信先へコピー（GitHub Pages なら `gh-pages` ブランチか `docs/`、
   Cloudflare Pages なら「ビルドコマンド `npm run build` / 出力 `dist`」、自サイトなら `/delist/` へ rsync）
2. **HTTPS で配ること**（PWA のインストールと Service Worker は HTTPS か localhost でしか動かない）
3. 置き換えたら、ブラウザを1回リロードして新しい Service Worker に入れ替わることを確認する
   （`dist/sw.js` はビルドごとに ID が変わるので、古いキャッシュは activate で消える）

確認すること（デプロイ手順を触ったとき）:

- 公開 URL を開いて `F12 > Application > Manifest / Service Workers` にエラーが無い
- OpenRouter の「ブラウザで承認する」が公開 URL に戻ってくる（`callback_url` はページ URL そのもの）
- リロードしてセッションが残る（保存先はブラウザの localStorage と IndexedDB）

## 3. インストーラの検証（インストーラのフックを触ったら必ず一巡させる）

NSIS のフック（`src-tauri/installer-hooks.nsh`）は**書いただけでは動いたか分からない**。2026-08-23 に3回無言で失敗した実績がある。

1. `makensis` で単体コンパイルして文字列解釈を先に確かめる（`%LOCALAPPDATA%\tauri\NSIS\makensis.exe`。警告 6000「unknown variable」＝`$` のエスケープ漏れ）
2. `/S` でサイレントにインストール → アンインストールを一巡させ、次の4つがすべて無いことを確認する（`rmdir` は数秒遅れる）
   - `%LOCALAPPDATA%\Delist`（インストール先）
   - `%APPDATA%\com.tokatokage.delist`（ユーザーデータ。**サイレントでは「アプリケーションデータを削除」が既定オフ**なので、これを検証するときは GUI でチェックを入れる）
   - `cmdkey /list` に `com.tokatokage.delist` が出ない（API キー）
   - `HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*` に `Delist` が無い
3. クリーン環境で起動 → 初回ウィザード → 生成 → 終了（X ボタン）→ 再起動でデータが残る

既知の落とし穴:
- `core:window:allow-destroy` が無いと X ボタンで終了できない（`onCloseRequested` 後の `destroy()` が黙って拒否される）
- アンインストーラは自分自身を消せない。`/REBOOTOK` はユーザー単位インストールでは HKLM 書き込みが要り黙って失敗する。終了を待って消す使い捨てプロセス方式にしてある
- NSIS の文字列は `'...'` の中に PowerShell の `'...'` を書くと途中で打ち切られる。バッククォート囲み＋`$$` エスケープ

## 4. Tauri 固有部を触ったときの手動チェック（`npm run tauri:dev`）

自動確認できないので、`appFetch` / `saveBlob` / ファイルストレージ / 資格情報 / OAuth を触ったときだけ実施:

1. 本編生成が逐次表示され、停止が効く
2. ComfyUI（通常起動）で画像生成 → 採用できる（`omitOrigin` の経路）
3. カード PNG・エクスポート JSON が保存ダイアログで保存できる
4. 再起動してセッション・画像が残っている（`%APPDATA%\com.tokatokage.delist\data\` の `state.json`・`sessions/`・`images/`・`checkpoints/`）。**セッションは1本＝`sessions/<id>.json`**（旧版から上げたときは `state.json.bak` に移行前の原文が残る）
5. API キーが `state.json` に入っていない（`cmdkey /list` にある）

## 5. データの場所（README と同じ）

```text
%APPDATA%\com.tokatokage.delist\data\
  state.json      … 素材・カセット・UI 設定・接続先（API キーは含まない）
  sessions\       … セッション1本ごとに1ファイル（`<id>.json`）
  images\         … 生成・添付画像
  checkpoints\    … 分岐用チェックポイント（gzip）
```

識別子 `com.tokatokage.delist` は公開後に変更不可（保存先そのもの）。

Web 版はブラウザの中（`localStorage` に軽い状態、IndexedDB `aist-sessions` / 画像 / チェックポイント）。
**オリジンごとに別物**なので、置き場所（ドメインやサブパス）を変えると前のデータは引き継がれない。
移すときは System の「全データをエクスポート」→ 新しい URL で取り込む。
